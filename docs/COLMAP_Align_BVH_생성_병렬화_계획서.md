# Align BVH 최초 생성 병렬화 계획

- 작성일: 2026-09-20
- 기준: 0.3.63, `cccore-native-v7`, `cccore-icp-v6`
- 범위: 전처리에서 수행하는 자체 C++ BVH 최초 생성
- 상태: 구현·실제 성능 검증 완료, 배포 검사 결과는 아래 기록 참조

## 1. 목표와 확인된 원인

`C:/Users/gksru/Desktop/Untitled.blend`의 동일 3점 정렬 입력에서 전체 Align은 46.03초, 전처리는 27.50초다. 두 메시의 BVH 최초 생성은 3.49초와 3.38초, 합계 6.87초다. 이후 준비·ICP·평가는 같은 두 트리를 재사용한다. 추가 생성이나 재사용 결함을 고치는 작업이 아니다.

현재 `MeshBvh::build`는 전체 삼각면 경계를 직렬로 계산한다. `buildNode`는 매 구간의 경계·중심 범위를 직렬 순회하고 `std::nth_element`로 중앙 분할한 뒤 왼쪽·오른쪽 하위 트리를 직렬 생성한다. 공유 노드 벡터의 `resize`와 직접 진행 콜백 호출 때문에 재귀 호출을 그대로 병렬화할 수 없다.

목표는 검색 품질을 보존하면서 생성 작업의 독립 부분을 병렬화하는 것이다. 이전 단일 메시 실험의 MeshLib 생성 0.46초는 개선 여지를 보여 주는 비교값이며, 이번 구현의 보장 시간이나 전체 변환 비용을 포함한 값이 아니다.

## 2. 보존 계약과 제외 범위

- 원본 삼각면·좌표·삼각형 번호, 결정적 중심/원본 번호 중앙 분할, 잎당 최대 8면을 유지한다.
- `nearest`, 보수적 경계 패딩, 정확 점–삼각면 함수, 동거리 원본 번호 선택을 유지한다.
- 표본 수·시드·후보 판정·누적표·ICP 변환·필터·종료 조건·품질 기준은 변경하지 않는다.
- 메시별 세션 캐시, 두 트리의 재사용, LRU·실패 시 정리·기존 실행/저장 계약을 유지한다.
- 공개 CCCoreLib API와 기존 패치 원문을 변경하지 않는다. 새 외부 의존성과 MeshLib 코드를 추가하지 않는다.
- UI·Modifier·Painting·기존 사용자 작업 파일·현재 Blender 프로젝트를 변경하지 않는다.
- 직전 0.3.63 실행 파일과 재빌드 원문을 별도 보존하고, 변경과 무관한 미커밋 작업을 배포본에 섞지 않는다.

## 3. 생성 구조

### 3.1 노드 저장 공간 선할당

기존 중앙 분할의 정확한 노드 수를 먼저 계산하여 노드·원본 번호·임시 경계 배열을 한 번 할당한다. 각 하위 트리에 겹치지 않는 노드 범위를 배정한다. 내부 노드의 두 자식이 연속 배치된다는 검색기 계약을 유지하며, 병렬 작업 중 공유 벡터 크기를 바꾸거나 잠금으로 노드를 하나씩 추가하지 않는다.

### 3.2 삼각면 경계 계산 병렬화

삼각면별 작업을 기존 oneTBB `parallel_for`로 분산한다. 작업자는 자신의 임시 배열 범위만 기록한다. 원본 메시 읽기는 동시 읽기가 가능한 기존 불변 SimpleMesh/PointCloud 수명 안에서 수행한다. 비유한 좌표·오류는 원자적 상태로 전달하고 완성되지 않은 트리를 공개하지 않는다.

### 3.3 하위 트리 병렬 생성

중앙 분할을 완료한 부모는 서로 겹치지 않는 왼쪽·오른쪽 삼각면/노드 범위를 병렬 생성한다. 큰 구간만 `parallel_invoke` 등으로 나누고 작은 구간은 같은 알고리즘을 직렬 실행하여 태스크 비용을 제한한다. 경계의 최솟값·최댓값 집계도 큰 구간에서 병렬화할 수 있으나 결과의 결정성과 메모리 상한을 검증한다. 단정도/배정도 연산과 중심 비교 규칙은 보존한다.

루트 중앙 분할까지 새로운 공간 분할 알고리즘으로 바꾸는 것은 이번 기본 범위에 포함하지 않는다. 성능이 불충분하면 구간별 계측을 근거로 판단하고, 근사 검색·표본 축소로 목표를 맞추지 않는다.

### 3.4 CPU·메모리·취소

워커의 기존 적용 스레드 수를 생성 함수까지 전달하고, 해당 상한의 `task_arena` 안에서 실행한다. 기존 생성 함수 호출은 기본 인자로 소스 호환성을 유지한다. 메모리 예상치에는 최종 배열·임시 배열·태스크 및 실제 oneTBB 스레드 스택 여유를 포함하고, 세션의 기존 BVH 예산/LRU 사전 검사에도 동일한 값을 사용한다.

진행·취소 콜백은 호출 스레드에서만 처리한다. 작업자는 원자적 취소 신호를 주기적으로 확인한다. 콜백 예외·할당 실패·사용자 취소 시 작업을 모두 합류시킨 뒤 배열을 해제하며, 실패한 트리와 불완전 통계를 성공으로 노출하지 않는다. 기존 단일 스레드 설정에서도 교착 없이 작동해야 한다.

## 5. 검증과 채택 기준

1. 변경 전 0.3.63 런타임·소스·해시를 보존한다. 실제 입력·CPU 상한·원본 지문을 고정한다.
2. 작은 메시에서 독립 전수 검색과 거리·최근접점·삼각형 번호를 정확 비교한다. 평면·중복면·같은 중심·동거리·얇은 면·큰 좌표·경계·트리 밖 점을 포함한다.
3. 1/2/4/자동 스레드의 결과와 반복 생성 결정성을 검사한다. 선행 및 생성 중 취소, 호출 스레드 콜백, 콜백 예외, 부족한 메모리 예산과 실패 후 재생성을 검사한다.
4. 실제 11,303,380면 입력에서 기존/수정 워커를 순차 교차 실행한다. 각각 예열 1회와 측정 3회 중앙값으로 최초 생성·후속 검색·워커 최고 메모리를 분리 보고한다. CPU를 쓰는 빌드/다른 성능 실험은 동시에 실행하지 않는다.
5. 정확 거리·등록/평가 표본은 기존과 동일해야 한다. 기존 전체 행렬 허용치 `2e-6`, 거리 `2e-7`, 독립 전수 ICP 엄격 비교를 완화하지 않는다. 생성만 바꾸므로 가능하면 실제 결과도 완전 동일함을 확인한다.
6. 기존 네이티브·솔버 통합과 영향받는 패키징 검사를 수행한다. 생성 시간 개선을 확인한 뒤 같은 `Untitled.blend`를 별도 검증용 Blender에서 실제 Align하고 46.03초 기준과 비교한다. 복원 시간은 별도 보고한다.
7. 생성 중앙값 최소 25% 감소를 채택 목표로 삼는다. 후속 검색/ICP가 유의하게 느려지거나 메모리·취소·정확도 조건을 위반하면 원인을 해결하기 전 채택하지 않는다. 전체 Align 개선폭은 실측값으로 보고하며 생성 시간 감소를 전체 시간으로 표현하지 않는다.

## 6. 산출물과 범위

검증 결과는 이 문서와 `build/verification/bvh-build-optimization/`에 기록한다. 검증된 Release 실행 파일과 다음 패치 버전 ZIP을 제공한다. 사용자 설치본 교체와 Git 커밋/푸시 수행 여부는 실제 완료 범위와 구분해 보고한다. 임시 진단 코드는 제품에 남기지 않는다.

## 7. 구현·실제 측정 결과

노드 선할당, 삼각면 경계 `parallel_for`, 큰 구간의 극값 `parallel_reduce`, 독립 하위 트리 `parallel_invoke`를 적용했다. 큰 구간 경계 집계는 262,144면부터, 하위 트리 병렬 생성은 65,536면부터 사용한다. 중앙 분할의 비교·잎 8면·경계 패딩·검색 함수는 유지했다. 워커의 기존 CPU 상한이 생성·예산 추정에 동일하게 전달된다.

### 최초 생성 분리 비교

같은 11,303,380면 원본과 다섯 배치의 50,000점 조회를 사용했다. 스레드 상한은 31이며 기존 0.3.63과 최종 Release 실행 파일을 교차 순차 실행했다. 각 예열 1회 뒤 측정 3회 중앙값이다. 생성 시간이 각 새 세션의 첫 조회에만 포함되도록 분리했다.

| 항목 | 기존 | 변경 |
| --- | ---: | ---: |
| 메시 한 개 BVH 생성 | 3.294808초 | 0.379302초 |
| 다섯 조회의 검색 합계 | 0.151795초 | 0.150002초 |
| 워커 최고 작업 집합 중앙값 | 745.63MB | 748.86MB |
| BVH 상주 배열 | 179.43MB | 179.43MB |

생성 시간이 88.49% 감소했다. 양쪽 각 4회 × 5만 점 × 5배치, 총 200만 개 거리 값은 보존 기준과 완전히 같았다. 각 세션의 생성 1회·재사용 4회·퇴거 0회를 확인했다. 메모리는 십진 MB다. 생성 최고 추정치는 작업자 스택·태스크 여유를 새로 포함하므로 495.99MB에서 530.53MB로 늘었으며 실제 작업 집합 증가와 구분한다.

### 실제 Blender 전체 Align

지정한 `Untitled.blend`를 별도 Blender 5.2의 격리 설치본에서 실행했다. 동일한 세 마커 초기 배치·등록/평가 표본·파라미터·31스레드를 사용했다. 기존과 변경본 각 1회의 전체 완료 기록이며 프로젝트 복원과 마커 설치는 전체 Align 시간에서 제외한다.

| 항목 | 기존 0.3.63 | 변경 0.3.64 |
| --- | ---: | ---: |
| 두 메시 BVH 생성 합계 | 6.87초 | 0.78초 |
| 전처리 | 27.50초 | 21.84초 |
| 강체·배율 ICP 합계 | 6.30초 | 6.41초 |
| 전체 Align | 46.03초 | 40.55초 |
| 워커 최고 작업 집합 | 1,153.74MB | 1,154.52MB |

전체 Align은 5.48초(11.91%) 감소했다. 최종 행렬의 최대 차이는 0이고 최종 품질 지표도 완전히 같다. 품질은 `PASS`, 등록·독립 평가 표본 지문과 정책은 동일하다. 두 트리를 한 번씩 생성하고 이후 26회 재사용했으며 퇴거는 없다. 변경본 프로젝트 복원은 27.51초로 별도 측정됐다. 원본 `.blend`와 OBJ의 크기·수정 시각은 실행 전후 같다.

C++ 전수 기준 검사는 262,145면 홀수 입력과 65,536면의 같은 중심·동률·평면 입력, 1·2·4·자동 스레드, 거리·최근접점·면 번호 완전 일치, 예산 경계·실패 복구를 통과했다. 독립 전수검색 ICP 16개 조합도 엄격 일치한다. 실제 1,130만 면의 경계 작성 이후 분할 도중 취소는 1스레드 0.048초, 31스레드 0.057초에 종료됐으며 거리 출력이 생성되지 않았다. 시험 실행기의 Windows 진행 파일 교체 잠금은 제한 시간 내 읽기 재시도로 처리했으며 제품 코드를 우회하지 않았다.

최종 네이티브 Release 회귀 51개, 실제 네이티브 통합을 포함한 Python 검사 107개, 확장 필수 구조·등록·스테이징 실제 정렬과 ZIP 격리 설치본 검사를 통과했다. 재빌드 원문과 현재 소스, ZIP·실제 전체 정렬 설치본·최종 워커의 일치도 확인했다. 산출물은 `build/colmap_tools-0.3.64.zip`이며 현재 사용자 설치본은 교체하지 않았다. 전체 결과와 실행 파일·ZIP 해시는 `build/verification/bvh-build-optimization/`에 기록한다. 다른 CPU·낮은 메모리 환경의 성능과 남은 21.84초 전처리의 개선은 이번 결과로 일반화하지 않는다.
