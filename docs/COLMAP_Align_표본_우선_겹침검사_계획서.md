- 목적: 전체 면의 겹침 거리를 먼저 검사하는 준비 과정을 없애고, 정렬·평가에 필요한 표본에만 정확 거리 검사를 수행한다.
- 대표 검증 파일: `C:/Users/gksru/Desktop/Untitled.blend`.

## 1. 변경 요약

```text
현재
원본 면 전체의 중심 거리 검사 → 후보 면 수집·경계 분할
    → 후보에서 정렬 50,000점·방향별 평가 30,000점 추출 → ICP → 독립 평가

변경
원본 면적 색인 생성 → 표면에서 표본 추출 → 추출점의 정확 거리 검사
    → 부족분 추가 추출 → 같은 목표 수 확보 → ICP → 독립 평가
```

원본 전체를 읽는 과정은 남는다. 제거하는 것은 **전체 면마다 상대 메시까지의 거리를 구하는 작업**이다. 정렬 표본 수를 줄여 속도를 맞추지 않는다.

변경 대상은 Blender Align의 Python 준비 과정이다. CCCoreLib의 정확 거리·ICP, 기존 C++ 워커와 격자 재사용은 그대로 사용한다. 앞서 제안한 두 번째 개선안인 준비 루프의 C++ 이관·파일 통신 구조 변경은 포함하지 않는다.

당초 구현 목표는 다음과 같다. 실제 달성 여부는 9절의 측정 조건과 함께 판단한다.

- 대표 프로젝트의 준비 시간 **40초 이하**, 실제 Align 전체 **60초 미만**을 목표로 한다.
- 높은 겹침 입력의 준비 거리 명령을 기존 대비 **90% 이상 감소**시킨다.
- 기존 정확도 허용값, 정렬용 50,000점, 방향별 독립 평가 30,000점을 유지한다.
- 메모리와 임시 디스크 사용량을 함께 측정하며, 부족한 메모리를 대량 병렬 실행이나 조회 묶음 확대로 보충하지 않는다.

근거 자료: [격자 재사용 및 0.3.59 실측](COLMAP_Align_격자_재사용.md), `build/verification/mesh-grid-followup/gui-project-candidate/result.json`과 `summary.json`. 기존 0.3.58의 22분 12초 실행은 취소한 기록이므로 완료 시간 비교에 사용하지 않는다.

## 3. 유지할 동작과 달라지는 의미

| 항목 | 적용 기준 |
| --- | --- |
| 원본 | 내장 정점·면·UV·재질·마커·축·출처·OBJ 파일 보존 |
| 계산 입력 | 기존 계산용 퇴화면 정리를 거친 원본 표면 유지 |
| 거리 대상 | 전체 계산용 원본 삼각면. 축소한 기준 메시로 교체하지 않음 |
| 거리 조회 묶음 | 최대 8,192점 유지 |
| 정렬 | 기존 강체·배율 2단계, 반복 상한 200/1,000, 추가 배율 ±10% |
| 반경 | 기존 초기 위치의 유효 반경과 그 두 배인 후보 반경을 고정 |
| 평가 | 초기 위치에서 고정한 독립 표본으로 모든 후보 비교 |
| 실행 | 단일 네이티브 세션, 격자 메모리 예산·재사용·취소·오류 검증 유지 |
| 사용자 흐름 | 미리보기·승인·버리기·Undo/Redo·저장·복원 유지 |

이 변경은 단순한 캐시 최적화가 아니라 **표본 생성 알고리즘 변경**이다. 이전 버전과 같은 시드라도 표본 좌표·지문과 결과의 작은 수치 차이가 생길 수 있다. 버전 간 표본의 비트 일치를 요구하는 대신, 공통 독립 검사점과 알려진 정답으로 정확도를 비교한다.

기존 [겹침 후보 우선 계획](temp/COLMAP_Align_CC_겹침후보_우선샘플링_계획서.md)의 메시 후보 구성 절차를 대체한다. 그 계획의 목적이었던 ‘실제 겹치는 부분에서 충분한 합격 표본 확보’는 유지한다. 전체에서 50,000점을 한 번만 뽑고 탈락 후 남은 소수 점으로 정렬하던 방식으로 돌아가지 않는다.

점군 후보 선별은 기존 경로를 유지한다. 현재 네 입력 조합에서 표면을 표본화하는 경로를 연결하되, 표면→점군의 역방향 등록과 점군→표면의 고유 점 선택은 바꾸지 않는다.

## 4. 표본 생성 절차

### 4.1 원본 면적 색인을 한 번 생성

1. 기존 초기 변환·정규화를 적용한 계산 메시를 고정한다.
2. 원본 삼각면을 제한된 묶음으로 읽어 면적을 계산한다. 이 과정에서는 네이티브 거리 명령을 호출하지 않는다.
3. 대상 경계상자를 후보 반경만큼 확장한다. 삼각형의 경계상자가 이 범위와 전혀 만나지 않을 때만 추출 대상에서 제외한다. 면 중심이나 꼭짓점의 포함 여부만으로 면을 버리지 않는다.
4. 원본 전체 면적과 추출 대상 면적을 따로 누적하고, 원본 면 순서에 대응하는 배정도 누적 면적 색인을 만든다. 제외된 면의 가중치는 0으로 둔다.
5. 합계의 유한성·양수 여부·누적값의 단조성과 양의 면적이 수치적으로 소실되는 조건을 검사한다. 문제가 있으면 명시적으로 중단한다.

경계상자 필터는 확실히 먼 면을 제외하는 용도다. 살아남은 면 전체가 실제 겹친다고 판정하지 않는다. 거리 반경 경계에 걸친 큰 면도 원본 그대로 표본 추출 대상으로 남는다.

### 4.2 면적 비례로 표면에서 점 추출

- 추출 대상 면적에 비례해 원본 면을 선택하고, 면 내부에서는 균일한 무게중심 좌표로 점을 생성한다.
- 면 번호를 균일하게 뽑거나 원본 정점 중 일부만 고르지 않는다. 삼각화 밀도가 높다는 이유로 그 부위의 기여가 커지지 않게 한다.
- 원본 모델·계산용 면 번호·표본 좌표·시드·생성 순서를 보존한다. 기존 계산용 면 번호를 정리 전 OBJ 면 번호로 잘못 표시하지 않는다.
- 표본은 최대 8,192개씩 기존 정확 거리 함수로 검사한다. 정렬용은 후보 반경, 평가용은 유효 반경을 통과한 점만 채택한다.
- 탈락분은 같은 고정 분포에서 추가 추출한다. 면을 쪼개어 전체 후보 영역을 먼저 만들지 않는다.
- 같은 면에서 여러 점이 나오는 것은 허용하지만, 좌표 복제로 목표 수를 채우지 않는다. 좌표 중복·수치적 퇴화 검사는 유지한다.

면적 비례 제안과 정확 거리 통과 조건을 함께 적용하면, 합격점은 해당 거리 조건을 만족하는 원본 표면에서 얻어진다. 사전 확장 경계상자가 실제 합격 영역을 누락하지 않는지 해석적 형상으로 검증한다.

표면의 면적에 따른 균일 표본화는 [Open3D 공식 설명](https://www.open3d.org/docs/release/tutorial/geometry/mesh.html#sampling)에서도 확인할 수 있다. 이번 구현은 기존 NumPy와 CCCoreLib를 사용하며 Open3D 의존성을 추가하지 않는다.

### 4.3 탐색용·정렬용·평가용 표본 분리

| 표본 | 목적 | 사용 원칙 |
| --- | --- | --- |
| 탐색용 | 합격률과 추가 조회 예산 추정 | 별도 고정 시드, 정렬·평가에 합치지 않음 |
| 정렬용 | 강체·배율 등록 | 합격한 50,000점, 두 등록 단계에서 같은 원본 표본 사용 |
| 겹침 평가용 | 초기·강체·배율 후보 비교 | 방향별 합격한 30,000점, 독립 시드·고정 분모 |
| 전체 참고용 | 원본 전체의 거리 변화 진단 | 기존 독립 표본과 보조 지표의 의미 유지 |

탐색 결과가 좋았던 좌표를 평가점으로 재사용하거나, 정렬 결과에 맞춰 평가점을 새로 뽑지 않는다. 전체 참고 표본을 만드는 기존 함수가 다시 전체 삼각형 좌표 배열을 복제한다면, 같은 면적 색인을 사용하는 제한된 표본 추출로 연결한다. 겹침 조건이 없는 전체 참고용 색인과 경계 필터를 적용한 색인은 구분한다.

### 4.4 낮은 겹침의 추가 탐색과 한도

새 제안 분포는 기존 후보 조각보다 넓다. 기존 `목표 표본 수 × 20` 한도를 그대로 적용하면 5% 미만 겹침에서 정상 입력도 탈락할 수 있으므로 준비 예산을 함께 바꾼다.

검증 출발 정책은 다음과 같다.

1. 별도 탐색 표본 8,192개로 두 반경의 합격률을 함께 측정한다.
2. 겹침 비율 문턱 부근처럼 판정이 불확실하면 총 32,768개, 최대 131,072개까지 정해진 단계로 탐색한다. 좋은 표본이 나올 때까지 무제한 반복하지 않는다.
3. 원본 대비 추정 겹침 비율은 `추출 대상 면적 / 원본 전체 면적 × 탐색 합격률`로 계산한다. 표본 수를 채우며 중단한 정렬·평가 표본의 합격률을 이 추정에 대신 쓰지 않는다.
4. 신뢰구간을 함께 기록한다. 3회까지 확인하는 구조를 반영해 전체 오류 확률 1%를 넘지 않도록 보정한 이항 비율 구간을 사용한다. 최소 겹침 1% 문턱을 구간이 가로지르면 추가 탐색하고, 마지막에도 불확실하면 판정 불가로 중단한다.
5. 충분한 겹침이 확인되면 합격률에 따라 추가 묶음 수를 산정하되, 생성 순서와 추출 확률은 바꾸지 않는다. 목표 합격 수를 채우면 바로 끝낸다.
6. 절대 제안 상한의 출발값은 표본 종류별 `ceil(2 × 목표 수 / 0.01)`로 둔다. 정렬 1,000만 개, 평가 방향별 600만 개이며 대부분의 입력에서 이 상한까지 실행한다는 뜻은 아니다. 낮은 겹침에서의 최악 작업량을 제한하는 값이다.

최소 겹침 문턱 1%는 유지하되, 그 근거가 후보 면적 계산에서 표본 추정으로 달라진다는 사실을 결과에 명시한다. 경계 입력의 판정이 달라질 수 있으므로 1% 전후 사례를 필수 검증한다. 위 탐색 수·신뢰수준·제안 상한은 구현 검증으로 확정하고 정책 버전과 매개변수 지문에 넣는다.

준비 명령 예산은 원본 면 수 대신 방향별 탐색·표본 제안 상한과 실제 묶음 경계로 계산한다. 기존 점군 경로가 필요한 명령도 합산한다. 네이티브 순번 9,999와 준비 최대 9,988, 후속 등록·평가·종료 예약은 지킨다. 입력이나 설정으로 예산을 넘으면 시작 전에 거부한다.

예산이 소진되면 확보 수·시도 수·중단 사유를 반환한다. 원본 전수 거리 검사로 자동 복귀하거나, 반경·표본 수·품질 기준을 완화해 정렬을 계속하지 않는다. 낮은 겹침에서는 조회량이 늘 수 있으며 모든 입력의 1분 미만을 보장하지 않는다.

### 4.5 공간 분포와 얇은 형상

- 기존 원본 대비 분산 범위, 점·직선 퇴화, 공간 구간별 대응 수·대응 유지 검사를 유지한다.
- 얇은 다리·갈비뼈·꼬리와 분리된 작은 조각이 있는 검증 입력에서 부위별 표본 수와 정답 변환 오차를 기록한다. 큰 삼각형 일부만 가까운 경우도 포함한다.
- 공간 분포가 부족하면 정해진 예산 안의 별도 탐색으로 원인을 확인한다. 먼 점을 합격점에 섞거나 부족한 구간의 좌표를 복제하지 않는다.
- 특정 공간 구간을 더 많이 뽑은 진단 표본은 면적 비례 정렬·평가 표본에 무가중으로 섞지 않는다. 유리한 영역만 골라 RMS를 낮추지 않는다.
- 유한한 표본으로 모든 가는 부위의 포함을 보장한다고 설명하지 않는다. 필요한 공간 분포를 확보하지 못하면 기존 차단·검토 기준을 적용하며, 회귀 검증을 통과하기 전에는 채택하지 않는다.

## 5. 메모리·취소·진행 표시

전체 후보 삼각형 좌표와 사분할 배열을 장기간 보관하지 않는다. 면적 색인과 필요한 합격 표본만 유지한다.

- 면적 색인은 작업 전용 파일의 배정도 메모리 매핑 배열로 작성해 전체 배열의 추가 RAM 복제를 피한다. 삼각형 좌표는 묶음별로만 만든다.
- 11,303,380면의 색인 하나는 `8 × 면 수`인 약 **86.2MiB**다. 경계 필터용과 전체 참고용 두 색인이 동시에 필요하면 약 **172.5MiB**의 파일 공간을 사용한다. 이는 전체 프로세스 메모리 상한이 아니다.
- 한 방향의 정렬·평가·전체 참고 표본을 확보한 뒤 색인 매핑과 파일을 해제한다. 다음 방향으로 전체 색인을 누적하지 않는다.
- 운영체제의 파일 캐시·페이지 입출력까지 계측한다. 메모리 매핑을 사용했다는 이유만으로 실제 메모리 사용량이 작다고 판단하지 않는다.
- 색인 작성 중과 표본 묶음 사이에 취소를 확인한다. 완료·취소·예외에서 자기 작업의 임시 파일만 정리하며 디스크 부족·읽기 실패는 정상 오류로 전달한다.
- 상태 메시지는 `표면 표본 준비`, `정렬 표본 확보 32,768 / 50,000`, `독립 평가 표본 준비`처럼 실제 작업을 표시한다. 불확실한 추가 탐색을 완료 비율로 과장하지 않는다.

이 구조는 기존 격자 포인터 배열의 메모리 예산과 별개다. [격자 메모리 예산](COLMAP_Align_격자_메모리_예산.md)은 그대로 유지한다.

| 전체 거리 명령 | 2,779회 | 21회 |

첫 실행의 전체 시간은 약 **86.9%**, 준비 시간은 약 **92.6%**, 전체 거리 명령은 약 **99.2%** 줄었다. 저장 프로젝트는 같은 메시 두 개가 같은 위치에 있는 조건이다. 결과가 기존 위치를 유지한 `REVIEW`인 것은 기준선과 같으며, 이 측정으로 위치가 어긋난 모든 입력의 1분 미만을 보장하지 않는다.

최종 설치본을 새 Blender 프로세스로 각각 열어 순차 반복한 결과는 다음과 같다. 각 반복에서 실제 원본 형상 지문과 정렬·방향별 평가 표본 지문이 동일했고, 결과 미리보기 생성·원본 해시 보존·오류 없음이 확인됐다.

| 반복 | 실제 Align 전체 | 준비 | 네이티브 ICP |
| --- | ---: | ---: | ---: |
| 1회 | 47.310초 | 24.047초 | 4.051초 |
| 2회 | 46.420초 | 24.078초 | 3.881초 |
| 3회 | 46.030초 | 23.937초 | 4.126초 |

반복 중앙값은 **46.420초**, 범위는 **46.030~47.310초**로 기존 전체 시간보다 **86.5% 단축**됐다. 준비 중앙값 **24.047초**로 대표 저장 상태의 준비 40초 이하·전체 60초 미만 목표를 충족했다. 세 반복 모두 준비 거리 명령 17회, 전체 거리 명령 21회, 준비 격자 생성 2회·재사용 15회였다. 첫 실행과 반복은 따로 보고하며, 운영체제 파일 캐시를 강제로 비운 측정은 아니다.

### 9.3 메모리와 원본 보존

첫 실제 실행의 Align 구간에서 0.25초 간격으로 관측한 Blender·Python·네이티브 프로세스 작업 집합 합계 최고값은 **6,247,821,312바이트(약 5.82GiB)**였다. 이는 관측된 합계이며 순간 최고값이나 시스템 전체 메모리 상한이 아니다. 개별 프로세스의 운영체제 최고 메모리 값은 발생 시점이 다르므로 서로 더하지 않는다.

면적 색인 두 파일은 한 방향에서 총 **180,854,080바이트(약 172.5MiB)**였다. 준비 단독 측정의 프로세스 합계 관측 최고값은 약 **1.65GiB**이며 Blender를 포함하지 않는다. 시스템 페이징 원시 측정값도 보관했으나 다른 프로세스의 입출력을 이 작업에 귀속하지 않았다. 메모리 관측 오류는 없었고, 첫 실행 전후 원본 프로젝트 해시는 같았다.

### 9.4 정확도 검사와 남은 한계

실제 네이티브 엔진을 포함한 솔버 **52개**, 기존 겹침 **15개**, 계약 **10개**, Blender 런타임 **8개**가 통과했다. 새 표면 샘플러 **15개**는 면적 분포, 독립성, 문턱 판정, 취소, 두 번째 색인 생성·확장 실패 시 정리, 누적 면적 정밀도 소실·오버플로 거부, 묶음 크기별 재현성을 포함한다. 배포 빌드의 필수 검사와 격리 설치의 네 입력 조합·승인/Undo·OBJ/UV 보존·환경 검사가 통과했다.

최종 소스로 Blender 저장·축 의존성 **10개**와 화면 연결 **11개**를 직접 재실행해 통과를 확인했다. 구버전 승인 기록의 복원 계약은 그대로 유지한다.

기존 비대칭 곡면의 겹침 **100%·70%·40%·20%**와 추가 **10%** 사례는 동일한 정답 오차 기준을 통과했다. 추가 진단 사례의 실패는 숨기거나 허용값을 완화하지 않았다.

| 추가 진단 | 0.3.59 | 0.3.60 | 판정 |
| --- | ---: | ---: | --- |
| 5% 겹침 위치 RMS / 대각선 | 0.004767 | 0.004704 | 양쪽 모두 0.003 초과 |
| 5% 겹침 상대 배율 오차 | 0.003609 | 0.003456 | 양쪽 모두 0.003 초과 |
| 5% 겹침 회전 오차 | 0.3683도 | 0.3641도 | 양쪽 모두 0.3도 초과 |
| 얇은 곡면 20% 겹침 상대 배율 오차 | 0.007138 | 0.007049 | 양쪽 모두 0.003 초과 |
| 얇은 곡면 100% 겹침 상대 배율 오차 | 0.006399 | 0.006506 | 양쪽 모두 0.003 초과 |

얇은 곡면은 기존 곡면의 두 축을 0.15배로 축소한 별도 진단 입력이다. 위 실패는 이전 정책에서도 재현된 한계이며 이번 준비 최적화가 해결한 것으로 표시하지 않는다. 기본 회귀 다섯 사례와 별도 선택하는 진단 사례를 구분해 실행했다.

실제 고양이 전체 입력에 회전 **0.1도**, 배율 **1.001**, 대각선에 비례한 작은 이동을 추가한 실험도 수행했다. 이 실험은 강체 ICP 내부에서 **120초 상한에 도달해 취소**했으며 완료 시간과 정답 복원 오차를 얻지 못했다. 성공한 정확도 검증으로 계산하지 않는다. 따라서 이번 대표 저장 상태의 1분 미만 목표와, 잔여 변환이 있는 대용량 메시의 정밀 등록 속도·정확도 검증은 구분해야 한다.

### 9.5 재현 자료

검증 자료는 저장소의 무시된 `build/verification/surface-sampling/` 아래에 보관한다. 사용자 절대 경로와 큰 입력·로그는 제품이나 커밋에 넣지 않는다.

- 준비 단독: `benchmark_preparation.py`, `preparation.json`.
- 실제 GUI: `run_gui_align.py`, `run_gui_repeats.ps1`, `gui-first/`, `gui-repeat-1/`~`gui-repeat-3/`의 `summary.json`·`result.json`.
- 반복 집계: `summarize_benchmarks.py`, `benchmark-summary.json`.
- 알려진 잔여 변환: `benchmark_known_transform.py`, `known-transform-report.json`, `known-transform/benchmark-progress.json`.
- 곡면: `partial-overlap.json`, `partial-overlap-thin20.json`, `partial-overlap-thinfull.json`, `baseline-partial-overlap-*.json`.
- 최종 빌드·실제 설치: `build-extension-final.log`, `installation.json`, `actual-installed.json`, `actual-install-final.log`.
- 표면 표본·저장 복원·화면 회귀: `surface-tests-final.log`, `persistence-tests.log`, `ui-tests.log`.

계약·Blender 런타임 검사는 실행 도구의 종료 코드와 출력으로 확인했고 별도 로그 파일은 생성하지 않았다. 위 자료가 없는 새 환경에서는 저장소의 관련 검사와 지정 프로젝트 측정을 다시 실행해야 한다.
