# COLMAP Align CCCoreLib 엔진 교체 계획서

- 작성일: 2026-09-03
- 상태: 실험 구현·설치·검증 완료
- 대상: `codex/align-test-env` 브랜치의 독립 실험 애드온 `colmap_align_test_env`
- 소스: `E:\DEV\DEV_RND\colmap_align_test_env\source`
- 목적: 현재 UI와 승인 흐름을 유지하면서 Small GICP 정밀 정렬을 CCCoreLib 기반 정렬로 교체한다.
- 실행 기록: [구현·검증 기록](COLMAP_Align_CCCoreLib_구현검증.md). 사용자 승인에 따라 실험 구현·설치를 진행했으며 main 통합은 별도 요청 대상으로 유지한다.

## 1. 결정 요약

1. 정밀 정렬 엔진을 **CCCoreLib 하나로 교체**한다. 사용자에게 Small GICP/CC 선택 메뉴를 추가하지 않는다.
2. `3점 마커 정렬`은 현재 구현을 유지한다. `Align`의 내부 처리만 **CC 이동·회전 정렬 → CC 균일 스케일 정밀 보정 → 평가**로 바꾼다.
3. 레이어의 기존 점군·표면 아이콘이 정밀 정렬의 입력 형상도 결정한다. 연결 메시를 선택했다면 희소 COLMAP 점군 대신 그 메시를 사용한다.
4. 표면 정렬에서는 기준 삼각면을 유지한다. 이동 표면에서 면적에 비례해 추출한 점을 기준 삼각면에 대응시킨다.
5. 결과는 모델 소유 ID의 공통 정렬 행렬 하나로 적용한다. 연결 COLMAP 점군·카메라·메시는 기존 좌표 계약에 따라 함께 이동한다.
6. `ICP 취소`, `결과 버리기`, `정렬 승인`, A 그룹 편입, 마커 정리, 되돌리기/다시 실행을 유지한다.
7. Blender 외부의 전용 실행 파일에서 CCCoreLib를 호출한다. 사용자의 CloudCompare 설치 경로나 GUI에 의존하지 않는다.
8. 실험 환경에서 검증한 뒤 통합 가능한 소스 구조로 관리한다. main 반영은 별도 요청 때 수행한다.

## 2. 현재 구현에서 확인한 출발점

| 항목 | 현재 구현 | 교체 시 처리 |
| --- | --- | --- |
| 작업공간 | A/P 이중 뷰와 오른쪽 제어 패널 | 유지 |
| Data Layers | 모델 이름, 점군, 표면, 축 설정, 전체 표시 아이콘 | 위치와 조작 유지 |
| 연결 OBJ | COLMAP과 같은 소유 ID, 별도 축 설정 | 유지 |
| 형상 표시 | 레이어별 점군 또는 표면 하나 선택 | 유지하고 실제 정렬 입력에 연결 |
| 마커 | A끼리 종류 고정, P끼리 독립 종류 고정 | 유지 |
| 초기 정렬 | 3점 마커 정렬 또는 현재 P 위치 | 두 경로 모두 유지 |
| 정밀 정렬 대상 | 숨김 여부와 무관한 A 그룹 전체, 선택 P 하나 | 유지 |
| Align | 정밀 Small GICP 후 Refine 자동 실행 | CC 기반 두 단계로 교체 |
| 스케일 | 마커용 체크박스와 자동 정밀 보정이 구분됨 | 의미 유지 |
| 완료 | 미리보기 후 버리기 또는 승인 | 유지 |
| 승인 | 공통 변환 확정, P의 A 편입, 마커 정리, Undo 기록 | 기존 원자적 승인 API 유지 |
| Export | 공통 변환과 COLMAP 축을 사용한 내보내기 | 좌표·카메라 계약 유지 |

확인한 코드:

- `tools/align/ui/panels.py`: 현재 패널과 버튼, 상태 로그.
- `tools/align/operators/marker_alignment.py`: 고정 자동 Align 실행과 승인.
- `tools/align/alignment/icp_runtime.py`: 입력 구성, 작업 상태, 결과 검증과 승인.
- `tools/align/model_repository.py`, `marker_geometry.py`: 소유 모델과 연결 형상의 구분.
- `tools/align/merge_export/transforms.py`: 앵커 COLMAP 좌표로 내보내는 변환.

현재 `Align`은 `PRECISE`, `SMALL_GICP`, `scale_refine_enabled=True`를 전달한다. 패널에는 엔진 선택이나 정밀 정렬용 별도 스케일 체크박스가 없다.

현재 정밀 입력 생성 경로는 `repository.models`의 등록점을 읽고, 연결 메시 저장소의 삼각면을 전달하지 않는다. 따라서 메시에서 마커를 찍는 기능과 메시를 실제 정밀 정렬에 사용하는 기능은 구분되어 있다. 이번 교체는 실행 엔진 이름만 바꾸는 작업으로 끝낼 수 없다.

## 3. 유지할 사용자 흐름

### 3.1 정렬 준비

1. 기존 방식으로 COLMAP 또는 OBJ를 불러온다.
2. 기존 레이어 아이콘에서 각 데이터의 점군 또는 표면을 선택한다.
3. 축이 다르면 기존 톱니 아이콘의 축 설정 창에서 조정한다.
4. 정렬할 P 하나를 선택한다. 기준은 기존과 동일하게 A 그룹 전체다.
5. 필요하면 마커 쌍을 지정하고 `3점 마커 정렬`로 초기 위치를 맞춘다.

이미 초기 위치가 충분히 가까운 경우 마커 없이 `Align`을 실행하는 경로도 유지한다.

### 3.2 Align 실행과 완료

```text
현재 P 위치 또는 3점 마커 정렬 미리보기
    ↓ Align
입력 형상·축·행렬 고정
    ↓
CC 이동·회전 정렬
    ↓
CC 균일 스케일 정밀 보정
    ↓
독립 평가 및 후보 선택
    ↓
결과 미리보기
    ├─ 결과 버리기 → 실행 전 상태 복원
    └─ 정렬 승인 → 공통 변환 확정, P를 A에 편입, 마커 정리
```

마커 미리보기에서 시작한 작업을 취소하거나 버리면 해당 마커 미리보기로 돌아간다. 현재 위치에서 직접 시작한 경우에는 실행 전 확정 위치로 돌아간다. 기존 시점 복원과 Undo/Redo 계약도 함께 보존한다.

### 3.3 UI에서 바뀌는 부분

새 패널, 엔진 선택 메뉴, 별도 표면 정렬 버튼은 추가하지 않는다. 기존 상태 로그와 안내 문구를 바꾼다.

| 위치 | 변경 내용 예시 |
| --- | --- |
| Align 설명 | 현재 P 위치 또는 마커 정렬 결과에서 CC 정밀 정렬을 실행합니다. |
| 기존 기준/이동 안내 | 기준: A 전체 2개 · 표면 / 이동: P 1개 · 표면 |
| 숨김 기준이 있는 경우 | 숨김 A 레이어 1개도 기준에 포함됩니다. |
| 실행 상태 | 입력 준비 → 이동·회전 정렬 → 스케일 정밀 보정 → 결과 평가 |
| 결과 상태 | 거리 RMS 전/후, 개선율, 스케일 변화, 검토 사유 |
| 애드온 환경 확인 | Small GICP 실행 환경 검사 → CC 정렬 엔진 검사 |

상태 로그에서 실제 사용한 형상 조합을 보여준다. 표면을 선택했는데 희소 점군을 사용하거나, 표면 정렬을 했는데 점군 RMS로 표시하는 일이 없어야 한다. 거리 단위를 확인할 수 없으면 모델 단위로 표시한다.

`Marker Refine Scale`은 **마커 초기 정렬에서 균일 스케일을 추정할지** 정하는 기존 의미를 유지한다. 체크를 해제해도 현재 Align의 자동 정밀 스케일 보정은 별도 단계라는 점을 툴팁에 명확히 한다.

## 4. 입력 형상 결정

### 4.1 레이어별 입력

| 레이어 선택 | 사용할 원본 | 표시 축 |
| --- | --- | --- |
| COLMAP 점군 아이콘 | 해당 COLMAP의 희소 타이포인트 | COLMAP 축 |
| 연결 표면 아이콘 | 같은 소유 ID의 연결 OBJ 정점과 삼각면 | 연결 메시 축 |
| 독립 OBJ 레이어 | 해당 OBJ 정점과 삼각면 | 독립 OBJ 축 |

메시에서 정점만 추출해 점군으로 취급하는 방식은 표면 정렬 경로로 사용하지 않는다. 텍스처·MTL·UV는 정렬 입력에서 제외하고 원본 데이터에는 손대지 않는다.

전체 눈 아이콘은 표시 기능을 유지한다. **숨겨진 A 레이어도 기존처럼 기준에 포함**하며, 숨기기 직전 선택된 형상 종류를 사용한다. 숨김으로 정렬 대상에서 제외되는 것처럼 동작을 바꾸지 않는다.

### 4.2 A/P 종류 고정과 충돌 처리

- A 역할과 P 역할의 형상 종류는 서로 달라도 된다.
- 마커 쌍이 있다면 마커의 A 종류와 P 종류를 각각 존중한다.
- 확인을 위해 다른 형상으로 보기를 바꾼 뒤 Align을 누를 경우, 현재 선택과 마커 종류가 다르면 해당 아이콘으로 되돌리도록 안내한다. 마커를 다른 형상에 재해석하지 않는다.
- A 그룹 전체의 선택 형상이 하나의 종류로 일치해야 한다. 점군과 표면이 섞이면 Align을 시작하지 않고 불일치 레이어를 알려준다.
- 마커가 없는 직접 Align도 A 그룹 전체의 종류를 통일하고 P는 독립적으로 선택한다.
- 연결 메시 누락, 유효 삼각면 없음, 형상 선택 없음, 입력 파일 변경은 시작 전에 구체적인 레이어 이름과 함께 안내한다.
- 메시 누락 시 점군으로 조용히 대체하지 않는다.
- 실행과 결과 미리보기 동안 입력을 바꾸는 종류 전환·축 변경·레이어 구성 변경은 잠근다. 표시만 바꾸는 기존 조작을 허용하는 경우에도 입력 스냅샷은 바꾸지 않는다.

안내 예시:

> A 그룹의 정렬 형상이 섞여 있습니다. Component 0은 점군, Component 1은 표면입니다. 레이어 아이콘에서 같은 종류로 맞추십시오.

이 제약은 CCCoreLib의 한 번의 등록 호출이 기준 점군 또는 기준 메시를 받는 구조에 맞춘 것이다. 점군과 메시가 혼합된 기준을 위해 일부 표면을 몰래 점으로 변환하는 처리는 하지 않는다.

### 4.3 지원 조합과 계산 방향

| A 기준 | P 이동 | 내부 계산 | 최종 적용 |
| --- | --- | --- | --- |
| 점군 | 점군 | P 점군 → A 통합 점군 | P에 결과 적용 |
| 표면 | 점군 | P 점군 → A 통합 삼각면 | P에 결과 적용 |
| 표면 | 표면 | P 표면의 면적 표본 → A 통합 삼각면 | P에 결과 적용 |
| 점군 | 표면 | A 통합 점군 → 현재 P 삼각면으로 역방향 계산 | 계산 결과의 역행렬을 P에 적용 |

마지막 조합에서도 사용자 화면과 저장 데이터의 A는 움직이지 않는다. 외부 작업용 복사 입력의 계산 방향만 바꾸고, P에 적용할 변환으로 되돌려 반환한다. 역방향 여부와 평가 거리의 방향을 결과 메타데이터에 기록한다.

CCCoreLib의 등록 API에서 메시가 기준 역할을 맡는다는 점에 근거한 설계다. 따라서 마지막 행은 점군–표면 대응을 유지하기 위한 어댑터 기능이며, CC가 이동 메시를 직접 받는 API라고 설명하지 않는다. [공식 등록 API](https://github.com/CloudCompare/CCCoreLib/blob/master/include/RegistrationTools.h)

여러 A 메시를 사용할 때는 각 A의 공통 변환과 메시 축을 반영한 후 정점·삼각면 배열을 결합한다. 원본 모델 ID와 면 소유 관계를 보존하며 새 메시 파일이나 Blender 오브젝트를 생성하지 않는다.

## 5. 엔진 구성

### 5.1 프로세스 구조

```text
Blender Align
  ├─ 기존 UI / 마커 / 정렬 상태 / 승인 / Undo
  ├─ 형상별 불변 입력 생성
  └─ 작업 디렉터리 + 실행 관리
          ↓
  colmap_cccore_worker.exe
          └─ 고정 버전 CCCoreLib 공유 라이브러리
          ↓
  진행 상태 / 결과 행렬 / 평가 수치
          ↓
Blender의 기존 결과 미리보기·승인 API
```

- C++ 전용 작업 실행 파일과 CCCoreLib 공유 라이브러리를 배포한다.
- Blender 프로세스에서 네이티브 라이브러리를 직접 불러오지 않는다.
- CloudCompare.exe 호출은 기존 비교 실험에만 사용한다.
- CloudCompare 앱의 GUI·qCC 구현을 제품에 복사하지 않고 CCCoreLib 공개 API에 연결한다.
- 외부 실행 파일의 오류가 Blender 종료로 이어지지 않도록 기존 프로세스 격리를 유지한다.
- 코드와 CMake 설정은 저장소에 두고 빌드 산출물은 Git 제외 캐시와 패키징 영역에 둔다.
- Small GICP가 없어도 가져오기·내보내기가 동작해야 한다. 다른 기능이 사용하는 Python/NumPy 런타임은 사용처를 확인해 유지한다.

### 5.2 버전과 빌드 고정

첫 구현 단계에서 CCCoreLib 커밋, 빌드 도구, 플랫폼, 옵션, 라이선스, 산출물 SHA-256을 고정한다. 변경되는 `master`를 실행 시 내려받지 않는다.

현재 공식 소스에는 `adjustScale`, `minScale`, `maxScale`이 있다. 이전 실험의 CloudCompare 2.13.2 실행 파일과 최신 코어의 기능이 같다고 가정하지 않는다. 이 API를 제공하는 후보 커밋에서 스케일 경계와 반환 변환의 일관성을 검증한 다음 채택한다. [공식 매개변수](https://github.com/CloudCompare/CCCoreLib/blob/master/include/RegistrationTools.h), [공식 계산 구현](https://github.com/CloudCompare/CCCoreLib/blob/master/src/RegistrationTools.cpp)

빌드는 Windows x64를 우선 대상으로 한다. CGAL과 QtConcurrent는 사용하지 않는 구성을 우선 검증한다. 병렬화 의존성은 성능 측정 후 필요한 경우에만 명시적으로 추가하고 버전·라이선스를 고정한다. [공식 빌드 설명](https://github.com/CloudCompare/CCCoreLib#main-cmake-options)

`CCCORELIB_SCALAR_DOUBLE`을 점 좌표의 배정밀도 보장으로 해석하지 않는다. 현재 공식 `PointCoordinateType`은 float이므로 큰 좌표와 작은 형상 오차를 다룰 수 있도록 입력 정규화를 별도로 적용한다. [공식 좌표 타입](https://github.com/CloudCompare/CCCoreLib/blob/master/include/CCTypes.h)

### 5.3 입력·출력 계약

기존 작업 ID, 입력 지문, 진행 파일, 취소 요청, 원자적 결과 확정 구조를 재사용한다. 점군 전용 계약에 삼각면과 형상 출처를 추가하므로 작업 프로토콜 버전을 올린다.

전달 항목:

- 소유 모델 ID와 MAIN/COMPANION 출처, 형상 종류.
- 정점/점의 float64 좌표, 삼각면 정수 인덱스, 원본 점 ID 또는 면 소유 정보.
- 원본 지문과 형상 리비전, 표시 축, 시작 공통 행렬.
- A 목록, P ID, 마커 서명, 샘플링과 정렬 매개변수.
- 좌표 정규화 행렬, 계산 방향, 엔진 버전과 작업 프로토콜 버전.

배열은 헤더가 명시된 little-endian 바이너리 파일과 JSON 명세로 교환한다. C++ 쪽에서 dtype, 크기, 인덱스 범위와 파일 길이를 검증한다. 불필요한 OBJ 저장·재파싱은 하지 않는다. 작업 디렉터리 밖을 가리키는 입력 참조와 불완전한 결과는 거부한다.

출력에는 P에 적용할 프로젝트 좌표계 변환, 선택 후보, 평가 수치, 스케일, 종료 사유, 입력 지문을 포함한다. 다른 엔진의 전용 필드를 가짜 값으로 채우지 않고 CC 결과 계약으로 파싱한 뒤 기존 미리보기·승인 인터페이스에 연결한다.

## 6. 자동 정밀 정렬 정책

### 6.1 이동·회전과 스케일 보정

| 단계 | 정책 |
| --- | --- |
| 초기값 | 현재 P 공통 행렬 또는 마커 미리보기의 최종 공통 행렬 |
| 1단계 | 크기를 고정하고 이동·회전을 계산 |
| 2단계 | 1단계 위치에서 양의 균일 스케일을 포함해 정밀 보정 |
| 스케일 한도 | Align 시작 시 P 크기를 기준으로 최종 추가 배율 0.90~1.10(±10%) |
| 선택 | 동일 평가 입력으로 1단계와 2단계를 비교 |
| 보정 미채택 | 2단계가 유효하지만 개선하지 않으면 CC의 1단계 후보를 유지하고 사유 표시 |
| 계산 실패 | 실패 또는 취소로 반환하고 실행 전 상태 복원 |

마커의 균일 스케일이 포함된 초기 행렬을 기준으로 추가 보정 범위를 계산한다. 1단계의 배율은 1이므로 단계별 보정이 누적되어 ±10% 한도를 벗어나면 안 된다.

역방향 계산에서는 코어에 적용하는 스케일 범위를 `1/1.10 ~ 1/0.90`로 바꾸고, P 방향으로 역변환한 결과에서 다시 검사한다.

코어의 경계 매개변수만 신뢰하지 않는다. 반환 행렬로 원본 입력을 다시 변환하여 경계·거리·행렬 일관성을 검증한다. 잘못된 결과를 사후에 배율만 잘라 맞추지 않는다. 경계에 도달한 결과는 검토 사유를 표시한다.

이전 Small GICP 자동 정렬의 횟수나 목적함수를 그대로 흉내 내는 것이 아니라, 같은 버튼 흐름을 유지하면서 ±10%로 확대한 보정 범위를 CC의 계산에 맞게 구현한다.

### 6.2 표면 표본과 부분 겹침

- P 표면 표본은 삼각형 면적에 비례해 추출한다. 정점 밀도를 표면 면적처럼 취급하지 않는다.
- 최적화와 평가 표본을 분리하고 각각 난수 시드와 입력 지문을 고정한다.
- A 삼각면은 정점 점군으로 대체하지 않는다.
- 점군 입력의 기존 유효점·노이즈 처리와 가중치 사용처를 확인하고, CCCoreLib에 맞는 매핑 여부를 검증한다.
- 코어 내부의 추가 무작위 재표본화를 통제하고 실제 사용 점 수를 기록한다. 외부 표본과 내부 표본 상한이 중복 적용되지 않게 한다.
- 기본 표면 거리는 부호 없는 거리로 시작한다. 노멀 방향·메시 개방 경계에 대한 검증 없이 부호 있는 거리를 기본으로 켜지 않는다.
- 겹침 비율은 계산에 남기는 data 쪽 점 비율이다. 특히 역방향 계산에서는 사용자 P 표면의 겹침 비율과 같다고 표시하지 않는다.
- 초기 실험값은 기존 비교 실험의 표면 표본 50,000개, 겹침 90%, 최대 100회에서 출발한다. 이 값은 배포 확정값이 아니며 희소 점군에 일괄 적용하지 않는다.
- 겹침이 낮은 자료와 형상 크기가 다른 자료를 포함해 검증 후 정밀 프리셋을 고정한다. 후보별로 겹침을 바꾸며 최저 RMS만 고르는 정책은 사용하지 않는다.

첫 교체에서는 수동 영역 선택이나 별도 고급 설정 패널을 추가하지 않는다. 부분 겹침 때문에 생기는 잔차가 재현되면 해당 기능은 후속 계획으로 분리한다.

## 7. 좌표·카메라·행렬 계약

기호:

- `C_i`: 소유 모델의 공통 정렬 행렬.
- `N_i,g`: 해당 모델의 선택 형상 g에 대한 표시 축 변환.
- `X_i,g`: 원본 점 또는 메시 정점.
- `D`: 이번 정밀 정렬이 산출한 프로젝트 좌표계의 추가 변환.

현재 표시와 입력은 다음 관계를 유지한다.

```text
프로젝트 좌표 = C_i × N_i,g × X_i,g
최종 P 공통 행렬 = D × 시작 P 공통 행렬
```

두 단계 결과를 합칠 때는 `D = D_refine × D_rigid`이다. 시작 공통 행렬에 이미 마커 정렬이 포함되어 있으면 마커 변환을 다시 곱하지 않는다.

연결 메시 축과 COLMAP 축은 별개다. 메시로 D를 계산했더라도 COLMAP에 메시 축을 적용하지 않는다. 각 형상은 자기 N을 유지한 채 같은 C를 공유한다.

정규화는 모든 입력에 같은 `H`를 적용한다. 공통 원점 이동과 양의 균일 길이 정규화를 사용하고, 결과는 다음과 같이 복원한다.

```text
정방향 D = inverse(H) × D_normalized × H
역방향 D = inverse(H) × inverse(E_normalized) × H
```

정규화 길이를 정할 수 없는 퇴화 입력은 거부한다. 원본 저장 좌표와 확정 공통 행렬은 float64로 유지한다. 비균일 스케일·반사·비강체 변환은 승인하지 않는다.

COLMAP 출력은 기존 식을 재사용한다.

```text
원본 COLMAP → 앵커 COLMAP
= inverse(N_anchor,colmap) × C_i × N_i,colmap
```

COLMAP의 world-to-camera 회전·이동은 기존 내보내기 함수를 통해 처리한다. 카메라 extrinsic에 메시용 4×4 행렬을 그대로 곱하는 방식으로 구현하지 않는다. 점과 카메라의 변환 후 재투영 불변성을 검사한다. [COLMAP 좌표와 포즈 형식](https://colmap.github.io/format.html#images-txt)

## 8. 결과 평가와 승인

### 8.1 평가값

CC 내부 최종 RMS와 애드온의 정렬 전후 평가를 구분한다.

- 점군–점군: 같은 평가 점을 이용한 점간 거리와 대응 분포.
- 점군–표면: 같은 평가 점에서 실제 삼각면까지의 거리.
- 표면–표면: 독립 면적 표본을 이용한 양방향 삼각면 거리.
- 역방향 점군–표면: 실제 거리 계산 방향을 표시하고, 거리 통계는 최종 P 변환을 적용한 프로젝트 좌표에서 다시 계산한다.
- 비교 항목: RMS, 거리 중앙값과 상위 백분위, 고정 비율 절사 RMS, 사용 표본/유효 대응 수, 공간 구간별 오차, 스케일 변화.
- 최적화 표본과 동일한 표본만으로 품질을 확정하지 않는다.

부분 겹침에서는 전체 RMS가 비겹침 영역의 영향을 받는다. 절사 RMS도 후보마다 남는 대상이 달라질 수 있으므로 실제 겹침 정답처럼 표시하지 않는다. 서로 다른 형상 모드의 거리나 이전 Small GICP 전용 임계값을 같은 기준으로 비교하지 않는다.

### 8.2 승인 가능 상태

| 상태 | 동작 |
| --- | --- |
| 유효하며 평가 통과 | 현재처럼 미리보기 후 사용자가 승인 |
| 유효하나 개선 미미·일부 구간 악화·스케일 경계 도달 | 검토 사유와 함께 미리보기, 승인 여부는 사용자가 결정 |
| 입력 불일치·행렬 오류·대응 부족·작업 실패 | 승인 차단, 원상 복원 |
| 사용자 취소 | 중간 결과를 승인 대상으로 남기지 않음 |

기존 PASS/REVIEW와 실패 구분을 유지하되, CC 거리 모드별 평가 계약과 버전을 둔다. 수치 임계값은 합성 정답과 실데이터 검증에서 고정하고 단순히 CC 최종 RMS가 감소했다는 이유로 PASS를 부여하지 않는다.

실행 입력 지문에는 원본, 삼각면, 형상 종류와 출처, 양쪽 축, 시작 공통 행렬, A 목록, P, 마커와 매개변수가 포함되어야 한다. 승인 직전 현재 상태와 다시 비교한다.

## 9. 취소·오류·저장 호환성

- 준비·정렬·평가 전체에서 취소를 받을 수 있어야 한다.
- 코어 진행 콜백을 기존 진행 표시와 취소 요청에 연결한다.
- 응답 없는 작업 프로세스는 정해진 유예 시간 후 종료하고 자식 프로세스까지 정리한다.
- 작업 파일은 작업 ID별로 분리하고 완성된 결과만 원자적으로 공개한다.
- 오류 시 모델 행렬·그룹·마커·Undo 기록이 일부만 바뀌지 않도록 기존 원자적 승인 경계를 유지한다.
- 이전 Small GICP 결과가 저장된 프로젝트의 공통 행렬과 출처 기록은 보존한다. 파일을 열었다는 이유로 정렬을 다시 수행하거나 기존 결과를 CC 결과로 바꾸지 않는다.
- 기존 엔진 식별자는 과거 결과를 읽는 호환 경로에서만 허용한다. 새 정렬은 CC로 실행한다.
- 새 CC 결과에는 코어 커밋, 실행 파일 지문, 알고리즘 버전, 형상 조합, 계산 방향, 표본 설정, 스케일 정책을 기록한다.
- 저장 스키마 변경은 필요한 필드에 한정한다. 기존 프로젝트의 축·연결 메시·마커 출처를 누락시키지 않는다.

### Small GICP 정리

교체 검증이 끝나면 실험 애드온의 실행 경로, 전용 solver/worker, Small GICP 의존성, 환경 검사, 빌드 프로필 문구를 정리한다. 다른 기능이 쓰는 공통 수치·평가·Python 런타임은 유지한다.

개발용 Open3D/Hybrid 파일과 통합 배포 스크립트는 사용처를 확인한다. 이번 교체를 이유로 관계없는 도구의 배포나 공개 API를 삭제하지 않는다. 실험 기본 배포에 다른 정렬 엔진을 포함하거나 CC 실패 시 자동 실행하지 않는다.

과거 프로젝트를 읽기 위한 식별자와 출처 해석은 삭제 대상에서 제외한다. 비교용 Small GICP 결과는 별도 산출물과 이전 Git 상태로 보존하며, 사용자 UI에 계속 두지 않는다.

## 11. 배포와 라이선스

CCCoreLib는 LGPL-2.0-or-later이며 CloudCompare 앱과 라이선스 범위를 구분해야 한다. 공유 라이브러리 연결을 기본으로 하고, 채택한 파일·의존성의 실제 라이선스와 배포 조건을 확인한다. [CCCoreLib 공식 라이선스](https://github.com/CloudCompare/CCCoreLib#license), [라이선스 원문](https://github.com/CloudCompare/CCCoreLib/blob/master/LICENSE.txt)

패키지에는 코어 버전, 라이선스와 저작권 고지, 해당 버전 소스 제공 정보, 수정 내역, 라이브러리 교체·재빌드에 필요한 정보를 포함한다. 공유 라이브러리라는 이유만으로 의무가 자동 충족된다고 가정하지 않는다.

기존 ADR-0006의 **프로세스 격리·고정 런타임·스테이징 검증** 원칙은 유지한다. Small GICP를 기본으로 지정한 부분은 CC 교체 검증 후 새 ADR로 대체한다. 현재 main의 배포 결정을 이 계획서 작성만으로 변경하지 않는다.

실험 환경 구성 변경과 기능 구현은 구분해 추적한다. 설치본과 ZIP을 직접 수정하지 않고 소스에서 빌드한다. 사용 중인 Blender를 임의로 종료하거나 설치 잠금 검사를 우회하지 않는다.

## 12. 구현 순서와 단계별 완료 기준

| 단계 | 작업 | 완료 기준 |
| --- | --- | --- |
| 1 | 현재 동작·입력·배포 기준 고정, 코어 커밋 선정 | UI 상태 계약과 라이브러리 버전·스케일 경계 검증 기록 |
| 2 | 독립 CC 실행 파일과 입력·결과 계약 구현 | Blender 없이 네 조합의 정답 변환·오류·취소 검사 통과 |
| 3 | 레이어 형상 입력과 좌표 어댑터 연결 | 연결 메시·독립 OBJ·복수 A·역방향 입력이 올바른 P 변환 반환 |
| 4 | 기존 Align 자동 실행과 승인 연결 | 직접/마커 시작, 미리보기, 버리기, 승인, Undo/Redo 통과 |
| 5 | 저장 호환·패키징·환경 검사 교체 | 이전 프로젝트 복원, CC 포함 설치본의 실제 정렬 통과 |
| 6 | 동일 초기값 실데이터 비교와 COLMAP 왕복 검증 | 전후 결과·변환·평가·실행 시간·메모리 기록 |
| 7 | Small GICP 전용 실행 의존성 정리와 문서 갱신 | CC 단일 기본 엔진으로 설치·사용 가능, 통합할 변경 범위 정리 |

단계 1에서 채택 후보 코어의 반환 변환과 스케일 경계가 일치하지 않으면 해당 버전으로 다음 단계에 진행하지 않는다. 검증을 우회하는 임시 보정 코드를 넣지 않는다.

실험이 마음에 들지 않으면 이전 작업트리 상태와 보존한 결과를 사용해 되돌릴 수 있어야 한다. 기존 사용자 입력과 `.blend`를 덮어쓰지 않으며 결과는 `E:\DEV\DEV_RND\colmap_align_test_env\outputs`에 별도로 저장한다.

## 13. 검증 항목

### 13.1 계산과 입력

- 네 가지 A/P 형상 조합에서 알려진 양의 Sim(3) 정답을 복원한다.
- 점군/메시의 축이 서로 다른 연결 모델과 독립 OBJ를 포함한다.
- 여러 A의 공통 행렬이 서로 달라도 통합 기준이 동일한 프로젝트 좌표에 놓인다.
- 역방향 경로에서 A 원본과 확정 행렬은 불변이고 P만 이동한다.
- 큰 원점 오프셋·작은 물체·서로 다른 단위에서 정규화 역변환을 검증한다.
- 0.90/1.10 안팎의 스케일, 경계 도달, 배율 누적을 검사한다.
- 잘못된 삼각면·빈 형상·퇴화 표면·비유한 좌표·불완전한 파일은 거부한다.
- 충분한 겹침이 없는 입력을 낮은 RMS만으로 정상 승인 가능 상태로 만들지 않는다.
- 합성 정답의 수치 허용치는 좌표 크기와 float 코어 정밀도를 고려해 먼저 고정한다. Blender의 행렬 적용/왕복 오차와 솔버의 추정 오차를 따로 측정한다.

### 13.2 UI와 상태

- 마커 없이 직접 Align, 3점 정렬 후 Align 모두 실행한다.
- 레이어 종류와 마커 종류가 다르면 원인·레이어·해결할 아이콘을 안내한다.
- 숨김 A 포함, 혼합 A 차단, P 하나 제한을 확인한다.
- 준비·정렬·평가 중 취소, 작업 프로세스 오류, 결과 지문 불일치에서 원상 복원한다.
- 결과 버리기는 시작 상태를 복원하고 정렬 승인은 기존 A 편입·마커 정리를 함께 수행한다.
- 승인 Undo/Redo가 행렬·그룹·마커 상태를 함께 복원한다.
- 저장하고 다시 연 이전 Small GICP 프로젝트와 새 CC 프로젝트를 확인한다.
- 현재 레이어 배치, 축 창, 마커 픽킹과 라벨 표시가 유지되는지 실제 Blender에서 확인한다.

### 13.3 실데이터와 RC 전달

기존 [CloudCompare 실데이터 실험](COLMAP_Align_CloudCompare_실데이터_실험.md)을 비교 기준으로 보존한다. 기존 결과는 **Small GICP가 적용된 상태를 CC로 추가 보정한 실험**이며 동일 초기값 엔진 비교가 아니다.

새 검증에서는 같은 3점 초기값 또는 같은 확정 행렬에서 Small GICP 기준 결과와 새 CC 결과를 각각 비교한다. 평가 표본·거리·스케일 정책을 기록하고 최적화에 사용하지 않은 표본으로 평가한다.

보존할 결과:

- 정렬 전후 `.blend`, 입력 지문과 옵션.
- 코어 반환값, 프로젝트 좌표 D, 최종 공통 행렬 C.
- 실제 사용한 형상 조합과 원본/표본 수.
- 정렬 전후 거리 분포·공간 구간별 잔차·스케일·실행 시간·최대 메모리.
- 내보낸 COLMAP의 점/카메라 재투영 관계와 재불러오기 결과.

RC 검증은 실제 사용 중인 COLMAP 전달·카메라 설정 경로를 확인한 뒤 같은 설정으로 수행한다. Blender에서의 겹침, 내보낸 카메라·점의 수치 일관성, RC 재구성 결과를 각각 구분해서 기록한다.

**RC에서 남는 국소 오차가 반드시 엔진 교체로 해결된다는 보장은 완료 기준에 포함하지 않는다.** 카메라 재최적화, 서로 다른 재구성 형상, 국소 변형, 메시 해상도 차이는 별도 원인일 수 있다. 이를 해결하기 위한 공동 번들 조정, 비강체 정렬, RC 설정 변경은 이번 구현 범위 밖이다.

## 14. 구현 완료 정의

- 기존 UI에서 점군–점군, 점군–표면, 표면–표면 정밀 정렬을 실행할 수 있다.
- 연결 표면을 선택하면 실제 삼각면 기반 대응이 사용된다.
- 기존 3점 정렬과 직접 Align, 자동 균일 스케일 보정, 결과 승인 UX가 유지된다.
- 공통 변환이 COLMAP 점군·카메라·연결 메시에 일관되게 적용된다.
- 취소·실패·버리기·Undo/Redo·저장 재열기가 검증된다.
- 사용자는 Small GICP나 CloudCompare를 별도로 설치하지 않아도 실험 애드온의 CC 정렬을 실행할 수 있다.
- 실험 결과와 통합 대상 변경이 문서화되어 있으며 main은 별도 통합 전까지 유지된다.


## 15. 구현 완료 기록

2026-09-03 사용자 승인에 따라 단계 1~7을 독립 실험 브랜치에서 완료했다. 최종 설치본 네 조합, 기존 소스 회귀 34개 파일, 실제 Blender GUI, 네이티브 16개·조정자 20개 회귀, 동일 C 실데이터 비교, 별도 저장본 재열기·COLMAP/OBJ 왕복을 통과했다.

자세한 결과와 최종 파일은 [구현·검증 기록](COLMAP_Align_CCCoreLib_구현검증.md)에 보존한다. RC 프로그램 내부 재구성은 이 기록의 검증 범위에 포함하지 않았다. main 통합과 Git 커밋은 수행하지 않았다.
