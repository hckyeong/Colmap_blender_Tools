# Align 불러오기 검증과 원본 버퍼 재사용

작성일: 2026-10-21. 브랜치: `codex/artec-align-engine`. 상태: 0.3.77 구현·검증·실제 설치 완료.

같은 두 대형 모델의 3회 중앙값에서 Align 호출 복귀가 **18.4695초 → 0.0126초**, 결과 미리보기까지가 **48.2296초 → 30.0152초**로 줄었다. 전체 시간은 **37.77% 감소**했다. 전체 정점 ID의 독립 거리 평가와 최종 행렬은 부동소수점 반올림 범위에서 같았다.

## 확인한 원인과 변경 범위

Align 버튼의 동기 시작 경로가 전체 원본 해시, 퇴화면·미참조 정점 검사, 좌표 변환과 공유 입력 작성을 수행한다. 기존 정리 캐시는 512MiB 상한으로, 현재 한 모델의 좌표·면 배열 약 1.45GB를 보관하지 못해 반복 실행도 전체 검사를 수행한다.

- 원본 좌표·삼각형을 불러올 때 읽기 전용 공유 매핑에 고정한다. 화면·마커·정렬이 같은 원본 배열을 읽고 원본 정점·면·UV·번호는 유지한다.
- 저장소 등록·복원 때 원본 지문과 정렬용 유효 형상을 준비한다. 형상 수명 동안 준비 결과를 보관하며 배열·모델·개정 번호 교체를 검사한다. 읽기 전용 플래그만 믿지 않고 쓰기 가능한 기반 버퍼를 노출하지 않는다.
- Align은 준비된 버퍼 설명자와 작은 변환 행렬만 전달한다. 좌표 변환과 여러 기준의 결합은 외부 작업 프로세스에서 기존 NumPy 연산 순서로 수행한다. 네이티브 정렬식·대응 검색·필터·종료식은 바꾸지 않는다.
- 계산 도중 모델이 제거돼도 작업이 원본 배열을 소유하고, 완료·실패·취소 후 작업 참조를 해제한다. 모델을 제거하거나 파일을 바꾸면 저장소 참조를 해제한다.
- 검사 실패 원인은 불러올 때 보관하고 정렬 시작 시 명시적으로 거부한다. 형상 편집은 새 불변 형상 등록으로 반영한다. 기존 파일 입력과 구엔진 계약은 유지한다.

공유 메모리의 수명은 [Python 공식 문서](https://docs.python.org/3/library/multiprocessing.shared_memory.html)를 따른다. Blender API를 별도 Python 스레드에서 호출하지 않고 기존 외부 프로세스를 유지한다. [Blender 공식 제약](https://docs.blender.org/api/current/info_gotchas_threading.html)

## 검증 방법

- 현재 데스크톱 2에 있는 같은 두 모델, 같은 초기 변환으로 공개 Align 호출 3회씩 비교한다. 클릭 호출 복귀 시간, UI 타이머 최대 간격, 결과 미리보기까지의 전체 시간을 분리한다.
- 원본 지문·면·UV·마커 ID와 정밀 좌표를 보존하고 최종 행렬·독립 대응 좌표 오차·수렴 상태를 비교한다.
- 점군·메시 네 조합, 여러 기준·축별 배율, 형상 교체 감지, 실패·취소·제거와 공유 버퍼 수명을 검사한다.
- 사용자 창·선택·확정 배치는 복원한다. 데스크톱 1 화면 전환·창 활성화는 하지 않는다.
- 실제 설치본은 검증된 패키지로 업데이트하고 파일 해시·버전을 확인한다.

## 구현

| 경로 | 변경 내용 |
|---|---|
| `tools/align/geometry_buffers.py` | Windows 이름 있는 매핑에 원본 좌표·삼각형을 한 번 고정하고 읽기 전용 배열과 최초 지문을 공유한다. 쓰기 가능한 매핑은 생성 직후 닫는다. |
| `tools/align/alignment/icp_prepared_input.py` | 등록 시 유효 형상 검사와 지문을 준비한다. 문제가 없는 메시에서는 정점·면 배열 자체를 재사용한다. |
| `tools/align/mesh_io/types.py`, `model_repository.py` | 모델 생성·등록·복원·삭제에 불변 원본과 준비 결과의 수명을 연결한다. 점군·연결 메시도 같은 계약을 적용한다. |
| `icp_geometry.py`, `icp_point_kd_input.py` | Align 시작·완료 검증에서 준비한 내용 지문과 모델·개정·배열의 동일성을 확인한다. 전체 해시·형상 검사를 반복하지 않는다. |
| `icp_point_kd_contract.py`, `icp_point_kd_runtime.py` | `WIN32_SHARED_LOCAL_V1` 입력으로 공유 원본 설명자와 작은 변환 행렬을 전달한다. |
| `icp_point_kd_transfer.py`, `icp_point_kd_worker.py` | 외부 작업 프로세스에서 좌표 변환·여러 기준의 결합을 수행하고 기존 C++ 입력 계약으로 전달한다. 성공·실패·취소 뒤 임시 매핑을 해제한다. |
| `operators/model_group.py` | 삭제 실패로 모델을 복원할 때 준비한 정렬 입력도 함께 복원한다. |

유효한 원본의 읽기 전용 배열은 화면·마커·정렬 준비에서 같은 저장소를 참조한다. **좌표 변환 결과와 네이티브 정렬 작업 메모리까지 없앤 것은 아니다.** 외부 작업 프로세스의 입력 준비 시간은 이번 3회에서 1.625~1.672초였으며, 이 비용은 전체 시간에 포함돼 있다.

퇴화면이나 미참조 정점이 있는 경우 기존 정리 정책에 필요한 계산용 배열만 별도로 만든다. 전부 퇴화한 형상 등은 등록 때 오류를 기록하고 Align에서 즉시 알린다. 모델·배열·개정이 교체되면 기존 준비 결과를 사용하지 않는다. 구형 저장소 호출과 다른 엔진의 검증 경로는 호환성을 위해 유지한다.

이전 사용자가 되돌리도록 요청한 OBJ 중복 제거는 다시 도입하지 않았다. `embedded_obj_store.py`와 `renderer.py`, GPU 마커·피벗 계산 및 C++ 엔진은 이번 패키지 차이에서 변경되지 않았다.

## 같은 두 모델의 실측 결과

Blender 5.2.0 LTS, Ryzen 9 7950X3D, RTX 4090, RAM 128GB, 정렬 작업 스레드 31개 환경이다. 사용자 데스크톱 2의 기존 Blender에 MCP로 명령을 전달했고, 사용자 데스크톱 1의 화면 전환이나 Blender 창 활성화는 하지 않았다.

대상은 `Gilt-bronze Pensive Maitreya Bodhisattva 78_high poly.obj`를 각각 가져온 두 독립 레이어다. 모델마다 **30,109,486개 정점, 60,206,247개 삼각형, 180,618,741개 UV 항목**이 있다. 두 모델 모두 준비한 유효 정점·면 수가 원본 수와 같고 원본 좌표·면 배열을 그대로 참조하는 것을 확인했다.

기존 0.3.76 설치본과 새 0.3.77 소스를 같은 장면·초기 변환·네이티브 엔진·매개변수로 각각 3회 실행했다. 공개 Align 연산자를 호출하고 실제 이벤트 루프에서 결과를 기다렸다. 매회 미리보기를 버렸으며 사용자 확정 변환과 선택을 복원했다. 대형 모델을 추가로 가져오는 대신 기존 모델을 임시로 새 입력 계약에 연결했고, 비교 후 코드·모델·GPU 참조도 원래 상태로 복원했다.

| 측정 항목 | 0.3.76 중앙값 | 0.3.77 중앙값 |
|---|---:|---:|
| Align 호출부터 제어 복귀 | 18.4695초 | 0.0126초 |
| UI 타이머 최대 간격 | 18.4764초 | 0.0559초 |
| Align 호출부터 결과 미리보기 관측 | 48.2296초 | 30.0152초 |

UI 타이머는 0.02초 간격으로 예약했다. 최대 간격은 해당 실행에서 이벤트 처리가 가장 오래 지연된 정도이며 화면 프레임 시간을 직접 측정한 값은 아니다.

| 실행 | 변경 전 클릭 복귀 | 변경 후 클릭 복귀 | 변경 전 전체 | 변경 후 전체 |
|---|---:|---:|---:|---:|
| 1 | 18.8450초 | 0.0188초 | 50.1130초 | 30.6229초 |
| 2 | 18.4695초 | 0.0118초 | 48.2296초 | 30.0152초 |
| 3 | 17.0148초 | 0.0126초 | 46.2691초 | 29.6450초 |

두 모델은 이미 대략 정렬된 상태였으며 모든 실행이 1회 반복으로 종료됐다. 큰 초기 오정렬이나 반복 수가 많은 입력에서 같은 단축률을 보장하는 측정은 아니다. 종료식·KD 검색·대응 제거·법선 계산은 바꾸지 않았다. 이번에 측정한 원본 연결·검증 준비 27.986초에는 기존 장면 이관과 비교용 전체 감사가 포함돼 있으므로 실제 OBJ 불러오기 증가 시간으로 해석하지 않는다. 불러오기 전체 시간의 별도 비교는 이번 실험 범위에 포함하지 않았다.

## 정확도와 원본 보존

같은 원본에서 온 두 모델이므로 전체 **30,109,486개 정점의 원본 ID 대응 거리**를 계산했다. 이 검사는 ICP의 KD 대응점 검색과 독립적이다. 단위는 프로젝트 좌표 단위이며 밀리미터로 가정하지 않았다.

| 검사 | 변경 전 | 변경 후 3회 |
|---|---:|---:|
| 전체 정점 ID 대응 RMS | 0.1497602973502438 | 0.1497602973502438 |
| 최대 정점 ID 대응 거리 | 0.26208253935492704 | 0.2620825393549269 |
| ICP 대응 RMS | 0.08972910888057861 | 0.08972910888057843 |
| 품질 판정 / 반복 수 | PASS / 1 | 모두 PASS / 1 |

변경 전후 최종 행렬의 최대 원소 차이는 `2.776e-17`, 최종 정점 좌표 차이는 최대 `5.462e-17`이었다. 두 입력의 전체 좌표·삼각형 해시는 같았고, UV·면·루프 대응 배열은 같은 객체로 유지했다. 원본 삼각형 번호나 마커 좌표 계산 경로를 변경하지 않았다. 이번 실측에서는 마커 클릭별 GPU 정확도 벤치마크를 다시 실행하지 않았다. 사용자 확정 변환도 초기 상태와 원소별 동일하게 복원했다.

이 입력에 기존 배율 약 `1.000569`가 포함돼 있고 엔진은 기존 정책대로 배율을 유지하기 때문에 동일 원본이라도 정점 대응 잔차가 0일 필요는 없다. 이 잔차와 실제 표면 최근접 오차는 다른 지표다.

## 메모리 사용량 조사

약 7.64GB OBJ의 파일 크기가 그대로 메모리 사용량이 되는 구조는 아니다. 현재 모델별 CPU 배열 항목의 `nbytes` 합은 **7.570GiB**, 두 모델 합은 **15.140GiB**다. 일부 인덱스가 저장소를 공유할 수 있으므로 이는 중복을 제거한 실제 할당량이 아니라 항목 합계다.

| CPU 배열 항목 | 모델 하나당 |
|---|---:|
| 배정밀도 좌표 | 689.15MiB |
| 삼각형 정점 번호 | 689.01MiB |
| UV 좌표 180,618,741 × 3 × 8바이트 | 4.037GiB |
| 삼각형 UV 번호 | 689.01MiB |
| 원본 루프 번호 | 689.01MiB |
| 나머지 등록·표시·재질·면 대응·UV 차원 배열 | 약 0.842GiB |

특히 **UV 좌표만 모델당 약 4GiB**로, 정렬용 정점 좌표보다 훨씬 크다. 이외에 Blender 내장 메시 두 개의 정점·면·루프·UV, GPU 표시 버퍼와 드라이버 자원도 유지한다. 따라서 높은 기본 사용량을 KD-tree나 좌표 배열 하나만으로 설명할 수 없다. GPU 사용량은 별도 측정 항목이며 CPU 메모리와 단순 합산하지 않는다.

초기 진단 때 Blender 작업 집합은 약 42.14GiB, 전용 커밋은 약 55.84GiB였고 정렬 워커는 이미 종료된 상태였다. 작업 집합은 물리 RAM에 상주하는 부분이며 전용 커밋과 다르다.

이후 새 경로 3회와 복원 과정의 135.4초 동안 598개 메모리 표본을 기록했다.

| 항목 | 관측값 |
|---|---:|
| Blender 전용 메모리: 측정 시작 → 완료·복원 후 | 55.839 → 55.751GiB |
| Blender 작업 집합: 측정 시작 → 완료·복원 후 | 36.059 → 36.160GiB |
| Blender 전용 메모리 표본 최대 | 57.062GiB |
| C++ 워커 전용 메모리 표본 최대 | 약 5.006GiB |
| 외부 Python 워커 전용 메모리 표본 최대 | 약 0.782GiB |
| 관측한 시스템 가용 RAM 최소 | 40.134GiB |

세 차례의 Python·C++ 정렬 워커는 모두 종료돼 마지막 표본에 남지 않았다. 새 공유 버퍼의 취소·실패·모델 제거 후 수명도 회귀 검사로 확인했다. **이 실험에서 실행마다 누적되는 메모리 증가는 관측되지 않았다.** 다만 비교·복원을 위해 이전 원본 배열도 보유했으므로 실험의 최고값을 새 버전의 일반적인 최고 메모리 사용량으로 단정하지 않는다. 공유 매핑이 있는 프로세스들의 작업 집합을 합치면 같은 페이지를 여러 번 셀 수도 있다.

이번 개선은 Align마다 원본을 다시 검사·복사하는 비용을 줄인다. 큰 UV 배열과 Blender 내장 메시의 중복 보관은 유지하므로 기본 메모리 사용량 전체를 줄였다는 결과는 아니다.

## 회귀·빌드·설치

- 점 기반 입력·계약 회귀 22개 통과. 새 원본 상주 입력 검사 7개를 포함한다.
- 실제 외부 워커를 사용하는 Blender 회귀 7개 통과. 승인·버리기·Undo/Redo·변경 감지·취소·실패 및 공유 버퍼 해제를 확인했다.
