# Align Python 스냅샷·입력 전달 개선 검증

2026-10-21 · `codex/artec-align-engine` · 네이티브 엔진 `1.3.0`

**변환 좌표를 작업별 Windows 공유 메모리에 직접 작성하도록 바꿨다. 같은 두 모델의 전체 정렬 시간 중앙값은 10.3~13.6%, 입력 준비·시작 시간은 30.9~35.9% 감소했다. 최종 행렬과 독립 표면 오차는 변경 전후 동일하며 새 엔진 18회 모두 수렴·PASS, REVIEW 없음이다.**

## 확인한 병목과 변경

직전 [1.2.0 구현](COLMAP_Align_Artec_KD_입력준비_개선검증.md)은 네이티브 안의 추가 좌표 복사를 제거했지만, Python은 공통 좌표 임시 배열과 불변 스냅샷을 만든 뒤 대형 바이너리 파일 4개를 기록했다. 같은 두 모델에서 파일 배열의 합은 **494,519,916바이트, 약 494.5MB**였다.

별도 단계 계측의 준비 실행 제외 2회 중앙값:

| 준비 단계 | 이전 | 개선 후 |
|---|---:|---:|
| 원본 전체 배열 해시 | 0.209초 | 0.196초 |
| 변환 좌표·불변 형상 생성 | 0.136초 | 해당 경로 제거 |
| 위 단계에 포함된 불변 배열 복사 | 0.028초 | 해당 경로 제거 |
| 대형 바이너리 파일 기록 | 0.282초 | 0초 |
| 공유 버퍼에 직접 좌표·면 번호 작성 | 없음 | 0.230초 |
| 외부 작업 시작 | 0.006초 | 0.006초 |
| 준비·시작 전체 | 0.645초 | 0.437초 |

중첩 단계가 있으므로 표의 모든 행을 더하면 안 된다. 단순히 `NumPy.tofile`을 메모리 뷰 기록으로 바꾸거나 Windows 임시 파일 속성을 사용하는 예비 실험은 약 0.225~0.230초로 의미 있는 개선이 없었다. 제품 코드에는 이 방식을 추가하지 않았다.

새 경로는 다음과 같다.

```text
원본 전체 해시·형상 검증과 기존 준비 캐시
  → 작업별 공유 버퍼 할당
  → 공통 좌표 변환을 버퍼에 직접 작성
  → 여러 기준 메시의 면 번호도 목적 버퍼에 직접 작성
  → 작은 JSON으로 이름·길이·출처 전달
  → 네이티브에서 읽기 전용 매핑·헤더 검증
  → 계산 소유 배열 하나로 복사
  → 기존 KD 생성·정렬 계산
```

- 좌표는 `float64`, 면 번호는 `uint32`를 유지한다. `np.matmul(..., out=...)`로 중간 변환 좌표 배열을 피한다. [NumPy 공식 문서](https://numpy.org/doc/stable/reference/generated/numpy.matmul.html)
- 기존 원본 정리 캐시와 원본 전체 해시를 유지한다. 시작·완료·승인의 원본 변경 검사, 형상 슬롯·축·배율·마커·A/P 선택 검사는 그대로다. 원본 배열을 쓰기 금지 상태로 바꾸거나 수정하지 않는다.
- 작업마다 새로운 UUID 이름을 사용하고, 고정된 로컬 이름 형식·예상 배열 크기·64바이트 헤더의 표식과 토큰을 검사한다. 네이티브는 요청 범위만 `FILE_MAP_READ`로 매핑하며 파일과 매핑의 중복 지정은 거부한다. [Windows 공식 문서](https://learn.microsoft.com/en-us/windows/win32/api/memoryapi/nf-memoryapi-mapviewoffile)
- 작업 핸들이 입력 수명을 소유한다. 완료·취소·시작 실패·일반 실패에서 해제하며 진단 JSON을 보존해도 입력 메모리는 해제한다. Windows에서는 마지막 핸들이 닫히면 공유 메모리가 해제된다. [Python 공식 문서](https://docs.python.org/3.14/library/multiprocessing.shared_memory.html)
- 네이티브의 계산용 소유 배열로 복사하는 과정은 남아 있다. 전체 경로를 무복사라고 부르지 않는다. 공유 버퍼 작성에도 새 페이지를 채우는 비용이 있다.
- 파일 입력 규약도 유지한다. Windows의 기본 경로는 공유 입력이며 다른 운영체제는 기존 파일 경로를 사용한다. 공유 메모리 실패를 파일 전달로 조용히 우회하지 않는다.

이 IPC 방식은 현재 프로젝트의 개선이다. Artec이 같은 Windows 프로세스 간 공유 메모리 방식을 사용한다고 확인한 것은 아니다.

## 비교 조건

- 동일한 `test.align.blend`, 작은 모델 188,400점·357,749면, 큰 모델 10,173,478점·20,128,488면. 합계 **20,486,237면**.
- 별도 Blender 5.2.0 LTS 프로세스에서 복원했다. 사용자에게 열린 장면을 조작하거나 `.blend`·OBJ를 저장하지 않았다. 원본 크기·수정 시각의 전후 동일성을 확인했다.
- 보존한 **1.2.0 Python 입력 준비 모듈·외부 조정기·네이티브 실행 파일**과 새 **1.3.0 배포 패키지의 공개 Align 경로**를 비교했다. 이전 입력 준비 모듈은 같은 공통 수명 관리 계층에서 실행했다. 공통 형상 검증·해시·원본 정리·ICP 런타임 코드는 보존한 이전 패키지와 바이트 단위로 동일하다.
- 종료식, 허용치 `double(float32(0.001))`, 전체 유효점, 대응 제거, 법선 정책, 배정도 계산, 31스레드는 같다. KD·좌표 버퍼·종료식 구현 파일도 이전과 동일하다.
- 정렬 상태, Z축 0.5°와 이동 `(0.6, −0.4, 0.2)` 추가, 기준·이동 역할 반전의 세 조건이다.
- 조건별 각 방식의 준비 실행 1회를 제외하고, 순서를 교차해 각각 5회 측정했다. 총 **36회**, 새 경로 **18회**다. 느린 실행도 제거하지 않았다.
- 시간은 입력 준비 시작부터 미리보기 결과 검증 완료까지다. 프로젝트 복원과 화면 그리기는 제외한다. 측정 중 다른 빌드·성능 작업을 병행하지 않았다.
- 준비 캐시가 있는 반복 Align의 비교다. 최초 형상 검증·정리 비용까지 사라진 것은 아니며, 교차 실험의 첫 준비 실행은 캐시 상태가 달라 전후 성능 비교에 사용하지 않았다.

## 정확도·기능·메모리

| 조건 | 갱신 횟수 이전 = 이후 | 표면 RMS 이전 = 이후 | 95백분위 이전 = 이후 |

| 회전·이동 추가 | 5 | 1.4838172991 | 3.6273437780 |

모든 반복에서 최종 행렬이 원소별로 정확히 같았다. 독립 평가는 양방향 삼각형 표면 표본 각 30,000개, 고정 겹침 59,187개를 사용했다. 표본과 마스크 해시가 직전 검증과 같다. 동일 행렬은 같은 표면 거리 평가를 재사용하며, 다른 행렬은 별도로 평가한다. 단위는 프로젝트 세계좌표이며 mm로 단정하지 않는다. 이전 브랜치 및 기존 CC 기준의 양방향 정확도 검사도 모두 통과했다.

새 엔진 18회는 모두 `SUCCESS / CONVERGED`, 상위 품질 `PASS`, 검토 사유 없음이다. REVIEW 판정을 숨기거나 정확도 기준을 완화한 변경은 없다. 점군끼리, 점군–메시 양방향, 메시끼리, 연결 메시, 여러 기준의 결합, 기존 배율·승인·실행 취소 계약을 검사했다.

**메모리와 진단의 차이도 있다.** 계산 중 공유 입력 약 **471.6MiB**를 유지한다. 정렬 상태에서 Blender의 관측 작업 집합 중앙값은 3,233.6→3,705.3MiB, 작업기 트리는 757.1→757.5MiB였다. 준비 단계의 짧은 최고점과 OS 파일 캐시는 같은 방식으로 계측하지 않았으므로 이 수치를 전체 시스템 메모리 증감으로 단정할 수 없다. 이번 개선은 메모리 절감보다 입력 전달 지연 감소를 목표로 한다. 대형 입력 파일을 남기지 않으므로 실패 진단 JSON만으로 같은 작업을 다시 실행할 수 없으며 원본에서 입력을 다시 준비해야 한다.

## 검증 결과와 한계

- 네이티브 검사 **26개**: 파일·공유 입력의 점대점/점평면 결과 동등성, 명시 법선·삼각형, 입력 보존, 잘못된 이름·헤더·크기·중복 설명자·닫힌/잘린 매핑 거부 포함.
- 공유 입력 검사 **6개**, 원본 준비 캐시 **15개**, Python 계약 **9개** 통과.
- Blender 연동 **7개** 통과: 미리보기·승인·Undo/Redo·출처·원본 변조 거부와 완료·취소·시작 실패 시 실제 공유 버퍼 해제 포함.
- 정확 KD 전수 비교 500회 및 Artec 종료식 실측 10건과 경계 검사 통과.
- 배포 빌드의 순수 검사 **314개**, 통합 등록·해제, 스테이징 실행, 격리 설치본의 실제 정렬 검사 통과.
- 대형 모델 새 경로 18회 모두 입력 파일 0개, 공유 버퍼 4개, 완료 뒤 매핑을 다시 열 수 없음을 확인했다.

추가로 실행한 구엔진 검사 두 개는 통과하지 못했다. `test_icp_runtime.py`는 앞선 공통 상태·수명 검사를 지나 마지막 구형 숨김 워커에서 `No module named 'shared'`로 실패했다. `test_icp_worker.py`는 예전 `colmap_align` 모듈 이름을 찾지 못했다. 실패한 import 경로의 제품 파일은 직전 배포본과 동일하고 해당 구형 검사·워커도 이번에 수정하지 않았다. 새 공유 입력 계산에 진입하기 전의 구엔진 경로 문제이며 요청 범위 밖이므로 우회 코드를 추가하지 않았다. 전체 구엔진 회귀가 모두 통과했다고 주장하지 않는다.

Artec을 이번에 다시 실행하거나 최종 변환을 독립 평가한 것은 아니다. 이 결과는 **직전 브랜치 구현 대비 속도 향상과 정확도 유지**를 뜻한다.
