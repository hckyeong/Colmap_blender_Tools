# Align 피벗 더블클릭 피킹 최적화

## 범위와 원인

대용량 OBJ의 표면을 더블클릭해 피벗을 옮길 때 첫 선택이 멈추는 문제를 개선한다. 피벗 좌표 설정, 정렬 알고리듬, 표시 형상, 저장 형식은 유지한다. 면 선택 코드를 함께 사용하는 마커도 같은 최적화를 적용받는다.

대상 `Taiwan_armadillo_scanHighpoly.obj`는 921,654,682바이트, 정점 10,173,478개, 삼각면 20,128,488개이다. 변경 전 첫 면 선택 34.500초 중 34.499초가 BVH 구축이었다. NumPy 정점·삼각형 배열을 `BVHTree.FromPolygons`에 전달하면서 Python 시퀀스 변환이 대량 발생했다. 캐시 재사용 선택은 이미 1밀리초 이내였고 피벗 좌표 설정 자체도 병목이 아니었다.

## 구현과 보존 계약

1. 내장 원본 Mesh가 있는 모델은 Blender의 `BVHTree.FromObject`로 검색 구조를 구축한다. 별도 C++ 모듈이나 외부 라이브러리를 추가하지 않고 Blender의 기존 네이티브 구현을 사용한다.
2. 최초 구축 전에 UUID·소유 모델 ID·스키마·리비전·비연결 조건·형상 개수와 좌표·삼각형·원본 면 대응 배열을 확인한다. Blender 기본 버퍼를 사용해 배정밀도 전체 복사를 피하며, 프록시와 불일치하면 실패한다. 검증 실패를 다른 검색 구조 생성으로 우회하지 않는다.
3. 구축 중에만 격리된 임시 Scene/Object에 내장 Mesh를 연결하고 `finally`에서 제거한다. 사용자 Scene·선택·모드·Mesh·UV·재질·Fake User는 유지한다. 내장 원본의 비연결 계약은 이 동기 처리 전후에 유지되며, 임시 객체를 저장하거나 다음 이벤트까지 남기지 않는다.
4. 네이티브 검색이 반환하는 원본 Polygon ID를 기존 프록시 Triangle ID로 대응시킨다. 적중 Polygon에 속한 삼각형에만 기존 float64 재교차를 수행하여 피킹 위치와 저장된 마커의 안정 ID 계약을 유지한다. 면 대응이 정렬되지 않은 경우에도 원래 삼각형 ID를 보존한다.
5. 원본 면 조회에는 배열과 같은 `uint32` 값을 사용한다. Python 정수를 검색 키로 전달하면 NumPy가 전체 면 배열을 다른 정수 형으로 변환하므로, 반복 클릭마다 발생할 수 있는 대형 복사를 방지한다.
6. 캐시는 모델·형상 슬롯·프록시 객체·리비전별로 재사용한다. 화면 회전이나 모델 정렬 변환으로 재구축하지 않는다. 모델 삭제가 성공한 뒤 해당 모델의 모든 형상 슬롯 캐시를 해제하고, 삭제 실패 시 유지한다. 같은 원본의 다른 레이어 캐시는 보존한다.
7. 면 미적중 후 정점 선택은 표시 정점과 원본 정점 인덱스를 직접 사용한다. 클릭마다 전체 정점 ID와 RGB 배열 약 112MB를 만드는 비용을 제거한다. COLMAP 점 ID와 기존 깊이·화면 거리 우선순위는 유지한다.

내장 원본이 없는 기존 배열 모델은 종전 `FromPolygons` 경로를 유지한다. 공개 피킹 함수와 반환 자료 구조는 바뀌지 않는다. 첫 검색 구조 구축은 여전히 동기 실행이며, 이 변경이 모든 첫 클릭을 즉시 응답하게 만드는 것은 아니다.

## 검증

Blender 5.2.0 LTS에서 다음 회귀 스크립트가 통과했다. 실행 형식은 `blender.exe --background --factory-startup --python-exit-code 1 --python tests/align/blender/<스크립트>`이다.

- 신규: `test_embedded_pick_bvh.py`, `test_picking_optimization.py`, `test_picking_cache_lifecycle.py`.
- 기존: `test_mesh_surface_picking.py`, `test_companion_marker_picking.py`, `test_geometry_axes_display.py`, `test_companion_display.py`, `test_companion_marker_alignment.py`, `test_companion_marker_persistence.py`, `test_layer_transform.py`.

삼각면·사각면·오목 N-gon의 선택 좌표와 Triangle ID, 비단조 면 대응, 변환 후 캐시 재사용, 동일 원본 중복 레이어 삭제·실패 복구, 원본·프록시 변조 거부, 생성 실패 시 임시 자료 정리, Edit 모드와 장면·선택 보존을 검증했다. 별도 검토에서 비평면 사각면·비평면 오목 오각형에 각각 500개 광선을 쏘아 기존 삼각형 BVH와 적중 여부·Triangle ID가 일치하는 것도 확인했다. 신규 스크립트 세 개는 정식 소스 회귀 목록에 등록했다.

Blender의 원본 Polygon 반환과 시퀀스 변환 구현은 [공식 mathutils BVH 소스](https://github.com/blender/blender/blob/main/source/blender/python/mathutils/mathutils_bvhtree.cc)를 확인했다.

## 실제 OBJ 성능

| 항목 | 변경 전 | 변경 후 |
|---|---:|---:|
| 최초 면 선택 | 34.500초 | 5.771초 |
| 캐시 재사용 면 선택, 10회 범위 | 0.275~0.780밀리초 | 0.234~0.536밀리초 |
| 면 미적중 후 정점 선택, 5회 범위 | 51~75밀리초 | 33~42밀리초 |
| 정점 선택 시 전체 ID·RGB 배열 생성 | 약 112MB/회 | 없음 |

최초 면 선택은 약 6배 빨라졌으며 대기 시간은 약 83% 감소했다. 개선 후 시간에는 원본 Mesh와 프록시의 일치 검증과 임시 장면 생성·정리가 포함된다. 네이티브 BVH 생성만 따로 측정하면 2.225초이므로, 검증까지 포함한 실제 제품 경로와 구분한다.

2026-09-18 동일 장비의 Blender 5.2.0 LTS에서 실제 OBJ를 가져온 뒤 실제 피킹 함수를 측정했다. 최초 선택은 각 조건 1회이며 통계적 평균이 아니다. 제어된 광선으로 비교했고 OBJ 가져오기·GUI 더블클릭 인식·화면 갱신은 제외했다. 반복 선택과 정점 선택에는 프로파일러가 포함됐다. 원본 크기·수정 시각은 유지됐다. 기록은 `build/pivot-review-20260918/`와 `build/pivot-optimized-20260918/`에 보관하며 Git에는 포함하지 않는다.

## 0.3.53 빌드·설치와 실제 화면 검증

정식 CCCoreLib 프로필로 `build/colmap_tools-0.3.53.zip`을 빌드하고 Blender 5.2의 기존 `user_default` 저장소에 설치했다. 이전 0.3.52 ZIP과 비교한 제품 변경은 버전 파일 두 개와 이번 피킹 관련 파일 세 개뿐이다. 기존 별도 작업의 수정 파일은 커밋 범위에 포함하지 않는다.

- 정식 빌드의 구조·공존·Core·Blender 등록·네이티브 정렬·ZIP 검사 통과.
- 격리 설치본 등록·네 가지 입력 조합 정렬·OBJ/UV 입출력 검사 통과.
- 실제 설치본 활성화와 배포 파일 1,171개의 해시 일치 확인. 환경설정 파일 해시는 설치 전후 동일.
- 별도 GUI Blender에서 동일 대용량 OBJ를 공개 모달 오퍼레이터로 27.293초에 가져온 뒤 실제 뷰포트의 피벗 처리 함수를 실행했다. 최초 5.584초, 재사용 0.479밀리초였다.
- 피벗과 뷰 중심의 이동, 같은 검색 구조 재사용, 모델·변환·선택·장면 보존, 임시 객체 제거, 원본 파일 보존을 확인했다. GUI 마우스 이벤트를 합성한 검사는 아니며 더블클릭 처리 함수를 실제 뷰포트 문맥에서 직접 호출한 측정이다.
- ZIP SHA-256: `4a89349e7b94b98249f86f7591f0a39e55ed28d6e92769caa51718f866b37e5c`.

설치·GUI 검증 기록과 화면은 `build/verification/pivot-optimization-0.3.53/`에 보관한다. 사용 중인 Blender는 재시작해야 갱신된 코드가 반영된다.

GUI 검증 프로세스 종료 때 Blender의 환경설정 자동 저장이 발생해 설정 파일 해시는 설치 직후와 달라졌다. 따라서 GUI 검사 후까지 설정 파일의 바이트 동일성을 주장하지 않는다. 이전 상태를 추측해 설정을 덮어쓰지 않았으며, 재실행용 검증 스크립트에는 자동 저장 차단을 추가했다. 사용자 작업 중인 Blender와 원본 OBJ에는 변경을 가하지 않았다.
