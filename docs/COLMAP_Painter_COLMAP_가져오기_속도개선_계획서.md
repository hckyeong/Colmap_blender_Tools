# Painter COLMAP 가져오기 속도 개선 계획서

- 작성일: 2026-10-06
- 기준: `main`의 제품 버전 0.3.73 작업 사본. 저장소 기준 커밋은 `48afa7d`이며 이후 미커밋 변경을 포함한다.
- 상태: 구현·기능 검사·실제 자료 벤치마크·최상위 ZIP 갱신 및 후속 요청에 따른 전체 설치 완료. 실행 중인 Blender의 Painter 이전 모듈은 재시작 후 전체 적용된다. 커밋·푸시는 수행하지 않았다. 실제 수행 범위와 측정 한계는 [구현·검증 결과](COLMAP_Painter_COLMAP_가져오기_속도개선_구현검증.md)를 참고한다.
- 대상: Projection Painting의 직접 COLMAP 가져오기.
- 선행 자료: [독립 가져오기 계획](COLMAP_Painter_독립_가져오기_공통IO_계획서.md), [구현·성능 측정](COLMAP_Painter_독립_가져오기_구현검증.md), [제품 경계](README.md).

## 1. 목표와 범위

카메라와 촬영 이미지는 모두 유지하고, 참고용 점군 상한의 기본값을 **20,000개**로 둔다. 후속 사용자 요청에 따라 COLMAP 가져오기 파일 탐색기의 **참고 점 최대 개수**에서 상한을 변경한다. 확정 전에 같은 자료를 다시 해석하는 작업, 필요 없는 관측 정보의 보관, 점별 파이썬 변환, 반복 오브젝트 검색과 과도한 화면 갱신을 줄인다.

개선 순서는 다음과 같다.

| 단계 | 변경 | 기대 효과 |
|---|---|---|
| 1 | 최초 검증 결과 재사용, 확정 전 원본 변경 검사 분리 | 전체 재파싱·점 검증·의미 지문 재계산 제거 |
| 2 | 참고용 읽기 정책과 읽는 중 2만 점 표본 보관 | 불필요한 관측 배열과 전체 점 속성 보관 감소 |
| 3 | 처리 예산과 화면 갱신 주기 분리 | 실제 화면에서 가져오는 시간과 이벤트 처리 비용 감소 |
| 4 | 점 검사·Blender 기록을 배열로 처리 | 점별 객체·중간 목록 생성 감소 |
| 5 | 카메라 오브젝트 조회표 재사용 | 카메라 수가 늘어날 때 반복 전체 검색 제거 |

Align·Modifier의 전체 입력, 정렬 엔진, OBJ 입력, 페인트 계산과 브러시 동작은 변경하지 않는다. 새로운 외부 정렬 라이브러리나 C++ 실행 환경은 도입하지 않는다. 공통 계층에 읽기 정책을 추가하더라도 기본 동작은 기존 전체 읽기다.

이번 정책은 신규 COLMAP 가져오기와 명시적인 재가져오기에 적용한다. 이미 저장된 점군을 파일 열기나 Painting Mode 진입 때 자동 축소하지 않는다.

## 2. 확인한 현행 비용과 측정 한계

기존 시험용 TXT 자료는 점 100,000개, 이미지 16개, 내부 카메라 1개다. 사용자 프로젝트의 새 측정 결과가 아니다.

| 구간 | 기존 측정 |
|---|---:|
| 최초 공통 읽기 | 약 0.52초 |
| 최초 점 검증 | 약 0.55초 |
| 최초 의미 지문 계산 | 약 0.44초 |
| Blender 자산 준비 | 약 0.42초 |
| 확정 직전 다시 읽기·검증·지문 계산 | 약 1.45초 |
| 백그라운드 전체 가져오기 | 3.39초 |
| 실제 화면의 모달 가져오기 | 10.94초 |

원시 결과는 `build/verification/painter-file-import-20261005/final-benchmark/direct.json`에 있다. 화면 시간과 계산 시간의 차이에는 이벤트 처리·다시 그리기·장면 갱신이 포함된다. 타이머 대기만으로 차이 전체를 설명하거나, 동일한 개선율이 실제 프로젝트에서도 나온다고 단정하지 않는다.

현재 코드에서 확인한 사항:

- `ImportStagingRevalidationJob`은 준비 작업을 다시 실행하여 전체 데이터를 재파싱한다.
- 공통 읽기는 파일 내용 해시를 계산하고, Painter는 별도로 전체 점의 의미 지문을 계산한다.
- `points2D`와 점의 관측 트랙을 전체 배열로 보관한다. Painter 투영에는 카메라 자세·내부 파라미터·촬영 이미지가 사용되며 관측 배열의 직접 사용은 확인되지 않았다.
- Painter 점 검증은 지연 레코드를 점마다 만들고 트랙도 원소마다 순회한다.
- 점 메시 생성은 좌표·색상·오차·식별자를 파이썬 목록으로 준비한다. 색상 등 일부 속성 기록은 이미 `foreach_set`을 사용한다.
- 가져오기 모달은 타이머 이벤트마다 한 단계를 진행하고 화면 갱신을 요청한다. 현재 작업 예산은 25밀리초, 타이머 간격은 10밀리초다.
- 확정 시 각 카메라 마커를 연결하기 위해 컬렉션 오브젝트를 반복 검색한다.

## 3. 유지할 동작과 호환성

1. 카메라 내부 파라미터·자세·이미지 이름·파일 경로·프레임 대응·축 설정은 유지한다. 지원 카메라 모델도 기존 범위를 따른다.
2. 원본 파일 내용 변경, 파일 교체·삭제, 입력 형식·모델 선택 변경, 이미지 경로·파일 식별 변경은 확정 전에 거부한다. 파일 크기와 수정 시간만으로 내용 변경 검사를 대체하지 않는다.
3. 준비 중에는 새 자원만 만든다. 실패·취소하면 이전 데이터셋·OBJ·페인트 대상·레이어·이미지 픽셀·선택 문맥을 유지한다.
4. 원본 파일은 읽기 전용으로 사용한다. 표본의 원본 점 식별자를 배열 순번으로 바꾸거나 부동소수점으로 변환하지 않는다.
5. 기존 공개 읽기 함수의 인자·반환형·예외·전체 읽기 기본값을 유지한다. Align·Modifier에서 표본 자료를 완전한 COLMAP 모델로 받는 일이 없어야 한다.
6. 표본 밖의 자료도 기존 Painter가 검사하던 구조·수치·자원 상한을 검사한다. 생략하는 것은 사용하지 않는 결과의 영구 보관과 중복 검사다.
7. 저장·복원은 기존 데이터와 신규 표본 자료를 모두 지원한다. 원본 OBJ 재읽기, 기존 페인트 레이어 초기화, 과거 프로젝트의 강제 재가져오기를 요구하지 않는다.

## 4. 단계별 설계

### 4.1 최초 검증 결과 재사용

최초 준비의 불변 결과를 가져오기 작업 동안 유지한다. 확정 전 검사에서는 원본 모델 선택·파일 식별·전체 파일 내용 해시·촬영 이미지 경로와 파일 식별만 다시 확인한다.

```text
현행: 해시 → 전체 읽기·검증·의미 지문 → 자산 준비
      → 해시·전체 읽기·검증·의미 지문 → 비교 → 확정

변경: 해시 → 전체 읽기·검증 → 불변 결과 → 자산 준비
      → 모델 선택·파일 해시·이미지 경로 검사 → 확정
```

- 내용 해시가 동일한 파일을 동일한 읽기 정책으로 처리한 결과는 최초 검증 결과를 재사용한다. 파일 내용은 다시 해시하지만 다시 파싱하지 않는다.
- 검사 전후와 확정 경계에서 파일 식별을 대조한다. 검사 중 파일이 바뀌면 실패한다. 현대 COLMAP의 추가 파일도 최초 선택된 파일 집합에 포함해 검사한다.
- 이미지 경로 검사에는 실제 경로·경로 상태·파일 식별을 포함한다. 수정 시간만 확인하고 경로 검사를 생략하지 않는다.
- 가져오기 취소와 증분 진행을 유지한다. 파일 해시 계산을 한 번의 긴 동기 호출로 바꾸지 않는다.
- 동기 실행과 모달 실행은 같은 변경 검사 구현을 사용한다. `source_prevalidated`는 실제 검사가 완료된 작업에서만 허용한다.
- 기존 의미 지문 공개 함수와 기존 전체 읽기의 의미 지문 형식은 유지한다. 신규 직접 입력에서는 원본 내용 지문과 표본 정책·표본 지문을 명확하게 구분해 저장한다. 기존 필드의 의미를 조용히 바꾸지 않는다.

완료 기준은 확정 전 전체 재파싱·점 수치 재검증·전체 점 의미 지문 재계산이 각각 0회이며, 기존 원본 변경 검사가 통과하는 것이다.

### 4.2 참고용 읽기와 2만 점 제한

공통 읽기 계층에 명시적인 참고용 보관 정책을 추가하고 Painter의 직접 입력에서만 선택한다. 파일 형식 해석은 기존 구현을 재사용하며 Painter용 파서를 통째로 복제하지 않는다.

| 자료 | 신규 Painter 직접 입력 |
|---|---|
| 카메라 내부 파라미터 | 전체 유지 |
| 이미지 자세·이름·촬영 이미지 경로 | 전체 유지 |
| 점 식별자·좌표·RGB·재투영 오차 | 선택된 최대 20,000점 유지 |
| 이미지의 2차원 관측·점의 관측 트랙 | 필요한 기존 검사를 수행한 뒤 보관하지 않음 |
| 원본 전체 점 개수·전체 경계·출처 지문 | 별도 메타데이터로 유지 |

표본 선택은 전체 파일을 대상으로 하는 **재현 가능한 우선순위 표본**을 기본안으로 한다. 원본 64비트 점 식별자로 고정 우선순위를 계산하고, 블록별 배열 처리로 우선순위가 높은 최대 20,000점만 유지한다. 동률은 원본 식별자로 결정한다. 처음 20,000점만 읽고 중단하지 않는다.

- 20,000점 이하는 유효한 점 전체를 유지한다. 빈 점군의 기존 허용 동작을 유지한다.
- 동일한 식별자 집합은 재입력과 TXT·BIN 입력에서 같은 표본을 선택한다. 원본 식별자 오름차순의 기존 점 표시 계약을 유지한다.
- 이 방식은 점 밀도를 따르는 대표 표본이다. 공간별 동일 개수를 보장하는 격자 표본으로 설명하지 않는다. 실제 자료에서 작은 부위·희소 부위의 표시 품질도 확인한다.
- 좌표·색상·오차·관측 결과를 모든 점에 대해 누적하지 않는다. 작업 블록과 표본 배열만 보관한다.
- 전체 원본 식별자 중복 검사를 유지하려면 별도 `uint64` 식별자 배열이 필요할 수 있다. 이를 허용하고 최대 메모리를 따로 측정한다. 점 수가 늘어도 모든 메모리가 20,000점으로 고정된다고 주장하지 않는다.
- 전체 경계는 읽는 중 모든 유효한 원본 좌표에서 누적한다. 표본에 극값이 포함되지 않았다는 이유로 데이터셋 경계가 축소되어서는 안 된다.
- 표본에 포함되지 않은 점의 수치 오류와 손상된 관측 구간도 기존 검사 기준으로 거부한다. 특히 BIN 구간을 건너뛰기만 해서는 필요한 범위 검사가 유지되지 않는 경우 블록 검증 후 폐기한다.
- TXT는 전체를 훑는 비용이 남는다. BIN도 구조 검사와 전체 파일 내용 해시가 필요하다. 점군을 2만 개로 제한한다고 파일 입출력이 2만 점만큼으로 줄지는 않는다.

참고용 결과는 원본 전체 모델과 구별되는 자료형·메타데이터로 반환한다. 트랙을 비운 일부 점군을 완전한 `ColmapModelData`로 위장해 전체 무결성 검사를 통과시키지 않는다.

파일 탐색기의 상한 기본값은 20,000개이며 허용 범위는 1부터 100,000,000개까지다. 마지막으로 확정한 값을 다음 선택 창에서 유지한다. 탐색기에서 값을 바꾼 뒤 취소하면 기존 경로·상한을 유지한다. 상한을 올리면 실제 보관량·메시 생성량이 늘어날 수 있다.

원본 점 수, 가져온 점 수, 전체 경계, 표본 정책·버전을 기록한다. 기존 `snapshot_point_count`는 실제 가져온 점 수 의미를 유지하며, 원본 수는 별도 기록한다. 필요한 점 수 안내만 기존 Dataset 영역에 추가하고 새로운 설정 패널은 만들지 않는다.

### 4.3 작업 처리와 화면 갱신 분리

우선 실제 화면에서 읽기·검증·자산 생성·확정의 수행 시간, 타이머 호출 수, 화면 갱신 요청 수와 전체 경과 시간을 분리 계측한다.

- 한 이벤트의 공통 작업 예산 안에서 여러 짧은 단계를 이어서 처리한다. 단계가 바뀔 때마다 다음 이벤트를 기다리는 구조를 줄인다.
- 초기 조정 범위는 현재 25밀리초에서 최대 50밀리초다. 취소 반응과 화면 입력 지연을 계측해 최종값을 정한다. 단일 Blender 호출은 예산을 넘길 수 있으므로 실제 최장 지연도 측정한다.
- 진행 화면은 약 100밀리초 간격으로 갱신하되 단계 변경·완료·오류·취소는 즉시 반영한다. 계산을 이 표시 주기에 맞춰 쉬게 하지 않는다.
- 큐에 쌓인 타이머 이벤트를 장시간 연속 소비하지 않는다. 다른 오퍼레이터의 타이머 이벤트를 가져오기 이벤트로 잘못 처리하는지도 확인한다.
- Blender 데이터 생성·변경은 메인 스레드에서 유지한다. 별도 스레드에서 `bpy`를 호출하지 않는다.
- 진행률은 원본 검사량과 표본 자산 생성량을 구분한다. 실제 수행하지 않는 전체 점 생성 수를 완료량으로 표시하지 않는다.

목표는 실제 화면에서 불필요한 대기·갱신 비용을 줄이면서 취소 응답 지연을 보통 100밀리초 이내로 유지하는 것이다. 긴 단일 API 호출의 예외와 측정된 최장값은 결과에 별도로 기록한다.

### 4.4 배열 검사와 메시 일괄 기록

- 좌표의 유한성, RGB 범위, 오차·식별자 범위를 블록 단위 배열 연산으로 검사한다. 오류가 있으면 해당 원본 식별자를 찾아 기존 수준의 오류 설명을 반환한다.
- 공통 검사와 Painter 전용 검사의 책임을 나누고 같은 배열의 같은 조건을 다시 검사하지 않는다. 지원 카메라 모델·촬영 이미지 경로 등 Painter 전용 검사는 유지한다.
- 신규 배열 입력에서는 점별 `PointPayload`와 좌표·색상 파이썬 목록 생성을 피한다. 기존 공개 레코드 입력도 계속 지원한다.
- 점 메시 정점을 할당한 뒤 좌표를 `foreach_set`으로 기록한다. 이미 일괄 기록 중인 색상·오차·식별자도 연속 배열로 전달한다.
- RGB 변환·알파·재투영 오차·가시성 속성·상하위 32비트 점 식별자 인코딩·원본 점 인덱스의 기존 의미를 유지한다. 표본 배열 순번과 원본 식별자를 혼동하지 않는다.
- 생성 실패 시 메시·재질·노드 그룹·오브젝트 등 이번 작업의 임시 자원만 정리한다.

### 4.5 카메라 조회표 재사용

카메라 오브젝트를 생성할 때 소유 식별자별 실제 오브젝트 조회표를 만든다. 확정 시 마커 연결과 최초 카메라 선택에 같은 조회표를 사용한다.

- 조회표는 현재 가져오기 작업에만 속하며 다른 도구나 가져오기와 공유하지 않는다.
- 생성 오브젝트의 소유권·참조 유효성을 확인한 뒤 연결한다. 누락·중복 식별자는 명확한 오류로 처리한다.
- 실패·취소·완료 시 조회표 참조를 해제한다. 저장 파일에는 런타임 오브젝트 포인터를 직렬화하지 않는다.
- 기존 마커 순서·이름·프레임·카메라 대응과 확정 실패 복구를 유지한다.

표의 `core/`, `blender/`는 별도 표기가 없으면 `tools/projection_paint/` 아래를 뜻한다. 예상 수정 대상은 실제 구현 전 공개 사용처를 확인해 좁힌다. 기존 UI·페인트 가시성·카메라 원근투영·사용자 미커밋 작업을 되돌리지 않는다.

제품 코드는 사용자 구현 요청 후 변경한다. 서브에이전트는 사용자가 직접 요청한 경우에만 사용하고 전역 지침을 따른다. 계획 작성만으로 설치·커밋·푸시를 수행하지 않는다.

## 6. 검증과 벤치마크

### 기능 검사

- TXT·BIN 각각의 0점, 20,000점 미만·동일·초과, 수백만 점 자료에서 원본 수와 가져온 수를 확인한다.
- 동일 자료 재입력, TXT·BIN 등가 자료와 레코드 순서 변경에서 표본 식별자·좌표·색상·오차가 일치한다. 큰 비연속 64비트 식별자도 포함한다.
- 표본 밖의 중복 식별자·NaN·무한대·음수 오차·잘못된 RGB·손상된 관측 구간을 넣어 기존 검사가 유지되는지 확인한다.
- 카메라 자세·내부 파라미터·프레임·사진 연결·축 변환·원본 전체 경계를 비교한다. 표본 경계와 원본 경계가 다른 자료를 포함한다.
- 파싱 중·자산 생성 중·확정 직전 파일 변경·삭제·교체를 검사한다. 크기와 수정 시간을 유지한 내용 변경도 해시로 감지해야 한다.
- 이미지 이동·누락·파일 교체, 다른 희소 모델 선택과 BIN·TXT 구성 변경을 검사한다.
- 각 단계 취소·실패·작업공간 이동·파일 로드·확장 해제 후 임시 자원·타이머·그리기 콜백이 남지 않는다. 기존 자산과 픽셀을 보존한다.
- 기존 저장 프로젝트의 전체 점군을 그대로 복원하고 신규 표본 프로젝트도 원본 메타데이터·촬영 이미지·페인트 레이어와 함께 복원한다.
- Align·Modifier의 전체 읽기와 기존 Painter 공개 읽기 API를 회귀 검사한다. 공통 기본 입력이 2만 점으로 제한되면 실패다.

### 성능 측정 방법

실제 프로젝트의 COLMAP 원본 경로는 현재 장면 설정에서 읽고, 해당 파일을 읽기 전용으로 사용한다. 기존 `Untitled.blend`와 현재 사용자 장면은 저장하거나 입력 교체하지 않는다. 사용자 자료를 같은 Blender 버전의 분리된 검사 환경에 입력해 비교한다.

| 비교 | 목적 |
|---|---|
| 현행 전체 입력 ↔ 1단계만 적용 | 원본 검사 재사용 효과 분리 |
| 1단계 ↔ 참고용 읽기·2만 점 | 보관 축소와 표본 선택 비용·효과 분리 |
| 같은 새 입력의 화면 갱신 조정 전후 | 이벤트·갱신 비용 분리 |
| 배열 기록·조회표 조정 전후 | 계산·자산 생성·확정 비용 분리 |
| 현행 ↔ 모든 단계 적용 | 최종 사용 시간·최대 메모리 비교 |

시험용 10만 점 자료와 사용자 실제 자료를 각각 최소 3회 측정하고 중앙값·범위를 기록한다. 카메라 조회 비용은 카메라 수가 작은 자료와 수백·수천 개인 자료를 나눠 확인한다. 첫 실행과 반복 실행, 운영체제 파일 캐시를 비우지 않았다는 조건을 구분한다.

기록 항목은 전체 경과 시간, 파일 해시·읽기·검증·표본 선택·자산 생성·변경 검사·확정 시간, 최대 작업 집합, 타이머·다시 그리기 요청 수, 취소 지연, 원본·표본·카메라·이미지 수다. 계산만 빠른 결과를 실제 화면 전체 시간 개선으로 보고하지 않는다.

효과를 먼저 수치로 보장하지 않는다. 사용자 자료의 화면 전체 시간과 메모리가 감소해야 하며, 단계를 추가한 뒤 회귀하면 그 단계의 구현을 보완하고 원인을 기록한다. 기존 자료를 미리 읽어 둔 결과와 새 파일 입력을 같은 비용으로 비교하지 않는다.

## 7. 완료 기준과 배포

1. 신규 Painter 입력은 기본 상한 20,000점이며 탐색기에서 정한 상한을 따른다. 카메라·이미지는 전체 유지된다.
2. 확정 전 전체 재파싱은 제거되고 원본 내용·파일 식별·이미지 경로 변경 검사는 유지된다.
3. 사용하지 않는 관측 배열을 보관하지 않으며 전체 원본 수·경계·식별자 검증의 메모리는 별도로 보고한다.
4. 기존 공개 API·저장 복원·소유권·실패 복구·취소와 도구 간 독립성이 검사된다.
5. 실제 자료의 계산 시간·화면 시간·메모리를 동일 조건으로 비교하고 정식 빌드의 필수 검사를 통과한다.
6. 구현 완료 후 정식 설치 ZIP은 저장소 최상위 `colmap_tools.zip`으로 갱신한다. 제품 로그에 일회성 계측·디버그 출력을 남기지 않는다.
7. 설치 교체·현재 Blender 반영·커밋·푸시는 후속 구현 요청의 승인 범위에 맞춰 수행하고 각각 실제 수행 여부를 구분해 보고한다.

## 8. 외부 근거

- [COLMAP 공식 파일 형식](https://colmap.github.io/format.html): TXT·BIN, 비연속 식별자, 카메라 자세와 2차원 관측·점 트랙의 저장 구조를 확인했다. BIN 우선 탐색은 현행 코드에 이미 있으므로 신규 개선 실적으로 계산하지 않는다.
- [Blender 컬렉션 일괄 기록 API](https://docs.blender.org/api/5.2/bpy.types.bpy_prop_collection.html): `foreach_set` 사용 근거. 실제 배포 대상 Blender 5.2에서 속성과 결과를 검증하며, 문서상의 API 지원을 실제 성능 개선으로 대신하지 않는다.
