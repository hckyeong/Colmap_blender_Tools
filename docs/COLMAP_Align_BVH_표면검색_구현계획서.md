# Align BVH 기반 정확 표면 검색 구현 계획

- 작성일: 2026-09-20
- 상태: 계획 확정, 구현·검증 진행 중
- 기준: 0.3.62, `cccore-native-v6`, `cccore-icp-v5`, 현재 최적화 브랜치
- 대상: `Untitled.blend`의 보존된 3점 정렬 입력과 고양이 원본 메시

## 1. 목표와 근거

기존 CCCoreLib의 변환 계산은 유지하고, 메시의 정확 최근접 표면 검색을 BVH로 바꾼다. 준비·등록·독립 평가가 동일한 불변 원본 메시의 검색 트리를 재사용한다.

직전 분리 실험에서 같은 원본 삼각면 11,303,380개에 대한 5만 점 조회 다섯 번은 CC 2.639초, MeshLib 0.147초였다. CC 격자는 한 번 생성되고 19회 재사용됐다. 기존 ICP 시간 136.649초 중 최근접점 검색은 127.848초다. 따라서 이번에는 격자 생성 횟수가 아닌 검색 경로를 교체한다. 다른 구현이 MeshLib의 18배를 그대로 달성한다고 가정하지 않는다.

## 2. 변경하지 않는 계약

- 50,000개 등록 표본, 독립 평가 표본·시드·공간 분포·겹침 반경을 유지한다.
- 기존 점-점 변환 산출, 먼 점·부분 겹침 필터, 강체 200회·배율 1,000회 상한, 종료 조건을 유지한다.
- 기존 누적 추가 배율 ±10%, 정·역방향 처리, 품질·후보 선택 규칙을 유지한다.
- 원본 메시·OBJ·마커·사용자 프로젝트, 점군 기준 검색과 기존 공개 CC 등록 API를 보존한다.
- 점-평면, 배율 동시 최적화, 표본 축소, 임의 거리 제한, 이전 대응 후보 재사용은 이번 범위에서 제외한다.
- 기존 작업 중인 Modifier·Painting·UI 변경 파일을 수정하거나 포함하지 않는다.

## 3. 구현 구조

### 정확 검색기

외부 MeshLib 코드를 가져오지 않고 작은 자체 C++ BVH 모듈을 작성한다. 기존 oneTBB와 CCCoreLib의 공개 점-삼각형 거리 연산을 활용한다. 새 제삼자 바이너리·라이선스 의존성은 추가하지 않는다.

트리는 원본 삼각형 ID의 순열과 경계 상자를 보관한다. 면 연결·좌표는 기존 불변 메시에서 읽는다. 삼각형 중심 분포의 구간별 표면적 비용을 사용해 분할하고, 분할이 불가능한 경우에도 종료 가능한 중앙 분할·잎 노드 정책을 둔다. 가용 메모리 검사와 취소를 포함해 한 번 생성한다. 병렬 검색 전에 완성된 읽기 전용 상태가 되어야 한다.

질의점과 상자 사이 최소 제곱거리로 후보를 제외하고, 가까운 자식부터 순회한다. 잎에서는 원본 삼각형의 정확한 최근접점·거리·ID를 구한다. 검색 상한은 실제 계산한 후보 거리에서만 나온다. 트리 밖의 점도 정확히 검색한다. 동거리 처리 순서를 결정적으로 고정하고 경계 반올림 때문에 더 가까운 삼각형을 누락하지 않는다.

조회 묶음은 oneTBB로 병렬 처리하되 결과는 질의 원래 인덱스에 기록한다. CCCoreLib 필터가 사용하는 최근접점 배열과 삼각형 번호 스칼라 필드를 함께 유지한다. 거리 스칼라 오프셋은 병렬 쓰기 전에 확정한다. 미완료·실패·취소된 결과를 성공으로 반환하지 않는다.

### 세션 캐시와 메모리

지오메트리 레지스트리가 원본 메시 항목의 BVH를 소유한다. 기준 메시가 고정되면 질의점 이동이나 묶음 변경으로 재생성하지 않는다. 강체·배율·평가 사이에도 유지하며, 서로 다른 원본은 구별한다. 명령 수명 메시의 트리는 명령 종료 때, 세션 수명 메시의 트리는 해제·세션 종료 때 반환한다.

추가 BVH 메모리 예산은 가용 물리·커밋 메모리의 작은 쪽을 기준으로 정하고 명시적인 상한을 둔다. 트리 상주 배열과 생성 중 임시 배열의 최고치를 모두 포함한다. 새 트리 생성 전 사용하지 않는 캐시를 해제할 수 있으나 현재 질의의 트리는 해제하지 않는다. 예산 부족은 진단 가능한 오류로 처리하며 근사 검색·자동 엔진 재시도로 우회하지 않는다. 전체 메시 좌표를 트리마다 다시 복사하지 않는다.

구체적인 노드 크기·잎 크기·생성 메모리 산정은 실제 C++ 자료형과 테스트로 확정하고 결과 절에 기록한다. 기존 격자 포인터 예산을 BVH 전체 예산으로 잘못 재사용하지 않는다.

### ICP 연결

기존 `ICPMeshRegistrationContext`에 선택적인 외부 정확 메시 거리 콜백을 추가하는 별도 패치를 둔다. 콜백이 없으면 기존 격자 경로와 공개 API가 유지된다. 제품 워커의 메시 등록은 세션 소유 BVH를 연결하고, 변환 계산·필터·반복은 그대로 CC가 수행한다. 외부 검색 경로에서는 사용하지 않는 메시 검색 단계 선택·질의 옥트리를 만들지 않는다.

기존 패치 원문과 해시를 변경하지 않고 `mesh-bvh-search-v1` 패치를 추가한다. 적용 순서·원문/결과 해시·LGPL 재빌드 원문을 빌드 산출물에 포함한다. 배포되는 결과와 캐시 폴더만 바꾼 실험 실행 파일을 혼동하지 않는다.

### 계약·계측

네이티브 프로토콜은 v7로 올려 실행 파일 혼용을 거부한다. 새 계산 경로의 알고리즘 식별자도 갱신하며 과거 승인 결과 복원은 유지한다. BVH 생성·적중·해제 횟수, 생성·검색 시간, 상주·생성 최고 바이트를 별도 이름으로 기록한다. BVH를 기존 `mesh_grid_*` 수치로 표시하지 않는다. ICP에서는 검색 방식·BVH 조회 횟수와 기존 실제 반복·필터·변환 구간을 구분한다.

현재 실행의 새 통계는 엄격히 검사하고, 과거 기록에는 존재하지 않는 새 필드를 요구하지 않는다. 사용자에게 새 성능 설정이나 엔진 선택 UI를 추가하지 않는다.

- 검색 구현 담당: 자체 BVH 모듈, 정확 거리·최근접점·삼각형 ID, 메모리·취소·병렬 처리.
- 네이티브 연결 담당: CC 콜백 패치, 워커 세션 캐시·등록/거리 연결·계측.
- 계약·배포 담당: Python 계약·과거 결과 호환·관련 테스트, 빌드 잠금·패키징·재빌드 검증.

주 에이전트가 이 계획과 관련 문서를 직접 검토하고 구체적인 API·수정 범위를 전달한다. 서브에이전트는 재위임하지 않으며 담당 파일 밖 변경은 협의한다.

## 5. 검증 순서와 채택 기준

1. 작은 삼각형 집합의 전수 검색과 거리·최근접점·삼각형 ID를 비교한다. 면 내부·변·꼭짓점·큰 좌표·얇은 면·동거리·평면·트리 밖 점·단일/다중 스레드를 포함한다.
2. 메모리 예산·생성/검색 취소·연속 명령·해제·변경된 지오메트리·범위 선언 오류를 검증한다. 사용자 시스템 메모리를 고갈시켜 테스트하지 않는다.
3. 같은 실제 입력의 고정 5만 점 조회 경로를 예열 1회+3회로 비교한다. 기존 격자와 새 BVH의 생성·검색 시간을 분리한다. 기존 정규화 거리 허용치 2e-7을 유지한다.
4. 같은 표본의 짧은 ICP부터 실행한다. 검색 교체 외 설정이 동일함을 확인하고, 실제 전체 등록은 효과가 확인된 뒤 수행한다. 독립 평가에는 보존한 기존 v6 실행 파일을 사용한다.
5. 전체 등록의 기존 최종 행렬 비교 허용치 2e-6, 기존 제품 품질, 알려진 정답의 부분 겹침 100·70·40·20·10% 기준을 유지한다. 수치 경로 차이는 기록하고 허용값을 사후 완화하지 않는다.
6. 네이티브·Python 계약/솔버·Blender 네 형상 조합·미리보기/승인/취소·저장 복원 중 영향받은 검사를 수행한다. Release와 배포 ZIP의 실행 파일·패치·원문 일치를 확인한다.
7. 마지막으로 별도 검증용 Blender에서 같은 3점 시작 상태의 실제 Align을 측정한다. 사용자 원본을 저장하거나 현재 작업을 덮어쓰지 않는다. 준비·등록·평가·전체 시간과 최고 메모리를 보고한다.

검색이 빨라져도 생성 비용 때문에 전체가 느리거나 정확도·메모리 조건을 충족하지 못하면 기본 제품 경로에 채택하지 않는다. 실패 이유를 숨기는 예외·자동 재실행·근사 대체를 넣지 않는다.

### 검증 중 확인된 공유 모서리의 수치 차이

고정 400점 사면체 시험에서 두 번째 조회의 한 점은 인접한 두 면의 공유 모서리에 투영된다. CC 원본 삼각형 함수의 제곱거리는 각각 `1.907910149980862e-05`, `1.9079101499807035e-05`다. 기존 격자는 중간 단정도 저장 후 두 값이 같아져 앞 면을 선택하고, BVH는 더 작은 원래 값을 선택한다. 저장된 최종 거리는 같지만 최근접 좌표는 `5.96e-8` 차이가 있다. 이 차이가 거의 수렴한 상태의 먼 점 필터에 누적되어 최종 잔여 점 개수가 달라졌다.

따라서 해당 조건의 **GRID 최종 개수 동일성**은 독립 전수검색 ICP와의 **종료 코드·최종 개수·행렬·배율·RMS 완전 동일성**으로 대체한다. 같은 고정 입력의 강체/배율·필터·먼 이상점·단일/다중 스레드 16개 조합을 모두 검사한다. 기존 GRID의 행렬 `2e-5`·RMS `2e-6` 회귀, 실제 입력의 행렬 `2e-6`·거리 `2e-7`·제품 품질 기준은 유지한다. BVH의 정확 최솟값 선택을 기존 반올림 결과에 맞추어 바꾸지 않는다.

## 6. 변경 대상과 완료 기준

변경은 `tools/align/native/cccore_worker`, `tools/align/alignment`의 계약·실행 부분, 해당 런타임 빌드 도구·검증 파일, 이 계획과 관련 배포 문서에 한정한다. 새 모듈은 C++17과 기존 Windows x64·oneTBB 환경을 유지한다. 변경·추가 함수에는 간단한 한국어 설명을 작성한다.

완료 보고에는 실제 적용 경로, 보존/추가된 API, 성능·오차·메모리·취소 결과, 재빌드 가능한 Release/ZIP 위치와 미검증 범위를 기록한다. 이번 승인 범위는 계획 작성과 구현·검증이다. 설치·원격 배포 여부는 실제 수행 결과와 구분한다.

정확도·계약 검증:

- 동일 5만 점의 다섯 배치를 4회 조회한 100만 개 거리 값이 기존 격자와 완전히 같았다. 생성 이후 다섯 조회의 중앙값 합계는 2.639초에서 0.145초로 줄었다. 이 분리 측정은 같은 BVH 구현의 개발 빌드이며 전체 Blender 결과와 구분한다.
- 실제 최종 행렬 최대 차이 `8.46e-8`로 기존 허용치 `2e-6` 이내다. 등록·독립 평가 표본 지문, 원본 형상·마커·파라미터·품질 정책이 동일하다.
- 제품 품질 판정과 보존한 기존 v6 엔진의 별도 평가가 모두 `PASS`다.
- 네이티브 회귀 51개, Python·네이티브 통합 107개, 전수 거리·취소 C++ 시험, 독립 전수 ICP 16개 조합을 통과했다.
- 부분 겹침 100·70·40·20·10% 모두 기존 정답 허용치 이내다. Blender 저장 복원 11개와 ZIP 격리 설치·실제 네 형상 조합·미리보기/승인/취소 검사도 통과했다.
- 지정한 `.blend`와 OBJ는 저장하지 않았으며 실행 전후 크기·수정 시각이 같다. 이는 파일 내용 전체 해시 검사와 구분한다.

배포 ZIP은 `build/colmap_tools-0.3.63.zip`, SHA-256은 `b8954732bff80d159241147734dfa6d6ae28a42c6bbb4494d2c8a8f5bc690039`다. 격리 설치본과 최종 런타임 바이너리 지문 일치를 확인했다. 실제 사용 중인 Blender 설치는 교체하지 않았다. 측정·한계·재현 파일은 [검증 결과](../build/verification/bvh-implementation/결과.md)에 정리했다.

남은 가장 큰 구간은 준비 단계 27.5초다. 이번 변경으로 준비 시간은 줄지 않았으므로 다음 개선은 준비 내부의 기하 정리·표본 생성·자료 전달을 별도로 계측해서 판단한다. 여러 실제 스캔 쌍·낮은 메모리 사양·다른 CPU에서의 전체 성능은 이번 수치로 일반화하지 않는다.
