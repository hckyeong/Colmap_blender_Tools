# ADR-0010: 실험 Align의 CCCoreLib 정렬 엔진

- 상태: 실험 브랜치 채택
- 결정일: 2026-09-03
- 적용: `codex/align-test-env`의 `colmap_align_test_env` 배포
- 관련: [엔진 교체 계획서](../COLMAP_Align_CCCoreLib_엔진교체_계획서.md), [CPU 멀티스레드 계획서](../COLMAP_Align_CCCoreLib_CPU_멀티스레드_적용_계획서.md), [ADR-0006](0006-small-gicp-runtime.md)

## 결정

실험 정밀 정렬의 기본 엔진을 CCCoreLib로 교체한다. 기존 마커 초기 정렬, 미리보기, 버리기, 승인과 Undo/Redo를 유지한다. 레이어의 점군·표면 선택으로 실제 입력을 정한다. A의 입력 종류가 섞이면 실행을 막는다.

점군–점군은 점 대응을, 기준 메시가 있는 경우는 삼각면 대응을 계산한다. P 메시/A 점군은 역방향으로 풀고 결과를 역변환해 P에 적용한다. 메시–메시는 면적 표본을 상대 삼각면에 대응시키며, 최적화와 별도 표본으로 양방향 거리를 평가한다. 강체 정렬 뒤 시작 행렬 대비 0.9~1.1 배율의 균일 스케일 보정을 실행한다.

Blender는 형상 스냅샷과 공통 행렬을 소유한다. 외부 CPython 조정자가 고정 버전의 CC 실행 파일을 호출하며 네이티브 라이브러리를 Blender에 직접 불러오지 않는다. 취소·강제 종료는 조정자와 자식 실행 파일을 함께 정리한다. CC 실패 시 다른 엔진을 자동 실행하지 않는다.

## 코어와 배포

코어는 `dc8c7d80f4ef8fd6a2c302c8d5f9c35099ba8432`와 `bounded-scale-v1` 최소 패치를 고정한다. 원본 코어에서 배율 제한 후 반환 행렬과 내부 RMS가 달라지는 오류를 재현했으며, 실제 단계 변환을 적용하기 전에 배율을 제한하고 이동을 다시 계산하도록 수정했다. 경계 밖 정답·정방향·역방향 검증을 통과한 패치만 배포한다.

CCCoreLib 공유 DLL, 실행 파일, oneTBB, Microsoft C++ 런타임, 라이선스, 변경 표시와 재빌드 가능한 전체 원문 ZIP을 패키징한다. 구체적인 해시와 재현 절차는 [재빌드 문서](../../tools/align/native/cccore_worker/REBUILD.md)에 둔다. Windows x64에서 oneTBB 2022.0.0을 고정하고 단일 프로세스 세션 런타임을 `cccore-native-v3`로 식별한다. 요청 상한은 1~1024이며 네이티브 워커가 Windows 활성 논리 프로세서 수로 다시 제한한다. Add-on Preferences의 기본 자동값은 논리 프로세서 하나를 남기고, 사용자는 같은 v3 바이너리를 1스레드로 실행할 수 있다.

실험 ZIP은 Small GICP solver/worker와 Python 패키지·전용 DLL을 제외한다. 개발 소스의 이전 엔진은 비교와 공개 API 호환을 위해 보존한다. ADR-0006의 외부 프로세스 격리·고정 런타임·스테이징 검증 원칙을 유지하며, 이 실험에서 기본 엔진을 지정한 부분만 대체한다. main과 통합 배포 스크립트의 결정은 별도 통합 전까지 바꾸지 않는다.

## 저장과 결과 평가

저장 스키마 8은 코어·작업자 해시·설정·형상 출처와 내장 OBJ 식별자를 저장한다. 스키마 1~7과 이전 Small GICP 및 `cccore-icp-v1`·`cccore-icp-v2` 출처를 읽을 수 있다. 새 작업은 `cccore-icp-v3`로 저장하며 요청·실제·하드웨어 스레드 수, oneTBB 버전, 단일 프로세스 수, 논리 연산 순서, 세션 시간과 geometry 캐시 통계를 함께 보존한다. 실제 사용한 A/P 형상 축이 변경되면 의존 결과의 품질 판정을 무효화하며 공통 행렬을 임의 변경하지 않는다. Undo/Redo는 이전 판정과 출처를 복원한다.

독립 거리 RMS·중앙값·95백분위·90% 절사 RMS, 유효 대응 비율과 공간 분포로 결과를 판정한다. 대응이 부족하거나 국소 접촉에 편중된 결과는 실패 처리한다. 검토 사유가 있는 유효 결과는 사용자 확인 상태로 표시한다. RC 재구성의 국소 오차 해결은 엔진 교체와 별도 검증이다.

## v2 검증 결과

2026-09-04 기준 oneTBB 런타임은 네이티브 통합·워커·Blender UI·런타임 검사 44개를 모두 통과했다. `Untitled.blend`의 같은 v2 바이너리 비교에서 1스레드 96.0219초, 자동 31스레드 90.4438초로 `1.0617배` 빨랐고 결과 행렬과 평가 지표의 차이는 0이었다. 동시 작업 집합 피크 증가는 4.8281MiB였다.

이 결과는 수치·메모리 기준을 통과했지만 계획의 전체 `1.25배` 성능 기준에는 미달한다. 실험 배포에서 자동·수동 선택은 유지하며 main 통합과 최종 기본 상한 결정은 추가 오정렬 실데이터와 2·4·8·16스레드 측정 뒤에 판단한다. 상세 조건과 원인은 [CPU 멀티스레드 계획서](../COLMAP_Align_CCCoreLib_CPU_멀티스레드_적용_계획서.md)에 기록한다.

## v3 세션 검증 결과

2026-09-05 기준 `cccore-native-v3`는 Align 하나에서 네이티브 프로세스 하나를 시작하고, 점군–점군 6개·점군–메시 5개·메시–점군 5개·메시–메시 8개의 기존 논리 연산을 같은 순서로 수행한다. 작업자 충돌, 취소, 손상·중복·누락 명령과 경로 이탈은 부분 결과나 이전 프로토콜 fallback 없이 실패한다. 취소 파일 조회는 원자 latch와 25ms 단일 조회 제한을 사용하고 terminal 진행 기록 전후에도 강제 확인해 마지막 커널 콜백과 성공 응답 사이의 취소를 놓치지 않는다. Python도 자식 종료 직후 검증된 세션 종료 파일을 재조회해 취소 파일 공개와 프로세스 종료의 관찰 경쟁을 닫는다.

기본 A/P geometry는 `SESSION` 범위로 close까지 유지하고, 평가·등록 변형 geometry는 `COMMAND` 범위에서 같은 명령 안에서만 재사용한 뒤 성공 응답 기록 직후 해제한다. 해제 ID 재사용은 오류이며, 오류·취소 시에는 세션 종료와 레지스트리 소멸로 전부 회수한다. close의 geometry 통계, 상주·최고 캐시 바이트와 물리 명령 counter는 공통 Python 계약이 합계를 교차 검증한다.

역방향 표면 평가는 기준 표본을 합성 후보의 역행렬로 옮겨 원본 이동 메시를 조회하고 양의 균일 배율을 거리에 복원한다. 기존 float64 변환 후 float32 적재 순서와 양방향 수치가 같음을 확인해 후보별 전체 변형 메시를 제거했다. 정확 후보 평가는 원시 표본·행렬·평가 계약의 bit-exact 키가 같을 때만 재사용한다. 항등 메시–메시 작업은 논리 8개 중 물리 4개를 실행하고 4개를 캐시에서 재사용했으며, 비트가 다른 실제 후보는 모두 miss였다.

공개 API 옥트리 재사용은 점군·모델에 같은 결합 정육면체 경계를 적용한 뒤 거리 바이트 일치를 확인했지만 5회 평균이 control보다 7.25% 느려 채택하지 않았다. 정확 후보 캐시 뒤 완전 키가 반복되는 메시 교차 격자도 없어 장기 grid cache는 만들지 않았다. 검증된 control 경로를 유지하고 해당 cache hit를 0으로 기록한다.

물리 명령마다 Python 요청 원자 기록 직전부터 응답과 거리·행렬 검증 완료 직후까지 host 단조 왕복 시간을 기록한다. 프로토콜 오버헤드는 왕복 시간에서 네이티브 응답의 실행 시간을 뺀 비음수 값이며, 물리 명령 합계와 전체 solver 시간 대비 비율을 중첩·최상위 감사 필드에 함께 둔다. 정확 후보 캐시의 논리 기록은 원본 측정값을 보존하되 물리 합계에는 한 번만 포함한다. 공통 계약과 복원 경계가 공식·합계·비율을 다시 계산해 손상 결과를 거부한다.

`Untitled.blend` 최종 run05 검증에서 aligned 자동 31스레드는 평균 `5.9969730초`로 v2 자동보다 `15.081577배`, 1스레드 대비 `1.708073배` 빨랐다. aligned v3 측정 3회 안에서 행렬·RMS·후보·품질은 bit-identical이었다. aligned는 논리 8개·물리 4개·정확 캐시 적중 4개, 오정렬은 논리 8개·물리 8개·적중 0이었다. 같은 입력의 v2 오정렬 평균 `502.1496997초` 대비 v3 평균 `106.0332545초`로 v3가 `4.735776배` 빠르고 시간을 `78.8841%` 줄였으며 PID는 8개에서 1개로 줄었다. v2/v3 최종 행렬·delta 최대 차이는 0, 품질과 후보는 동일하며 trimmed RMS 차이 `3.7746634e-9`는 기존 허용오차 안이다. aligned·오정렬 최대 작업 집합 증가는 2.8513%·3.4366%로 통과했다. 오정렬 등록 두 호출 합계는 전체의 94.6548%였지만 내부 가속 구조만의 시간은 분리되지 않아 6단계 등록 내부 가속 구조 재사용 성능 패치를 적용하지 않는다. 이미 채택한 `multithread-state-race-v1` 동시성 패치는 유지한다. 최종 runtime 지문은 worker `45AED37A...`, 원문 ZIP `A76CCFF1...`, Manifest `2982BC7C...`다.

직접 계측한 전체 solver 대비 프로토콜 오버헤드는 aligned 자동 3.3668~5.0927%, 1스레드 1.2896~2.2335%로 1% 기준을 실패했고, 오정렬은 0.2675~0.2977%로 통과했다. 전체 최대값은 5.092686%이며 Paging counter는 미측정이다. run03의 7/12 지점에서 발견한 정상 close 응답·exit 0 관찰 경쟁은 종료 상태 검증 뒤 응답 경로를 재확인하도록 수정했고, 결정적 경계와 실제 정상 close 16회를 포함한 solver 41/41 및 Blender UI 9/9·runtime 7/7·persistence 9/9를 통과했다. run04는 이전 바이너리 이력으로 보존하고 상대 Manifest·호스트 경로 제거 뒤 최종 워커로 수행한 run05를 채택한다. 성능·수치·메모리·단일 PID 기준은 통과했지만 프로토콜 기준 실패와 Paging 미검증 때문에 전체 판정은 `EXPERIMENT_ONLY`로 유지한다.
