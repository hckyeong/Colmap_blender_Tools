# ADR-0011: CC 정식 배포와 v3 채택

- 결정일: 2026-09-05
- 상태: 정식 채택
- 적용: `colmap_tools` 0.3.37
- 대체: ADR-0006의 기본 엔진·배포 결정, ADR-0010의 실험판 한정 적용 범위
- 근거: [마이그레이션 계획](../COLMAP_Align_main_마이그레이션_계획서.md), [승격 기록](../migration/ALIGN_CC_MAIN_RELEASE_NOTE.md)

## 정식 실행 계약

기본 엔진은 `CCCORELIB`, 알고리즘·작업·네이티브 프로토콜은 각각 v3로 유지한다. 실험판의 네이티브 바이너리와 계산 경로를 그대로 검증해 이관한다. 등록 내부 옥트리·메시 격자에 새 캐시 패치를 추가하지 않는다.

Blender는 별도 전용 Python 조정자를 실행하고, 조정자는 Align 작업 하나에 네이티브 세션 워커 하나를 실행한다. 기본 A/P 형상은 세션 종료까지 보존하며 변형 임시 형상은 명령 완료 뒤 해제한다. 오류·취소·프로토콜 위반 시 부분 결과 승인이나 구엔진 재시도를 하지 않는다.

CPython 3.12.10, NumPy 1.26.4, 고정 CCCoreLib 커밋과 두 기존 패치, oneTBB 2022.0.0을 사용한다. 배포는 Windows x64를 대상으로 한다. 빌드는 원본 다운로드 해시, 실제 버전과 최소 연산, 네이티브 잠금 파일·라이선스·원문·바이너리 해시를 검사한다. Git 줄바꿈 차이는 네이티브 빌드 원문과 소스를 대조할 때만 정규화하며, 배포 파일의 원래 SHA-256 검사를 대체하지 않는다.

Root Preferences 하나에서 CPU 상한을 저장한다. 자동은 기존 실험판과 같은 논리 CPU 수에서 하나를 남기는 정책이며, 사용자는 단일·수동 상한을 선택할 수 있다. 실행 중 설정 변경은 다음 작업에 반영한다. 이번 승격은 CPU별 최적 상한 탐색이나 GPU 엔진 추가 작업을 포함하지 않는다.

## 배포 프로필

| 빌드 인자 | 기본 엔진 | 포함 실행 환경 | 용도 |
|---|---|---|---|
| 생략 또는 `CCCoreLib` | CC | CC 전용 Python·네이티브 워커 | 정식 사용자 배포 |
| `SmallGicp` | Small GICP | 기존 Small GICP Python | 희소 점군 비교 |
| `Full` | CC | CC 전용 Python·네이티브 워커 | 선택형 구엔진 소스를 포함한 개발 비교 |

Full의 선택형 구엔진은 필요한 패키지가 설치된 외부 Python을 명시해 실행한다. Full에 Small GICP·Open3D 실행 패키지를 자동 혼합하지 않는다. SmallGicp 비교판은 모든 A/P 레이어의 점군 선택을 요구하여 표면을 몰래 점군으로 바꾸지 않는다.

## 제품 경계와 저장

Root Shell과 공용 작업공간 교대 계약을 유지하며 Modifier·Projection Painting 소스는 변경하지 않는다. Align OBJ 원본은 Blender Mesh로 내장하고 삼각형 프록시를 정렬에 사용한다. COLMAP은 외부 원본 참조를 유지한다. 저장 스키마 8과 구현된 이전 스키마 읽기를 보존한다. 테스트 파일의 백업·일괄 변환은 사용자가 제외했으며 새 파일 저장·재연결은 계속 검증한다.

## 기존 성능 목표의 처리

실험 run05의 최대 프로토콜 오버헤드 `5.092686%`는 기존 `1%` 목표를 **충족하지 못했다**. 당시 페이징도 미측정이었으므로 `EXPERIMENT_ONLY` 판정은 이력으로 유지한다.

정식 채택에서는 해당 비율을 최적화 목표로 유지하되 단독 배포 차단 조건에서 분리한다. 동일한 소량의 명령 교환 비용도 이미 정렬된 입력에서 계산 시간이 줄수록 비율이 커진다. 정렬 입력 약 6초와 실제 오정렬 약 106초의 전체 시간, 왕복의 절대 비용, 이전 v3와 동일한 정확성·프로세스 수·메시 적재 횟수로 이관 결과를 판단한다. 기존 v2 대비 평균 15.08배·4.74배 개선을 없애고 구엔진으로 복귀시키는 근거로 비율 하나만 사용하지 않는다.

정확성 허용오차, 승인·취소·손상 결과 거부, 메모리 증가 제한은 완화하지 않는다. 시스템 PDH의 디스크 페이지 입출력과 페이지 파일 점유를 별도로 계측하며, 일반 페이지 폴트는 페이징 증거로 사용하지 않는다. 전역 카운터의 파일 읽기·다른 프로세스 영향을 특정 워커의 스왑 읽기로 오인하지 않는다.

정식 설치본의 3회 평균은 정렬 상태 `6.141806초`, 오정렬 상태 `102.505927초`다. 기존 v3 대비 각각 +2.42%·−3.33%이며 최종 행렬·5개 거리 지표의 차이는 0이다. 워커별 생애 최고 작업집합 합계의 증가는 +0.13%·+0.33%이고, 페이지 쓰기·페이지 파일 점유는 측정 구간에서 0이었다. 실제 디스크 페이지 읽기는 존재하므로 “모든 페이징이 없다”고 판정하지 않는다. 충분한 가용 RAM과 미사용 페이지 파일, 쓰기 없음에 근거해 이 입력·컴퓨터에서 메모리 압박으로 인한 스왑 악화 증거가 없다고 판단한다.

짧은 입력의 프로토콜 비용은 0.152~0.221초(3.29~4.80%)로 여전히 1% 목표를 충족하지 못한다. 오정렬은 0.279~0.403초(0.277~0.400%)다. 전체 시간·정확성·메모리·기능 검증을 근거로 v3를 정식 채택하며 1% 미달 사실과 등록 내부 추가 캐시 미채택 결론은 유지한다. 측정 조건과 계측 한계는 [승격 기록](../migration/ALIGN_CC_MAIN_RELEASE_NOTE.md)에 남긴다.
