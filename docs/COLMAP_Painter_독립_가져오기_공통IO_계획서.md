# Painter 독립 가져오기와 공통 파일 읽기 계층 계획서

- 작성일: 2026-10-05
- 기준: `main`, `48afa7d`, 제품 버전 0.3.72
- 상태: 2026-10-05 구현·검증·0.3.73 설치 ZIP 빌드 완료. 결과와 기존 검사 실패는 [구현·검증 기록](COLMAP_Painter_독립_가져오기_구현검증.md)에 구분한다.

## 1. 목표와 작업 범위

Painter의 Dataset에 **COLMAP 불러오기 / OBJ 불러오기** 버튼을 만들고, **Modifier에서 업데이트** 기능을 제거한다. Align에서 검증된 파일 읽기 코드를 공통 계층으로 옮겨 사용하되, 읽은 뒤의 데이터 구성과 실행 상태는 각 도구가 독립적으로 관리한다.

사용 흐름은 `Painter 열기 → COLMAP 불러오기 → OBJ 불러오기 → 기존 페인팅 절차`다. Modifier의 편집 결과가 필요하면 COLMAP으로 내보낸 뒤 Painter에서 해당 파일을 불러온다. Align이나 Modifier를 먼저 실행할 필요가 없다.

이번 범위에 포함하는 작업:

- COLMAP 탐색·읽기·파일 구조 검증의 공통화.
- Blender 기본 OBJ 가져오기 호출·임시 자원 관리의 공통화.
- Painter의 직접 입력 버튼, 가져오기 처리, 저장·복원 연결.
- 기존 Modifier 업데이트 UI·오퍼레이터와 그 전용 연결 제거.
- 기존 Align 가져오기와 저장된 Painter 프로젝트의 호환성 검증.

정렬 엔진, ICP·BVH, Modifier 편집 기능, 페인팅 알고리즘, 다중 COLMAP 데이터셋 관리, 자동 UV 생성은 변경하지 않는다. 공통화 대상 이외의 내보내기·투영 계산 모듈도 일괄 이동하지 않는다.

## 2. 현행 구조에서 확인한 사항

| 위치 | 현재 역할 | 변경 원칙 |
|---|---|---|
| `tools/align/colmap_io/` | TXT·BIN 탐색, 읽기, 자료형, 파일 지문, 구조 검증 | 도구 의존성이 없는 부분을 공통 계층으로 이동 |
| `tools/align/importer.py` | 파일 읽기 외에 레이어 등록, 표시 표본, GPU 준비, 확정 처리 | Align에 유지 |
| `tools/align/mesh_io/obj_native_import.py` | 기본 OBJ 가져오기, 임시 메시 관리, Align 자산 소유 태그 | 범용 가져오기·정리만 분리하고 Align 소유 처리는 유지 |
| `tools/align/mesh_importer.py` | 정렬용 메시 자료와 표시·등록 준비 | Align에 유지 |
| `tools/projection_paint/blender/camera_import.py` | Painter 카메라·점군 생성과 가져오기 확정 | 직접 파일 입력 결과를 연결해 재사용 |
| `tools/projection_paint/blender/core_adapter.py` | 기존 파일 입력 요청 구성 | 공통 읽기 결과를 받도록 조정 |
| `tools/projection_paint/blender/snapshot_update.py` | Modifier 제공자 접근과 Painter 데이터 복사 | 업데이트 경로 제거, 준비 상태 판정은 보존 또는 별도 분리 |
| `tools/projection_paint/blender/panels.py` | Modifier 업데이트 버튼과 표시 설정 | 두 개의 파일 입력 버튼으로 변경 |
| `tools/projection_paint/blender/paint_workspace.py` | 진입 시 Modifier 입력을 요구하는 안내 | 파일 직접 입력 안내로 변경 |

Painter에는 기존 `projection_paint.import_colmap` 오퍼레이터와 파일 준비 코드가 있지만, 현재 등록 목록과 요청 생성 함수 연결이 빠져 있다. 버튼만 추가해서는 동작하지 않는다. 직접 입력 결과를 현재 데이터 준비 상태·영구 기록·생명주기까지 연결해야 한다.

또한 OBJ 임시 결과의 확정 과정은 현재 Align의 자산 식별자와 소유 태그를 요구한다. 해당 클래스를 통째로 Painter에서 호출하면 소유권 경계가 깨지므로, 범용 부분을 분리해야 한다.

## 3. 목표 구조

```text
COLMAP 파일 → 공통 COLMAP 읽기·검증 ┬→ Align: 정렬용 레이어·표시·GPU 준비
                                  └→ Painter: 카메라·점군·촬영 이미지 연결

OBJ 파일 → 공통 Blender OBJ 가져오기 ┬→ Align: 정렬용 메시·표본·등록 준비
                                    └→ Painter: 실제 메시·재질·페인트 대상 준비
```

공유하는 것은 **코드와 반환값의 형식**이다. 한 도구에서 읽은 결과를 다른 도구의 실행 상태로 넘기거나, 같은 Blender 오브젝트를 두 도구가 함께 소유하는 구조는 만들지 않는다.

### 3.1 공통 COLMAP 계층

목표 위치는 `shared/colmap_io/`다.

- TXT·BIN 탐색, 증분 읽기, 카메라 모델 정의, 읽기 오류, 원본 파일 식별과 구조 검증을 포함한다.
- 원본 ID, 좌표, 카메라 자세, 배열 형식과 순서를 보존한다. 원본 ID를 배열 순번으로 바꾸지 않는다.
- 불변 배열·값을 반환하고, Blender·도구 Runtime·레이어·GPU·페인트 상태를 참조하지 않는다.
- 현재의 BIN 우선 탐색과 기존·현대 COLMAP 파일 구조 지원 및 오류 판정을 유지한다.
- 공통 구조 검증은 한 가져오기에서 재사용한다. Painter의 투영 가능 카메라·이미지 경로 검사는 별도로 수행한다.
- 출처 지문과 파일 변경 검사는 유지한다. 구조 검증 재사용을 이유로 확정 직전의 원본 변경 검사를 생략하지 않는다.
- Align 전용 로거 의존성은 중립 로깅으로 바꾼다. 공통 코드가 Align을 역으로 가져오지 않도록 한다.

기존 `tools/align/colmap_io/`의 공개 경로는 필요한 범위에서 공통 구현을 다시 내보내는 호환 모듈로 유지한다. 함수 인자·반환형·예외형과 클래스 동일성을 확인하고, 같은 읽기 구현을 두 벌로 복사하지 않는다.

`shared/colmap_dataset`의 과거 공용 데이터셋 구조를 신규 실행 상태 저장소로 사용하지 않는다. 읽기 결과에 도구별 UUID·수정 번호·표시 설정을 붙이는 작업은 각 도구의 연결 계층에서 수행한다.

### 3.2 공통 OBJ 가져오기 계층

목표 위치는 `shared/blender_runtime/obj_import.py`다. 이 계층은 Blender API를 사용하는 보조 코드로, 순수 COLMAP 읽기 계층과 구분한다.

- Blender 기본 `bpy.ops.wm.obj_import` 호출과 이번 호출이 만든 자원의 추적·실패 정리를 공통화한다.
- 기존 Align의 축·배율·오브젝트 분할 정책을 유지한다. Painter에서도 원본 좌표로 읽은 뒤 자기 축 설정을 적용해 축 변환 중복을 방지한다.
- 현재 단일 메시 입력 계약을 유지한다. 기존 가져오기에서 합쳐지는 OBJ 그룹을 새 기능에서 임의로 여러 대상으로 분할하지 않는다.
- 선택·활성 오브젝트·작업 컬렉션 등 호출 전 문맥을 복구한다.
- 임시 결과는 호출 도구에만 전달하고, Align 자산 태그와 Painter 소유 태그는 각 도구가 별도로 부여한다.
- 실패·취소 시 이번 호출이 새로 만든 자원만 정리한다. 기존 사용자 이미지·재질·다른 도구의 오브젝트를 이름으로 삭제하지 않는다.
- Painter는 원본 폴리곤·UV·재질 슬롯·텍스처 연결을 유지한다. 가져오기를 이유로 원본 메시를 삼각화하거나 정렬용 전체 배열로 복제하지 않는다.

기본 OBJ 가져오기 호출 도중에는 즉시 취소를 보장할 수 없다. 호출 전후에 취소 상태를 확인하고, 호출이 끝나면 임시 결과를 폐기할 수 있도록 한다. 별도 프로세스나 자체 OBJ 파서 도입은 이번 범위에서 제외한다.

## 4. Painter 입력과 UI

Dataset 패널에 다음 구성을 적용한다.

후속 UI 요청에 따라 실제 입력 영역은 **COLMAP 불러오기 / OBJ 불러오기** 버튼만 각각 한 줄로 표시한다. 아래 표의 상세 경로·축 입력란은 패널에서 제거했으며, 완료 동작은 [구현·검증 기록](COLMAP_Painter_독립_가져오기_구현검증.md)의 입력 UI 단순화를 따른다.

| UI | 동작 |
|---|---|
| COLMAP 불러오기 | 데이터셋 폴더를 선택하고 희소 모델과 촬영 이미지 폴더를 확인한 뒤 가져오기 |
| OBJ 불러오기 | OBJ 파일을 선택해 Painter 전용 메시 오브젝트로 가져오기 |
| 입력 정보 | 선택한 경로와 가져온 카메라·점 수 등 필요한 정보 표시 |
| 표시 설정 | 현재 점 크기·카메라 표시 크기 설정 유지 |
| 진행 상태·취소 | 파일 읽기, Painter 데이터 생성, 검증·확정 상태 표시 |

- 기존 경로 탐색과 입력 설정을 활용한다. 폴더 구조가 자동 탐색되지 않을 때 희소 모델·이미지 폴더를 명시할 수 있게 한다.
- `Modifier에서 업데이트` 버튼과 Modifier를 먼저 사용하라는 안내를 제거한다.
- COLMAP과 OBJ는 각각 불러올 수 있다. OBJ만 있으면 메시를 표시할 수 있고, 촬영 이미지 투영에는 유효한 COLMAP 카메라와 이미지가 필요하다.
- COLMAP을 다시 불러오면 새 입력이 완전히 검증·확정된 시점에 기존 카메라·점군만 교체한다. 기존 메시와 페인트 레이어는 유지한다.
- OBJ는 신규 오브젝트로 가져온다. 기존 페인트 대상이나 작업 중인 레이어를 자동 교체하지 않는다. 새 파일은 기존 대상 선택 흐름에서 고를 수 있게 한다.
- COLMAP과 OBJ의 축 설정은 각 원본 좌표계를 고려하는 기존 Painter 설정을 사용한다. 두 파일에 같은 원본 축을 강제하지 않는다.
- 페인팅 중에는 입력 교체를 막고, 파일 선택 창 취소는 기존 데이터·입력 설정을 보존한다.

## 5. 데이터 확정·저장·복원

파일 입력도 `준비 → 검증 → 확정` 순서를 사용한다. 새 Painter 카메라·점군·메시는 확정 전에 임시 자원으로 관리하며, 실패·취소 시 기존 확정 결과로 돌아간다.

직접 COLMAP 입력에서는 다음을 연결한다.

1. 공통 읽기 결과를 Painter의 카메라 입력 요청으로 변환한다.
2. 촬영 이미지 경로, 카메라 내부 파라미터, 프레임 대응과 축 설정을 검증한다.
3. 기존 카메라·점군 생성 작업으로 Painter 전용 자원을 만든다.
4. 원본 파일 변경 여부를 재검사하고 영구 기록·준비 상태·카메라 마커를 함께 확정한다.

현재 Painter 투영 검증이 허용하는 `SIMPLE_PINHOLE`·`PINHOLE` 기준을 유지한다. 공통 읽기가 다른 카메라 모델을 읽을 수 있어도 Painter 투영 지원으로 간주하지 않는다. 지원하지 않는 모델은 명확하게 알리고, 왜곡 파라미터를 조용히 버리지 않는다.

저장·복원 호환 원칙:

- 신규 출처 구분을 파일 입력과 기존 Modifier 복사 데이터로 나눈다. 기존 출처 필드는 이전 프로젝트 해석에 필요한 범위에서 유지한다.
- 파일 입력에도 현재 준비 상태 판정에 필요한 데이터셋 식별자·스키마·내용 지문·영구 기록을 생성한다. 기존 요청의 기본 스키마 값만 사용해 준비 상태가 되지 않는 문제를 막는다.
- 이미 저장된 Painter 카메라·점군·페인트 레이어는 Modifier 없이 복원한다. 과거 출처가 Modifier였다는 이유로 다시 업데이트를 요구하지 않는다.
- `.blend`에 저장된 실제 OBJ 메시 복원은 원본 OBJ 재읽기를 요구하지 않는다. 외부 촬영 이미지·텍스처 경로의 기존 복원 규칙은 유지한다.
- 작업공간 종료·파일 로드·확장 해제 때 해당 도구의 가져오기 작업과 임시 자원을 정리한다. 다른 도구의 카메라·마커·View Layer는 변경하지 않는다.

## 6. Modifier 연결 제거 범위

- Painter 업데이트 오퍼레이터 등록, 제공자 호출, 업데이트 가능 판정, 진입 안내를 제거한다.
- 카메라 검토·페인팅·스텐실·작업공간 복원에서 쓰는 준비 상태 판정은 유지하거나 별도 공통 Painter 모듈로 옮긴다.
- `tools/modifier/blender/projection_snapshot_provider.py`와 생명주기의 제공자 등록·해제는 사용처를 확인한 뒤 Painter 전달 전용 연결만 제거한다.
- `shared/colmap_transfer`의 자료형·복원 계약을 일괄 삭제하지 않는다. 기존 저장 자료나 다른 사용처에 필요한 계약은 보존한다.
- Modifier의 자체 가져오기·편집·내보내기와 독립 실행 상태는 변경하지 않는다.

## 7. 구현 순서와 변경 대상

| 단계 | 작업 | 주요 대상 | 통과 기준 |
|---|---|---|---|
| 1 | 공개 읽기 API와 저장 자료 호환 기준 확정 | 기존 읽기·복원 테스트 | TXT·BIN·대형 ID·기존 Painter 저장 자료 기준 확보 |
| 2 | COLMAP 읽기 공통화 | `shared/colmap_io/`, Align 읽기 호환 모듈 | 기존 Align 가져오기 결과·오류·성능 유지 |
| 3 | OBJ 호출·임시 자원 공통화 | `shared/blender_runtime/obj_import.py`, Align OBJ 연결 | 메시·UV·재질·축·소유권 회귀 검증 통과 |
| 4 | Painter 직접 COLMAP 가져오기 연결 | `core/colmap/`, `core_adapter.py`, `camera_import.py`, `properties.py` | Modifier 없이 직접 입력 후 준비 상태·카메라 검토 가능 |
| 5 | Painter OBJ 가져오기와 UI 연결 | `model_import.py`, `panels.py`, `lifecycle.py`, `paint_workspace.py` | 독립 OBJ 표시·대상 선택과 기존 페인트 데이터 보존 |
| 6 | Modifier 업데이트 경로 제거 | `snapshot_update.py`, 제공자·등록 사용처 | 새 입력 경로 동작, 기존 파일 복원, 도구 간 공존 통과 |
| 7 | 실제 입력 검증·문서·배포 확인 | 관련 테스트, 사용자 매뉴얼, 빌드 검사 | 아래 완료 기준 충족 |

Painter의 기존 파일 파서 사용처를 먼저 확인한다. 새 직접 입력은 공통 읽기를 사용하고, 더 이상 필요 없는 중복 읽기 구현은 참조를 제거한 범위에서 정리한다. 기존 파서를 오류 시 대체 경로로 남기지 않는다.

## 8. 검증과 성능 측정

### 기능·호환성 검증

- 같은 TXT·BIN의 ID·좌표·카메라 자세가 공통화 전후에 동일하다. BIN·TXT 동시 존재, 큰 비연속 ID, 기존·현대 파일 구성, 누락·손상 입력의 판정을 확인한다.
- Align의 COLMAP·OBJ 가져오기, 동일 원본 중복 가져오기, 저장·복원과 실제 등록 검사를 수행한다.
- Modifier 데이터를 준비하지 않고 Align을 실행하지 않은 상태에서 Painter의 두 가져오기 버튼이 동작한다.
- COLMAP만 입력, OBJ만 입력, 두 입력의 순서 변경, COLMAP 재입력을 확인한다.
- 파일 선택 취소, 가져오기 실패, 원본 변경, 작업공간 이동·파일 로드 시 이전 데이터와 자원 소유권을 보존한다.
- OBJ의 UV·폴리곤·재질·텍스처 연결, 원본 좌표, 가져오기 전 선택 문맥을 확인한다.
- 기존 페인트 대상·레이어·이미지 내용은 COLMAP 재입력이나 추가 OBJ 입력으로 변경되지 않는다.
- 0.3.72의 Painter 저장 프로젝트와 신규 파일 입력 프로젝트를 별도 Blender에서 저장·재열기한다. 준비 상태·이미지 경로·카메라 마커·페인트 데이터 복원을 확인한다.
- 도구 간 직접 import 금지와 비활성 도구의 카메라·타임라인·View Layer 격리를 검사한다.

### 성능 검증

이번 구조의 이점은 Modifier 선행 작업과 도구 간 데이터 복사를 없애는 것이다. 파일 읽기 자체가 반드시 빨라진다고 가정하지 않으며, 구현 후 실제 소요 시간과 메모리로 판단한다.

| 비교 대상 | 측정 범위 |
|---|---|
| 기존 최초 입력 | Modifier 파일 가져오기 + Painter 업데이트의 전체 시간 |
| 기존 준비된 데이터 | Modifier 데이터가 이미 있는 상태의 Painter 업데이트 시간 |
| 신규 직접 입력 | Painter 파일 선택 이후 읽기·검증·카메라·점군 생성·확정의 전체 시간 |
| OBJ 가져오기 | 기본 가져오기 호출 + Painter 오브젝트 연결·검증·확정 |

- 같은 COLMAP·촬영 이미지·OBJ로 비교하고, 최초 실행과 재실행을 구분해 기록한다. 비교할 기존 결과는 연결 제거 전에 확보한다.
- 파일 읽기, 지문·검증, Painter 변환, 점군 생성, 카메라·이미지 연결, 확정 시간을 나누어 계측한다.
- 대용량 OBJ는 앞서 사용한 `Taiwan_armadillo_scanHighpoly.obj`도 사용한다. 실제 파일 크기·정점·면 수와 Blender 버전을 함께 기록한다.
- 메모리는 Blender 프로세스의 최대 사용량을 확인한다. 파이썬 할당량만으로 전체 메시 메모리를 판단하지 않는다.
- 입력 전체를 배열·객체 목록으로 중복 보관하는 구간을 확인하고, 기존 증분 처리와 배열 기반 읽기의 이점을 유지한다.
- 계측은 검증 도구에서 수행하고, 제품에 문제 해결용 임시 로그를 남기지 않는다. 사용자 작업 중인 Blender 파일은 저장하거나 덮어쓰지 않는다.

## 9. 완료 기준과 후속 배포

다음 조건을 모두 만족해야 구현 완료로 보고한다.

1. Painter에서 Modifier·Align 선행 실행 없이 COLMAP과 OBJ를 직접 불러올 수 있다.
2. 공통 읽기는 하나의 구현을 사용하며 도구의 실행 상태와 Blender 자원은 독립적이다.
3. Modifier 업데이트 UI·실행 연결이 제거되고, 이전 Painter 파일은 정상 복원된다.
4. 기존 Align 가져오기·복원, Painter 페인팅, 세 도구 공존 검증이 통과한다.
5. 같은 입력의 기존·신규 시간과 최대 메모리를 실제 측정해 보고한다.

구현 후 [통합 구조 문서](README.md)와 [Painter 사용자 매뉴얼](https://github.com/hckyeong/Colmap_blender_Tools/blob/f5c816d335cba5ef9808919cacbda73edb90a931/docs/manual/PROJECTION_PAINT.md)의 입력 절차를 수정했다. [최상위 설치 ZIP 규칙](COLMAP_설치ZIP_최상위_배포.md)에 따라 0.3.73 설치 ZIP을 생성하고 격리 설치 검사를 수행했다. 후속 설치 요청에 따라 실제 Blender 사용자 프로필도 백업 후 0.3.73으로 교체·검증했다. 커밋·푸시는 진행하지 않았다. 상세 완료 범위와 검증의 한계는 [구현·검증 기록](COLMAP_Painter_독립_가져오기_구현검증.md)을 따른다.

## 10. 확인 근거

- 프로젝트 규칙: [제품 구조와 개발 규칙](README.md#boundaries). 도구 간 직접 import 금지, 독립 자원 소유, 준비·검증·확정 경계를 적용한다.
- [COLMAP 공식 출력 형식](https://colmap.github.io/format.html): TXT·BIN 구성, BIN 우선 선택, ID와 순번의 구분, 카메라 자세 형식을 확인했다.
- [Blender 공식 OBJ 가져오기 API](https://docs.blender.org/api/main/bpy.ops.wm.html#bpy.ops.wm.obj_import): 축·배율·분할·메시 검증 인자를 확인했다. 실제 구현은 프로젝트 지원 Blender의 API와 현재 Align 호출을 기준으로 검증한다.

위 공통 계층 경로와 연결 방식은 이 프로젝트 코드 검토에 따른 설계안이다. 외부 문서가 Painter의 제품 구조를 규정하는 것은 아니다.
