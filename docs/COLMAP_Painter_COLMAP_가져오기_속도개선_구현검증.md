# Painter COLMAP 가져오기 속도 개선 구현·검증

- 검증일: 2026-10-06
- 환경: Windows x64, Blender 5.2.0 LTS
- 제품: `main`의 0.3.73 작업 사본. 기존 미커밋 변경을 포함하며 이번에도 커밋·푸시는 수행하지 않았다.
- 대상: [가져오기 속도 개선 계획서](COLMAP_Painter_COLMAP_가져오기_속도개선_계획서.md)

## 1. 사용자 동작과 구현

**COLMAP 불러오기**의 파일 탐색기 오른쪽에 **참고 점 최대 개수**를 표시한다. 초기 기본값은 **20,000개**이고 허용 범위는 1부터 100,000,000개까지다. 확정한 값을 다음 탐색기에 다시 표시하며 취소하면 기존 설정을 유지한다. 카메라·촬영 이미지는 전체를 가져온다.

현재 새 입력의 점 수와 원본 전체 점 수를 구분해 표시한다. 이미 저장된 점군은 파일 열기나 페인트 재진입 때 자동으로 축소하지 않는다. 명시적으로 다시 가져오면 선택한 상한을 적용한다.

| 개선 | 적용 내용 |
|---|---|
| 중복 준비 제거 | 확정 전 전체 재파싱·점 검증·의미 지문 재계산을 없앴다. 전체 원본 파일 내용 해시·파일 식별·선택 모델·촬영 이미지 경로 검사는 유지한다. |
| 참고용 입력 | 카메라·이미지·현대 COLMAP의 리그·프레임은 유지하고, 사용하지 않는 2차원 관측·점 트랙은 필요한 검사 후 폐기한다. 공통 읽기의 기본값은 전체 입력이다. |
| 읽는 중 표본 보관 | 전체 파일을 검사하면서 원본 64비트 점 식별자의 고정 우선순위로 상한만큼 유지한다. 파일 순서·TXT/BIN 형식이 달라도 같은 점 집합을 고른다. |
| 배열 검사·기록 | 작업 블록의 수치 검사와 표본 선택을 배열로 수행한다. 점 좌표·색상·오차·식별자를 Blender 메시 속성에 일괄 기록한다. |
| 모달 처리 | 작업 예산을 50밀리초로 조정하고 짧은 단계를 한 호출에서 진행한다. 화면 갱신 요청은 단계 전환 또는 약 100밀리초 간격으로 제한한다. |
| 카메라 조회 | 준비 중 생성한 카메라 조회표를 확정까지 재사용한다. 소유권 검사와 실패 시 정리는 유지한다. |
| 저장 | 원본 수·경계·표본 정책·상한·표본 지문을 별도 메타데이터로 저장한다. 전체 자료형과 참고 자료형을 분리한다. |

원본 전체 경계는 표본이 아닌 전체 좌표에서 누적한다. 원본 중복 식별자 검사를 위해 전체 `uint64` 식별자 배열과 검사 작업 공간은 일시적으로 필요하다. 따라서 모든 메모리가 2만 점으로 고정되는 구조는 아니다. 상한을 크게 설정하면 보관·메시 생성 비용도 증가한다.

Align·Modifier의 전체 COLMAP 입력, OBJ 입력, 정렬 엔진과 페인트 계산은 이번 변경 대상이 아니다. 새 외부 라이브러리나 실행 환경을 추가하지 않았다.

## 2. 실제 자료 성능

현재 연결된 Blender에서 확인한 원본 경로 `C:/Users/gksru/Desktop/temp/ban78_maual/colmap_merged`를 읽기 전용으로 사용했다. 원본은 점 **709,048개**, 촬영 이미지 **593개**이며 `images.txt`와 `points3D.txt` 합계 약 218 MB다. 관측 3,126,440개와 점 트랙 2,880,086개를 검사했다.

사용자 장면을 초기화·재가져오기·저장하지 않고, 같은 Blender 버전의 별도 프로세스에 같은 원본을 입력했다. 이전 코드는 변경 전 ZIP에서 따로 보존했다. 1단계 비교본은 이전 코드의 확정 전 재검증 작업만 새 구현으로 교체하여 전체 709,048점을 그대로 가져온다.

| 측정 | 1회 | 2회 | 3회 | 중앙값 |
|---|---:|---:|---:|---:|
| 이전 전체 입력, 백그라운드 | 38.40초 | 39.26초 | 39.38초 | **39.26초** |
| 중복 재검증 제거만 적용, 백그라운드 | 24.51초 | 25.31초 | 22.59초 | **24.51초** |
| 모든 개선 적용·2만 점, 백그라운드 | 10.73초 | 10.99초 | 11.49초 | **10.99초** |
| 이전 전체 입력, 실제 화면 모달 | 81.10초 | 98.80초 | 95.46초 | **95.46초** |
| 모든 개선 적용·2만 점, 실제 화면 모달 | 11.58초 | 13.22초 | 13.50초 | **13.22초** |

실제 화면 시간은 중앙값 기준 **86.2% 감소**, 약 **7.2배** 빨라졌다. 백그라운드 최대 작업 집합은 세 번 반복한 프로세스 기준 **976.4 MiB → 378.5 MiB**, 약 **61.2% 감소**했다. 카메라·이미지 593개를 모두 유지하고 참고 점 표시량을 줄인 결과이며, 같은 표시량의 알고리즘만 빨라진 것으로 설명하지 않는다.

| 화면 처리 계측 | 이전 | 개선 후 |
|---|---:|---:|
| 작업 진행 호출 수 | 1,967~2,042회 | 195~197회 |
| 화면 갱신 요청 수 | 1,969~2,044회 | 104~107회 |
| 가장 긴 작업 호출 | 0.319~0.745초 | 0.249~0.505초 |

가져오기 버튼 실행부터 준비·확정·실제 카메라 검토 연결 완료까지 측정했다. 최종 화면 검사에서 진행 그리기 오류와 카메라 연결 경고는 없었다. 실제 파일 탐색기를 열어 기본 20,000 표시와 옵션 취소 시 기존 값 보존도 확인했다. 변경값 반영은 실제 Blender 입력 검사에서 상한 5로 확정하여 5점만 생성되는 것으로 확인했다.

참고용 TXT 100,000점·이미지 16개 입력도 세 번 측정했고 0.73/0.70/0.71초, 중앙값 **0.71초**였다. 기존 독립 가져오기 기록의 같은 규모 백그라운드 시간 3.39초와 별개 측정이며 사용자 자료의 수치로 혼동하지 않는다.

### 측정 한계와 남은 비용

- 운영체제 파일 캐시를 비우지 않았다. 한 프로세스에서 세 번 반복했으며 사용자 컴퓨터의 다른 작업을 통제하지 않았다. 실제 화면 비교에서 일부 짧은 회귀 검사가 겹쳤으므로 엄격한 전용 장비 실험으로 해석하지 않는다.
- 원본 TXT 전체 해석·수치 검사와 전체 파일 해시는 남는다. 최종 백그라운드에서는 읽기 구간 약 8.8~9.1초와 확정 전 내용 해시 약 1.2~1.3초가 주요 비용이다. 읽기 구간에는 최초 원본 내용 해시와 표본 선택도 포함된다.
- 짧은 단계를 묶어 진행하므로 단계별 계측은 호출을 시작한 단계로 비용이 집계된다. 작은 단계의 단독 시간이 0으로 보이거나 다른 구간에 합쳐질 수 있다. 세부 표의 값을 개별 함수의 정확한 실행 시간으로 해석하지 않는다.
- 확정·기존 자원 교체는 원자성을 유지하는 동기 구간이다. 최장 호출이 약 0.5초 남아 있어 모든 구간이 50밀리초 이하라고 보장하지 않는다. 자동 취소 지연의 전체 분포는 측정하지 않았다.
- 재검증 제거만의 효과와 최종 전체 효과를 비교했다. 나머지 개선 각각의 독립 제거 실험, 수천 카메라 자료, 수백만 점 자료의 성능 측정은 수행하지 않았다.

## 4. 산출물과 재현

아래 ZIP 크기·지문은 이 속도 개선 완료 당시의 기록이다. 이후 [Modifier 눈금 격리 보완](COLMAP_Modifier_미터눈금_후발레이어_격리.md)에서 최상위 ZIP을 다시 갱신했다.

- 최상위 설치 파일: `colmap_tools.zip`, 내부 버전 **0.3.73**.
- ZIP 크기: **48,285,968바이트**.
- SHA-256: `215d465a3f2113f121ebf6d12f65be60197ae31b2ea72c3da08bd9f07ab418bd`.
- 사용자 설명: [Painter 매뉴얼](manual/PROJECTION_PAINT.md).
- 검사 결과: `build/verification/painter-import-speed-20261006/`. Git에서 제외된 로컬 산출물이다.

백그라운드 재현 도구는 `tests/projection_paint/benchmark_file_import.py`의 `--dataset-root`·`--point-limit` 옵션, 화면 도구는 `tests/projection_paint/gui_import_speed.py`다. 정식 빌드는 `build_tools/build_extension.ps1`을 사용했다. 계측은 별도 검증 프로세스에만 설치했고 제품에 일회성 계측·디버그 로그를 추가하지 않았다.

코드와 정식 ZIP 갱신까지 완료했다. **현재 실행 중인 사용자 Blender의 설치본 교체·장면 입력 교체·프로젝트 저장·커밋·푸시는 수행하지 않았다.**

### 후속 전체 설치 · 2026-10-06

위 문장은 최초 구현 완료 당시의 상태다. 이후 사용자의 설치 요청에 따라 [Modifier 눈금 격리 보완을 포함한 최신 ZIP 전체](COLMAP_Modifier_미터눈금_후발레이어_격리.md)를 Blender 설치본에 반영했다. 전체 설치 폴더를 백업했고 ZIP의 1,199개 파일과 설치본의 내용이 모두 일치한다.

새 Blender 프로세스에서 실제 설치본의 참고 점 기본값 20,000·파일 탐색기 옵션·메타데이터 속성과 확장 활성화를 확인했다. 원본 사용자 환경설정과 현재 프로젝트는 유지했다. 실행 중인 사용자 Blender에는 이전 Painter 모듈이 남아 있으므로 재시작 후 속도 개선과 점 수 설정이 전체 적용된다. 프로젝트 저장·강제 종료·커밋·푸시는 수행하지 않았다. 결과는 `build/verification/full-install-20261006/`에 보관한다.
