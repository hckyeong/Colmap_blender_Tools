## 1. 사용자 요구와 기록 원칙

앞으로 작업 계획은 해당 작업트리의 `docs/`에 Markdown으로 기록하고, 대화에는 핵심 결정과 문서 링크만 남긴다. 추가 요구가 생기면 기존 계획서를 갱신해 최신 설계를 한곳에서 확인할 수 있게 한다.

이번 요구는 다음과 같다.

1. `images/`, `sparse/`와 같은 위치에 OBJ가 있으면 COLMAP과 함께 불러온다.
2. 자동 연결 OBJ에는 텍스처가 필요하지 않으며 MTL을 탐색하거나 읽지 않는다.
3. COLMAP과 OBJ 원본은 같은 축·원점·위치·단위를 갖는 것을 입력 원칙으로 한다.
4. COLMAP을 표시할 때 적용하는 축 변환을 연결 OBJ에도 동일하게 적용한다.
5. 점군과 표면을 겹쳐 볼 수 있고, 각각 독립적으로 켜고 끌 수 있는 UI를 제공한다.
6. 향후 메시에서 구한 정렬 결과를 해당 COLMAP 점군과 카메라에 적용할 수 있도록 연결 관계를 보존한다.

현재 자동 연결 구현은 이 문서의 1단계를 따른다. 기본 표시값은 연결 성공 시 표면만 표시이며, 복수 OBJ는 파일 경로로 명시 선택한다. 후속 실제 입력 진단에서 COLMAP과 OBJ 사이의 축 차이를 확인했고, 이를 처리할 개별 축 설정과 UI 변경은 13절에 기록한다.

## 3. 입력 폴더와 OBJ 탐색 규칙

```text
데이터셋/
├─ images/
├─ sparse/
│  └─ 0/
│     ├─ cameras.bin
│     ├─ images.bin
│     └─ points3D.bin
└─ model.obj
```

TXT 입력과 `sparse/`에 모델 파일이 직접 있는 기존 구조도 유지한다. 사용자가 루트 또는 표준 sparse 하위 경로를 선택해도, 탐색기가 확인한 데이터셋 루트 바로 아래에서 OBJ를 찾는다.

- `.obj` 확장자는 대소문자를 구분하지 않는다.
- 하위 폴더 전체를 재귀 탐색하지 않는다.
- MTL, 이미지, 텍스처 폴더는 후보 탐색 대상에 포함하지 않는다.
- 후보 경로는 기존 탐색기의 실제 파일·경로 검증 규칙을 따른다.
- 후보 0개: 기존 COLMAP 단독 가져오기를 수행한다.
- 후보 1개: 해당 OBJ를 자동 연결 대상으로 제시한다.
- 후보 2개 이상: 이름순 첫 파일을 임의 선택하지 않고, 가져오기 UI에서 파일 하나를 선택한다.
- 여러 sparse 모델이 있는 루트: 실제 불러올 sparse 경로와 OBJ의 대응을 명시적으로 확정한다. 명시적으로 선택한 모델과 실제 확정된 모델이 다른 상태로 자동 연결하지 않는다.
- 가져오기 옵션에 기본 활성화된 `OBJ 함께 불러오기`를 둔다. 사용자가 끄면 기존 COLMAP 단독 경로로 진행한다.

프로젝트 복원에서는 폴더를 다시 탐색해 새로운 OBJ를 고르지 않는다. 저장된 연결 파일만 읽는다.

## 4. 데이터 소유와 연결 구조

Data Layers에서는 COLMAP과 연결 OBJ를 하나의 데이터셋 행으로 취급하는 방식을 권장한다.

```text
COLMAP 데이터셋 — 기존 model_id
├─ 기존 희소 점군·카메라 데이터
├─ 선택적인 연결 메시 — 원본 정점·삼각면·경로·지문
├─ 공통 표시 축 변환과 정렬 변환
└─ 점군 표시 / 표면 표시
```

구현 방향은 다음과 같다.

- 기존 COLMAP 모델 자료형과 원본 점·카메라 식별자를 유지한다.
- 저장소에 COLMAP `model_id`를 소유자로 하는 선택적 연결 메시 영역을 추가한다. 구체적인 자료형·필드 이름은 구현 시 확정한다.
- 연결 메시의 형상은 기존 삼각형 메시 자료형과 읽기·검증 코드를 재사용한다.
- 연결 메시를 독립 A/P 정렬 후보나 별도 앵커로 자동 등록하지 않는다.
- 정렬 변환의 권위는 COLMAP 데이터셋 하나에 둔다. 점군용과 메시용 변환을 각각 수정한 뒤 맞추는 이중 상태를 만들지 않는다.
- 기존 독립 OBJ 가져오기는 독립 메시 모델로 계속 동작한다.
- 데이터셋을 이동·회전·균일 스케일하거나 A/P 그룹을 바꾸면 연결 표면도 같은 결과를 따른다.
- 데이터셋 삭제·취소·세션 종료 때 연결 형상과 GPU 자원을 함께 정리한다. 원본 파일은 수정하지 않는다.

## 5. 축과 좌표 처리

### 5.1 동일한 원본 좌표계인 경우

COLMAP 원본 점을 `p`, OBJ 원본 정점을 `v`, 데이터셋의 표시 축 행렬을 `D`, 현재 정렬·미리보기 행렬을 `A`라고 할 때 열벡터 표기는 다음과 같다.

```text
점군 표시 좌표 = A × D × p
표면 표시 좌표 = A × D × v
```

- OBJ 정점은 파일 수치를 그대로 float64로 읽는다.
- `D`는 COLMAP 가져오기에서 확정된 변환을 사용한다. 이전에 독립 OBJ 가져오기에서 선택한 축 설정을 가져오지 않는다.
- 실제 표시 행렬은 기존 공통 계산 함수를 재사용해 미리보기·수동 변환·정렬 승인 이후에도 일관되게 유지한다.
- Blender 기본 OBJ 가져오기 연산자의 축 변환을 추가로 적용하지 않는다. 기존 Align OBJ 읽기 경로를 사용한다.
- 임의의 90도 회전, 중앙 이동, 단위 맞춤을 추가하지 않는다.
- 화면 표시를 위해 원본 점군·OBJ 정점·카메라 자세를 덮어쓰지 않는다.

따라서 사용자가 제안한 동일 축 변환은 두 원본이 같은 좌표계라는 입력 조건에서 올바른 방식이다. 어떤 프리셋을 선택했는지보다 두 데이터가 같은 변환을 한 번만 사용하는 것이 핵심이다.

### 5.2 확인이 필요한 실제 데이터 조건

일반 Blender 가져오기에서 OBJ 방향이 달라 보였다는 관찰만으로 원본 파일의 좌표가 다르다고 확정할 수 없다. 먼저 같은 RC 컴포넌트의 COLMAP·OBJ를 공통 표시 변환으로 겹쳐 확인한다.

공통 변환 뒤에도 상대적인 회전·이동·크기 차이가 남으면 RC 내보내기 좌표계 또는 내보내기 변환부터 확인한다. 실제 차이의 근거 없이 자동 보정하지 않는다. RC/RealityScan 공식 문서에는 내보내기 좌표계와 이동·회전·스케일 설정이 설명되어 있다. [공식 모델 내보내기 설명](https://rshelp.capturingreality.com/en-US/tools/export.htm)

원본 좌표계가 다른 것으로 확인되면 `OBJ → COLMAP` 변환을 별도로 정의하는 다음 설계가 필요하다. 동일한 `D`를 두 번 적용해서 보정하지 않는다. RC가 카메라 배치 자체를 다시 최적화한 경우 원래 COLMAP으로 단일 행렬을 전달할 수 있는지도 별도로 검토한다.

## 6. 텍스처 없는 OBJ 읽기

자동 연결 경로에서는 형상 전용 읽기 정책을 사용한다.

- 필요한 데이터: 정점 `v`, 삼각면 `f`의 정점 연결, 표시 법선과 경계 등 형상에서 계산하는 값.
- `mtllib`와 `usemtl`은 외부 파일 접근이나 재질 생성으로 이어지지 않는다.
- MTL·텍스처가 없거나 그 참조가 유효하지 않아도 형상 읽기 성공 여부에 영향을 주지 않는다.
- UV·텍스처 배열과 이미지 GPU 자원은 자동 연결 표시에 사용하지 않는다.
- `f v`, `f v/vt`, `f v//vn`, `f v/vt/vn` 토큰에서도 정점 인덱스를 올바르게 읽는다. 형상 전용 경로에서 무시하는 UV 인덱스 때문에 실패하지 않도록 파싱 정책을 구분한다.
- 삼각면 정점 인덱스, 유한한 좌표, 기존 형상 제한은 검증한다.
- 기존 독립 OBJ의 UV·재질·텍스처 가져오기 및 내보내기 계약은 유지한다. 해당 기능을 전역에서 제거하지 않는다.
- 자동 연결 메시의 지문은 실제 소비하는 OBJ 파일에 대해 계산하며 MTL이나 텍스처 파일을 읽어 해시하지 않는다.

## 7. 표시 토글과 UI

Data Layers의 데이터셋 행에 짧은 `점군`, `표면` 토글을 둔다. 공간이 부족하면 해당 행 바로 아래에 배치한다. 초기 구현은 의미가 분명한 텍스트 버튼과 눌림 상태를 사용한다.

```text
데이터셋 A    [전체 표시]    [점군] [표면]
데이터셋 B    [전체 표시]    [점군] [표면]
```

### 7.1 적용한 기본값

| 가져온 데이터 | 점군 | 표면 |
|---|---|---|
| COLMAP만 있음 | 켜짐 | 비활성화 |
| COLMAP과 OBJ 연결 성공 | 꺼짐 | 켜짐 |
| 저장 프로젝트 복원 | 저장값 | 저장값 |

사용자는 점군만, 표면만, 둘 다, 둘 다 숨김을 선택할 수 있다. 두 토글을 라디오 버튼처럼 상호 배타적으로 만들지 않는다.

### 7.2 동작 계약

- 실제 점군 표시 = 기존 전체 표시 AND 점군 토글.
- 실제 표면 표시 = 기존 전체 표시 AND 표면 토글.
- 전체 표시를 껐다 켜도 점군·표면의 개별 설정은 유지한다.
- 토글은 표시와 그 표시 대상의 피킹에만 영향을 준다. A/P 소속, 앵커, 정렬 결과, 기존 GICP 입력, COLMAP 내보내기 대상은 바꾸지 않는다.
- 이 단계의 정렬 계산 입력은 계속 기존 COLMAP 희소 점군이다. 표면 표시 여부를 정렬 입력 선택으로 사용하지 않는다.
- 숨긴 점군을 마커 입력에서 몰래 선택하지 않는다. 점군 마커가 필요할 때는 점군 토글을 켜도록 안내한다.
- 연결 표면의 새 마커 입력과 표면 기반 GICP는 다음 단계다. 기존 독립 OBJ의 표면 마커 기능은 유지한다.
- 이미 확정된 마커와 미리보기 안내 도형은 기존 표시 정책을 유지한다.
- 기본 화면과 정렬 미리보기의 상대 그룹 표시에도 같은 토글을 적용한다.
- 화면 맞춤은 현재 보이는 형상을 기준으로 계산하며, 둘 다 숨겼을 때 빈 경계를 정상 처리한다.
- 토글 변경만으로 원본 파일을 다시 읽거나 전체 GPU 배치를 재생성하지 않는다.

## 8. 가져오기 수명과 실패 처리

하나의 가져오기 작업 안에서 다음 순서를 사용한다.

1. COLMAP 모델과 실제 데이터셋 루트 확정.
2. OBJ 후보·연결 대상·형상 전용 읽기 정책 확정.
3. 기존 COLMAP 증분 읽기와 검증.
4. 선택한 OBJ 증분 읽기와 검증.
5. 공통 표시 변환과 연결 메타데이터 준비.
6. COLMAP·연결 메시·카탈로그·GPU 상태를 함께 등록.
7. 완료 알림과 화면 맞춤을 한 번 수행.

- 읽기와 취소 처리는 기존 TIMER 기반 구조를 따른다.
- OBJ가 없으면 COLMAP 단독 경로를 사용한다.
- 연결 대상으로 선택한 OBJ가 잘못됐으면 실패 원인을 표시한다. 이번 작업의 일부만 성공한 연결을 남기지 않는다.
- 취소·실패 시 이번 작업에서 준비한 자료와 자원만 정리하고 기존 데이터셋·앵커·선택 상태를 보존한다.
- 같은 COLMAP을 다시 불러와 중복 데이터셋을 만들지 않는다.
- 외부 파일이 읽기 도중 바뀌면 기존 지문 검증 정책에 따라 확정을 중단한다.
- 비삼각형 입력은 명시적으로 처리 범위를 안내한다. 삼각면 개수는 인위적으로 제한하거나 자동 절삭하지 않으며 실제 처리는 사용 가능한 메모리와 GPU 자원의 영향을 받는다.

## 9. 프로젝트 저장·복원

저장할 정보는 데이터셋 소유 ID, OBJ 절대·상대 경로, OBJ 지문, 형상 전용 읽기 정책, 점군·표면 표시 상태다. 연결 메시의 대형 배열을 프로젝트 JSON에 복제하지 않는다.

- 기존 COLMAP 표시 축·정렬 변환을 그대로 재사용하며 OBJ에 별도 변환 복사본을 저장하지 않는다.
- 현재 저장 계약에 맞춰 새 스키마 버전을 명시한다. 무시될 수 있는 임의 필드를 기존 문서에 붙이지 않는다.
- 기존 연결 정보가 없는 프로젝트는 기존 동작으로 읽는다. 복원 시 발견한 OBJ를 임의로 추가하지 않는다.
- 저장된 OBJ가 누락되거나 변경됐으면 명확한 복원 오류를 내고 기존 정상 상태를 보존한다. 다른 파일을 대신 선택하지 않는다.
- 재실행·작업공간 전환·저장 후 재열기에도 개별 토글과 연결 관계를 유지한다.
- 기존 COLMAP 내보내기는 데이터셋 소유자의 변환을 사용한다. 연결 메시 때문에 내보내기 모델 수가 두 배로 늘지 않아야 한다.

| OBJ `.rsInfo`의 추가 내보내기 설정 | 회전 0/0/0, 이동 0/0/0, 스케일 1/1/1, `transformToModel`은 항등행렬 |

거리 수치는 원본 좌표 단위이며, 메시 표면 오차나 GICP 정렬 개선율이 아니다. 원점을 고정한 축 회전 후보 비교로 이번 방향 차이의 근거를 확인한 것이다. 다른 RC 자료에도 같은 수치를 보장하지 않는다.

COLMAP `export_manifest.json`에 기록된 컴포넌트 GUID와 OBJ `.rsInfo`의 GUID는 다르다. COLMAP 3파일은 해당 manifest의 지문과 일치했다. 컴포넌트 재생성·다른 내보내기 시점의 가능성이 있으므로 GUID 차이를 근거로 파일을 자동 교체하거나 현재 쌍을 임의 거부하지 않는다.

RC/RealityScan은 모델 내보내기 좌표계와 추가 이동·회전·스케일을 별도로 설정할 수 있고, `.rsInfo`에 좌표계 관계와 내보내기 정보를 기록한다. 따라서 이번에 확인한 값을 **명시적인 RC 기본 프리셋**으로 제공하고, 모든 OBJ의 좌표계를 확장자만으로 판정하지 않는다. [RealityScan 공식 내보내기 설명](https://rshelp.capturingreality.com/en-US/tools/export.htm)

### 13.2 사용자에게 보이는 기본 동작

1. 새 RC COLMAP·OBJ 연결 가져오기는 점군과 메시의 입력 축을 각각 RC 기본값으로 초기화한다.
2. 각 데이터셋은 계속 한 행이며, COLMAP 점군·카메라와 연결 메시를 같은 정렬 행렬로 이동한다.
3. 레이어 행의 **톱니바퀴 설정 아이콘**을 클릭하면 그 데이터셋 하나의 축 설정 팝업을 연다.
4. 팝업에서 COLMAP과 메시의 축을 별도로 바꾸며, 다른 레이어에는 적용하지 않는다.
5. 행 오른쪽의 점군·메시 아이콘으로 해당 레이어의 표시만 켜고 끈다.
6. 설정은 미리보기 후 적용·취소하며, 적용은 세션 Undo 한 번으로 되돌릴 수 있다.

현재 넓은 `점군`·`표면` 버튼도 내부적으로는 `model_id`별 동작이다. 이번 UI 변경은 두 번째 줄을 없애고 적용 대상을 같은 행에서 분명하게 보여주는 변경이다. 선택된 여러 레이어를 일괄 처리하는 동작은 추가하지 않는다.

### 13.3 레이어 행과 클릭 동작

```text
[핀]  Component 1 · COLMAP       [점군 아이콘] [메시 아이콘] [설정 아이콘] [눈]
[핀]  Component 2 · COLMAP       [점군 아이콘] [메시 아이콘] [설정 아이콘] [눈]
```

대괄호 안 설명은 설계용 표기이며, 실제 점군·메시·설정·눈 버튼은 아이콘만 사용한다. 기존 핀은 이름 영역의 A 역할 표현으로 유지한다.

| 위치 / 입력 | 동작 |
|---|---|
| 이름 한 번 클릭 | 기존 단일 선택 |
| 이름 Ctrl / Shift 클릭 | 기존 복수·범위 선택 |
| 같은 이름 더블클릭 | 기존 A/P 그룹 이동 유지 |
| 톱니바퀴 설정 아이콘 | 그 행의 축 설정 팝업 열기 |
| 점군 아이콘 | 그 행의 희소 점군 표시 반전 |
| 메시 아이콘 | 그 행의 연결 표면 표시 반전 |
| 눈 아이콘 | 그 데이터셋 전체 표시 반전 |

구체적인 규칙:

- 이름 더블클릭의 A/P 그룹 이동과 기존 `toggle_data_layer_group` 연산자를 그대로 유지한다. 별도 그룹 버튼은 추가하지 않고 마지막 A 보호 등 기존 그룹 규칙을 보존한다.
- 이름 영역의 기존 A 핀, 앵커 판정, 선택 강조는 유지한다. 설정 아이콘은 A/P 이동이나 앵커 변경을 수행하지 않는다.
- 점군 아이콘은 `POINTCLOUD_DATA`, 메시 아이콘은 `MESH_DATA`를 사용한다. 켜짐은 눌림·강조 상태, 꺼짐은 비강조 상태로 구분한다.
- 각 버튼 설명에 레이어 이름과 `점군 표시/숨기기`, `메시 표시/숨기기`, `축 설정 열기`를 포함한다. 설정 버튼은 Blender 기본 톱니바퀴 아이콘을 사용하며 실제 설치 버전의 아이콘 식별자를 확인한다.
- 연결 메시가 없으면 메시 아이콘을 비활성화한다. 독립 OBJ 행은 메시 아이콘만 활성화한다.
- 눈을 껐다 켜도 개별 점군·메시 설정은 유지한다. 전체 숨김 중 개별 아이콘 상태는 보존값을 나타내며 눈을 켜야 화면에 표시됨을 설명한다.
- 아이콘 클릭은 이름 선택이나 더블클릭으로 처리하지 않는다. 모든 아이콘 연산자가 더블클릭 후보를 초기화한다.
- 여러 행이 선택되어 있어도 표시·설정 아이콘은 클릭한 `model_id` 한 개만 대상으로 고정한다. 설정 창을 열기 위해 기존 복수 선택을 해제하지 않는다.
- 점군이 숨겨졌다는 안내는 각 행 아래에서 반복하지 않고 마커 입력 영역의 현재 대상 안내로 옮긴다.

### 13.4 축 설정 팝업

Blender 안에서 뜨는 속성 팝업을 사용한다. 별도 Blender 프로세스나 새 작업공간을 만들 필요는 없다. 등록된 연산자의 `invoke_props_dialog` 경로를 우선 사용하고, 실제 Blender 5.2에서 적용·취소·미리보기를 검증한다.

```text
Component 1 · 축 설정
이 설정은 Component 1에만 적용됩니다.

[RC 기준으로 맞추기]

COLMAP — 점군·카메라
  원본 축 프리셋   [RC COLMAP                 v]
  전방 축          [ Z  v]    위쪽 축 [ -Y v]
  추가 회전        X [0°]  Y [0°]  Z [0°]
  [이 항목을 RC 기본값으로]

연결 메시 — lowpol_LOD0.obj
  원본 축 프리셋   [RC 표준 OBJ               v]
  전방 축          [ Y  v]    위쪽 축 [  Z v]
  추가 회전        X [0°]  Y [0°]  Z [0°]
  [이 항목을 RC 기본값으로]

[미리보기 켜짐]                       [취소] [적용]
```

- 이름과 대상 ID는 창을 열 때 고정한다. 전역 `selected_model_id`가 바뀌었다고 적용 대상이 바뀌면 안 된다.
- COLMAP 칸은 점군과 카메라의 좌표계 설정이다. 점군만 움직이고 카메라를 남겨두는 설정으로 만들지 않는다.
- 기본 프리셋: `RC COLMAP`, `RC 표준 OBJ`, `원본 축 유지`, 기존 Maya/Houdini 프리셋, `직접 설정`.
- 기존 `REALITY_CAPTURE` 식별자와 축 의미는 유지한다. `RC 표준 OBJ`는 이번 표준 입력의 메시 기본값이며, 사용자에게 COLMAP용 RC 값과 구분해 보여준다.
- 고정 프리셋의 Forward/Up은 표시용이다. 직접 수정하면 `직접 설정`으로 전환한다. 같은 기준축을 Forward와 Up에 동시에 지정하지 못한다.
- 추가 회전은 각 형상마다 X/Y/Z 도 단위로 제공하며 기본값은 0이다. 프리셋 선택과 추가 회전은 별도 값이다. 초기화 버튼은 해당 프리셋과 추가 회전 0을 함께 적용한다.
- `RC 기준으로 맞추기`는 열린 데이터셋의 COLMAP과 연결 메시 두 항목을 RC 기본 조합으로 되돌린다. 다른 레이어나 A/P 정렬 행렬에는 적용하지 않는다.
- 연결 메시가 없으면 메시 영역을 비활성화하고 없음을 표시한다. 독립 OBJ는 COLMAP 영역 없이 메시 설정만 편집한다.
- 이동·단위 변경·비균일 스케일·미러링은 이번 창에 추가하지 않는다. 이번 요청의 방향 설정과 기존 레이어 정렬 변환의 경계를 유지한다.

### 13.5 RC 기본값과 변환 순서

이번 구현에서 통일할 정렬 전 기준축은 현재 Blender 표시와 같은 **Y Forward / Z Up**이다. 같은 정규화 행렬을 두 종류에 강제로 적용하는 대신, 각 원본에서 이 기준으로 들어오는 행렬을 따로 계산한다.

| 원본 종류 | 초기 Forward / Up | 원본 → 공통 기준의 축 변환 |
|---|---|---|
| RC COLMAP | Z / -Y | 기존 RC 변환, X축 -90도 |
| RC 표준 OBJ | Y / Z | 항등변환 |
| 이미 COLMAP과 같은 좌표인 OBJ | COLMAP과 동일한 축을 사용자가 지정 | COLMAP과 같은 기본 축 변환 |

열벡터 기준으로 `A`는 데이터셋의 공통 정렬 행렬, `B`는 원본 축 프리셋 변환, `Q`는 추가 회전이다.

```text
N_colmap = Q_colmap × B_colmap
N_mesh   = Q_mesh   × B_mesh

점군 표시 = A × N_colmap × 원본 점
메시 표시 = A × N_mesh   × 원본 정점
```

- 추가 회전은 원본 축 정규화 후, 데이터셋 정렬 전에 적용한다. 고정된 공통 기준축에 대해 X → Y → Z 순서이며 `Q = Rz × Ry × Rx`다.
- 회전 중심은 원본 데이터셋의 원점이다. 메시 경계 중심이나 현재 선택 중심으로 자동 이동하지 않는다.
- 두 형상의 `N`은 독립 값이고 `A`만 공유한다. 점군 설정을 바꿀 때 메시 설정을 암묵적으로 복사하지 않는다.
- OBJ → COLMAP 변환이 필요하면 `C = inverse(N_colmap) × N_mesh`로 유도할 수 있다. 이를 별도 편집 상태로 중복 저장하지 않는다.
- 기본 RC 조합의 `C`가 앞서 확인한 X축 +90도다. 따라서 `A × N_colmap × C × OBJ`와 `A × N_mesh × OBJ`가 같으며, +90도를 두 번 적용하지 않는다.
- 정점·희소 점·카메라 원본 배열은 변경하지 않는다. 정규화 행렬과 공통 정렬 행렬을 통해 표시·계산·내보내기에 반영한다.
- 회전은 유한값, 역행렬, 직교성, 행렬식 +1을 검증한다. 축 순서나 부호 변경으로 잘못된 반사·스케일이 섞이지 않게 한다.

새 가져오기에서 COLMAP 입력 프리셋이 RC이면 이 RC 조합으로 초기화한다. 다른 프리셋의 연결 가져오기는 기존 설정을 초기값으로 복사하되, 등록 후에는 두 형상이 각자 설정을 소유한다. 기존 프로젝트 복원에는 새 기본값을 소급 적용하지 않는다.

RC 내보내기에서 별도 회전·위치·스케일을 준 입력은 이 기본값만으로 완전히 일치한다고 보장하지 않는다. 이번 범위는 사용자가 프리셋·축·추가 회전을 명시적으로 조정하는 기능이며, `.rsInfo` 전체 좌표 변환의 자동 추론이나 ICP 자동 보정은 별도 과제다.

### 13.6 내부 소유 구조와 공개 API 호환

- 기존 `ModelRepository.display_transforms[model_id]`는 주 모델의 현재 축 정규화 값으로 유지한다. COLMAP 점군·카메라·기존 희소 GICP·COLMAP 출력이 이 값을 사용한다.
- 연결 메시에는 소유 ID별 별도 축 정규화 값과 조회 함수를 추가한다. 메시가 없는 레이어에 빈 형상이나 가짜 모델을 만들지 않는다.
- 기존 `ModelDisplayTransform` 생성·조회 API의 기본 호출은 기존 동작을 유지한다. 추가 회전은 기본 0인 선택 인자로 확장하고, 기존 0도 데이터의 행렬·지문 호환을 검증한다.
- 유효 변환 계산은 형상 종류를 받는 공통 경계로 모은다. 점군 경로는 주 모델 값, 연결 메시 경로는 메시 값을 선택하고 둘 다 같은 `A`를 곱한다.
- 독립 OBJ의 기존 호출은 계속 자기 주 모델 축을 사용한다. 연결 메시 조회를 독립 OBJ에 중복 적용하지 않는다.
- 현재 축 설정과 최초 가져오기 출처를 구분한다. `source_metadata`의 원본 지문·가져오기 축 기록을 사용자 축 편집으로 덮어쓰지 않는다.
- 삭제·전체 비우기·복원 rollback에서 연결 메시의 축 값도 함께 정리한다. 삭제 실패 복원은 형상·출처·축 값 전체를 보존해야 한다.
- GPU에는 원본 좌표 배치를 유지한다. 축 편집은 표시 행렬과 변환에 의존하는 경계·피킹·계산 캐시만 갱신하고, 원본 재읽기나 메시 재생성을 하지 않는다.

### 13.7 미리보기·적용·취소·Undo

1. 창을 열 때 대상의 확정 축 값·공통 정렬 지문·형상 revision을 캡처한다.
2. 편집 값은 축 설정 전용 임시 상태에 저장한다. 미리보기는 이 상태를 참조해 두 형상을 다시 그린다.
3. 미리보기 동안 확정 저장소·원본·저장 JSON은 바뀌지 않는다. 보이는 마커와 형상 경계는 같은 미리보기 행렬로 계산한다.
4. `적용`에서 축 유효성과 대상 생존·revision·기준 정렬 지문을 다시 확인한다.
5. 두 형상 설정과 관련 검증 상태를 한 트랜잭션으로 갱신하고 세션 Undo 한 건을 남긴다. 실패하면 전부 이전 상태로 복원한다.
6. `취소`·Esc·창 이탈·파일 로드·애드온 해제는 임시 상태만 폐기한다. 다시 열면 마지막 확정 값이 나온다.
7. 변경 없음은 Undo를 추가하지 않는다. Undo/Redo는 COLMAP·메시 축과 관련 상태를 함께 복원한다.

동시 편집 규칙:

- 가져오기·복원·마커 드래프트·GICP 실행/미리보기·레이어 변환·내보내기 중에는 축 편집을 시작하지 못하도록 기존 잠금 경계를 확장한다. 막힌 이유를 짧게 표시한다.
- 축 팝업 미리보기 중에는 정렬·내보내기·그룹 변경·다른 축 편집을 시작하지 않는다.
- 일반 점군·메시 표시 토글은 계산 입력을 바꾸지 않으며 기존 동작을 유지한다.
- 완료된 마커의 원본 ID·원본 로컬 좌표는 유지한다. COLMAP 축 적용 후 표시 위치와 다음 정렬 입력은 새 `N_colmap`에서 계산한다.
- 공통 정렬 `A`, 그룹, 앵커, 다른 데이터셋의 축은 자동 초기화하지 않는다. COLMAP 축을 바꾸면 실제 정렬 배치가 달라지므로 기존 잔차·품질 지표를 유효한 결과처럼 재사용하지 않는다.
- COLMAP 축 편집은 기존 수동 변환 정책과 같이 해당 변경을 수동 수정으로 기록하고 이전 자동 정렬 품질 수치를 무효화한다. 해당 데이터셋을 참조한 정렬 입력·품질 캐시도 지문 불일치로 폐기한다. 이 상태도 Undo에 포함한다.
- 연결 메시 축만 바꾸면 현재 희소 GICP의 입력은 동일하다. COLMAP 정렬 지표를 불필요하게 초기화하지 않는다. 향후 표면 정렬 도입 시에는 `N_mesh` 지문을 그 입력에 포함한다.

### 13.8 카메라·정렬·내보내기 연결

축 변경은 화면만 돌리는 장식 설정으로 처리하지 않는다.

- COLMAP 정렬 입력은 원본 점에 현재 `N_colmap`을 적용한다. 화면에서 보이는 점과 GICP가 사용하는 점의 좌표 기준을 일치시킨다.
- 점 피킹, 독립 OBJ 피킹, 완료 마커 표시, A/P 미리보기, 경계·화면 맞춤은 각 대상 형상의 같은 유효 행렬을 사용한다.
- COLMAP 출력의 기존 앵커 원본 좌표 정책을 유지한다. 모델 i의 출력 변환은 기존 계약에 맞춰 `inverse(N_anchor_colmap) × A_i × N_i_colmap`을 사용한다.
- 같은 출력 변환을 점과 카메라 위치·자세에 일관되게 적용하여 영상 투영을 보존한다. 카메라 내부 파라미터와 원본 point/image ID는 축 설정 때문에 바꾸지 않는다.
- 연결 메시 축만 바꿔도 COLMAP 출력 행렬·대상 수가 바뀌면 안 된다.
- 독립 OBJ의 축 변경은 기존 OBJ 내보내기에 반영하고 UV·재질 계약을 유지한다. 연결 메시를 새로운 독립 내보내기 대상으로 자동 추가하지 않는다.
- 기존 A/P 정렬 결과의 공통 `A`가 메시에도 적용되므로 이후 표면 정렬로 얻은 결과를 COLMAP 소유자에 전달하는 구조를 유지한다. 표면 샘플링과 정렬 알고리즘 구현은 이번 범위에 포함하지 않는다.

### 13.9 저장·복원과 기존 파일

저장 스키마를 v5로 확장하는 안으로 한다.

- 최초 원본 출처와 별개로 현재 주 모델 축 설정, 선택적 연결 메시 축 설정을 저장한다.
- 저장값: 프리셋 ID, Forward/Up, 추가 회전, 검증 가능한 최종 행렬 또는 그 지문. 편집 설정이 행렬을 재현하는지 읽기에서 검사하며 독립된 두 권위를 만들지 않는다.
- 기존 원본 출처 필드는 원본 재읽기·지문 검증을 위해 그대로 보존한다.
- v1~v3는 기존 단독 모델 축을 복원한다. 복원 시 새로운 OBJ 자동 연결은 하지 않는다.

- 복원은 기존 별도 Runtime 준비 → 축 설정 검증 → GPU 준비 → 성공 시 교체 순서를 따른다. 오류 시 기존 정상 상태를 유지한다.
- 임시 미리보기는 저장하지 않는다. 표시 토글은 기존 값 그대로 저장·복원한다.

| 변경 전: 두 형상에 COLMAP 축 적용 | 6.430981 | 7.619656 | 18.184883 |
| 변경 후: RC 형상별 기본 축 적용 | 0.035726 | 0.042641 | 0.089020 |

단위는 원본 좌표 단위다. 이 수치는 입력 축 보정 검증이며 메시 표면 정렬의 개선율을 뜻하지 않는다. 표면 샘플링·표면 GICP는 이번 구현에 포함하지 않는다.

주요 증거는 실험 루트의 다음 위치에 보관한다.

- `outputs/axes-integrated/report.json`: 최종 19개 소스 검사 결과
- `outputs/axes-integrated/final-code-report.json`: 검사 수와 소스 지문
- `outputs/axes/real-rc-axis-report.json`: 실제 입력의 같은 표본 거리 비교
- `outputs/axis-ui-verification/`: 네이티브 팝업 화면과 GUI 실행 결과
- `outputs/axis_review/`: 독립 원자성·창 종료 검증 결과
- `outputs/axis-ui-integration/outputs/companion-gui-report.json`: 실제 소스 작업공간 표시·축 팝업 통합 결과

전체 작업공간 검사는 각 VIEW_3D의 WINDOW 영역을 지정한 `DRAW` 호출로 실제 점·면 제출을 검증한다. 초기 검사에서 전체 창 그리기 요청만으로는 영역 갱신이 발생하지 않아 검사 하니스를 수정했다. 작업공간 스크린샷은 검게 나오는 경우가 있어 시각적 증거와 완료 판정에서 제외했다. 실제 RC 결과는 원본 읽기·동일 표본 수치와 변환 경로 검사로 확인했다. 설치 갱신 후에는 실제 설치 모듈에서 두 역할의 점·면 제출, 속성 팝업 취소·적용, 세션 Undo/Redo 검사를 통과했다.

### 14.4 설치 및 최종 확인

처음에는 실행 중인 실험 Blender 때문에 기존 관리기의 재설치 보호가 작동했다. 사용자가 창을 종료한 뒤 같은 관리 명령을 다시 실행하여 최신 소스를 빌드·설치하고 검증을 완료했다. 보호 절차를 우회하거나 사용자 창을 강제로 종료하지 않았다.

- 빌드 파일: `E:\DEV\DEV_RND\colmap_align_test_env\dist\colmap_align_test_env-0.1.0.zip`
- 설치 모듈: `bl_ext.colmap_align_test_env.colmap_align_test_env`
- 최종 게이트: 설치본 격리·재등록 + 소스 19개 파일 + 설치본 작업공간 GUI, 총 21개 항목 통과
- 설치본 GUI: 표시 4조합, 실제 세션 입력 가드, 팝업 취소·적용, Undo/Redo 통과
- 키맵: 실제 GUI 저장값과 활성값 모두 `Industry_Compatible`
- 최종 보고서: `outputs/verification-report.json`, `outputs/companion-gui-report.json`, `outputs/axes/keymap-gui-report.json`
- 원본 `main` 작업트리는 깨끗하며 실험 브랜치는 `codex/align-test-env`다. 커밋·통합은 수행하지 않았다.

재검증 명령은 다음과 같다. 사용자용 실험 Blender를 종료한 상태에서 실행한다.

```powershell
& "E:\DEV\DEV_RND\colmap_align_test_env\runtime\python\python.exe" -B -I -X utf8 "E:\DEV\DEV_RND\colmap_align_test_env\source\test_env\manage.py" verify --gui
```
