# Align 전처리 반복 계산 최적화 계획서

- 작성일: 2026-09-20
- 기준: BVH 생성 최적화가 적용된 0.3.64 개발 작업본.
- 요청 범위: 후보 면 판정, 취소 확인 경로 처리, 전체 형상 범위 재사용.
- 기존 측정: 동일 `Untitled.blend` 입력 전처리 비계측 중앙값 21.439초. 표본 자료 준비 7.662초, 메시 검사 7.562초. 후보 면 판정 단독 비교는 기존 3.977초에서 대안 0.220초였다.

## 현행 동작과 유지 조건

전처리는 원본 좌표 검사, 공통 정규화, 단정도 정밀도 검사, 겹침 반경·범위 계산, 면적 비례 표본 준비 순서로 실행된다. 두 메시 검사는 판정 기준이 다르므로 모두 유지한다. 원본 메시, 면 순서, 마커, 저장 형식, 표본 수·난수열, 면적 누적 순서와 품질 판정을 변경하지 않는다.

수정은 Align 파이썬 전처리와 해당 회귀·실험 도구에 한정한다. CCCoreLib·BVH·ICP 수식과 네이티브 통신 규약, CPU 제한, 묶음 크기를 변경하지 않는다. 기존 작업 중인 다른 도구·UI·문서를 포함하거나 되돌리지 않는다.

## 1. 후보 삼각면 판정

- `icp_cccore_overlap.py`에서 각 삼각형의 세 정점을 좌표축별로 직접 비교한다.
- 기존 `(면적 > 0) AND (모든 축의 최대 >= 하한) AND (모든 축의 최소 <= 상한)` 조건과 경계 포함 규칙을 보존한다.
- 면 묶음 크기는 최대 8,192개로 유지한다. 길이 8,192 이하의 배정도 작업 배열 두 개를 재사용하며 추가 작업 배열은 최대 128KiB다.
- 좌표 추출·면적·누적표·난수열을 그대로 유지한다. 전체 면의 경계를 별도 대형 배열로 캐시하지 않는다.

## 2. 취소 파일 경로 재사용

- `NativeRunner` 초기화에서 고정 취소 파일 경로를 검증하고 작업 수명 안에서 보관한다.
- 정상 반복 중 파일 부재는 링크를 따라가지 않는 파일 상태 조회로 확인한다. 작업 디렉터리 소실도 확인해 유효하지 않은 작업을 계속 실행하지 않는다.
- 파일·심볼릭 링크·정션 등 경로 항목이 존재하면 기존 `job_path` 해석과 작업 경계 검증을 수행한다. 깨진 링크도 파일 부재와 구분한다.
- 외부 취소 콜백, 확인 횟수, 응답 대기의 취소 유예·프로세스 정리 동작은 유지한다. 일반 입력·출력 파일의 `job_path` 규칙을 완화하지 않는다.
- 응답 대기와 일반 계산의 취소 판정에 같은 내부 함수를 사용한다.

## 3. 전체 형상 범위 재사용

- `make_normalization`에서 이미 구한 두 메시의 최소·최댓값으로 각각의 대각 길이를 계산한다. `np.ptp`의 중복 전체 순회를 제거한다.
- 정규화와 단정도 정제가 끝난 최종 계산 형상의 최소·최댓값을 각 1회 구하고 겹침 반경·공통 검색 범위·표면 샘플러에 전달한다.
- 원본 좌표 범위와 정규화 범위는 공유하지 않는다. 퇴화면 제거·정점 압축 이전의 범위도 재사용하지 않는다. 작업 종료 후 남는 전역 캐시는 만들지 않는다.
- 기존 호출자는 선택적 인자를 생략하면 기존처럼 범위를 계산한다. 표면 샘플러는 전달받은 범위의 형식·유한성·순서를 검사하고 정점 유한성 검사와 취소 확인을 유지한다.
- 공분산·분포 검사, 점군의 중복점 처리, 겹침 품질 기준은 변경하지 않는다.

## 수정 대상

- `tools/align/alignment/icp_cccore_overlap.py`: 후보 면 판정과 선택적 원본 범위 전달.
- `tools/align/alignment/icp_cccore_solver.py`: 고정 취소 경로와 전처리 범위 전달.
- `tests/align/`: 후보 경계·누적표·표본 동일성, 범위 재사용·정제 이후 경계, 취소·링크 안전성 회귀.
- `tests/align/experiments/`: 필요한 경우 재현 가능한 비교 도구. 실제 데이터와 측정 출력은 `build/verification/preparation-optimization-20260920/`에 보관한다.

## 검증 순서와 완료 조건

1. 변경 전 전체 정렬 모듈과 파일 해시를 별도 검증 폴더에 보존한다.
2. 후보 판정의 통과·탈락·경계 접촉, 영 면적, 묶음 경계, 누적표·표본 지문이 기존과 같은지 비교한다.
3. 전달 범위가 없을 때의 호환 동작, 최종 형상 범위 전달, 정제 전후·큰 좌표 정규화와 점군 혼합 모드를 검사한다.
4. 취소 파일 없음·생성·삭제·디렉터리·내부 링크·외부 및 깨진 링크, 외부 콜백, 응답 대기와 작업 디렉터리 소실을 검사한다. 플랫폼에서 실제 링크를 만들 수 없는 경우 검증 한계를 명시한다.
5. 기존 표면 표본·겹침·솔버·네이티브 네 형상 조합과 취소 회귀를 실행한다.
6. 같은 `Untitled.blend`에서 보존한 입력·실행 파일·31 스레드 설정으로 전처리를 변경 전후 각각 준비 실행 1회, 본 측정 3회 교차 실행한다. 표본 해시·진단·정규화를 정확 비교하고 프로세스 최대 메모리를 확인한다.
7. 동일 실제 입력으로 전체 정렬을 실행해 기존 최종 변환·거리 품질·표본 지문과 비교한다. 원본 `.blend`를 저장하거나 변경하지 않는다.

성능 수치는 이번 변경 전후의 동일 조건 측정으로 확정한다. 후보 판정 단독 94% 감소를 전체 전처리 개선으로 보고하지 않는다. 소스 구현, 검증, 배포·설치 여부를 구분해 결과에 기록한다.

## 구현·검증 결과

2026-09-20에 1~3번 소스 구현과 검증을 완료했다.

- 실제 변경한 정렬 모듈은 `icp_cccore_solver.py`, `icp_cccore_overlap.py` 두 개다. C++ 실행 파일은 동일하다.
- 후보 판정은 좌표축별 직접 비교와 최대 128KiB 작업 배열 재사용으로 변경했다. 기존 면적 누적 순서·표본 수·묶음 크기는 유지했다.
- 취소 확인은 고정 경로의 `lstat` 결과가 없을 때만 반복 해석을 생략한다. 항목이 있으면 기존 `job_path` 검증을 사용하며 실제 내부·외부·깨진 링크 검사를 통과했다. 확인 주기를 늘리지 않았다.
- 원본 좌표의 정규화 범위와 최종 정제 형상의 범위를 각각 필요한 단계 안에서 재사용한다. 정점 유한성 검사와 두 종류의 메시 검사를 유지했다.
- 새 집중 회귀 10개, 기존 표면 15개·겹침 15개·계약 19개·솔버 58개를 검증했다. 기존 솔버 대역 중 생성자를 생략하는 네 곳에 새 고정 경로 필드를 반영했으며 관련 순수 계약 36개를 다시 실행해 통과했다. 실제 네 형상 정렬·취소·자식 종료도 통과했다.
- 동일 실제 입력의 별도 프로세스 교차 측정: 각 준비 실행 1회 뒤 본 측정 3회. 전처리 중앙값 **21.4869초 → 15.1616초**, **29.44% 감소**. 모든 표본 해시·정규화·설정과 시간 항목을 제외한 진단이 같았다.
- 전처리 파이썬 프로세스 최대 작업집합 중앙값은 1,041,760,256 → 1,041,731,584바이트로 같은 수준이었다. 이는 Blender 및 네이티브 자식 전체의 합계가 아니다.
- 별도 검증용 Blender에서 `C:/Users/gksru/Desktop/Untitled.blend`의 실제 Align 연산자를 실행했다. 전체 시간은 이전 **40.5478초 → 35.2386초**였다. 각각 단일 실행이며 프로젝트 복원·마커 준비 시간은 제외한다. 이번 실제 전처리는 15.2040초였다.
- 최종 행렬 최대 차이 0, 표본 지문과 최종 거리 품질 지표 동일, 품질 `PASS`. 원본 `.blend`와 OBJ의 크기·수정 시각이 유지됐다.
- 검증용으로 기존 0.3.64 배포본의 별도 복사본에 두 모듈을 반영했다. 사용자 설치본, 제품 버전, Git 커밋·원격 저장소는 변경하지 않았다.

재현 결과와 비교 스크립트: `build/verification/preparation-optimization-20260920/`. 상세 결과는 해당 폴더의 `결과.md`, `comparison.json`, `paired-comparison.json`에 있다. 계측 도구는 `tests/align/experiments/profile_preparation.py`, 집중 회귀는 `tests/align/test_icp_preparation_optimization.py`다.
