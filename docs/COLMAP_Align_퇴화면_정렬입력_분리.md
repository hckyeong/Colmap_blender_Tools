# Align 퇴화면과 정렬 계산용 메시 분리

## 적용 범위

0.3.55에서 일부 퇴화 삼각면 때문에 전체 정렬이 중단되던 동작을 변경했다. 정상 면이 남아 있으면 퇴화면만 정렬 계산에서 제외한다. 원본 OBJ, 내장 Blender Mesh, 프록시 배열, 원본 면 매핑, UV, 재질, 마커 번호는 변경하지 않는다.

서로 다른 면이 같은 표면을 덮는다는 이유만으로 면을 삭제하지 않는다. 이번 변경의 대상은 정점 중복·공선성 또는 계산 정밀도 때문에 유효한 면적을 갖지 못하는 삼각면이다.

## 계산 과정

1. Blender 입력 스냅샷을 만들 때 원본 배정도 좌표로 퇴화면을 검사한다.
2. 유효면만 별도 계산 배열에 남기고, 유효면이 참조하지 않는 정점을 계산 배열에서 압축·재색인한다. 멀리 있는 퇴화면 전용 정점이 정규화 범위를 오염시키지 않도록 한다.
3. 작업 프로세스에서도 공통 좌표 메시를 정제하고, 두 입력의 공통 원점·길이 단위로 정규화한다.
4. 실제 C++ 입력과 같은 단정도 반올림 후 면 유효성을 다시 확인한다. 이 단계에서 무너지는 작은 면도 계산에서만 제외한다.
5. 겹침 후보, 표면 표본, 정렬과 결과 거리 평가가 동일한 최종 계산 메시를 사용한다.

면 검사는 65,536개씩 처리한다. 면 순서를 유지하며, 모든 면·정점이 유효하면 정제 함수는 입력 배열을 그대로 반환한다. C++ 실행 파일, 통신 규약, 영속 저장 형식은 바꾸지 않았다.

## 원본 보존과 중단 조건

- 출처 정보의 정점·면 수와 내용 지문은 압축된 계산 배열이 아닌 원본 전체를 기준으로 유지한다.
- 계산에서 제외한 면·정점이 나중에 바뀌어도 원본 내용 재검증에서 변경을 감지한다.
- 원본 배열의 읽기 전용 상태와 기존 마커 ID를 유지한다.
- 비유한 좌표, 범위 밖 인덱스, 유효면이 전혀 없는 메시는 계속 거부한다.
- 기존 표본 수, 대응 분포, 겹침과 정렬 품질 검증을 완화하지 않는다. 점군의 퇴화 검사도 유지한다.

## 검증

Blender 5.2와 배포에 사용하는 실제 CCCoreLib 작업 프로세스로 확인했다.

- 순수 계약 29개와 메시 정제 5개 통과.
- 원점에서 매우 먼 퇴화면과 단정도에서만 무너지는 면을 추가한 실제 메시–메시 정렬 통과. 결과 변환을 알려진 정답과 비교하고 원본 입력 파일 해시 보존을 확인했다.
- 기존 네 가지 점군·메시 입력 조합 통과.
- Blender 형상 입력 14개, CC 실행·승인·실행 취소 8개 및 관련 영속 저장·UI·표면 선택 회귀 통과.
- 정상 사각면과 퇴화 삼각면을 함께 가진 OBJ에서 원본 7정점·3개 프록시 삼각면을 계산용 4정점·2면으로 분리했다. `.blend` 저장 후 원본 OBJ를 지우고 복원한 뒤 OBJ로 다시 내보내도 원본 면 구성·UV·재질과 마커 번호가 유지되는 것을 확인했다.

### 실제 오류가 발생한 고양이 OBJ

검사 파일: `Taiwan_cat_bone_GaussianToMesh.obj`, 857,143,860바이트.

| 항목 | 결과 |
|---|---:|
| 원본 정점 | 5,651,583개 |
| 원본 프록시 삼각면 | 11,303,398개 |
| 배정도 검사에서 제외한 퇴화면 | 18개 |
| 단정도 검사에서 추가 제외한 면 | 0개 |
| 정렬 계산용 삼각면 | 11,303,380개 |
| 불러오기 | 14.19초 |
| 원본 검사·정제·계산용 스냅샷 | 3.63초 |
| 단정도 유효성 검사 | 1.13초 |
| 실제 CC 메시 적재·128점 표면 거리 평가 | 2.34초 |

원본 좌표·면 배열의 해시, 내장 메시 정점·면·UV 수, 원본 파일 크기·수정 시각 보존을 확인했다. 거리 평가도 통과했다. 이 수치는 별도 백그라운드 프로세스의 단일 측정이며, 두 실제 레이어 사이의 전체 정렬 시간은 아니다.

### 앞서 제공된 아르마딜로 OBJ

`Taiwan_armadillo_scanHighpoly.obj`의 10,173,478정점·20,128,488삼각면에서는 두 검사 모두 퇴화면을 찾지 못했다. 원본 검사·스냅샷 5.86초, 단정도 검사 1.76초였으며 원본 보존 검사를 통과했다.

별도로 수행한 128점 표면 거리 평가에서는 네이티브 오류 `-973`이 발생했다. 로컬 CCCoreLib에서 이 값은 `ERROR_INTERSECT_MESH_WITH_OCTREE_FAILURE`로, 삼각면–옥트리 교차 격자 구성 실패를 뜻한다. 퇴화면 검출 오류와 구분되며, 이 코드만으로 메모리 부족 등 세부 원인을 확정할 수 없다. 해당 진단을 전체 정렬 성공으로 간주하지 않았고 이번 변경에 원인 미확정 수정은 포함하지 않았다.

검증 기록은 로컬 `build/verification/degenerate-mesh-0.3.55/`에 보관한다. 임시 진단 코드는 제품 코드나 Git 커밋에 포함하지 않는다.

## 배포 확인

- 정식 `build_extension.ps1` 빌드와 `test_installed_extension.ps1` 격리 설치 검사가 통과했다. 격리 설치본의 실제 정렬·승인·실행 취소와 OBJ 입출력도 확인했다.
- `colmap_tools-0.3.55.zip`을 실제 Blender 5.2 사용자 확장에 설치했다. 설치된 1,172개 파일의 해시가 ZIP과 일치하고 확장이 활성화된 것을 별도 백그라운드 프로세스에서 확인했다.
- 사용자 설정 파일을 설치 전에 백업했으며 설치·검증 전후 해시가 같다. 사용자가 실행 중인 Blender는 종료하거나 재시작하지 않았다. 열려 있는 Blender에는 재시작 후 새 코드가 적용된다.
- 이전 0.3.54 ZIP과 비교하면 정제 모듈 1개가 추가되고 버전 파일 2개·관련 정렬 모듈 3개만 변경됐다. 기존의 별도 작업 변경을 이번 커밋에 포함하지 않는다.
