# Artec 16 수동 Align의 종료식

2026-10-21, Artec Studio 16 Professional 16.0.8.2의 수동 강체 Align에서 사용한 `relativeDelta` 경로를 분석했다. **오차 조건 하나, 또는 이동·회전 조건 둘을 만족하면 종료한다. 세 조건을 모두 요구하지 않는다.**

## 확인한 수식

`E_k`는 갱신 후 대응을 다시 찾은 뒤 계산한 접평면 잔차 RMS다. `t_k`와 `r_k`는 이번 한 번의 강체 갱신 행렬에서 얻은 이동 벡터와 회전 벡터다. `r_k`는 회전축에 라디안 회전각을 곱한 값이다. 누적 최종 변환과 구분해야 한다.

```text
ε = 10⁻⁹
오차 변화 = |E_k − E_(k−1)| / (E_(k−1) + ε)
이동 변화 = ‖t_k − t_(k−1)‖ / (‖t_(k−1)‖ + ε)
회전 변화 = ‖r_k − r_(k−1)‖ / (‖r_(k−1)‖ + ε)

종료 = (오차 변화 < 0.001)
       또는 ((회전 변화 < 0.001) 그리고 (이동 변화 < 0.001))
```

- 실제 설정은 단정도 `0.0010000000474974513`이다. 비교 연산은 `<`이며 `≤`가 아니다.
- 세 값 모두 상대 비율이다. 이동을 모델 경계상자 크기로 나누지 않으며 회전각 자체가 `0.001 rad` 미만인지를 검사하지 않는다.
- 오차 조건을 먼저 검사하고 만족하면 즉시 반환한다. 이때 이동·회전 이력은 갱신하지 않는다. 그렇지 않으면 이전 갱신 벡터와 비교하고 이력을 갱신한다.
- 이동·회전 이력은 작업 시작에 영벡터로 초기화한다. 첫 갱신에서도 오차 변화만 작으면 종료할 수 있다.
- 이 종료 분기에는 전후 대응점 수가 같아야 한다는 조건이 없다. 이전 실제 Align에서 유효 대응은 140,012개에서 140,021개로 달라졌지만 종료했다.
- 오차 변화에는 절댓값을 사용하므로 소폭 증가도 조건을 만족할 수 있다. 바깥 반복문은 최저 오차의 누적 변환을 별도로 보관한다. 따라서 종료 조건이 최근 변환의 채택을 곧바로 뜻하지 않는다.
- 수동 Align에서 관측한 최대 갱신은 30회다. 취소·유효 대응 없음·다른 종료 모드는 이 수식과 별도 분기다.

오차 계산 함수는 0이 아닌 가중치를 가진 대응에 대해 다음을 계산한다.

```text
E = sqrt( Σ [w_i · n_iᵀ(q_i − p_i)]² / N_(w≠0) )
```

잔차와 가중치 곱은 단정도 계산 후 배정도로 제곱·누적한다. 분모는 가중치 합이 아닌 0이 아닌 가중치의 개수다. 먼 대응의 가중치를 0으로 만든 뒤 계산한다. 이는 정점 간 유클리드 거리 RMS나 독립적인 양방향 표면 오차와 다르다.

## 추적한 주소와 검증

주소는 실행 파일 로드 기준 주소에 대한 상대 주소다.

| 상대 주소 | 역할 |
|---|---|
| `0x21fe850` | 갱신, 재검색, 오차 계산, 종료 검사와 최저 오차 변환 보관 |
| `0x21ff739`·`0x21ff73d`·`0x21ff743` | 직전·현재 오차의 실수 인자 전달과 종료 함수 호출 |
| `0x21e87f0` | 오차 조건 즉시 반환 뒤 회전·이동 조건 검사 |
| `0x49f4f30` | 분모에 더하는 배정도 상수 `1e-9` |
| `0x1a2ba00`·`0x1a2f250` | 갱신 회전 행렬을 사원수, 회전축·각으로 변환 |
| `0x51d3418` | `niChenMedioniAligner` 가상 함수 표. `+0x18`이 아래 오차 함수 |
| `0x1a30880` | 가중 접평면 잔차 RMS |

과거 메모리 덤프의 종료 함수·호출부·회전 보조 함수 네 구간을 현재 프로세스 명령 바이트와 비교했고 모두 같았다. 실행 파일 SHA-256도 이전 조사와 같다. 기존 Ghidra 프로젝트를 읽기 전용으로 열어 관련 함수를 추가 해석했으며 데이터베이스 변경은 저장하지 않았다.

독립적으로 할당한 입력 버퍼만 사용해 실제 Artec 종료 함수에 10개 사례를 전달했다. 오차 조건만 만족, 변환 둘 다 만족, 한쪽만 만족, 영 분모 보호, 절대 이동이 커도 상대 변화는 작은 경우를 포함하며 예측과 반환값이 모두 일치했다. 회전 보조 함수는 네 회전각에서 축·각을 확인했다. 오차 함수에는 잔차 `[2, 4, 6]`, 가중치 `[1, 0.5, 0]`을 주어 결과 `2`를 확인했다.

이 호출들은 **종료식 검증용 합성 입력**이며 사용자 모델로 새 Align을 실행한 관측이 아니다. 이전 실제 Align이 어느 수치에서 오차 조건을 만족했는지는 과거 로그에 실수 인자가 없어 소급 확정하지 않는다. 사용자 메시·장면·실행 파일을 수정하지 않았고 임시 계측 세션은 종료했다.

## 우리 엔진과의 차이

| 항목 | Artec에서 확인한 식 | 분석 당시 브랜치의 0.001 설정 |
|---|---|---|
| 결합 | 오차 또는 (회전 그리고 이동) | 오차 그리고 이동 그리고 회전 |
| 이동 | 이전 갱신 이동 벡터 대비 변화 | 이번 갱신의 중심 이동량 / 모델 대각선 |
| 회전 | 이전 갱신 회전 벡터 대비 변화 | 이번 갱신의 회전각 자체 |
| 오차 분모 | 직전 오차 + `1e-9` | 직전 목적함수 RMS와 `D × 1e-15` 중 큰 값 |
| 대응 수 | 이 분기에는 동일 개수 조건 없음 | 갱신 전후 동일 개수 필요 |

따라서 세 허용치를 0.001로 바꾸는 것과 Artec 종료식을 구현하는 것은 서로 다른 변경이다. 이번 분석 요청으로 조건 결합이나 정규화 방식을 추가 변경하지 않았다.

후속 구현에서 종료식을 적용한 결과는 [정확한 종료식 적용 검증](COLMAP_Align_Artec_종료식_적용검증.md)에 별도로 기록한다. 위 비교표는 종료식 적용 이전 상태다.
