# Painter 실행 취소·다시 실행 시 뷰포트 유지

- 작성일: 2026-10-06.
- 범위: Projection Paint의 실행 취소·다시 실행 후 카메라 세션 복구.

## 원인과 변경

실행 취소·다시 실행 후 수명주기 복구가 `activate_managed_frame`을 호출하면서 현재 프레임의 카메라 뷰까지 강제로 진입했다. 원근·정사·카메라 뷰 각각에서 두 복구 경로의 카메라 진입 호출을 재현했다.

프레임 활성화의 카메라·마커·소스 동기화와 뷰 진입을 분리한다. `enter_camera_view`는 기본값을 참으로 두어 기존 호출을 유지한다. `undo_post`·`redo_post` 복구에서만 거짓으로 전달한다. 현재 투영·위치·회전·거리·카메라 확대·이동을 변경하지 않으면서 복원된 카메라 데이터와 세션 권한을 연결한다.

실제 단축키 검사에서는 복구 뒤 같은 프레임의 이미지 갱신이 지연 예약되며 카메라 뷰에 재진입하는 경로도 확인했다. 카메라 런타임에 마지막 활성화 프레임을 기록하고, 지연 소스 갱신은 실제 프레임이 바뀐 경우에만 카메라 뷰로 진입한다. 같은 프레임의 소스 갱신·재시도는 현재 뷰를 유지한다. 이 기록은 저장 데이터에 추가하지 않으며 실행 취소·로드 때 런타임과 함께 재구축한다.

가져오기 완료, 작업공간 진입, 명시적 스텐실 재연결과 일반 프레임 전환의 카메라 뷰 진입은 유지한다. Align·Modifier의 실행 취소나 전역 키맵은 변경하지 않는다. 파일 로드와 등록 시 복구 동작도 유지한다.

## 검증

- Blender 5.2에서 원근·정사·카메라 뷰 × 실행 취소·다시 실행의 여섯 경로를 검사한다. 탐색 상태 유지, 새 카메라 세션 토큰과 마커 연결, 수명주기 오류 부재를 확인한다.
- 기존 카메라·배경·프레임 전환·스텐실 소스 회귀와 수명주기 등록 검사를 실행한다.
- 별도 숨김 Blender 창에서 실제 페인트 스트로크와 `Ctrl+Z`·`Ctrl+Shift+Z` 입력의 픽셀 복구 및 시점 유지 여부를 검사한다. 사용자 프로젝트는 수정하거나 저장하지 않는다.
- 최상위 `colmap_tools.zip`을 갱신하고 설치 파일과 대조한다.

Blender 실행 취소 전후의 공식 처리 경계는 [Blender 5.2 핸들러 문서](https://docs.blender.org/api/5.2/bpy.app.handlers.html)를 따른다.

## 결과

- 카메라 회귀 21개와 수명주기 회귀 15개 통과. 같은 프레임의 지연 갱신은 자유 뷰를 유지하고 실제 다른 프레임 선택은 카메라 뷰로 이동함을 확인했다.
- 실제 페인트 스트로크의 `Ctrl+Z`·`Ctrl+Shift+Z` 입력 × 세 투영 상태의 여섯 검사에서 픽셀 복구와 탐색 상태 보존을 확인했다.
- 정식 빌드의 순수 검사 314개, 통합 등록·해제 및 네이티브 스테이징 정렬 검사를 통과했다. 최상위 설치 ZIP 버전은 0.3.75다.
- 검증 결과는 `build/verification/painter-undo-viewport-20261006/`에 보관한다. 실행 중인 사용자 Blender는 MCP가 연결되지 않아 직접 검증하지 못했다.
