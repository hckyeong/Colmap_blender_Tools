# Align 후보 준비 단계의 중복 거리 계산 제거 계획서

- 작성·수정일: 2026-09-18
- 상태: 0.3.57 구현·회귀·격리 설치·실제 설치 검증 완료
- 기준: `codex/align-large-mesh-optimization`, 0.3.56, 커밋 `665db34`
- 목적: 메시 후보를 처음 검사한 결과를 첫 분류에서 다시 사용하여 같은 면 중심의 거리 조회를 한 번 줄인다.
- 범위 결정: 기존 격자 재사용 계획을 이 계획으로 대체한다. 우선 중복 계산만 제거하고, 거리 조회 묶음 크기는 8,192개로 유지한다.
- 관련 문서: [겹침 후보 정책](temp/COLMAP_Align_CC_겹침후보_우선샘플링_계획서.md), [격자 메모리 예산](COLMAP_Align_격자_메모리_예산.md).

## 1. 이번에 개선할 부분

대상은 `tools/align/alignment/icp_cccore_overlap.py`의 `build_overlap_domain()` 메시 경로다. 이 함수는 다음과 같이 같은 면 중심을 두 번 조회한다.

1. 원본 면을 8,192개씩 읽고 경계상자와 면적으로 먼저 거른다.
2. 남은 면의 중심 거리로 확실히 먼 면을 제외한다.
3. 살아남은 원본 면을 모은다.
4. 첫 분류 단계인 `depth == 0`에서 **같은 중심 거리를 다시 조회**해 완전한 내부 면과 경계에 걸친 면을 나눈다.
5. 경계 면을 분할하고, 새 부분면의 중심 거리를 조회한다.

이번에는 2번에서 얻은 결과로 4번의 판정까지 준비한다. 5번에서 새로 생긴 중심점이나 실제 정렬·평가 표본은 계속 새 거리를 계산한다.

격자·옥트리 재사용, 묶음 확대, C++ 이관, 다른 거리 엔진, 점군 경로의 별도 중복 제거는 이번 범위에 넣지 않는다.

## 2. 유지할 동작

| 항목 | 유지 기준 |
|---|---|
| 조회 묶음 | 최대 8,192개, 메모리 사양에 관계없이 이번 변경에서 확대하지 않음 |
| 후보 판정 | 기존 거리 반경, 면 중심과 반경을 이용한 보수적 판정식 |
| 분할 정책 | 깊이 8, 추가 조각 250,000개 등 기존 설정과 전역 예산 적용 순서 |
| 표본 | 정렬 표본 50,000개, 평가 표본 30,000개, 시드·생성 순서·제안 상한 |
| 정렬 | 기존 강체·배율 단계, 반복 상한, 품질·후보 선택 기준 |
| 원본 | 정점·면·UV·마커·출처와 원본 면 번호 |
| 네이티브 | 현재 CCCoreLib 바이너리·정확 거리 방식·메모리 예산 패치 |
| 취소·저장 | 기존 취소 응답, 승인·Undo·이전 `.blend` 복원 계약 |

거리 조회가 줄어든 만큼 실제 준비 명령 수·소요 시간·실행 감사 기록은 달라진다. 제거된 호출을 실행한 것처럼 기록하거나 기존 명령 수에 맞추려고 빈 호출을 넣지 않는다.

## 3. 재사용할 정보와 처리 순서

면의 중심 거리를 `d`, 중심에서 가장 먼 꼭짓점까지의 거리를 `r`, 후보 반경을 `t`라고 한다.

- 초기 후보 유지: `d - r <= t`
- 완전히 내부인 면: `d + r <= t`
- 초기 후보로 유지됐지만 완전히 내부가 아닌 면: 경계 분할 대상

### 3.1 첫 조회에서 분류 결과를 함께 보관

초기 거리 배열을 받으면 기존 방식대로 후보를 선택하고, 살아남은 면마다 `d + r <= t`의 결과를 `numpy.bool_` 배열에 기록한다. 이 배열은 같은 순서의 `pending` 면과 `pending_ids`에 대응한다.

전체 거리값·중심점·반경을 새 캐시로 보관하지 않는다. 초기 묶음에서 이 값들을 사용한 뒤, 후속 단계에는 내부 여부만 넘긴다.

### 3.2 첫 분류에서 재조회 제거

모든 초기 후보를 모은 뒤 첫 분류에서 보관된 내부 여부를 사용한다. 처음 이미 후보로 인정된 면이므로 나머지는 경계 면으로 분류한다. 이 단계의 중심·반경 재계산과 `_distances()` 호출을 제거한다.

기존 순서를 반드시 유지한다.

- 전체 원본 면 순서로 후보와 내부 여부를 결합한다.
- 먼저 내부 면을 기존 순서대로 유지한다.
- 경계 면 전체에 기존 전역 분할 예산을 한 번 적용한다.
- 예산 때문에 분할하지 못한 면을 기존 위치에 남기고, 나머지 면의 자식은 기존 순서로 만든다.

묶음마다 분할 예산을 따로 배분하거나 내부·경계 면을 도착 순서대로 섞으면 최종 면 순서와 표본이 달라질 수 있으므로 그렇게 변경하지 않는다. 분할 깊이 0이나 분할 예산이 부족한 경우도 기존 의미를 유지한다.

### 3.3 새로운 질의는 그대로 계산

`depth >= 1`의 부분면 중심과 추출한 실제 표본은 새 질의점이다. 부모 면의 거리나 내부 여부로 이들의 정확 거리 조회를 대신하지 않는다.

분류 정보는 한 번의 `build_overlap_domain()` 안에서만 사용한다. 다른 대상, 반경, 정규화 좌표, 정렬 변환, 양방향 검사, 다음 작업으로 넘기지 않는다. 공용 좌표 해시나 전역 캐시는 만들지 않는다.

## 4. 메모리와 수명

보관 정보는 최초 후보 면 수 `M`에 대한 불리언 배열이다. 현재 사용할 NumPy 런타임의 `itemsize`를 확인하며, 원소 저장량은 보통 면당 1바이트다. 거리값을 배정도로 전부 보관하는 방식의 면당 8바이트보다 작다.

고양이 메시의 11,303,378개 면이 모두 초기 후보로 남는 경우, 분류 배열의 원소 저장량은 약 **10.8MiB**다. 묶음 배열과 결합 배열이 동시에 존재하면 약 **21.6MiB**까지 겹칠 수 있다. 이는 해당 배열 원소의 계산값이며 객체·리스트·다른 임시 배열이나 전체 프로세스 메모리의 상한은 아니다. [NumPy 메모리 크기 정의](https://numpy.org/doc/stable/reference/generated/numpy.ndarray.nbytes.html), [불리언 저장 형식](https://numpy.org/doc/stable/reference/c-api/dtype.html).

결합 뒤 묶음별 분류 배열의 참조를 즉시 해제하고, 첫 분류를 마치면 결합된 분류 배열도 해제한다. 예외·취소 시 함수 밖으로 유지하지 않는다. 기존 `OverlapDomain` 공개 필드나 저장 형식에 새 캐시 필드를 추가하지 않는다.

검증에서는 분류 배열의 `nbytes`와 실제 Python 프로세스의 최고 작업집합·커밋을 함께 측정한다. 다른 작업의 메모리 여유를 기대하고 묶음 크기를 늘리거나 전체 거리 배열을 추가로 복제하지 않는다.

기본 구현은 Python 후보 준비 함수 안에서 끝낸다. C++ 워커, 코어 패치, 거리 API, 네이티브 프로토콜의 변경을 기본안에 포함하지 않는다. 기존 명령 집계 검사나 테스트가 특정 준비 명령 수를 전제로 한다면, 줄어든 실제 명령 수와 일치하도록 필요한 검사만 조정하고 검증 강도를 낮추지 않는다.

새로 작성하거나 수정한 함수에는 짧은 한국어 주석 또는 문서화 문자열을 작성한다. 임시 진단 로그는 검증 후 제품에서 제거한다.

## 6. 검증 순서

### 1단계: 중복 조회를 재현하는 기준선

고정된 해석적 거리 함수와 조회 기록기를 사용해 초기 후보 `M`개가 첫 분류에서 다시 조회되는 것을 확인한다. 원본 면·후보 면·분할 결과·표본의 배열과 메타데이터를 기준선으로 보관한다.

성능 비교는 원래 후보 준비 함수를 실제로 실행하는 방식으로 한다. 기존 네이티브 명령 파일만 그대로 재생하면 Python에서 제거한 조회가 다시 실행되므로 이번 최적화의 비교 방법으로 쓰지 않는다.

### 2단계: 정확성과 경계 조건

- 모두 내부인 면, 모두 제외되는 면, 내부와 경계가 섞인 면을 검사한다.
- 8,192개 경계를 넘는 면 수와 경계상자에서 일부만 살아남는 입력을 검사한다.
- 중심과 꼭짓점이 멀어도 일부가 겹치는 큰 삼각면을 보존한다.
- 깊이 0, 분할 예산 소진, 250,000개보다 많은 원본 면에서 기존 후보·원본 면 번호·최종 순서를 유지한다.
- 동일 좌표의 서로 다른 원본 면은 자동 병합하지 않는다.
- 초기 거리의 NaN·무한대·음수·잘못된 배열 크기는 계속 거부한다.
- 초기 조회와 첫 분류 사이, 첫 분류·부분면 처리 중 취소를 확인한다. 네이티브 호출을 제거한 구간에서도 기존 취소 확인을 유지한다.
- 점군 경로와 새 부분면·실제 표본의 거리 조회가 줄어들거나 생략되지 않았는지 확인한다.

기존 첫 검사와 재검사의 묶음 구성은 다를 수 있고, CCCoreLib의 자동 격자 단계와 부동소수점 연산 결과도 달라질 수 있다. 따라서 같은 중심점이라는 이유만으로 두 조회의 결과가 항상 비트 단위로 같다고 가정하지 않는다.

임계값 부근의 실제 네이티브 거리도 비교하여 **후보 포함·분할 여부·면 순서·표본 좌표와 원본 번호가 유지되는지** 검사한다. 수치는 기존 허용오차로 확인하고, 표본 지문 차이가 나면 거리값 때문인지 구분한다. 후보 판정이 바뀌면 원인을 해결하기 전에는 배포하지 않는다. 반경이나 허용오차를 늘려 통과시키지 않는다.

### 3단계: 실제 정렬·저장 회귀

겹침 후보 단위 검사, v4 명령 순서·집계, 솔버의 네 입력 조합, 단일·병렬 스레드, 부분 겹침, Blender 정렬·승인·취소·저장 검사를 실행한다.

준비 명령이 줄어도 이후 등록·평가 순서와 표본 수·시드는 유지해야 한다. 실행 통계와 저장 감사 요약은 실제 명령만 집계하며, 과거 승인 기록은 계속 읽는다.

### 4단계: 대용량의 제한된 구간 비교

고양이 계산 입력에서 동일한 원본 면 65,536개를 고정 구간으로 선택하고, 기준 대상은 전체 메시로 유지하여 후보 준비 함수를 비교한다. 선택 구간과 원본 면 대응을 기록하고 기존·변경 코드를 같은 입력·31스레드에서 순차 실행한다. 예열과 측정 3회를 분리한다.

준비 시간, 네이티브 호출 수, 조회점 수, 분류 배열 크기, Python·네이티브 최고 메모리를 기록한다. 이 검증은 제한된 구간의 후보 준비이며 전체 정렬 완료 시간이나 품질 검증으로 표시하지 않는다.

## 7. 효과의 범위와 채택 기준

한 방향에서 최초 후보로 살아남은 원본 면이 `M`개라면, 기존 첫 분류가 조회하던 `M`개 중심점과 약 `ceil(M / 8192)`회의 네이티브 호출을 제거하는 것이 목표다. 두 방향이면 각각 별도로 계산한다. 이 식은 초기 후보 분류에 대한 것이며 전체 정렬 시간이 같은 비율로 줄어든다는 뜻은 아니다.

| 항목 | 채택 기준 |
|---|---|
| 중복 제거 | 첫 분류 재조회가 없어지고, 이후 새 중심·표본 질의는 그대로 수행 |
| 결과 | 원본·후보·분할·표본 순서·품질 판정 유지, 수치 기존 허용오차 충족 |
| 호출 집계 | 예상 제거 수와 실제 감소 수 일치, 네이티브·Python·저장 기록 일관성 |
| 속도 | 같은 대용량 구간의 준비 시간 중앙값 감소. 호출 수만 줄고 느려지면 배포 보류 |
| 메모리 | 원소당 불리언 보관량과 일시 복제를 설명할 수 있고, 해제 후 새 캐시가 남지 않음 |
| 취소·오류 | 기존 취소 응답과 유효하지 않은 입력의 거부 동작 유지 |

특정 개선 배수나 절감 초를 사전에 약속하지 않는다. 격자 생성 단독 시간은 이번 효과 계산에 필요한 전제가 아니다. 줄어든 실제 거리 호출의 전체 비용과 새 분류·메모리 비용을 함께 측정한다.

## 8. 남는 제약과 후속 작업

`CC_MAX_PREPARING_OPERATIONS = 2048`은 그대로 유지한다. 중복을 제거하면 준비 명령은 줄지만, 1,130만 면을 양방향으로 처음 훑는 데만 경계 필터 결과에 따라 이 상한을 넘을 수 있다. 전체 검사 가능 여부를 별도로 확인하고, 상한을 임의로 높이거나 검사를 건너뛰지 않는다.

격자 재사용·옥트리 재생성 축소·묶음 크기 조정은 이번 결과를 본 뒤 별도 계획으로 검토한다. 사용자 선택에 따라 중단했던 수시간 규모의 전체 정렬 검증을 계획 수정 과정에서 재시작하지 않는다.

구현·검증 후 필요한 버전 갱신, 기존 네이티브 런타임을 포함한 ZIP 빌드, 격리·실제 설치 확인, 관련 변경만 커밋·푸시 순서로 마무리한다.

## 9. 0.3.57 구현과 실제 검증 결과

### 구현 범위

`build_overlap_domain()`의 초기 메시 조회에서 후보별 내부 여부만 보관하고 첫 분류에서 재사용했다. 결합 직후 묶음별 불리언 참조를 해제하고, 첫 분류에 사용한 불리언도 면 선택 직후 해제한다. 이후 사분할 중심과 실제 표본은 기존대로 조회한다.

제품 변경은 해당 Python 함수와 두 버전 표기에 한정했다. 0.3.56과 0.3.57 ZIP의 1,173개 항목을 비교했으며 변경 파일은 `__init__.py`, `blender_manifest.toml`, `tools/align/alignment/icp_cccore_overlap.py` 세 개뿐이다. CCCoreLib 실행 파일·DLL·런타임은 바이트 단위로 동일하다.

### 고양이 메시의 제한 구간 비교

- 입력: 기존 고양이 정렬 작업에서 추출한 공통 좌표 계산 입력. 제품과 같은 정규화·계산용 퇴화면 정리를 거친 **앞 65,536개 면**을 사용했다. 이 번호는 정리 후 계산 입력 기준이다.
- 대상: 11,303,378개 면의 전체 기준 메시. 요청·실제 스레드 모두 31개, 거리 묶음 8,192개.
- 방법: 버전별 예열 1회 뒤 측정 3회. 각 실행은 새 Python 프로세스·네이티브 세션이며 기준선과 변경본을 순차 실행했다. 시간은 후보 준비 함수만 포함한다.

| 측정 | 기존 0.3.56 | 변경 0.3.57 |
|---|---:|---:|
| 1회 | 29.391초 | 15.031초 |
| 2회 | 29.828초 | 14.719초 |
| 3회 | 29.281초 | 14.985초 |
| 중앙값 | 29.391초 | 14.985초 |
| 후보 준비 거리 호출 | 16회 | 8회 |
| 후보 준비 조회점 | 131,072개 | 65,536개 |

중앙값은 **49.02% 감소**했다. 모든 실행에서 후보 면·면적·원본 면 번호 배열 지문과 메타데이터가 일치했다. 예열에서 별도로 추출한 정렬 표본 50,000개와 평가 표본 30,000개의 좌표·거리·원본 번호를 포함한 지문 및 메타데이터도 일치했다. 원본 계산 입력과 각 비교 입력 지문도 보존됐다.

이 구간은 모든 초기 후보가 내부 면으로 분류되어 사분할이 필요하지 않았다. 전체 고양이 메시나 경계 면이 많은 입력의 개선율을 뜻하지 않는다. 실행 순서는 기준선→변경본으로 고정했고, 예열로 초기 파일 캐시 영향을 줄였지만 순서 효과를 완전히 제거한 실험은 아니다. 전체 정렬 시간은 측정하지 않았다.

### 메모리·수명

NumPy 1.26.4의 불리언은 원소당 1바이트다. 별도 65,536면 수명 검사에서 결합 분류 배열 `nbytes`는 **65,536바이트(64KiB)**였고, 반환 후 묶음별 배열과 결합 배열의 약한 참조가 모두 해제됐다. 예외·취소 경로의 회귀 검사도 통과했다.

메모리 계측기의 동시 갱신을 제거한 3차 실행에서 읽기 오류 없이 Python·네이티브 프로세스를 관측했다. 아래 값은 입력 로딩을 포함한 각 프로세스의 최고값이며, 추가 불리언만의 메모리나 동시에 발생한 합계 상한이 아니다.

| 프로세스별 최고값 | 기존 | 변경 |
|---|---:|---:|
| Python 작업집합 | 456.18MiB | 453.84MiB |
| Python 커밋 | 1,183.81MiB | 1,181.45MiB |
| 네이티브 작업집합 | 607.64MiB | 605.07MiB |
| 네이티브 커밋 | 608.15MiB | 604.79MiB |

예열 메모리는 실제 표본 생성까지 포함하므로 위 본측정과 섞어 비교하지 않는다. 실험 JSON의 `classification_array_bytes`는 면 수에서 계산한 불리언 저장량이며 전체 최고 메모리 측정값이 아니다.
