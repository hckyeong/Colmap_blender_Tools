# Align 정확 거리 격자 재사용

## 원인과 변경 범위

0.3.57의 중복계산 제거는 동일 면 중심의 두 번째 거리 조회를 없앴다. 남은 8,192점 조회마다 CCCoreLib가 전체 대상 메시의 교차 격자를 다시 만들었다. 실제 연결 Blender의 준비 명령을 계측했을 때 묶음당 격자 생성 중앙값은 1.243초, 거리 검색 자체는 0.009초였다.

0.3.58은 v4 네이티브 워커에서 정확 거리 격자 한 개를 보관한다. Blender 표본화·면·좌표·반경·8,192점 묶음·스레드 수를 바꾸지 않는다. 이번 변경은 준비 단계와 독립 거리 명령의 재사용이며, ICP 등록 내부 반복은 기존 경로를 유지한다.

## 재사용과 수명

- 불변 메시 ID와 해당 `SimpleMesh`, 결합 큐브의 최소·최대 경계, 실제 단계, 셀 크기가 모두 같을 때만 재사용한다.
- 조회점 옥트리·자동 단계 선택·가용 메모리 예산은 매 명령 계산한다. 요청 단계가 달라도 예산 적용 후 실제 단계가 같으면 재사용할 수 있다.
- 평면 메시의 내부 축 보정 전 경계를 캐시 키에 보관한다.
- 조건 변경 시 이전 격자를 파괴한 뒤 새로 만든다. 포인터 배열 용량까지 반환하므로 작은 격자로 바뀌어도 큰 배열이 남지 않는다.
- 대상 변경·등록 시작·COMMAND 메시 해제 시 캐시를 해제한다. 취소·오류·종료 시 메시보다 먼저 파괴한다. 생성 실패나 거리 계산 실패의 격자를 재사용하지 않는다.
- 한 세션에 하나만 보관한다. Windows 포인터 배열 예산 `min(256 MiB, min(가용 물리 메모리, 가용 커밋)/16)`은 유지한다. 이는 전체 프로세스 메모리 상한이 아니다.

기존 공개 거리 함수는 그대로 유지하며, 별도 `computeCloud2MeshDistancesWithCache`를 추가한다. 외부 호출자는 캐시를 사용하는 동안 메시 형상을 변경하지 않아야 한다. 제품 워커는 불변 지오메트리 ID·설명과 순차 명령 계약으로 이를 보장한다.

## 통계와 배포

기존 v4 `mesh_grid_build_count`·`mesh_grid_cache_hits`가 실제 생성과 재사용을 집계한다. `mesh_grid_seconds`는 생성·메모리 추정 시간이며 재사용 시 0이다. 이 시간은 `kernel_seconds`와 중복 합산하지 않는다. 격자 포인터 배열과 셀별 삼각형 목록 용량을 소유 지오메트리의 `estimated_bytes` 및 세션 상주·최고 추정치에 더한다.

`mesh-grid-reuse-v1` 패치는 기존 메모리 패치의 최종 원문을 입력으로 사용한다. 잠금 파일, 빌드 스크립트, Python 실행 전 검사, 원문 ZIP 검증과 설치 검사가 새 패치를 확인한다. `mesh_grid_source_sha256`는 이전 메모리 패치 단계의 해시를 보존하고, `mesh_grid_reuse_source_sha256`가 재사용 패치 후 최종 네 파일을 식별한다. 과거 저장 기록의 읽기 계약은 바꾸지 않는다.

## 실제 대용량 재생 결과

연결된 Blender 프로젝트 `C:/Users/gksru/Desktop/Untitled.blend`의 준비 단계에서 확보한 정규화 입력을 사용했다. 대상은 5,651,583정점·11,303,380삼각면이며, 연속 8개 명령의 조회점은 각각 8,192개다. 원본 프로젝트나 OBJ를 변경하지 않았다.

기존 0.3.57과 변경 워커를 동일 입력·31스레드·v4 단일 세션으로 번갈아 3회씩 순차 실행했다. 비교 중 다른 성능 검사는 실행하지 않았다.

| 항목 | 기존 | 재사용 |
| --- | ---: | ---: |
| 8개 명령 세션 시간 중앙값 | 14.155초 | 5.444초 |
| 첫 명령 시간 중앙값 | 2.068초 | 2.041초 |
| 이후 명령 시간 중앙값 | 1.682초 | 0.418초 |
| 세션당 격자 생성 | 8회 | 1회 |
| 세션당 격자 재사용 | 0회 | 7회 |
| 최고 작업 집합 범위 | 552.9~560.0 MiB | 542.5 MiB |

반복 명령 약 75.1%, 8개 명령 전체 약 61.5% 단축이다. 모든 48개 결과 배열이 원래 Blender가 반환한 거리와 바이트 단위로 일치했다. 새 격자의 상주 추정량은 약 176.0 MiB이며 한 개만 유지됐다. 세션의 최고 작업 집합과 상주 추정량은 서로 다른 지표다.

이 수치는 대용량 준비 단계의 고정 구간 비교이며 전체 Align 완료 시간은 아니다. 첫 호출의 메시 적재·격자 생성, 매 호출 대상 옥트리와 자동 단계 선택은 남는다. 원본 면 수에 따른 기존 준비 명령 상한 2,048회도 변경하지 않았다.

재생 명령·응답·거리·세션 통계 및 보고서는 `build/verification/mesh-grid-reuse/`에 보관한다. `benchmark-results.json`, `benchmark-runtime-manifest.json`은 측정 실행 파일의 식별 정보이며, 기준 런타임은 `baseline-runtime/`에 보관한다.
