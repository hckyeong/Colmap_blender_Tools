# Align 정확 거리 격자 재사용

## 원인과 변경 범위

0.3.57의 중복계산 제거는 동일 면 중심의 두 번째 거리 조회를 없앴다. 남은 8,192점 조회마다 CCCoreLib가 전체 대상 메시의 교차 격자를 다시 만들었다. 실제 연결 Blender의 준비 명령을 계측했을 때 묶음당 격자 생성 중앙값은 1.243초, 거리 검색 자체는 0.009초였다.

0.3.58은 v4 네이티브 워커에서 정확 거리 격자 한 개를 보관한다. Blender 표본화·면·좌표·반경·8,192점 묶음·스레드 수를 바꾸지 않는다. 이번 변경은 준비 단계와 독립 거리 명령의 재사용이며, ICP 등록 내부 반복은 기존 경로를 유지한다.

## 재사용과 수명

- 불변 메시 ID와 해당 `SimpleMesh`, 결합 큐브의 최소·최대 경계, 실제 단계, 셀 크기가 모두 같을 때만 재사용한다.
- 조회점 옥트리·자동 단계 선택·가용 메모리 예산은 매 명령 계산한다. 요청 단계가 달라도 예산 적용 후 실제 단계가 같으면 재사용할 수 있다.
- 평면 메시의 내부 축 보정 전 경계를 캐시 키에 보관한다.
- 조건 변경 시 이전 격자를 파괴한 뒤 새로 만든다. 포인터 배열 용량까지 반환하므로 작은 격자로 바뀌어도 큰 배열이 남지 않는다.
- 대상 변경·등록 시작·COMMAND 메시 해제 시 캐시를 해제한다. 취소·오류·종료 시 메시보다 먼저 파괴한다. 생성 실패나 거리 계산 실패의 격자를 재사용하지 않는다.
- 한 세션에 하나만 보관한다. Windows 포인터 배열 예산 `min(256 MiB, min(가용 물리 메모리, 가용 커밋)/16)`은 유지한다. 이는 전체 프로세스 메모리 상한이 아니다.

기존 공개 거리 함수는 그대로 유지하며, 별도 `computeCloud2MeshDistancesWithCache`를 추가한다. 외부 호출자는 캐시를 사용하는 동안 메시 형상을 변경하지 않아야 한다. 제품 워커는 불변 지오메트리 ID·설명과 순차 명령 계약으로 이를 보장한다.

## 통계와 배포

기존 v4 `mesh_grid_build_count`·`mesh_grid_cache_hits`가 실제 생성과 재사용을 집계한다. `mesh_grid_seconds`는 생성·메모리 추정 시간이며 재사용 시 0이다. 이 시간은 `kernel_seconds`와 중복 합산하지 않는다. 격자 포인터 배열과 셀별 삼각형 목록 용량을 소유 지오메트리의 `estimated_bytes` 및 세션 상주·최고 추정치에 더한다.

`mesh-grid-reuse-v1` 패치는 기존 메모리 패치의 최종 원문을 입력으로 사용한다. 잠금 파일, 빌드 스크립트, Python 실행 전 검사, 원문 ZIP 검증과 설치 검사가 새 패치를 확인한다. `mesh_grid_source_sha256`는 이전 메모리 패치 단계의 해시를 보존하고, `mesh_grid_reuse_source_sha256`가 재사용 패치 후 최종 네 파일을 식별한다. 과거 저장 기록의 읽기 계약은 바꾸지 않는다.

## 실제 대용량 재생 결과

연결된 Blender 프로젝트 `C:/Users/gksru/Desktop/Untitled.blend`의 준비 단계에서 확보한 정규화 입력을 사용했다. 대상은 5,651,583정점·11,303,380삼각면이며, 연속 8개 명령의 조회점은 각각 8,192개다. 원본 프로젝트나 OBJ를 변경하지 않았다.

기존 0.3.57과 변경 워커를 동일 입력·31스레드·v4 단일 세션으로 번갈아 3회씩 순차 실행했다. 비교 중 다른 성능 검사는 실행하지 않았다.

| 항목 | 기존 | 재사용 |
| --- | ---: | ---: |
| 8개 명령 세션 시간 중앙값 | 14.155초 | 5.444초 |
| 첫 명령 시간 중앙값 | 2.068초 | 2.041초 |
| 이후 명령 시간 중앙값 | 1.682초 | 0.418초 |
| 세션당 격자 생성 | 8회 | 1회 |
| 세션당 격자 재사용 | 0회 | 7회 |
| 최고 작업 집합 범위 | 552.9~560.0 MiB | 542.5 MiB |

반복 명령 약 75.1%, 8개 명령 전체 약 61.5% 단축이다. 모든 48개 결과 배열이 원래 Blender가 반환한 거리와 바이트 단위로 일치했다. 새 격자의 상주 추정량은 약 176.0 MiB이며 한 개만 유지됐다. 세션의 최고 작업 집합과 상주 추정량은 서로 다른 지표다.

이 수치는 대용량 준비 단계의 고정 구간 비교이며 전체 Align 완료 시간은 아니다. 첫 호출의 메시 적재·격자 생성, 매 호출 대상 옥트리와 자동 단계 선택은 남는다. 원본 면 수에 따른 기존 준비 명령 상한 2,048회도 변경하지 않았다.

재생 명령·응답·거리·세션 통계 및 보고서는 `build/verification/mesh-grid-reuse/`에 보관한다. `benchmark-results.json`, `benchmark-runtime-manifest.json`은 측정 실행 파일의 식별 정보이며, 기준 런타임은 `baseline-runtime/`에 보관한다.

## 0.3.59: 전체 준비 실행의 반복 비용 제거

0.3.58을 `C:/Users/gksru/Desktop/Untitled.blend`의 실제 Align 연산자로 실행했을 때, 1,762회 조회까지 약 22분 12초가 걸렸고 아직 준비 단계였다. 이 실행은 사용자 지시에 따라 취소했다. 완료 시간이나 실패 시간으로 해석하지 않는다. 검색 단계 선택용 옥트리 생성에 516.685초, 격자 생성에 443.908초, 거리 계산 구간에 38.601초가 누적됐다. 격자는 399회 생성되고 1,363회 재사용됐다.

원인은 동일 대상의 전체 옥트리와 조회점 옥트리로 자동 단계를 매 호출 다시 선택하는 구조였다. 선택 결과가 바뀌면 격자도 다시 만들었다. 이번 변경은 CCCoreLib 코어의 공개 거리 API를 바꾸지 않고 C++ 워커의 세션 준비 수명을 수정한다.

- 동일 대상의 첫 거리 명령에서만 자동 단계를 선택한다. 선택에 사용한 두 옥트리는 바로 해제하고 실제 격자 단계 값 하나만 보관한다.
- 후속 조회는 해당 단계를 사용한다. 정확 거리 계산용 조회점 옥트리와 거리 계산은 계속 새로 수행한다.
- 매 호출의 가용 메모리 검사와 격자 예산은 유지한다. 예산으로 단계가 낮아지면 해당 대상의 연속 명령에서 낮아진 단계를 유지한다.
- 대상 변경·등록 시작·COMMAND 대상 해제 시 단계도 초기화한다. 경계·셀 크기가 달라지면 기존처럼 격자를 재생성한다.
- 전체 옥트리를 상주시켜 메모리를 늘리지 않는다. 실제로 저장하지 않은 옥트리의 재사용을 `octree_cache_hits`로 기록하지 않는다.

준비 조회 한도도 원본 면 수에 맞춘다. 각 방향의 원본 개수를 8,192로 나눈 올림 횟수에 추가 탐색 예산 2,048회를 더한다. 이 프로젝트의 양방향 원본 순회는 2,760회이므로 준비 예산은 4,808회다. 기존 고정 한도 2,048회가 정상 원본 순회를 막던 문제를 제거한다. 네 자리 네이티브 순번 9,999 안에 후속 등록·평가 최대 10회와 종료 명령 1회를 남겨, 준비 예산의 절대 상한은 9,988회다. 입력 크기만으로 이를 넘으면 거리 조회 전에 명시적으로 거부한다.

조회 묶음 8,192개, 원본 면 전체 검사, 표본 수·시드·반경·분할·정확 거리·품질 판정은 유지한다. 원본 `.blend`와 OBJ는 저장하거나 수정하지 않는다. 향후 성능 보고는 이 프로젝트의 실제 Align을 기준으로 하며, 앞부분 재생 수치를 전체 완료 시간으로 대신하지 않는다.

### 0.3.59 실제 프로젝트 검증

일반 Blender 5.2의 별도 숨김 프로세스에서 같은 `.blend`를 열고 기존 A/P 레이어를 선택한 뒤 실제 Align 연산자를 실행했다. 입력·형상·설정 지문은 기존 실행과 모두 일치했다. 설치된 0.3.59의 전체 Align은 **345.041초(5분 45초)**에 결과 미리보기까지 완료됐다. 워커 계산은 332.516초, 준비 단계는 317.812초였다. 원본 `.blend`는 실행 전후 SHA-256이 같았다.

최종 품질은 `REVIEW`이며 사유는 기존 위치보다 독립 평가 RMS가 충분히 감소하지 않았기 때문이다. 기존 위치가 최종 후보로 유지됐고 추가 회전·이동·배율 변화는 없다. 계산 오류나 준비 조회 상한 오류는 발생하지 않았다. 이를 정렬 품질 `PASS`로 보고하지 않는다.

동일한 앞 1,762회 거리 명령을 비교하면 다음과 같다. 아래 시간은 전체 Align 시간이 아닌 해당 명령의 네이티브 누적 시간이다.

| 항목 | 0.3.58 | 0.3.59 |
| --- | ---: | ---: |
| 네이티브 명령 누적 | 1,214.487초 | 80.570초 |
| 선택용 옥트리 생성 | 516.685초 | 0.622초 |
| 메시 격자 생성 | 443.908초 | 2.609초 |
| 격자 생성 횟수 | 399회 | 2회 |

전체 실행에서는 거리 조회 2,779회와 실제 등록 2회를 처리했다. 등록 시작과 대상 전환에 따른 정상 초기화를 포함해 격자 생성 6회, 재사용 2,773회였다. 남은 비용에는 원본 면 전체 검사·정확 거리 계산·파일 프로토콜이 포함된다. 워커가 측정한 파일 프로토콜 오버헤드는 121.957초이며, 전체 실행이 즉시 끝난다고 주장하지 않는다.

네이티브 44개, 실제 네이티브 통합을 포함한 솔버 52개, 겹침 후보 15개, v4 계약 7개와 부분 겹침 100%·70%·40%·20% 검사를 통과했다. 확장 빌드의 필수 검사와 스테이징 실제 정렬 검사도 통과했다. 사용자 설치본의 활성 상태·1,174개 파일 해시·환경설정 보존을 별도 Blender에서 확인했다.
