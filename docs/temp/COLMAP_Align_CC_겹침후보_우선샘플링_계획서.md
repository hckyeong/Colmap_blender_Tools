## 1. 결정 요약

처리 순서를 다음과 같이 변경한다.

```text
3점 초기 정렬 또는 현재 위치 고정
    → 여유를 둔 겹침 후보 영역 선별
    → 후보 영역에서 정렬용 50,000점 확보
    → CC 이동·회전 정렬과 먼 대응점 제거
    → 같은 표본으로 ±10% 배율 정밀 보정
    → 고정된 독립 겹침 평가 표본으로 후보 비교
    → 기존 미리보기·승인 흐름
```

- 전체에서 50,000점을 먼저 뽑고 탈락한 뒤 적은 표본으로 정렬하는 방식을 변경한다.
- 면적에 비례하는 표면 샘플링 자체는 유지하되, 추출 범위를 전체 메시에서 겹침 후보 영역으로 바꾼다.
- 후보 선별을 위한 거리 조회와 최종 정렬용 샘플링을 구분한다. 선별에도 거리 계산은 필요하다.
- 50,000점은 ICP에 넣기 전의 메시 표본 목표다. ICP 내부에서 추가로 제외된 뒤에도 항상 50,000개의 대응점을 유지한다는 뜻은 아니다.
- 원본 메시, 내장 토폴로지, COLMAP 점·카메라와 출력 파일은 자르거나 변경하지 않는다. 정렬용 임시 후보와 표본만 생성한다.
- 겹침 후보는 초기 위치에서 추정한 영역이다. 실제 동일 부위를 자동으로 완벽하게 식별한다고 설명하지 않는다.

## 2. 현재 구현과 문제 범위

| 점군 등록 입력 | 원본 전체 | 후보 점 선별 후 최대 50,000개, 부족하면 고유 점 전체 |

| CC 겹침 비율 | `cc_overlap_ratio=0.9` 고정 | 선별된 입력 내부의 유효 대응 비율로 산정 |

| 평가 표본 | 전체 형상에서 독립 표본 최대 30,000개 | 고정 겹침 평가 영역에서 독립 표본 최대 30,000개 |

## 3. 유지할 계약

- 레이어 아이콘에 따른 입력 선택, 숨김 A도 포함하는 기준 그룹 정책을 유지한다.
- A끼리·P끼리의 마커 형상 종류 고정과 3점 정렬 솔버를 유지한다.
- 마커 미리보기에서 시작할 때 그 초기 변환을 한 번만 적용한다. 현재 위치 직접 정렬도 지원한다.
- 결과는 P 소유 모델의 공통 행렬 하나에 적용하며, 연결 COLMAP과 OBJ는 각각 자기 축 변환을 유지한다.
- 강체 정렬 후 시작값 대비 최대 ±10% 배율 보정, 미리보기·승인·버리기·Undo를 유지한다.
- 작업당 네이티브 세션 프로세스 하나, 기본 형상 1회 적재와 조건이 일치하는 캐시 재사용을 유지한다.
- 원본 파일 재읽기, Blender Scene 공유, GPU 엔진, 수동 영역 편집 UI는 이번 범위에 넣지 않는다.
- 계획 작성 단계에서는 제품 코드·설치본·버전·사용자 파일을 변경하지 않는다. 구현과 설치는 후속 요청에서 진행한다.

## 4. 후보 영역 선별

### 4.1 시작 좌표와 거리 정의

현재 축과 초기 정렬이 반영된 프로젝트 좌표를 기준으로 A/P를 고정한다. 기존 공통 정규화를 적용한 뒤 선별·등록·평가에서 동일한 길이 단위를 사용한다.

표면 대상은 정점까지의 거리가 아니라 실제 삼각면까지의 unsigned 최근접 거리를 사용한다. 점군 대상은 실제 점까지의 최근접 거리를 사용하며, 점 간격을 거리 기준에 반영한다. 현재 설치된 CC 거리 연산을 활용하고 법선 방향은 선별의 필수 조건으로 사용하지 않는다.

두 거리 기준을 둔다.

- `τ_valid`: 초기 상태에서 가까운 대응을 판정하는 기준. 독립 평가 영역과 후보 내부 대응 비율 산정에 사용한다.
- `τ_candidate`: 초기 오차와 경계 부분을 허용하는 더 넓은 선별 기준. 정렬용 표본의 추출 범위를 정한다.

검증 출발값은 아래와 같이 명시하되, 제품 확정값으로 간주하지 않는다.

```text
D = 양쪽 유효 형상 경계상자 대각선 중 작은 값
h = 대상이 점군일 때 추정한 대표 점 간격, 표면이면 0
e = 유효한 마커 초기 정렬의 잔차 RMS, 마커를 사용하지 않으면 0
τ_valid = max(0.01 × D, 3 × h, 2 × e)
τ_candidate = 2 × τ_valid
```

`τ_valid > 0.05 × D`이거나 D가 퇴화하면 자동으로 반경을 더 키우지 않고 초기 정렬·점 간격 검토 대상으로 중단한다. 잔차가 큰 잘못된 마커 때문에 전체 형상을 겹침으로 받아들이지 않도록 한다. 마커 잔차는 선별 여유의 근거이며 독립 정확도 정답이 아니다.

이 계수는 합성·실데이터 검증 후 하나의 버전 있는 정책으로 고정한다. 후보 RMS를 낮추기 위해 실행 중 여러 반경을 시도하고 유리한 값만 선택하지 않는다. 가까운 평행면·대칭면은 거리만으로 구분할 수 없으므로 공간 분포 검사와 최종 시각 비교가 필요하다.

### 4.2 표면 후보

1. 대상 형상의 경계상자를 `τ_candidate`만큼 확장해 확실히 먼 삼각면을 먼저 제외한다. 경계상자 교차 자체를 실제 겹침 판정으로 사용하지 않는다.
2. 남은 면은 실제 표면 거리로 후보를 판정한다. 중심점이나 정점이 멀다는 이유만으로 면 전체를 버리지 않는다. 큰 면의 일부만 겹치는 경우도 포함한다.
3. 면 중심 c, 중심에서 가장 먼 꼭짓점까지의 거리 r, 대상까지의 거리 d(c)를 이용한다. 거리 함수의 변화량이 이동 거리 이하인 성질을 이용해 `d(c) - r > τ_candidate`인 경우에만 전체 면을 확실한 제외 대상으로 분류한다. `d(c) + r <= τ_candidate`이면 전체가 후보 안에 있다.
4. 경계에 걸친 면은 정렬용 임시 부분 삼각형으로 분할해 범위를 좁힌다. 원본 정점·면·UV 배열은 바꾸지 않는다. 분할 상한에 도달한 불확실한 부분은 보수적으로 후보에 남기고 실제 추출점 거리로 최종 판정한다.
5. 각 부분면에 원본 모델 ID, 면 인덱스와 면적을 유지한다. 부분면은 원본 면적을 중복 계산하지 않도록 겹치지 않게 구성한다.

기준 대상의 전체 삼각면은 거리 조회와 CC 등록에 유지한다. 후보 선별 때문에 기준 표면에 구멍을 만들거나 새로운 인공 경계를 만들지 않는다.

### 4.3 점군 후보

점군에는 후보 공간 안의 원본 고유 점만 남긴다. 대상이 표면이면 점→삼각면 거리, 점군이면 점→점 거리로 선별한다.

후보가 50,000개보다 많으면 공간 구간을 고려해 원본 밀도 편중을 완화하며 50,000개를 선택한다. 그보다 적으면 고유 점 전체를 사용한다. 점을 복제하거나 임의 보간해 50,000개를 채우지 않는다. 기존 전체 점군 정책에서 바뀌는 부분이므로 별도 회귀 검증 대상으로 둔다.

### 4.4 네 입력 조합

| 사용자 P → A | 실제 등록 데이터 | 후보 선별과 표본 |
|---|---|---|
| 표면 → 표면 | P 표면 표본 → A 원본 삼각면 | P의 A 근접 후보에서 50,000점 |
| 점군 → 표면 | P 점군 → A 원본 삼각면 | P 후보 고유 점 최대 50,000개 |
| 점군 → 점군 | P 점군 → A 원본 점군 | P 후보 고유 점 최대 50,000개 |
| 표면 → 점군 | A 점군 → P 원본 삼각면으로 역방향 계산 | A 후보 고유 점 최대 50,000개, 결과를 역변환해 P에 적용 |

표면→표면 평가에서는 양쪽에 별도로 후보를 만든다. 역방향 조합의 비율은 실제 등록 데이터인 A 점군 기준임을 기록한다. A 여러 레이어의 기여량은 기록하되 멀리 떨어진 A 레이어에도 억지로 샘플 할당량을 주지 않는다.

## 5. 후보 안에서 최종 표본 확보

- 후보 면적에 비례해 부분면을 선택하고, 선택한 부분면 안에서는 균일하게 점을 추출한다.
- 불확실한 경계 부분의 추출점은 실제 거리를 검사한다. 탈락분은 같은 후보 영역에서 추가로 추출해 합격한 정렬용 표본을 50,000개까지 확보한다.
- 넓은 경계상자나 전체 메시로 돌아가 먼 점을 섞어 목표 수를 채우지 않는다.
- 같은 면에서 여러 점이 나오는 것은 허용하지만, 같은 좌표를 복사해 표본 수를 늘리지 않는다.
- 후보 선별, 정렬용 추출, 평가용 추출은 서로 다른 고정 시드를 사용한다. 강체와 배율 보정 단계는 같은 정렬용 원본 표본에 단계 변환만 적용한다.
- 원본 면적 대비 후보 면적, 후보의 공간적 범위와 분포를 함께 검사한다. 아주 작은 접촉면에 50,000점을 찍었다고 정렬이 충분히 구속된 것으로 판정하지 않는다.

거리 질의는 묶음 단위로 실행하고 취소를 확인한다. 초기 검증에서는 묶음 크기 8,192점, 가상 분할 깊이 최대 8, 표본 제안 누적 최대 목표의 20배를 상한으로 둔다. 전체 부분면 개수·임시 메모리에도 명시적 상한을 둬야 하며 구현 시 입력 크기별 계측으로 고정한다.

상한 때문에 충분한 표본을 확보하지 못하면 사유와 실제 개수를 반환하고 정렬을 시작하지 않는다. 희소 점군은 50,000개 미달 자체로 실패시키지 않고 고유 점 수와 분포로 판단한다. 임의의 소수 대응만으로 계속 진행하거나 반경을 무제한 확대하는 경로는 두지 않는다.

## 6. CC 내부 대응점 처리

사전 후보 선별과 ICP 반복 중 대응점 제거는 별개로 유지한다.

1. 강체·배율 단계 시작마다 동일한 입력 표본의 현재 거리를 계산한다.
2. `τ_valid` 안의 표본 비율로 후보 내부의 유효 대응 비율을 추정한다. 이것은 전체 원본이 얼마나 겹치는지 나타내는 비율이 아니다.
3. 이 비율을 `finalOverlapRatio`로 전달해 전체 원본에 대한 고정 90% 가정을 제거한다. 비율의 불확실성과 추정 분포도 기록하며 RMS가 가장 작아지는 비율을 탐색하지 않는다.
4. 현재 계약의 최소 허용 비율 0.1 미만이거나 수·분포 조건을 충족하지 못하면 정렬 시작 또는 해당 후보 승인을 차단한다. 비율을 임의로 상향해 사용 가능한 것처럼 만들지 않는다.
5. `filterOutFarthestPoints`를 명시적 매개변수로 연결하고 활성화한 조합을 검증한다. 코어의 잔차 분포에 따른 제거이며, `τ_candidate`라는 절대 거리 제한을 매 반복 그대로 적용하는 API라고 설명하지 않는다.
6. `finalPointCount`와 최종 실제 사용 비율을 기록하고 표본 고갈·퇴화 여부를 확인한다. 단순히 코어 호출이 성공했다는 이유로 후보를 채택하지 않는다.

CCCoreLib의 현재 공개 등록 API를 사용한다. 절대 거리 문턱을 코어 반복 안에 새로 추가하는 패치는 이번 기본안에 포함하지 않는다. 공개 기능으로 목표 품질을 만족하지 못한다면 그 원인을 검증 기록에 남기고 별도 범위를 결정한다.

## 7. 독립 평가와 후보 선택

### 7.1 고정된 평가 대상

초기 위치에서 `τ_valid`를 만족하는 평가 후보 영역을 한 번 정한다. 정렬용과 다른 시드로 방향별 최대 30,000개의 평가 표본을 확보하고, baseline·rigid·scale_refine에 같은 원본 표본과 같은 분모를 사용한다.

후보가 바뀔 때 평가 대상이나 문턱을 다시 골라 나쁜 잔차를 없애지 않는다. 최초 평가 집합에 들어온 점은 나중에 멀어져도 RMS와 대응 손실에 남긴다. 정확한 실제 겹침 정답이 아니라 **고정 겹침 후보에 대한 평가**라는 의미를 유지한다.

표면→표면은 두 방향을 따로 평가하고 그 RMS의 평균을 주 점수로 사용한다. 점군·표면 혼합은 기존 실제 등록 방향의 거리 종류와 역변환·배율 환산을 유지한다. 형상 모드마다 평가 방향을 메타데이터에 기록한다.

### 7.2 수치가 작아지는 것만으로 선택하지 않기

- 고정 겹침 평가 RMS를 기본 후보 선택 기준으로 사용한다.
- 같은 평가 집합에서 유효 대응 수·비율, 공간 구간별 대응 유지와 잔차 악화를 검사한다.
- 대응점이 한 부분에 몰리거나 이전에 겹치던 영역을 크게 잃은 후보를 배제한다. 개선이 미미한 경우 baseline 또는 더 나은 강체 후보를 유지한다.
- 추가 배율이 ±10% 경계에 닿거나 공간 구간 일부가 악화되면 기존 REVIEW 사유를 유지한다.
- 평가용 원본 표본 수와 유효 대응 수를 구분한다. 후보 영역 내 비율과 전체 원본 대비 추정 비율도 서로 다른 항목으로 기록한다.
- 원본 전체의 별도 고정 표본에서 전체 거리 RMS·중앙값·꼬리 분포를 참고 진단으로 보존한다. 겹치지 않는 원본 부분 때문에 이 수치가 큰 것만으로 최종 후보를 고르거나 실패시키지 않는다.
- 가까운 90% RMS는 참고 통계로 남길 수 있지만, 표본이 달라지는 지표를 새 주 점수와 혼용하지 않는다.

전체 참고 진단과 겹침 평가 표본은 한 거리 요청에 묶어 계산한 뒤 범위를 구분해 통계를 만들 수 있다. 요청 묶음 자체가 계산 범위나 캐시 키를 바꾸면 이를 명시적으로 반영한다.

## 8. 진행 표시와 오류 안내

기존 패널과 버튼을 유지하고 상태 로그에서 아래 정보를 구분한다. 새 고급 설정 UI는 추가하지 않는다.

```text
겹침 후보 찾는 중
후보 영역에서 정렬 표본 준비 · 50,000 / 50,000
CC 정렬 중
겹침 평가 RMS · 정렬 전 → 정렬 후
유효 대응 · 사용 개수 / 평가 개수
```

전체 RMS는 보조 진단으로 표시하고 개선율은 겹침 평가 RMS와 동일한 기준으로 계산한다. 후보 선별의 추가 시간이 기존 진행률에 포함되어야 한다.

차단 사유는 `초기 위치가 멉니다. 3점 정렬을 먼저 확인하십시오.`, `겹침 후보가 작은 영역에 집중되어 있습니다.`, `후보 영역에서 필요한 표본을 확보하지 못했습니다.`처럼 구체적으로 표시한다. 취소·실패 시 기존 시작 행렬과 마커 상태로 돌아가며 승인할 부분 결과를 남기지 않는다.

| `tools/align/ui/panels.py` | 겹침 RMS·개선율·실제 표본 수와 부족 사유 |

| CC 빌드·배포 검증과 관련 문서 | 새 실행 파일·정책·버전 일치와 재현 기록 |

알고리즘과 작업 프로토콜은 새 계산 의미를 구분하도록 v4로 올린다. 네이티브 프로토콜도 새 매개변수와 명령 단계 계약에 맞춰 v4로 갱신한다. CCCoreLib 자체의 고정 커밋·기존 패치는 유지한다. 통합 검증에서 확인한 메시 먼 점 필터의 대응 면 번호 누락은 별도 `farthest-mesh-correspondence-v1` 패치로 수정하고, 패치·적용 원문·결과 해시를 잠근 뒤 재빌드한다.

현재 `CC_NATIVE_OPERATION_SEQUENCES`는 모드별 5~8개의 연산 순서를 고정 검증한다. 선별 거리 조회가 추가되므로 이 계약과 테스트를 함께 변경한다. 명령 검증을 끄거나 새 조회를 기존 평가 결과로 위장하지 않는다. 준비 조회는 PREPARING에서 제한된 횟수로 허용하고 강체·배율·평가 순서와 명령 ID는 계속 검증한다.

후보 영역·표본·반경·정책 버전·원본 면 ID·초기 행렬·시드는 입력 지문과 평가 캐시 키에 포함한다. v3 결과나 다른 후보 집합의 평가 캐시를 새 계산에 재사용하지 않는다. 기본 형상은 세션 내에서 계속 공유하고, 선별 질의점과 부분면 버퍼는 사용이 끝나면 해제한다.

이전 `.blend`의 확정 행렬·축·마커·OBJ 원본은 그대로 읽는다. 새 진단은 우선 실행 결과 메타데이터에 추가하고, 저장 스키마는 실제 저장 필드가 달라질 때만 변경한다. 새 정책으로 이전 저장 결과를 자동 재계산하지 않는다. 제품 버전은 실제 구현 시 다음 가용 버전으로 올린다.

## 10. 구현 순서와 검증 기준

| 단계 | 작업 | 완료 기준 |
|---|---|---|
| 1 | v3 기준선과 입력 고정 | 같은 파일·축·초기 행렬·마커·스레드 설정으로 재현 가능 |
| 2 | 후보 선별·정렬 표본 구현 | 큰 경계 면을 잘못 제거하지 않고, 후보 안에서 50,000점 확보 |
| 3 | 네 입력 조합과 CC 설정 연결 | 정·역방향 행렬, 실제 대응 수, 세션·취소 계약 통과 |
| 4 | 고정 독립 평가·후보 선택 연결 | 평가 집합 축소로 수치만 좋아지는 후보를 차단 |
| 5 | 기존 UI와 출처·배포 연결 | 지표 의미 일치, 저장·재연결·승인·내보내기 회귀 통과 |
| 6 | 합성·실데이터·성능 비교 | 정확도·분포·시간·메모리를 함께 확인하고 계수 확정 |

중요한 검증 사례:

- 알려진 변환을 가진 비대칭 형상의 100%, 70%, 40%, 20% 부분 겹침. 수치만이 아니라 회전·이동·배율의 정답 오차를 비교한다.
- 원본 전체 RMS는 작지만 실제 겹침 위치는 나쁜 후보와, 전체 RMS는 크지만 실제 겹침이 맞는 후보를 구분한다.
- 큰 삼각형 일부만 교차하는 경우, 얇은 부분, 멀리 떨어진 작은 조각, 서로 가까운 평행면, 대칭 형상, 매우 다른 점 밀도.
- 점 후보 50,000개 미만에서 중복·보간 없이 처리되는지와, 작은 영역에 50,000점을 모아 잘못 통과시키지 않는지.
- 평가 대상 일부를 멀리 보내거나 한 구간만 맞춘 후보가 분포·대응 유지 조건에서 차단되는지.
- 초기 마커가 잘못됐거나 위치가 먼 경우, 후보 없음·퇴화·분할 상한·취소·파일 변경을 정상 처리하는지.
- 같은 입력·시드로 후보 ID·표본·선택 결과가 재현되는지. 스레드 수 차이는 허용 수치 오차 내에서 검사한다.

사용자 `Untitled.blend`는 구현 검증 시작 시 별도 검사 경로로 복사하고 파일 지문을 기록한다. 사용자 원본은 저장하지 않는다. 저장된 마커 3쌍으로 동일한 초기 변환을 먼저 만든 뒤 v3와 v4를 비교한다. 파일에 최종 미리보기 행렬이 저장되어 있다고 가정하지 않는다.

실데이터는 양쪽 표면의 공통 부위 확대 화면과 독립적으로 지정한 검사점 또는 검토한 공통 부위의 거리로 확인한다. 초기 정렬에 쓴 마커만 정확도 정답으로 사용하지 않는다. 실데이터의 정확한 정답이 없으면 개선율을 확정하지 않고 시각·국소 거리 결과와 한계를 함께 기록한다.

전체 시간뿐 아니라 후보 선별, 50,000점 확보, 강체, 배율, 독립 평가 시간을 분리한다. 전체·높은 겹침 자료와 낮은 겹침 자료를 각각 3회 측정하고 표본 탈락률·네이티브 요청 수·메시 적재 횟수·최고 메모리를 함께 비교한다. 후보 선별 자체가 추가 비용이므로 속도 향상을 미리 보장하지 않는다.

성공 기준은 **정렬에 쓸 표본이 공통 부위에 충분히 분포하고, 알려진 정답 및 검토한 공통 부위의 오차가 개선되며, 기존 높은 겹침 자료와 승인·저장 계약이 악화되지 않는 것**이다. 표시 RMS 감소만으로 구현 완료를 판정하지 않는다.

### 통합 검증에서 확인한 사항

- 준비 조회의 전체 진단을 승인 기록에 복제하면 기존 256 KiB 한도를 초과하므로, 실행 원문 검증은 유지하되 승인 저장 때만 PREPARING 명령·COMMAND 형상을 개수·원문 SHA-256으로 요약한다. 등록·평가 기록, SESSION 형상, 세션 합계, 품질·표본 진단은 보존하며 `execution_audit_storage`에 요약 계약을 명시한다. 최대 2,048회 준비 조회와 이전 저장 기록의 복원을 검사한다.
- 후보 임시 분할 예산 250,000개는 추가 조각에만 적용한다. 원본 면 수를 제한하지 않는다.
- 점군은 중복 좌표를 제거하고 최초 원본 인덱스를 유지한다. 50,000개 미만이면 고유 후보 수 그대로 전달한다.
- 등록 직전 거리 조회와 실제 등록은 같은 불변 표본을 공유하므로, 등록 표본 두 개의 수명을 세션까지 유지한다. 명령 종료 시 해제하는 일회성 질의와 구분한다.
- 초기 구현을 실제 메시로 검사하던 중 `0xC0000005` 접근 위반이 발생했다. 고정 코어의 `filterOutFarthestPoints` 분기가 메시 최근접점 좌표만 복사하고 삼각면 번호 필드를 누락했으며, 이어지는 부분 겹침 필터가 해당 필드를 읽는 경로였다. 전체 검증을 중단한 뒤 원인을 수정했다. 먼 점 필터를 꺼서 우회하지 않는다.
- 네이티브 워커는 백그라운드 프로세스이므로 운영체제 충돌 대화상자를 열지 않는다. 오류 종료 코드와 기존 실패 상태는 그대로 전달한다.
- 표본 영역이 줄어들면서 기존 100회 상한에서 수렴이 끝나지 않는 사례가 있었다. 점→메시는 200회로 기존 위치 오차 기준을 회복했지만 완만한 부분 곡면은 더 긴 배율 수렴이 필요했다. 강체 200회·배율 1,000회를 각각 기본 상한으로 분리했다. 이미 코어 종료 조건을 만족하면 상한 전에 끝나며, 등록 단계 수는 두 번 그대로다. 명시적 반복 상한은 작업 계약과 단계 진단에 기록한다.

## 11. 공식 자료와 적용 범위

- [CCCoreLib 등록 API](https://github.com/CloudCompare/CCCoreLib/blob/master/include/RegistrationTools.h): 겹침 비율·먼 점 제거·샘플 상한과 메시가 기준 역할을 맡는 등록 API를 제공한다.
- [CCCoreLib 등록 구현](https://github.com/CloudCompare/CCCoreLib/blob/master/src/RegistrationTools.cpp): 비율 기반 대응 선별과 잔차 분포 기반 먼 점 제거가 별개로 수행된다.
- [CloudCompare 앱 등록 전처리](https://github.com/CloudCompare/CloudCompare/blob/master/qCC/ccRegistrationTools.cpp): 사용자 겹침 비율에 여유를 더해 입력을 미리 줄이는 구현을 참고했다. 앱 코드는 이동 메시를 먼저 샘플링하므로 이번의 ‘후보 영역 선별 후 최종 50,000점 확보’와 동일한 절차는 아니다.

외부 master 자료는 기능 확인 근거다. 배포 시에는 저장소가 고정한 코어 커밋과 기존 패치를 대상으로 매개변수의 실제 동작을 다시 확인한다. CloudCompare 앱 코드를 복사하지 않고 현재 네이티브 워커와 CCCoreLib 공개 API 안에서 구현한다.
