# Modifier 미터 눈금의 후발 표시 레이어 격리

- 작성·검증일: 2026-10-06
- 상태: 수정·회귀 검사·ZIP 갱신·관련 설치 파일 교체·현재 Blender 반영 완료
- 제품: 0.3.73 작업 사본
- 관련 계약: [표시 크기·미터 눈금](COLMAP_Modifier_표시크기_고정_미터눈금_계획서.md), [도구 경계](README.md)

## 원인과 수정 범위

Modifier 미터 눈금은 별도 소유권을 갖는 글자 20개와 선 1개다. 기존 가시성 동기화는 당시 존재하는 레이어에서 눈금 컬렉션을 Modifier 전용 레이어에만 허용한다. 이후 Painting 레이어를 만들면 제외 상태가 기본값으로 시작하고, Painting은 자신의 데이터 컬렉션만 동기화하므로 Modifier 눈금의 제외 상태가 누락됐다.

실제 연결된 프로젝트에서 일반 레이어는 제외, Modifier는 표시, Painting은 표시 상태였으며 별도 Blender에서도 같은 순서로 21개 눈금 노출을 재현했다.

수정 방침은 Modifier가 자신의 눈금 표시를 계속 책임지도록 유지하는 것이다. Painting에서 Modifier 모듈을 직접 호출하거나 전역 오브젝트 숨김으로 우회하지 않는다.

| 수정 대상 | 변경 |
|---|---|
| `modifier_data_visibility.py` | 기존 눈금 컬렉션의 제외 상태만 적용하는 함수를 분리한다. 눈금·데이터·레이어를 새로 만들지 않으며 승인된 Modifier 전용 레이어에서만 표시한다. |
| `meter_grid_guide.py` | Window의 표시 레이어·작업공간·Scene 변경 알림을 구독하고 분리된 가시성 함수를 호출한다. 파일 로드 후 구독을 복구하고 해제·등록 실패 시 구독과 콜백을 정리한다. |
| `lifecycle.py` | 기존 복원 함수와 가벼운 표시 동기화 함수를 각각 전달한다. 기존 단일 인자 등록 호출도 지원한다. |

새 레이어가 실제 Window에서 활성화되거나 작업공간·Scene이 전환될 때 표시를 재적용한다. 비활성 새 레이어의 생성 즉시 제외 상태를 바꾸는 전역 생성 훅을 추가한 것은 아니다. 표시 전환 알림을 실제 Blender 화면에서 검증했다. 매 프레임 점군·카메라를 검색하거나 눈금 형상을 다시 만들지 않는다.

알림은 Blender의 RNA 메시지 구독을 사용하며 오퍼레이터 완료 후 처리된다. [공식 메시지 버스 문서](https://docs.blender.org/api/main/bpy.msgbus.html)의 지연 알림·로드 시 구독 해제 계약을 확인하고 실제 Blender 5.2.0 LTS로 검증했다.

## 검증

| 검사 | 결과 |
|---|---|
| 기존 미터 눈금 회귀 | 생성·재사용·단위·선택·독립 Scene·누락 복구·저장 재열기·등록 해제 통과 |
| 추가 후발 레이어 검사 | Painting·일반 레이어에서 눈금 제외, 동일 이름 사용자 컬렉션 보존, 기존 눈금 오브젝트 포인터 유지 |
| 실제 화면 알림 | 후발 Painting·일반 레이어 자동 격리, Modifier 복귀 시 21개 유지, 반복 Painting 전환, 작업공간 전환으로 제외 상태 복구 등 5개 시나리오 통과 |
| 화면 오류 출력 | 별도 GUI 검사 표준 오류 출력 0바이트 |
| 정식 빌드 | 구조 17·공존 11·Modifier 핵심 235·Painter 핵심 51, 314건 통과 |
| 배포 검사 | 통합 등록·해제, CCCoreLib 실제 정렬, TOML·ZIP 구조 검사 통과 |
| 현재 사용자 Blender | 일반 0개·Modifier 21개·Painting 0개 표시 확인. 실제 화면에서 눈금이 사라진 것도 확인 |

GUI 검사는 별도 숨김 Blender 프로세스에서 수행했다. 기존 단위·형상·사용자 컬렉션과 소유권 계약을 유지한다. 표시 레이어가 없는 Scene에서는 눈금을 다른 레이어에 표시하지 않는다.

## 설치와 산출물

설치본의 수정 전 3개 파일이 보존한 이전 소스와 같음을 먼저 확인했다. 세 파일을 백업 후 교체하고 소스와 SHA-256 일치를 확인했다. 실행 중인 Blender에서는 눈금 구독·복원 처리기와 관련 함수만 갱신했다. 확장 전체 해제나 클래스 재등록을 하지 않았고 오브젝트·메시·Curve·카메라·이미지·재질 포인터, 작업공간·활성 레이어·프레임·페인트 상태·레이어 수가 유지됐음을 확인했다.

사용자 프로젝트는 저장하지 않았다. 이번 설치 교체 범위는 Modifier의 위 3개 파일이며, 앞선 Painter 가져오기 속도 개선의 전체 설치 교체를 수행한 것으로 집계하지 않는다. 커밋·푸시는 수행하지 않았다.

- 최신 설치 ZIP: 최상위 `colmap_tools.zip`, 내부 버전 0.3.73.
- 크기: 48,286,457바이트.
- SHA-256: `7a7e4cdea75696e6889fa231a2c35613153db01e70b8cdce8a63fcf16bc2de3d`.
- 로컬 검증 결과: `build/verification/modifier-meter-isolation-20261006/`.
- 주요 기록: `meter-tests.log`, `gui.json`, `gui.stderr.log`, `build.log`, `install.json`, `live-update.json`.
- 설치 전 파일: 같은 경로의 `install-backup/`. Git에서 제외된 검사 산출물이다.
- 재현 코드: `tests/modifier/blender_background/test_meter_grid_guide.py`, `tests/modifier/gui_meter_visibility.py`.

제품에 일회성 계측·디버그 로그를 추가하지 않았다.

## 최신 전체 패키지 설치 · 후속 요청

같은 날 사용자의 추가 설치 요청에 따라 최신 ZIP 전체를 설치본에 반영했다. 직전 설치 폴더 전체를 `build/verification/full-install-20261006/backup/colmap_tools/`에 백업하고, 달라진 11개 파일과 신규 참고용 읽기 파일 1개를 교체·추가했다. 설치 파일 1,199개가 위 최신 ZIP과 모두 일치한다. 원본 환경설정의 내용 지문도 유지했다.

사용자 환경설정을 별도 폴더에 복사한 새 Blender 프로세스에서 실제 설치 경로·확장 활성화·참고 점 기본값 20,000·파일 탐색기 상한·원본 메타데이터 속성·눈금 전환 콜백 등록을 확인했다. 결과는 `build/verification/full-install-20261006/install.json`, `probe.json`, `probe.log`에 있다.

현재 사용자 Blender의 프로젝트·작업공간·표시 레이어·프레임을 유지했고 Painting의 눈금은 숨김 상태다. 앞선 눈금 수정은 실행 중인 화면에도 반영됐지만 Painter 속도 개선은 현재 프로세스의 이전 모듈이 남아 있어 재시작 후 전체 적용된다. 사용자 프로젝트를 저장하거나 Blender를 강제로 종료하지 않았다. 커밋·푸시는 수행하지 않았다.
