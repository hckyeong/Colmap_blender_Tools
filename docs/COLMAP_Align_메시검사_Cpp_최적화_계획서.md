# Align 메시 검사 C++ 최적화 계획서

- 작성일: 2026-09-20
- 기준: 점–평면 배율 보정을 적용한 0.3.67 작업본.
- 요청: 전처리 메시 검사 최적화, 서브에이전트 구현, 실제 프로젝트 벤치마크.
- 기존 실제 `Untitled.blend` 측정: 전체 Align 31.394초, 솔버 전처리 14.593초. 메시 검사 자체의 이전 세부 계측은 두 메시 합계 7.562초이며 이번 기준선에서 다시 측정한다.

## 범위와 기존 동작

Blender는 원본 좌표를 검사하고 정렬 전용 배열을 만든다. 솔버는 공통 좌표에서 정제한 뒤 두 메시의 정규화 범위를 구하고, 정규화 좌표를 단정도로 반올림했을 때 무너지는 면을 다시 제외한다. 좌표계와 판정식이 달라 두 솔버 검사를 삭제하거나 하나로 합치지 않는다.

이번 변경은 **솔버 전처리의 두 메시 검사 구현**에 한정한다. Blender 입력 준비의 검사·해시·사본 정책, ICP 수식·수렴 조건, BVH, 겹침 판정·표본 수·난수열·면적 누적 순서, 원본 OBJ·Blender Mesh·마커·UV를 유지한다. CCCoreLib 원문을 수정하지 않는다. 기존 공개 파이썬 정제 함수와 Blender 경로는 그대로 유지한다.

## 구현 구조

1. 자체 네이티브 소스에 `colmap_mesh_cleanup.dll`을 추가한다. CPython 조정기가 `ctypes`로 검증된 절대경로 DLL을 불러오며 현재 NumPy 좌표·면 버퍼를 읽기 전용으로 전달한다. 정제를 위해 대형 이진 파일을 한 번 더 기록하지 않는다.
2. C ABI 1의 입력은 연속된 float64 좌표, uint32 삼각면, 개수, 검사 종류, CPU 상한과 취소 콜백이다. 출력은 기존과 같은 면 유효 마스크와 참조 정점 마스크다. 예외는 ABI 밖으로 내보내지 않고 오류 코드로 반환한다.
3. C++에서 각 면의 세 정점을 직접 읽고 변·외적·임계값 판정을 수행한다. `(면 수, 3, 3)` 좌표 사본, 변 배열, 외적 배열을 생성하지 않는다. 기존 65,536개 면 묶음을 유지하며 oneTBB의 작업 영역으로 사용자 CPU 상한을 지킨다.
4. 유효 면 마스크는 서로 다른 슬롯에 병렬 기록한다. 정점 참조 표시는 순차 결합하여 중복 정점 기록의 경합을 방지한다. 면·정점 정렬 순서와 재색인, 모두 유효할 때 입력 배열을 그대로 반환하는 동작을 유지한다.
5. 원본 검사에서 변 최대 성분으로 정규화한 외적과 `32 * float64 epsilon` 기준을 유지한다. 단정도 검사에서 각 좌표를 float32로 반올림한 뒤 float64 변·외적·제곱합과 기존 `1e-16` 상대 기준을 유지한다. 연산 재결합·FMA로 경계 판정이 달라지지 않도록 엄격한 부동소수점 옵션을 사용한다.
6. 비유한 좌표, 인덱스 범위, 단정도 오버플로, 변 차이 오버플로, 유효면 없음 오류를 유지한다. 콜백은 호출 스레드에서 묶음 경계마다 검사하며 취소 예외를 Python에서 보존한다. 네이티브 실패를 기존 구현으로 숨기는 자동 대체는 넣지 않는다.
7. 새 DLL·ABI·소스 해시를 런타임 Manifest와 배포 검증에 포함한다. 현재 네이티브 작업 프로토콜 v8과 저장 형식은 유지한다. 재빌드 ZIP에 소스·시험을 포함하고 정식 빌드로 검증한다.

추가 대형 메모리는 기존에도 존재하던 면·정점 마스크 수준으로 제한한다. 스레드별 전체 메시 사본이나 정점 마스크를 만들지 않는다.

## 역할과 수정 대상

- 감독 에이전트: 문서·인터페이스 결정, 배포/Manifest 통합, 빌드, 코드 검토, 모든 성능 측정과 최종 판정.
- 네이티브 담당: `mesh_cleanup.h/.cpp`, CMake 대상. C++ 면 판정·CPU 제한·취소·오류 처리.
- 연결 담당: `icp_mesh_cleanup_native.py`, `icp_cccore_solver.py`. DLL 연결·입출력 검증과 솔버 전처리만 전환.
- 검증 담당: 새 네이티브 정제 회귀 및 기존 Python 결과와의 정확 비교. 부모가 전달한 요구를 기준으로 작업하고 재위임하지 않는다.
- 변경한 함수마다 짧은 한국어 설명을 작성한다. 기존 별도 UI·Modifier 작업은 변경하거나 되돌리지 않는다.

## 검증과 벤치마크

1. 변경 전 정렬 모듈·네이티브 배포본을 `build/verification/mesh-cleanup-native/baseline/`에 보존한다.
2. 정상·혼합 퇴화·모든 면 퇴화·미참조 정점·음수/범위 밖 인덱스·NaN/Inf·극대/극소 좌표·단정도 붕괴·두 임계값 바로 안팎·65,536 경계·읽기 전용 입력·단일/다중 스레드·취소를 검사한다. 마스크·재색인·출력 배열을 기존식과 정확 비교한다.
3. 현재 프로젝트에서 보존한 두 실제 메시를 같은 순서·좌표계로 처리해 정제 결과 해시·정규화·표본 지문이 같음을 확인한다.
4. 같은 입력과 CPU 31에서 변경 전후 각 준비 실행 1회와 본 측정 3회를 교차 수행한다. 전처리 비계측 시간, 별도 메시 검사 함수 시간, Python과 네이티브 프로세스 메모리를 구분해 기록한다. 측정 중 다른 CPU 시험/빌드를 병행하지 않는다.
5. 기존 솔버·계약·부분 겹침·취소·네 형상 조합 회귀를 실행한다. 최신 점–평면/노말 동작과 독립 품질 판정을 유지한다.
6. 별도 Blender 5.2에서 `C:/Users/gksru/Desktop/Untitled.blend`와 동일한 3점 마커·CPU 설정으로 실제 Align 연산자를 실행한다. 변경 전후 전체 Align, 입력 준비, 솔버 전처리, ICP, 최종 변환·품질을 비교한다. 프로젝트 복원 시간은 Align 시간과 분리한다.
7. 원본 프로젝트/OBJ는 저장하지 않는다. 사용자 실행 중 Blender를 재시작하거나 강제 재로딩하지 않는다. 정식 빌드·격리 검증과 실제 사용자 설치·Git 푸시는 별도 상태로 보고한다.

### 실제 프로젝트 성능

`C:/Users/gksru/Desktop/Untitled.blend`를 별도 Blender 5.2에서 열고 동일한 3점 마커, CPU 31 설정으로 비교했다. 두 계산 메시 각각 정점 5,651,583개와 삼각면 11,303,380개다. 원본 프로젝트와 OBJ는 저장하거나 변경하지 않았다.

| 측정 구간 | 변경 전 0.3.67 | 변경 후 0.3.68 | 단축률 |
|---|---:|---:|---:|
| 솔버 메시 검사 4회 합계 | 7.105초 | 0.460초 | 93.5% |
| 솔버 전처리 전체 | 14.672초 | 7.938초 | 45.9% |
| 실제 Blender 전체 Align | 31.670초 | 25.620초 | 19.1% |
| Blender 입력 준비 | 6.501초 | 6.420초 | 변경 대상 아님 |

전처리는 버전별 예열 1회 후 교차 실행한 본 측정 3회의 중앙값이다. 변경 전은 14.328/14.672/14.750초, 변경 후는 7.938/8.000/7.828초였다. 메시 검사 합계는 별도 함수 계측 각 1회, 실제 Blender 전체 Align도 각 1회이므로 반복 변동에 대한 한계가 있다. 표의 시간은 서로 다른 실행에서 측정했으므로 행끼리 합산하지 않는다.

실제 Blender 실행에서 솔버 전처리는 14.719초에서 8.047초로 줄었다. 변경하지 않은 강체 ICP는 4.536초에서 5.187초로 변동했으며 두 버전 모두 200회, 배율 단계는 두 버전 모두 6회였다. 프로젝트 열기·복원은 각각 26.710초와 26.123초로, 위 전체 Align 시간에서 제외했다.

### 정확성과 메모리

- 정제 후 두 메시의 좌표·삼각면 파일 SHA-256, 모든 전처리 실행의 표본 지문과 정규화 값이 같았다.
- 실제 Blender의 최종 4×4 변환 행렬과 거리 품질 수치는 정확히 같았다. 두 버전 모두 품질 `PASS`, 정규화 평균 RMS는 `6.4547538165005755e-9`다.
- BVH 생성 2회·재사용 26회·퇴출 0회로 같으며, CCCoreLib 패치·ICP·BVH 원문 해시도 그대로다.
- 전처리 Python 프로세스 최대 작업 집합의 중앙값은 1,048,461,312바이트에서 1,050,746,880바이트로 약 2.18MiB(0.22%) 증가했다. 네이티브 프로세스 최대 작업 집합은 실제 Blender 실행에서 1,154,658,304바이트와 1,154,592,768바이트로 거의 같았다. 서로 다른 프로세스의 최고값이며 Blender를 포함한 전체 RAM 사용량으로 합산하지 않는다.
