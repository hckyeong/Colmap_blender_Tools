# COLMAP Align 실험 기능의 main 마이그레이션 계획서

- 작성일: 2026-09-05
- 상태: 계획 작성 완료, 구현·병합 전
- 출발점: `codex/align-test-env`의 실험 Align
- 도착점: `main`의 정식 `colmap_tools` 애드온
- 근거: [main 승격 검토](COLMAP_Align_main_승격_검토.md)

## 1. 목표와 사용자 결정

실험 환경에서 구현한 Align 기능을 정식 COLMAP Tools에 넣고, 정식 설치 ZIP만으로 CC 정렬과 기존 세 도구가 정상 동작하게 한다.

사용자는 현재 `.blend`가 테스트 파일이므로 보존할 필요가 없다고 결정했다. 이에 따라 **기존 테스트 파일 백업·일괄 변환·구버전으로 되돌리는 변환 기능은 필수 작업에서 제외한다.** 파일을 보존하지 않아도 된다는 결정은 코드의 저장·불러오기 기능을 제거한다는 뜻이 아니다. 새 정식판의 저장·재열기는 검증용 파일로 확인한다. 테스트 입력의 자동 삭제는 이번 계획에 포함하지 않는다.

정식 애드온 식별자는 `colmap_tools`로 유지한다. 실험 애드온 `colmap_align_test_env`의 설치 폴더를 이름만 바꾸어 배포하지 않는다.

위 통합 경로와 브랜치는 구현 단계에서 생성한다. 이미 존재하면 내용을 확인하고 재사용 가능 여부를 판단하며 덮어쓰지 않는다. 통합 작업트리는 세 도구가 모두 있는 전체 체크아웃으로 만든다.

현재 확인한 기준은 main `16695ae`, 실험 `b7c5f1e`다. 실험에는 자동 재연결 관련 미커밋 변경이 남아 있다. 구현 시작 시 최신 이력과 작업 상태를 다시 확인한다. 통합 중 main에 다른 변경이 생기면 최종 반영 전에 통합 브랜치로 가져와 영향받은 검증을 다시 수행한다.

기존 정식·실험 Blender 설정은 유지하고 통합 설치 검사는 별도의 사용자 설정에서 실행한다. 한 Blender 프로세스에 실험 Align과 정식 Align을 동시에 등록하지 않는다.

## 3. 이관할 기능과 경계

### 포함

- COLMAP과 같은 데이터 루트에 있는 연결 OBJ 탐색·불러오기.
- Blender OBJ 불러오기, 원본 토폴로지·UV 보존, 내장 OBJ와 삼각형 정렬 프록시.
- 레이어별 점군·표면 선택과 개별 축 설정.
- 점군·표면 마커 지정, A끼리/P끼리 입력 종류 고정, 기존 3점 정렬.
- CC 기반 점군–점군·점군–메시·메시–점군·메시–메시 정렬.
- 초기값 대비 최대 ±10% 균일 배율 보정.
- 단일 세션 워커·형상 캐시·CPU 스레드 설정.
- 미리보기·승인·버리기·Undo/Redo·취소와 결과 평가 표시.
- 스키마 8 저장 및 구현된 이전 스키마 읽기 지원.
- 파일을 열 때 Align 작업공간에 세션을 자동으로 연결하는 최신 수정.

### 유지할 제품 경계

Root Shell은 정식 등록·해제·메뉴·환경설정을 소유한다. Align은 자기 데이터·마커·그리기·작업공간을 소유한다. Modifier와 Projection Painting의 데이터, Undo, 카메라 세션은 기존처럼 분리한다. 공통 작업공간 교대 계약을 사용하며 도구끼리 런타임을 직접 참조하지 않는다.

실험 실행기·실험 애드온 래퍼·환경 식별 파일·사용자 설정·캐시·테스트 결과는 정식 제품으로 이관하지 않는다. 단, 실험 관리기에만 들어 있는 필수 검증은 정식 테스트 경로로 옮긴다.

## 4. 단계별 작업

### 1단계 — 이관할 소스 확정

1. main과 실험의 현재 커밋·미커밋 변경·원격 상태를 확인한다.
2. 자동 재연결 수정의 코드와 소스 검증 결과를 확인하고 기능 변경과 실험 검증기 변경을 구분해 커밋한다. 기존 실험 커밋은 재작성하지 않는다.
3. 최종 실험 커밋을 이관 기준으로 기록한다. 설치본이나 ZIP 안의 파일을 소스 대신 사용하지 않는다.
4. main에서 새 통합 브랜치와 전체 작업트리를 만든다.
5. main→실험의 경로별 변경 목록을 기록해 기능·관련 테스트·네이티브 빌드·관련 문서만 선별한다.

현재 큰 기능 커밋에는 `test_env` 변경이 섞여 있다. 커밋 제목만 보고 전체 cherry-pick하지 않고, 통합 작업트리에서 필요한 변경을 선별한 새 통합 커밋을 만든다. 실험의 선택적 체크아웃 때문에 디스크에서 빠진 다른 도구를 삭제로 처리하지 않는다.

완료 기준: 이관 기준 커밋과 파일 목록이 확정되고, 기존 두 작업트리의 사용자 변경이 보존된다.

### 2단계 — Align 기능 이관

1. 고정한 실험 기준의 `tools/align` 변경을 같은 상대 경로에 반영한다.
2. 관련 `tests/align`, CC 네이티브 소스·패치·잠금 파일·재빌드 문서를 함께 반영한다.
3. 실험 전용 `test_env` 탐색에 기대는 개발 실행 경로와 오류 문구를 점검한다. 정식 설치 실행 경로는 패키지 내부 런타임을 기준으로 확정한다.
4. 자동 재연결 검증을 정식 패키지 식별자로 실행할 수 있도록 정식 GUI 테스트에 연결한다.
5. 기능 파일과 함께 필요한 의존 변경이 모두 들어왔는지 원본 변경 목록과 대조한다.

완료 기준: 정식 Root 아래에서 Align이 등록되며 이관한 공개 Operator·Property·저장 계약과 기존 기능의 호환성이 유지된다. 이 단계의 소스만으로 정식 배포 완료를 선언하지 않는다.

### 3단계 — 정식 CC 실행 환경 패키징

정식 `build_tools/build_extension.ps1`의 기본 프로필을 `CCCoreLib`로 추가·전환하고, 설치본 `_build_profile.py`에는 `CCCORELIB`를 기록한다.

정식 CC 패키지의 구조:

```text
colmap_tools/
├─ __init__.py
├─ blender_manifest.toml
├─ shell/
├─ shared/
└─ tools/
   ├─ align/
   │  ├─ alignment/
   │  └─ runtime/
   │     ├─ python/     # 전용 CPython과 NumPy
   │     └─ cccore/     # CC 워커, DLL, 라이선스, 재빌드 원문
   ├─ modifier/
   └─ projection_paint/
```

작업 내용:

1. 전용 CPython·NumPy와 CC 워커·CCCoreLib·oneTBB·C++ 런타임의 고정 버전 및 검증 계약을 실험 빌드에서 이관한다.
2. 생성물은 통합 소스 내부 `.cccore-runtime/`에 준비하고 Git 및 배포 원문 탐색에서 제외한다. 예: `python/`, `cccore/`, `cache/`를 이 루트 아래에 둔다.
3. `prepare_cccore_runtime.ps1`에는 위 루트와 출력 경로를 명시해 저장소 부모를 실험 환경으로 가정하지 않게 한다. 정식 소스 단독으로 준비·재빌드할 수 있어야 한다.
4. 라이선스·변경 표시·재빌드 가능한 원문 ZIP·Manifest를 네이티브 실행 환경과 함께 포함한다. 설치 환경 해시 검사는 유지한다.
5. 스테이징에서 CC 최소 정렬 검사를 실행하고, ZIP 생성 후 필수 파일과 기본 엔진을 다시 검사한다.
6. `test_installed_extension.py` 등 정식 설치 검사의 기본 대상을 CC로 바꾼다. 실행 파일 존재 여부뿐 아니라 실제 CC 계산 성공을 확인한다.
7. 기존 `SmallGicp`·`Full` 명시 프로필의 호출 호환성을 유지한다. 각 프로필에서 표시하는 엔진과 실제 포함/요구하는 실행 환경을 일치시킨다. 정식 기본 CC 프로필에는 Small GICP 실행 패키지를 넣지 않고, 개발·명시적 비교용 소스는 보존한다.

완료 기준: 실험 환경 변수와 실험 폴더 접근 없이 정식 설치 ZIP 안의 실행 환경으로 CC 정렬이 완료된다. 생성된 ZIP에 실험 애드온 래퍼·사용자 설정·캐시가 포함되지 않는다.

### 4단계 — 정식 환경설정 연결

`shell/preferences.py`의 기존 Root Preferences에 다음을 연결한다.

- CPU 스레드 수: 0 자동, 1 단일, 2 이상 수동 상한.
- 감지한 스레드 수와 다음 작업에 적용할 수.
- CC 정렬 환경 검사 버튼과 결과 표시.
- 개발 프로필에서 필요한 명시적 외부 실행 경로.

설정 해석은 기존 Align의 스레드 계산 함수를 재사용한다. Root 설정이 값과 표시를 소유하고 Align은 해당 값을 읽는다. 실험 Preferences 클래스를 같은 정식 식별자로 추가 등록하지 않는다. 이전 설정에 CC 속성이 없는 경우 기본값 0으로 초기화한다.

완료 기준: 정식 Preferences는 하나만 등록되며 스레드 설정이 재시작 뒤 유지되고 다음 CC 작업에 반영된다. 일반 사용자 설정을 강제로 초기화하거나 실험 단축키 설정을 복사하지 않는다.

### 5단계 — 정식 설치본 기능 검증

기존 실험의 37개 통과 보고서는 이전 ZIP 기준이므로 완료 근거로 재사용하지 않는다. 최종 통합 소스로 만든 정식 ZIP을 격리 설치하고 다음을 확인한다.

| 검증 영역 | 확인 내용 |
|---|---|
| 등록·해제 | 세 도구 등록, 재등록, 해제, 등록 실패 시 자원 정리 |
| 입력·축·표시 | 연결 OBJ, 독립 OBJ, 레이어별 형상 선택, 축 설정, 표시와 입력 일치 |
| 마커·정렬 | A/P 입력 종류 고정, 3점 정렬, 네 가지 CC 입력 조합, ±10% 배율 보정 |
| 작업 제어 | 미리보기·승인·버리기·Undo/Redo, 작업 취소·실패 후 새 작업 |
| OBJ 입출력 | 내장 OBJ, 쿼드/N곤 토폴로지·UV, 공통 행렬을 적용한 내보내기 |
| 저장·복원 | 검증용 파일 저장·재열기, 레이어·마커·확정 행렬·내장 OBJ 복원 |
| 자동 재연결 | 실제 레이어가 있는 파일로 새 Blender 시작, 수동 탭 전환 없는 Align 진입 |
| 도구 공존 | Align·Modifier·Projection Painting 교대, 카메라·마커·Undo·표시 격리 |
| 환경설정 | 자동·단일·수동 스레드 설정과 실제 작업의 요청/적용값 일치 |

기존 Architecture·Coexistence·Modifier/Projection Core·통합 등록·작업공간 격리·Camera Marker 교대 검사를 유지한다. 구엔진에 한정된 검사는 새 프로필 계약으로 갱신하고, 관련 없는 회귀 검사를 삭제하거나 건너뛰지 않는다.

현재 사용자의 테스트 파일을 보존·마이그레이션할 의무는 두지 않는다. 기존 파일이 없어도 저장·복원 검증용 파일은 테스트가 생성할 수 있어야 한다. 기존 스키마를 읽는 구현과 회귀 검사는 유지하되, 스키마 8을 구버전 형식으로 내보내는 기능은 추가하지 않는다.

완료 기준: 설치한 정식 ZIP의 해시와 검증 보고서가 일치하며, 저장·자동 재연결·세 도구 공존을 포함한 관련 검사가 통과한다.

### 6단계 — 성능·메모리 채택 근거 확정

이번 작업은 실험 v3의 성능을 정식 설치본에서도 유지하는 것이 목적이다. 새로운 정렬 알고리즘이나 등록 내부 캐시 패치를 추가하는 작업은 포함하지 않는다.

1. 기존 v3 벤치마크의 동일 입력·행렬·설정·스레드 조건을 정식 설치본에서 재현한다. 이전 v2 기준 실행을 불필요하게 반복하지 않는다.
2. 정렬 상태와 오정렬 상태에서 워밍업 1회, 측정 3회로 전체 시간·행렬·거리 지표·네이티브 프로세스 수·메시 적재 횟수를 기록한다.
3. 차이가 있으면 동일한 최신 실험 v3를 대조 실행해 환경 차이와 이관으로 인한 회귀를 구분한다. 기존 정확성 허용오차를 완화해 통과시키지 않는다.
4. 작업집합과 커밋 메모리 외에 실제 페이징을 구분할 수 있는 계측을 추가한다. 계측 방식과 시스템 부하를 기록하며 일반 페이지 폴트 수나 작업집합만으로 페이징 없음이라고 판단하지 않는다.
5. 기존 최대 5.0927% 프로토콜 오버헤드와 1% 목표 미달을 그대로 기록한다. 기존 목표 충족 여부와 전체 시간·절대 비용을 함께 평가해 정식 채택 결론을 별도 작성한다.

기존 보고서의 `EXPERIMENT_ONLY`를 이름만 바꾸어 통과 처리하지 않는다. 미측정 항목이나 기존 기준의 처리 결정이 남으면 정식 채택 완료로 표시하지 않는다. 기준 변경이 필요한 경우 근거와 변경안을 문서에 명시하고 확정한 뒤 main 반영 단계로 진행한다.

완료 기준: 이관에 따른 정확성·작업 동작 회귀가 없고, 성능·메모리 및 기존 미완료 항목에 대한 정식 채택 결론이 기록된다.

### 7단계 — 릴리스와 main 반영

1. `__init__.py`와 `blender_manifest.toml`의 버전을 함께 갱신한다. 현재 `0.3.36` 다음 릴리스 번호를 사용하며 구현 시 최신 main 버전을 기준으로 확정한다.
2. 정식 기본 엔진·CC 실행 환경·설정·내장 OBJ·저장 형식·재연결 동작을 릴리스 문서에 기록하고 ADR·빌드/설치 안내·테스트 문서를 갱신한다.
3. 확정한 버전의 최종 ZIP을 생성·설치 검증하고 커밋, 런타임 해시, ZIP 해시, 검증 결과를 하나의 승격 기록으로 묶는다.
4. main이 진행됐다면 통합 브랜치에 반영하고 변경 영향에 맞춰 검증한다. 검증한 최종 커밋을 main에 병합한다.
5. main에서 생성하는 정식 산출물이 검증한 소스와 같은지 확인한다. 실제 일반 사용자 Blender 설치는 검증된 ZIP을 사용한다.

실험 브랜치와 환경은 남겨 두어 이후 실험에 재사용할 수 있게 한다. 원격 푸시, 실험 폴더 삭제, 사용자 Blender 강제 종료는 별도 요청 없이 수행하지 않는다.

완료 기준: main이 검증된 통합 커밋을 포함하고, 정식 `colmap_tools` ZIP에서 실험 Align 기능이 동작한다.

## 6. 커밋과 복귀

통합 브랜치에서는 다음 단위로 커밋한다.

1. Align 기능·의존 테스트 이관.
2. 정식 CC 빌드·실행 환경·프로필·환경설정 연결.
3. 정식 설치본·저장·세션 공존 검증.
4. 성능 채택 기록·릴리스 버전·문서 확정.

실험 이관 기준과 최종 main 기준을 기록한다. 병합 전 문제는 통합 브랜치에서 수정하고, 중간 빌드를 정식 사용자 환경에 설치하지 않는다. 병합 후 복귀가 필요하면 승격 전 코드와 설치 ZIP을 기준으로 되돌린다. 현재 테스트 `.blend`는 사용자 결정에 따라 복귀 대상에서 제외한다.
