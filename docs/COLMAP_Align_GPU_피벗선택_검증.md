# 화면 ID·깊이를 이용한 기즈모 피벗 선택

검증일: 2026-10-21. 대상 브랜치: `codex/artec-align-engine`.

## 변경과 원인

표면 더블클릭 처리 함수 `set_layer_transform_pivot_from_event()`가 공용 선택 함수에 `screen_surface=True`를 전달하도록 변경했다. 기존에는 기본값 `False`를 사용해 첫 클릭에서 전체 메시의 CPU BVH를 만들었다. 마커는 이미 화면 ID·깊이 경로를 사용하고 있었다.

이제 피벗도 가져오기 때 준비한 표시·마커 공용 GPU 버퍼로 작은 ID·깊이 패스를 그린다. 반환된 원본 삼각형 후보만 원본 좌표에서 배정밀도로 다시 교차 검사한다. GPU 버퍼와 삼각형 대응표를 재사용하며, 화면 ID·깊이는 선택할 때 현재 시점으로 다시 계산한다. 화면 선택 결과 전체를 이전 클릭에서 그대로 재사용하는 구조는 아니다.

GPU 실패는 상태 메시지로 알리고 기존 피벗과 카메라 위치를 유지한다. 숨긴 레이어를 선택 대상에서 제외하는 규칙, 선택한 여러 레이어의 공통 피벗, 원본 좌표 보관, 점군 선택과 정렬·실행 취소 계약은 유지했다. 명시적으로 기존 경로를 호출하는 코드의 호환성을 위해 공용 선택 함수의 기본값과 BVH 구현은 남겼다.

원본 정점·면·UV와 가져오기·GPU 표시 준비 코드는 변경하지 않았다. 브랜치 소스 검증 후 사용자의 추가 요청으로 0.3.76 ZIP을 빌드하고 실제 설치본까지 갱신했다.

## 측정 조건

- Blender 5.2.0 LTS, NVIDIA GeForce RTX 4090.
- 현재 열린 동일 모델 `Gilt-bronze Pensive Maitreya Bodhisattva 78_high poly.obj`.
- 원본 정점 30,109,486개, 삼각형 60,206,247개.
- 실제 A 뷰포트 1,277 × 1,449픽셀, 현재 사용자의 원근 시점에서 서로 다른 표면점 세 곳.
- 실행 중인 설치본의 모델·공용 의존성을 그대로 사용했다. 변경 전 파일과 설치 파일의 일치를 확인하고, 변경 전후 소스에서 실제 피벗 함수만 읽어 같은 의존성에 연결했다.
- 표시 준비가 끝난 상태에서 최초 선택을 각 1회, 반복 선택을 각 30회 측정했다. 반복 검사는 세 점 각각 10회이며 측정 순서를 번갈아 배치했다.
- 최초 BVH는 임시 빈 캐시에서 새로 만들었고, 최초 GPU 선택은 선택 셰이더 참조를 비운 상태에서 실행했다. 기존 사용자의 캐시는 별도로 보관한 뒤 복원했다. 그래픽 드라이버의 셰이더 디스크 캐시까지 초기화한 검사는 아니다.
- 실제 뷰포트 문맥에서 더블클릭 처리 함수를 직접 호출했다. 물리 마우스 이벤트, 더블클릭 인식 대기 시간, 가져오기와 호출 후 화면 재그리기는 측정에 포함하지 않았다.

## 속도

| 항목 | 변경 전 BVH | 변경 후 GPU ID·깊이 |
|---|---:|---:|
| 최초 선택, 각 1회 | 20.887463초 | 0.018163초 |
| 반복 선택 중앙값, 각 30회 | 0.7536밀리초 | 18.1308밀리초 |
| 반복 선택 범위 | 0.5761~1.0027밀리초 | 17.6752~19.6772밀리초 |
| 최초 선택 뒤 BVH 캐시 수 | 1 | 0 |

최초 선택은 이 측정에서 약 1,150배 빨라졌다. 반면 BVH를 이미 만든 뒤의 반복 선택은 기존 방식이 빠르며, GPU 방식은 중앙값 기준 약 17.38밀리초가 더 걸렸다. 모든 선택이 빨라진 변경으로 해석하면 안 된다. 최초 구축 비용을 없애고 표시 버퍼를 재사용하되, 클릭마다 GPU 선택 패스와 소량 결과 읽기가 필요하다.

## 정확도와 기존 경로의 차이

각 화면점에서 **원본 전체 60,206,247개 삼각형**을 독립적인 평면 교차·면적 부호 검사로 조사했다. 이 검사는 GPU ID, BVH, 제품의 삼각형 교차 구현을 기준 답으로 사용하지 않는다. 현재 화면 투영 행렬에서 배정밀도로 복원한 광선에 가장 먼저 닿는 원본 면을 기준으로 삼았다.

| 화면점 | GPU와 독립 검사의 원본 삼각형 ID | 원본 좌표 차이 | 기존 결과의 화면 오차 | GPU 결과의 화면 오차 |
|---|---:|---:|---:|---:|
| 1: (845, 620) | 16,229,468 | 0 | 8.189493픽셀 | 7.03 × 10⁻⁹픽셀 |
| 2: (768, 708) | 1,283,797 | 5.21 × 10⁻¹³ | 3.902192픽셀 | 4.47 × 10⁻⁹픽셀 |
| 3: (728, 557) | 2,597,174 | 2.34 × 10⁻¹³ | 0.700415픽셀 | 1.01 × 10⁻⁸픽셀 |

좌표 차이는 원본 모델 좌표계의 거리이며, 실제 물체의 물리적 정확도를 뜻하지 않는다. 세 점 모두 반복 선택에서 같은 원본 ID·좌표를 반환했다. 원본 좌표는 배정밀도로 피벗 상태에 그대로 보관된다. Blender의 카메라 중심 속성은 단정밀도이므로 별도로 허용 오차 `1e-4` 이내인지 검사했다.

초기 비교에서는 기존 BVH와 GPU의 삼각형 ID가 달라 추가 조사했다. 기존 경로는 Blender의 `view3d_utils.region_2d_to_vector_3d()`와 `region_2d_to_origin_3d()`로 광선을 구한다. 설치된 구현은 `mathutils` 행렬 역산과 카메라 원점 차감으로 방향을 계산한다. 현재 시점은 가까운 클리핑 거리 약 0.01, 먼 거리 약 2,259.14이며 큰 좌표에서 이 계산의 정밀도 차이가 나타났다.

원인은 검색 구조 자체와 구분해 확인했다. **기존 BVH에 GPU 경로와 같은 배정밀도 화면 광선을 넣으면 세 점 모두 GPU·독립 검사와 같은 면과 좌표가 나왔다.** 기존 결과를 화면에 재투영하면 위 표처럼 클릭 위치에서 벗어나며, GPU 결과는 클릭 위치로 돌아왔다. 따라서 이번 시점에서 기존 결과의 ID를 그대로 유지하는 것을 정확도 기준으로 삼지 않았다. 피벗이 기존 마커의 배정밀도 화면 광선 경로를 사용하게 된 효과이며, 별도의 광선 알고리즘 수정은 하지 않았다.

이 결과는 해당 모델·시점·세 화면점의 검증이다. 다른 모델이나 모든 시점에서 같은 오차와 속도가 나온다고 일반화하지 않는다.

- 실제 설치 경로: `C:/Users/gksru/AppData/Roaming/Blender Foundation/Blender/5.2/extensions/user_default/colmap_tools`.
- 설치 파일 1,231개가 빌드 ZIP과 일치하며 활성화 상태를 확인했다.
- 버전 0.3.76, 기본 엔진 `POINT_KD_ICP`, 피벗의 `screen_surface=True` 호출을 확인했다.
- 앞서 되돌린 CPU 중복 제거 변경은 재도입하지 않았으며 CPU 배열 재사용과 GPU 버퍼 공유는 유지했다.
- 설치 및 배경 검증 전후 환경설정 파일 해시는 같았다.
- ZIP SHA-256: `7c9db9dedcd4bcee17f653779594de8af1fde4d38cfe091bd56e8fd02d698a37`.

설치 근거와 백업은 `build/verification/pivot-install-20261021/`에 보관한다.

새 설치본을 데스크톱 2에 배치하고 동일 원본 OBJ를 공개 가져오기 명령으로 다시 불러왔다. 약 83.93초에 정점 30,109,486개·삼각형 60,206,247개·공용 GPU 배치 22개가 준비됐다. A 레이어를 선택하고 기즈모 표시가 켜져 있으며 피벗 입력을 막는 상태가 없는 것도 확인했다. 화면 캡처로 모델 표시를 확인한 뒤 창을 열어 두었다.

Windows의 숨김 시작 옵션만으로 본창이 숨겨지지는 않았다. 이후 본창을 활성화하지 않고 DWM으로 가린 상태에서 `MoveWindowToDesktop`으로 데스크톱 2에 배치하고 가림을 해제했다. 모델 가져오기는 데스크톱 2 소속을 확인한 뒤 시작했다. 사용자 활성 데스크톱은 전후 모두 1이며, Blender 창을 전경으로 활성화하거나 데스크톱 화면을 전환하는 명령은 사용하지 않았다. 사용자 측 전경 창은 준비 도중 달라졌으므로 이번 설치 실행에서 전경 창 핸들이 전후 동일했다고 주장하지 않는다.
