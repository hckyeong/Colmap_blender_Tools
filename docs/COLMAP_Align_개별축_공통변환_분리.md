# 개별 원본 축과 데이터셋 공통 변환 분리

## 변경 범위

- COLMAP 점군·카메라와 연결 OBJ는 축 프리셋·Forward/Up만 각각 설정한다.
- 이동·회전·XYZ 배율·비율 잠금·원점 이동은 데이터셋 공통 설정 한 벌로 함께 적용한다. 회전·배율 중심은 존재하는 두 형상의 월드 경계 상자를 합친 중심이다.
- 축 설정 팝업이 열린 동안 대상 레이어의 실제 존재하는 점군·메시를 모두 표시한다. 미리보기 선택과 무관하게 비교할 수 있으며 기존 표시 토글과 눈 상태는 변경하거나 저장하지 않는다. 적용·취소·작업공간 이탈 시 표시 상태는 기존 값으로 돌아간다.
- 독립 OBJ와 COLMAP 단독 레이어는 있는 형상만 표시하고 설정한다.

## 변환과 호환성

1. 형상별 원본 축 `Aᵢ`, 데이터셋 공통 변환 `U`, 기존 개별 설정을 보존하는 기준 `Kᵢ`를 분리한다. 최종 표시 행렬은 `Nᵢ = U Kᵢ Aᵢ`다. 기존 공통 정렬 `C`는 그대로 유지한다.
2. 편집 시작 시 `Kᵢ = U⁻¹ Nᵢ Aᵢ⁻¹`로 기존 배치를 보존한다. 개별 축 조작은 해당 `Aᵢ`만, 공통 조작은 두 형상의 `U`를 함께 바꾼다. 원본 배열과 파일을 수정하지 않는다.
3. 표시 변환의 원본 기준 행렬로 `Aᵢ⁻¹ Kᵢ Aᵢ`를 보관한다. 공통 회전·이동·배율과 중심은 각 원본 축에 맞게 표현한다. 서로 다른 RC 원본 축과 기존 개별 비균일 배율도 손실 없이 유지한다.
4. 저장 스키마 10에 원본 기준 행렬을 추가하고 버전 1–9는 항등 기준으로 읽는다. 무변경 적용과 취소는 기존 float64 행렬·지문을 정확하게 유지한다. 확정·Undo/Redo는 기존 단일 편집 경계를 사용한다.
5. 개별 RC 초기화는 원본 축만 바꾼다. 데이터셋 변환 초기화는 공통 이동·회전·배율만 초기화한다. 기존 개별 보정은 호환 기준으로 유지한다.

## 검증 기준

- 원본 축만 개별 조절되고 이동·회전·비균일 배율은 같은 변화량으로 함께 적용된다.
- 전체 경계 중심 고정·월드 원점 이동·비율 잠금, COLMAP 단독·OBJ 단독·연결 OBJ.
- 존재하는 두 형상 동시 표시 및 미리보기 토글·취소·적용·작업공간 이탈 후 기존 표시 복원.
- 무변경 정밀도·원본 배열 보존·단일 Undo/Redo·구버전 읽기·새 설정 실제 저장과 복원.
- 실제 Blender RNA·팝업 화면, Align 필수 회귀·등록·정렬·배포 패키지 검사.

RNA 갱신 콜백은 [Blender 공식 속성 API](https://docs.blender.org/api/main/bpy.props.html)의 연산자 속성 래퍼에서도 편집 토큰으로 동작한다.

## 구현·검증 결과

- 버전 0.3.72: 개별 원본 축 박스 두 개와 데이터셋 공통 변환 박스 한 개로 UI를 분리했다. 존재하지 않는 형상 박스는 표시하지 않는다.
- Align 필수 회귀 45개 파일 통과. 신규 검사에서 기존 개별 배치·비균일 배율 보존, 공통 변화량, 전체 중심·원점 이동, 실제 RNA 자물쇠, 무변경 정밀도, Undo/Redo와 저장·복원을 확인했다.
- 별도 숨김 Blender GUI에서 원래 숨겨진 레이어의 실제 점군·표면 GPU 배치를 함께 그렸고 팝업 화면을 확인했다. 실제 키 이벤트로 취소·적용·작업공간 이탈, 독립 OBJ 팝업을 검증했다.
- 빌드 검사 298개, 통합 등록·해제, CCCoreLib 스테이징 실제 정렬과 격리 ZIP 설치 검사가 통과했다.
- 최상위 `colmap_tools.zip`을 0.3.72로 갱신하고 실제 사용자 설치본의 관련 파일 12개만 교체했다. 각 설치 파일은 ZIP·소스와 해시가 같으며 별도 프로세스에서 새 공통 변환 RNA·저장 버전·등록과 해제를 확인했다.
- 검증 자료: `build/verification/axis-split-20261001/`. 열려 있는 Blender 프로젝트는 저장하거나 다시 불러오지 않았다. 실행 중인 기존 버전은 Blender를 재시작한 뒤 교체된다.

## 0.3.80 기즈모 중심·원점 이동 · 2026-10-22

- 공통 변환 박스에 **기즈모를 바운딩 박스 중심으로**, **물체를 이동해 기즈모를 원점으로**를 추가했다. 기존 **중심을 원점으로**와 회전·배율 중심의 의미는 유지한다.
- 중심 지정은 존재하는 주 형상·연결 메시의 저장된 경계 코너를 현재 월드 행렬로 변환해 합친 중심을 사용한다. 원본 배열을 순회하거나 GPU 버퍼를 재생성하지 않는다. 중심은 주 형상 원본 좌표의 앵커로 보관해 이후 이동을 따라간다.
- 원점 이동은 현재 선택 범위의 사용자 피벗을 사용한다. 없으면 기존 기즈모 규칙인 선택 원점 평균을 사용한다. 팝업 대상이 선택되지 않았으면 대상 하나의 범위를 사용한다. 다른 레이어는 움직이지 않고 피벗을 대상에 다시 연결한다.
- 현재 피벗의 월드 위치 `p`, 기존 정렬 행렬 `C`에 대해 두 표시 변환의 평행이동에 `C.linear⁻¹ × (−p)`를 동일하게 더한다. 회전·배율·개별 축·기존 보정·공통 정렬과 원본 정점·면·UV는 유지한다.
- 기즈모 앵커는 팝업 후보 상태에만 보관하다 적용 시 축과 함께 확정한다. 취소·Esc·작업공간 이탈은 후보를 폐기한다. Undo/Redo와 기록 실패 시 복구에 앵커도 포함한다. 기즈모만 바꿀 때는 축 저장소 갱신과 정렬 품질 무효화를 생략한다.
- 기즈모는 기존과 같이 세션 상태이며 파일 스키마는 변경하지 않았다. 물체 이동은 기존 표시 변환 저장 경로를 사용한다. 팝업 중 기즈모를 숨기는 기존 입력 잠금도 유지한다.
- 신규 수치 회귀는 독립 OBJ·COLMAP 단독·연결 OBJ, 복수 선택·미선택 팝업 대상, 사용자 피벗과 기본 피벗, 회전·비균일 배율·서로 다른 축, 미리보기 끄기, 적용·취소·Undo/Redo·기록 실패 복원을 확인했다. 월드 원점 오차 허용치는 `1e-10`이며 관련 기존 회귀 8개 파일도 통과했다.
- 데스크톱 2의 별도 비활성 Blender 창에서 실제 팝업의 두 RNA 버튼·Enter 적용·Esc 취소·Undo/Redo를 검증하고 화면을 확인했다. 사용자 전경 창과 데스크톱 1을 전환하지 않았다. 검증 자료는 `build/verification/axis-gizmo-20261022/`에 보관한다.
- 빌드 검사 314개, 통합 등록·해제, 두 네이티브 정렬 환경의 실제 계산 및 격리 설치 검사를 통과했다. 정식 ZIP과 사용자 설치본을 0.3.80으로 갱신했고 배포 파일 1,235개의 해시·새 버튼 등록·환경설정 보존을 확인했다. ZIP SHA-256은 `9848d0012f5c06dc3703c88a4a42adc74cfa01a5d46e64f6a4ea0a4b186a0e31`이다.
- 실행 중인 사용자 Blender 0.3.79의 두 모델·배치·기즈모·선택·미저장 상태를 설치 전후 동일하게 유지했다. 실행 중 모듈은 교체하지 않으므로 작업을 저장한 뒤 Blender를 재시작하면 새 버튼을 사용할 수 있다.

## 0.3.81 각 버튼의 독립 즉시 실행 · 2026-10-22

- 사용자 요청에 따라 기즈모 중심 지정과 기즈모 기준 원점 이동을 각각 클릭 즉시 확정한다. 버튼마다 `EDIT_GEOMETRY_AXES` 세션 이력 한 건을 남기며, 팝업의 적용을 기다리지 않는다. 팝업 취소·Esc·작업공간 이탈은 즉시 실행 결과를 되돌리지 않는다. 팝업을 닫은 뒤 기존 실행 취소·다시 실행으로 한 단계씩 복원한다.
- 기즈모만 지정할 때 물체 행렬·정렬 품질은 바꾸지 않는다. 원점 이동 버튼은 중심 지정 없이 현재 피벗을 사용한다. 공통 정렬·원본 정점·면·UV·다른 모델은 유지한다.
- 즉시 실행과 미적용 입력의 확정 경계를 분리했다. 현재 표시 배치에서 피벗과 이동량을 구하되, 확정 저장소에는 해당 이동·기즈모만 반영한다. 미적용 회전·배율·축은 남겨 두고 같은 평행이동을 후보에도 더한다. 팝업 기준 스냅샷을 새 확정 상태로 갱신해 이후 적용에 중복 이력이 생기지 않는다. 취소하면 미적용 입력만 폐기한다. 미리보기를 끈 상태에서는 확정 배치를 기준으로 계산한다.
- 즉시 실행 이후 미적용 축 입력을 취소하면 그 입력에 의한 배치 변화는 복원된다. 따라서 물체에 붙은 기즈모의 표시 위치도 달라질 수 있다. 기즈모 자체의 즉시 지정·이동 이력은 유지된다.
- 축 팝업 대상의 기즈모를 계속 표시하고 `hide_select`로 드래그를 잠근다. 팝업 종료 후 원래 조작 가능 상태로 복원한다. 기존 G/R/S 시작과 팝업 중 전체 이력 변경 차단은 유지한다. [Blender 5.2 Gizmo API](https://docs.blender.org/api/5.2/bpy.types.Gizmo.html)의 표시·선택 분리 속성을 사용한다.
- 수치 회귀 6개 함수에서 즉시 확정·독립 이력·팝업 취소·Undo/Redo·실패 시 복구·미적용 입력 보존·미리보기 켜짐/꺼짐·COLMAP/연결 OBJ/독립 OBJ·복수 선택·읽기 전용 기즈모를 확인했다. 기존 관련 회귀 8개 파일도 통과했다.
- 데스크톱 2의 별도 비활성 창에서 실제 두 버튼을 마우스로 클릭했다. 기즈모가 `(4, 5, 6)`에서 경계 중심 `(9.5, 5.75, 6)`으로, 이어 물체와 함께 `(0, 0, 0)`으로 즉시 이동했다. 팝업 Esc 후에도 두 단계가 남고 각 Undo/Redo로 복원됨을 확인했다. 실제 그리기 좌표와 드래그 차단 및 갱신된 이동 입력을 검증했다. 기록은 `build/verification/axis-gizmo-immediate-20261022/`에 보관한다.
- 빌드 검사 314개, 통합 등록·해제, 네이티브 정렬 환경의 실제 계산과 격리 설치 검사를 통과했다. 정식 ZIP과 실제 사용자 설치본을 0.3.81로 갱신하고 배포 파일 1,235개의 해시·새 실행 경로·환경설정 보존을 확인했다. ZIP SHA-256은 `db45ff89c7f958bc957dad4aeef309348bfed29b48e71e2ba7d6dae7aecde5dd`이다. 실행 중인 사용자 모델·배치·선택·피벗·파일 상태는 설치 전후 그대로 유지했으며 재시작은 수행하지 않았다.
