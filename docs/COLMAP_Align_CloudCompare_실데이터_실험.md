# CloudCompare 표면 정렬 실데이터 실험

- 입력: 사용자가 지정한 바탕화면 `Untitled.blend`의 확정 저장 상태.
- 작업 위치: `codex/align-test-env`의 `tests/align/experiments/`.
- 결과 위치: 실험 루트의 `outputs/cloudcompare_surface_날짜_시각/`.
- 제품 엔진 변경과 main 통합은 이번 실험 범위에 포함하지 않는다.

## 절차

1. 원본 파일을 복사하고 파일 지문, 저장 상태, 연결 OBJ 지문, 형상별 축과 기존 정렬 행렬을 확인한다.
2. 기준 Component 1과 이동 Component 0 메시를 현재 표시 좌표로 내보낸다. 좌표는 `A × N_mesh × 원본 정점`이다. MTL과 텍스처를 읽지 않는다.
3. 설치된 CloudCompare 2.13.2 CLI로 두 메시를 입력한다. 이동 메시의 표면 표본을 기준 메시 삼각면에 대응시킨다. 겹침 90%, 표본 상한 50,000, 최대 100회로 스케일 고정과 균일 스케일 허용을 비교한다.
4. 별도로 추출한 고정 난수 표면 표본 각 30,000개로 양방향 삼각면 거리를 측정한다. 원래 상태, 두 후보의 전체·90% 절사·백분위 오차와 높이별 오차를 기록한다. 표본 대응 RMS만으로 개선을 단정하지 않는다.
5. CC의 float 행렬에서 확인된 반올림 오차만 가장 가까운 양의 Sim(3)으로 정규화하고 그 차이를 보고한다. 비균일 스케일·반사·큰 정규화 오차는 거부한다.
6. 검증된 결과 D를 `새 A_P = D × 기존 A_P`로 합성한다. 저장 스키마의 공통 정렬 행렬을 갱신하여 COLMAP 점군·카메라·연결 메시에 동일하게 적용한다.
7. 원본을 덮어쓰지 않고 적용 결과 `.blend`와 정렬 전 복사본을 각각 보존한다. 정렬 전후 파일과 보고서로 비교할 수 있게 하고 실험 Blender에서 결과를 연다.
8. 실제 설치본에서 모델 복원, 최종 행렬, 메시 표시를 확인한다. 원본 파일 지문이 그대로인지 마지막에 검사한다.

## 비교의 한계

현재 Small GICP 결과에서 시작하는 표면 정밀 보정 실험이다. 동일 3점 초기값에서 두 엔진을 독립 비교한 성능 순위나 일반적인 정확도 개선율은 아니다. 원본 좌표의 실제 길이 단위를 확인하지 않았으므로 수치는 모델 단위로 보고한다.

## 재현

`tests/align/experiments/cloudcompare_surface.py`는 Blender 백그라운드에서 `prepare`, `evaluate`, `publish`, `verify` 단계를 명시적으로 실행한다. `prepare`와 `publish`는 기존 결과를 덮어쓰지 않는다. 각 후보의 `run.json`에 실제 CC 인자 목록과 실행 시간을 기록했다. 같은 옵션으로 재실행할 때는 새 결과 폴더와 입력 복사본을 사용한다.

`tests/align/experiments/show_cloudcompare_result.py`는 전용 사용자 환경과 설치본 경로·파일 지문을 확인한 뒤 결과를 연다. `verify` 단계는 사용자가 열어 둔 GUI를 건드리지 않고 결과 파일을 다시 읽어 검사한다.
