# COLMAP Modifier 표시 크기 고정·미터 눈금 계획서

- 작성일: 2026-09-16
- 상태: **0.3.50 구현·배포·설치본 검증 완료 / 사용자 가독성 검수 대기**
- 기준: COLMAP Tools 0.3.49와 현재 작업 트리
- 요청: 데이터셋 배율을 바꿔도 점·카메라 표시 크기를 설정값에 유지하고, 격자 위에 1~10m 텍스트를 상시 배치한다.
- 관련 규칙: [현재 구조](README.md), [데이터셋 변환 계획](COLMAP_Modifier_기즈모_데이터셋_변환_계획서.md), [Modifier 매뉴얼](https://github.com/hckyeong/Colmap_blender_Tools/blob/f5c816d335cba5ef9808919cacbda73edb90a931/docs/manual/MODIFIER.md)

## 1. 사용자에게 보이는 결과

1. `Point Scale`이 0.05라면 데이터셋을 10배 확대하거나 0.1배 축소해도 점의 **월드 공간 표시 반지름**은 0.05를 유지한다.
2. `Camera Frustum Size`도 같은 설정값을 유지한다. 카메라 위치 간격은 데이터 배율을 따라 바뀌지만 절두체 표시 크기는 함께 커지지 않는다.
3. 배율 드래그 중부터 보정한다. 확정·취소·Undo·Redo·파일 복원 이후에도 같은 규칙을 적용한다.
4. Modifier 바닥 격자의 원점에서 +X·+Y 방향으로 1m 간격의 `1 m`부터 `10 m` 텍스트를 배치한다. 각 축 10개, 총 20개다.
5. 눈금은 데이터셋 이동·회전·배율이나 더블클릭 피벗 변경을 따라가지 않는다. 점·카메라 편집 중에도 표시하며 선택·삭제 대상에 포함되지 않는다.

표시 크기 고정은 화면 픽셀 크기 고정이 아니다. 줌인·줌아웃과 원근에 따라 화면에서 보이는 크기는 정상적으로 변한다. 카메라 설정값은 절두체의 표시 배율 기준이며, 화각과 종횡비가 다른 모든 카메라의 폭·높이가 그 수치와 같다는 의미는 아니다.

## 2. 현재 코드에서 확인한 원인

| `tools/modifier/blender/scene_elements.py` | 점의 Geometry Nodes 반지름에 `Point Scale`을 직접 연결 | 부모 배율을 상쇄하는 표시 반지름 계산 추가 |

| `point_display.py` | N패널과 Geometry Nodes의 Point Scale을 양방향 동기화 | 보정값을 사용자 설정 변경으로 오인하지 않도록 공개 입력 유지 |

현재 구조에는 부모 배율과 표시 크기를 분리하는 경로가 없다. 실제 Blender에서 배율별 표시를 재현한 후 아래 계약을 검증한다. 이 문서 작성 중 제품 코드와 열린 Blender 데이터는 변경하지 않는다.

## 3. 좌표·크기 계약

기존 좌표 변환은 유지한다.

```text
D = 표시 축 변환
T = 확정 또는 드래그 미리보기의 데이터셋 변환
s = T의 양수 균일 배율
점의 표시 위치 = D × T × 원본 점 좌표
카메라 중심 = D × T × 원본 카메라 중심
```

회전·이동·배율의 권위는 기존 Modifier Domain에 둔다. 보정값은 표시용 파생 값이며 별도 편집 명령이나 변환으로 누적하지 않는다. `s`는 현재 미리보기 또는 확정 행렬에서 구하며, 직전 값에 역배율을 반복 곱하지 않는다.

### 3.1 점 표시

```text
r = 사용자가 설정한 Point Scale
Geometry Nodes 내부 반지름 = r / s
최종 월드 공간 반지름 = s × (r / s) = r
```

- 기존 Geometry Nodes의 공개 `Point Scale` 입력과 N패널 값은 모두 `r`로 유지한다.
- 내부에 관리용 역배율 값과 곱셈 노드를 추가하고 `Mesh to Points → Radius` 앞에서만 적용한다. 원본 정점 좌표나 오브젝트 위치에는 이 보정을 적용하지 않는다.
- 내부 역배율 변경은 기존 양방향 동기화에서 사용자 입력으로 취급하지 않는다. 노드의 공개 Point Scale을 직접 바꾸는 기존 동작도 유지한다.
- `Point Scale`의 의미는 기존과 같은 반지름이다. 기본값·저장값을 재해석하지 않는다. N패널에도 기존 노드 입력과 같은 거리 단위 표시를 적용해 Scene 단위가 있는 경우 두 입력의 표시 단위를 맞춘다.
- Edit Point에서 사용하는 Blender 기본 편집 정점의 픽셀 크기는 이번 변경 대상이 아니다. Object 모드의 점 표시와 편집 종료 후 복구되는 표시를 보정한다.

### 3.2 카메라 절두체 표시

`Camera.display_size`는 설정값 그대로 두고, 카메라 로컬 회전 부분에 `1/s`의 균일 배율을 적용한다. 로컬 이동 성분은 유지한다.

```text
L = 원본 카메라 위치·방향으로 만든 로컬 행렬
카메라 로컬 표시 행렬 = L × Scale(1/s)
최종 표시 행렬 = D × T × L × Scale(1/s)
```

카메라 중심에는 데이터셋 배율이 반영되고 최종 오브젝트 배율은 1이 된다. 표시 크기를 매번 `display_size / s`로 바꾸지 않으므로 설정값과 실제 속성값이 일치하며, 큰 배율에서 `display_size`의 최소값 제한 때문에 보정이 깨지는 문제도 피한다.

- 카메라 내부 파라미터, 초점거리, 센서 크기, 클리핑, 배경 이미지 크기를 대신 변경하지 않는다.
- 구현 전 Blender 5.2의 카메라 표시·카메라 검토에서 이 행렬 방식이 위치·방향·화각을 보존하는지 작은 재현 데이터로 검증한다.
- 정식 카메라 생성·표시 교체·실패 복구가 로컬 행렬을 다시 설정하므로, 모든 경로에서 원본 자세와 현재 `s`로 보정을 재구성한다.
- COLMAP 내보내기와 Painter 전달은 기존 Domain의 `T`를 사용한다. 표시 보정 행렬을 출력 데이터에 포함하지 않는다.

### 3.3 갱신 경계와 성능

- Import, 기존 파일 복원, 표시 재생성, 축 프리셋 변경, 변환 미리보기·확정·취소, Undo·Redo·초기화, Export 후 새 기준 채택에서 일관되게 적용한다.
- Export 성공 후 `T = I`가 되면 표시 보정도 1로 돌아간다. 새 기준 좌표와 표시 크기에 배율을 이중 적용하지 않는다.
- 변환 시작 시 소유한 점 표시 노드·카메라 참조를 수집해 재사용한다. 드래그마다 전체 Scene을 검색하지 않는다.
- 이동·회전으로 `s`가 변하지 않았으면 표시 크기 갱신을 생략한다. 배율 변경 때 카메라 갱신은 카메라 수에 비례하므로 실제 드래그 비용을 측정한다.
- Python에서 점 좌표 전체 복사·Mesh 재생성·관측 관계 인덱스 재구축을 추가하지 않는다. 노드 입력 변경에 따른 Blender 평가 비용도 검증에 포함한다.
- 비유한 보정값이나 표현 범위 초과는 확인 가능한 오류로 처리한다. 설정값을 몰래 제한하거나 잘못된 표시를 성공으로 확정하지 않는다.

## 4. 1~10m 격자 표기

### 4.1 배치

- Blender 실제 Text 오브젝트(`FONT`) 20개를 사용한다. 외부 `.txt` 파일이나 매 프레임 생성하는 문자열은 사용하지 않는다.
- Modifier 월드 XY 평면의 원점을 기준으로 +X·+Y 축에 각각 1~10m를 표시한다. 음수 방향과 Z축 눈금은 이번 범위에 추가하지 않는다.
- 텍스트는 눈금에서 약 0.15m 옆, 바닥에서 약 0.01m 위에 배치한다. 글자 기준 크기는 약 0.15m로 하고 실제 가독성 검수로 조정한다.
- XY 바닥에 놓인 고정 방향 텍스트로 시작한다. 매 시점마다 오브젝트를 회전시키는 카메라 추적 처리는 추가하지 않는다.
- Blender의 기본 격자는 줌에 따라 간격이 달라질 수 있다. 따라서 1m 위치를 확실히 식별하도록 X·Y 기준선과 1m 간격 짧은 눈금을 하나의 표시용 Curve로 함께 만든다.
- 눈금과 글자는 데이터 루트의 자식으로 두지 않는다. 격자 원점을 기준으로 고정하며 피벗 변경이나 데이터셋 변환을 따라가지 않는다.
- 일반 탐색과 점·카메라 편집에서 계속 표시한다. 시야 밖·클리핑·바닥을 옆에서 보는 각도에 따른 가시성까지 화면 고정 안내문처럼 보장하는 뜻은 아니다.

### 4.2 미터 기준

- Scene이 Metric 또는 Imperial이면 `unit_settings.scale_length`를 이용해 `1m = 1 / scale_length` Blender 단위로 환산한다. 텍스트 간격·높이·크기를 같은 비율로 환산한다.
- Scene 단위가 None이면 Modifier 눈금은 `1 Blender 단위 = 1m`를 기준으로 표시한다.
- 기존 Scene의 전역 단위 설정을 자동 변경하지 않는다. 다른 작업공간의 수치 표시에 영향을 주지 않는다.
- Scene 단위 설정이 바뀌면 눈금 배치를 다시 계산한다. 데이터셋 Scale과 Scene 단위 변경은 서로 다른 경로로 처리한다.
- 자동 생성 시 단위 설명을 툴팁 또는 Modifier 매뉴얼에 기록한다. COLMAP 데이터의 실제 물체 크기가 자동 보정된다는 의미는 아니다. 알려진 길이에 맞춰 데이터 배율을 조절해야 실제 미터 크기와 일치한다.

### 4.3 소유권과 격리

- Scene당 하나의 Modifier 눈금 컬렉션을 만들고 별도 역할·UUID·스키마 표식을 부여한다. 데이터셋이 없는 Modifier 첫 진입에서도 만든다.
- 기존 데이터셋 루트 조회·정리 함수에 눈금을 데이터로 등록하지 않는다. 별도의 `METER_GUIDE` 역할로 구분한다.
- `modifier_data_visibility.py`에서 이 소유권이 확인된 컬렉션만 전용 View Layer 표시 대상에 추가하고 일반·Align·Painting View Layer에서는 제외한다. 같은 이름의 사용자 컬렉션은 변경하지 않는다.
- Text와 Curve는 선택 잠금, 렌더 제외, 위치·회전·배율 잠금을 적용한다. 표시상 가려짐을 줄이는 앞쪽 표시도 전용 가이드에만 적용한다.
- 전체 선택, 박스 선택, 카메라 Remove, Edit Point Remove, 프레이밍, 피벗 피킹, 통계, COLMAP 내보내기와 Painter Snapshot에 포함되지 않아야 한다.
- 화면에 존재하는 보조 오브젝트 때문에 Remove가 잠겼던 문제가 재발하지 않도록 실제 전체 선택 경로로 검증한다.

### 4.4 저장·재진입

- 눈금은 Blender의 파생 표시 자원이다. Modifier 편집 Journal과 Domain Payload에 추가하지 않는다.
- `.blend`에 남아 있는 관리 눈금은 재사용한다. 이전 파일처럼 눈금이 없으면 생성한다. 같은 Scene 재진입과 Undo 복구에서도 중복되지 않아야 한다.
- 데이터셋 교체·삭제 편집에 따른 표시 재생성이 눈금을 제거하거나 배율을 적용하지 않도록 데이터 수명과 분리한다.
- Modifier 종료 시 기존 View Layer 전환에 따라 보이지 않게 한다. 애드온 해제 시 자기 소유 가이드와 등록한 단위 변경 감시만 정리한다. 다른 도구·사용자의 Text와 Curve는 유지한다.
- 지속적인 전체 Scene 폴링을 추가하지 않는다. 단위 변경은 메시지 버스 등 변경 알림으로 받고, 등록·파일 로드·해제 경계에서 구독을 재설정·해제한다.

## 5. UI와 호환성

- 현재 N패널의 `Point Display`, `Camera Display`, `Dataset Transform` 배치를 유지한다.
- 점·카메라 표시 옵션의 설명에 데이터셋 배율과 독립적인 월드 공간 표시 크기임을 명시한다.
- 미터 눈금은 Modifier에서 기본 상시 표시한다. 이번 범위에 별도 설정 패널이나 표시 토글을 추가하지 않는다.
- 기존 `.blend`의 설정값과 확정 데이터 배율을 유지한다. 구형 관리 Point 노드에만 표시 보정 노드를 한 번 연결한다. 사용자 노드나 다른 도구의 노드는 수정하지 않는다.
- 기존 관리 노드를 예상대로 식별할 수 없으면 임의의 연결을 덮어쓰지 않는다. 관리 표시 재생성 경로로 복구 가능한지 확인하고 복구 실패는 명확히 보고한다.
- 표시 보정 자체는 Undo 단계나 데이터 Revision을 추가하지 않는다. 사용자가 확정한 데이터 변환은 기존처럼 한 단계로 남는다.

## 8. 이번 작업의 산출물과 제외 범위

계획 작성 당시의 산출물은 이 문서였으며 제품 코드는 변경하지 않았다. 이후 사용자가 서브에이전트 구현과 설치를 승인하여 아래 0.3.50 작업을 진행했다. 실행 중 사용자 Blender를 변경하거나 커밋·푸시하는 작업은 포함하지 않는다.

이후 구현 범위에도 앞서 확인한 OBJ 재질 검증 버그 수정, Edit Point 누적 성능 개선, Z축 높이 눈금, 실제 길이 기반 자동 스케일 추정은 포함하지 않는다.

## 9. 확인한 공식 자료

- [Blender 5.2 Scene Units](https://docs.blender.org/manual/en/latest/scene_layout/scene/properties.html): 단위 스케일은 내부 좌표와 UI 길이 표시 사이의 환산 기준이다. 가이드 배치는 이 환산을 사용하며 데이터셋 좌표를 자동 변경하지 않는다.
- [Blender 5.2 UnitSettings](https://docs.blender.org/api/5.2/bpy.types.UnitSettings.html): `scale_length`, `system`의 정의.
- [Blender Camera API](https://docs.blender.org/api/3.6/bpy.types.Camera.html): `display_size`는 뷰포트의 카메라 표시 크기 속성이다. 설치된 Blender 5.2에서 실제 제한값과 표시 동작을 재확인한다.
- [Blender TextCurve API](https://docs.blender.org/api/5.0/bpy.types.TextCurve.html): Text 오브젝트의 문자열·정렬 속성. 설치된 Blender 5.2에서 생성·선택 잠금·View Layer 가시성을 검증한다.

위 자료는 API 의미의 근거이며, 여기서 제안한 역배율 보정과 가이드 격리의 동작 검증을 대체하지 않는다.

## 11. 후발 표시 레이어 격리 보완 · 2026-10-06

Modifier 이후 새로 생성한 Painting 레이어에서 눈금 제외 상태가 누락되는 것을 실제 프로젝트와 별도 Blender에서 재현했다. 레이어·작업공간·Scene 전환 알림에 눈금 전용 가시성 동기화를 연결했다. 눈금 자원을 다시 만들거나 다른 도구의 컬렉션을 직접 제어하지 않는다. 실제 화면의 5개 전환 시나리오와 기존 미터 눈금 회귀, 정식 빌드를 통과했고 관련 설치 파일 3개와 현재 Blender의 눈금 구독을 갱신했다. 상세 내용은 [후발 레이어 격리 기록](COLMAP_Modifier_미터눈금_후발레이어_격리.md)에 있다.
