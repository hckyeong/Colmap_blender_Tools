# COLMAP Align 연결 메시 마커와 역할별 종류 고정 계획서

- 작성일: 2026-09-03
- 상태: 소스 구현·회귀 검증 완료 / 실행 중 실험 Blender 종료 후 설치·GUI 검증 필요
- 대상: `colmap_align_test_env` 실험 애드온
- 작업트리: `E:\DEV\DEV_RND\colmap_align_test_env\source`
- Git 브랜치: `codex/align-test-env`
- 이번 문서의 목적: 연결 메시 마커, 레이어별 단일 형상 표시, 모든 대응쌍에 걸친 A/P 역할별 마커 종류 고정의 구현 기준을 정한다.

## 1. 대화에서 확정한 요구

1. COLMAP 데이터셋에 연결하여 가져온 OBJ 메시에도 마커를 지정한다.
2. 기존 독립 OBJ의 표면 마커 피킹과 A/P 대응쌍 정렬 기능을 재사용한다.
3. 한 레이어에서는 점군 또는 메시 중 하나만 표시한다. 다른 레이어의 표시 선택을 일괄 변경하지 않는다.
4. 쌍 지정을 시작할 때 현재 표시 대상과 종류를 기억하고, 입력 도중 다른 종류를 사용하려 하면 안내하고 차단한다.
5. 종류 제한은 현재 입력하는 한 쌍에만 적용하지 않고 전체 대응쌍에 적용한다.
6. A와 P의 종류를 하나로 묶지 않는다. 모든 A끼리, 모든 P끼리 각각 같은 종류를 사용한다.
7. 대응 마커에서 계산한 변환은 이동 대상 COLMAP 데이터셋의 공통 정렬 행렬에 반영한다. 그 데이터셋의 점군·카메라·연결 메시가 함께 움직인다.
8. 계획은 실험 작업트리의 `docs/`에 기록하고, 구현과 검증도 실험 환경에서 수행한다.

| 전체 A 마커 | 전체 P 마커 | 허용 여부 |
| --- | --- | --- |
| 점군 | 점군 | 허용 |
| 메시 | 메시 | 허용 |
| 메시 | 점군 | 허용 |
| 점군 | 메시 | 허용 |
| A1은 메시, A2는 점군 | 한 종류 | 차단 |
| 한 종류 | P1은 점군, P2는 메시 | 차단 |

종류는 사용자 관점의 **점군 / 메시** 두 가지다. 독립 OBJ의 기존 정점 마커와 표면 마커, COLMAP 연결 메시의 표면 마커는 모두 메시 종류에 속한다.

## 2. 현재 구현과 이번 변경 범위

기반 문서는 [COLMAP OBJ 자동 연결·표시·축 설정 계획서](COLMAP_Align_COLMAP_OBJ_자동연결_표시토글_계획서.md)다. 현재 코드를 확인한 결과는 다음과 같다.

| 항목 | 현재 동작 | 이번 변경 |
| --- | --- | --- |
| 연결 OBJ | COLMAP 소유 모델에 별도 형상으로 보관 | 소유 관계 유지 |
| 형상 축 | COLMAP 축과 연결 메시 축이 분리됨 | 마커에도 선택한 형상의 축 적용 |
| 레이어 표시 | 점군·메시를 각각 켜서 동시 표시 가능 | 두 아이콘을 상호 배타적인 선택으로 변경 |
| 표면 피킹 | 독립 OBJ의 삼각형 표면 지원 | 같은 경로를 연결 메시까지 확장 |
| 마커 참조 | 소유 모델, 점 종류, 원본 ID, 원본 좌표 | 주 형상 / 연결 형상 식별 추가 |
| 종류 제한 | 모든 쌍의 역할별 제한 없음 | A/P 각각 전체 쌍 검증 |
| 정렬 | 기존 마커 기반 강체·유사변환과 미리보기 | 입력 형상 해석을 확장하여 재사용 |
| 저장 | 스키마 v5, 형상별 축과 연결 OBJ 저장 | v6에서 마커의 형상 출처 저장 |

이 문서는 기존 문서 중 동시 표시 허용과 연결 메시 마커 미지원 방침을 다음 구현에서 대체한다. 기존의 원본 불변, 형상별 축, 공통 정렬, 독립 실험 환경 원칙은 유지한다.

이번 범위는 **메시에서 지정한 대응 마커를 이용한 정렬**이다. 메시 표면 샘플링, 표면 기반 GICP, 자동 대응점 생성, 정렬 개선율의 정량 실험은 후속 범위다. 기존 COLMAP 희소 점군 GICP의 입력을 연결 메시로 바꾸지 않는다.

## 3. 레이어 표시와 UI

### 3.1 기존 행의 아이콘 재사용

행 구성은 다음 의미를 유지한다.

```text
[활성 상태] 레이어 이름    [점군] [메시] [축 설정] [눈]
```

- 점군 아이콘 선택: 해당 레이어의 점군을 켜고 메시를 끈다.
- 메시 아이콘 선택: 해당 레이어의 메시를 켜고 점군을 끈다.
- 이미 선택된 형상 아이콘을 다시 눌러도 선택을 유지한다.
- 전체 숨김과 다시 표시는 눈 아이콘이 담당한다. 숨겨도 마지막 형상 선택은 유지한다.
- 연결 메시가 없는 COLMAP은 점군만, 독립 OBJ는 메시만 선택할 수 있다.
- 축 설정은 기존 톱니 버튼을 사용한다. 더블클릭 동작은 추가하지 않는다.
- 신규 연결 OBJ 가져오기의 기본 선택은 메시로 제안한다. 메시가 없으면 점군을 선택한다.
- 카메라 표시와 기존 레이어 선택·활성화 동작은 기존 기능을 따른다.

현재 `show_points` / `show_surface` 필드를 유지하되, 변경 진입점에서 유효한 형상 하나만 선택되도록 보장한다. 같은 의미의 별도 표시 상태를 추가하여 두 곳에서 관리하지 않는다.

### 3.2 마커 UI의 최소 추가

기존 마커 패널의 상태 안내에 역할별 종류를 함께 표시한다.

```text
A: 메시 고정  ·  P: 점군 고정
```

아직 결정되지 않은 역할은 `선택 전`으로 표시한다. 혼합 표시된 여러 A 레이어 중 첫 선택이 필요한 경우 `A: 첫 마커로 결정`으로 안내한다. 별도 종류 선택 팝업이나 A/P 공통 강제 스위치는 추가하지 않는다.

일반 확인 중에는 레이어의 표시 종류를 바꿀 수 있다. 다만 기존 마커의 종류가 따라서 바뀌지는 않으며, 다음 쌍 지정 때 역할별 기준을 다시 검증한다.

## 4. 쌍 지정 시작과 역할별 종류 고정

### 4.1 기억할 표시 상태

새 쌍 지정 또는 기존 쌍 편집을 시작할 때 다음을 임시 스냅샷으로 기록한다.

- A 역할의 표시 중인 활성 레이어 목록
- P 역할의 선택된 비활성 레이어 하나
- 각 대상 레이어의 표시 여부와 선택한 형상 종류
- 대상의 소유 모델 ID, 주 형상 / 연결 형상 구분, 원본 형상 리비전
- 해당 형상의 축과 공통 정렬 상태를 식별하는 값
- 기존 확정 마커에서 유도한 A/P별 종류

여기서 기억하는 뷰 상태는 **데이터 표시 상태**다. 사용자는 쌍 지정 중에도 시점을 회전·이동·확대할 수 있으며, 취소 시 카메라 시점을 되돌리지 않는다.

### 4.2 종류를 결정하는 순서

1. 확정 마커가 있으면 전체 확정 목록에서 역할별 종류를 유도한다. 쌍을 새로 시작할 때 초기화하지 않는다.
2. 기존 종류가 없다면 시작 스냅샷의 해당 역할 후보가 한 종류일 때 그 종류를 이번 입력의 잠정 기준으로 삼는다.
3. A는 여러 레이어를 대상으로 할 수 있다. 점군을 표시한 A 레이어와 메시를 표시한 A 레이어가 함께 있으면, 첫 유효한 A 클릭이 이번 입력의 A 종류를 결정한다.
4. 첫 클릭 이후 다른 종류의 A 클릭은 차단한다. P에도 독립적으로 같은 원칙을 적용한다.
5. 쌍 확정 후에는 저장된 마커 목록 자체가 지속 기준이 된다.
6. 기존 고정 종류와 맞는 표시 후보가 전혀 없으면 시작을 거부하고, 맞는 형상으로 전환한 뒤 다시 시작하도록 안내한다.

여러 A 레이어가 섞인 경우의 첫 클릭 결정은 이번 계획에서 정한 세부 정책이다. 다른 A 레이어의 표시를 자동 전환하거나, 모든 레이어에 동일한 표시 선택을 강제하지 않는다.

### 4.3 입력 중 변경과 잘못된 클릭 처리

- 입력 스냅샷에 포함된 대상 레이어의 형상 전환, 숨김, A/P 소속 변경 등 피킹 대상이 달라지는 조작은 쌍 확정·취소 전까지 차단한다.
- 축 편집·정렬 등 좌표계를 바꾸는 기능과의 기존 상호 배제 규칙을 유지한다.
- UI 밖에서 원본·축·정렬 상태가 바뀌면 다음 클릭 또는 확정 시 스냅샷 불일치를 검출하고 재시작을 안내한다.
- 종류가 맞지 않는 보이는 형상을 클릭하면 그 클릭을 거부한다. 그 뒤에 있는 다른 점이나 메시를 대신 선택하지 않는다.
- 숨긴 형상은 피킹하지 않는다. 화면에 없는 형상을 이용하여 마커를 보정하지 않는다.
- 빈 공간 클릭과 종류 오류를 구분한다. 종류 오류는 사용자에게 이유를 보여준다.
- 차단 시 기존 마커, 현재 후보, 정렬 행렬, 확정 마커의 Undo 기록을 변경하지 않는다.

안내 문구 예시:

- `A 마커는 메시로 고정되어 있습니다. 점군에는 지정할 수 없습니다.`
- `P 마커는 점군으로 고정되어 있습니다. 점군을 표시한 뒤 쌍 지정을 시작하십시오.`
- `마커 입력 중에는 표시 대상을 바꿀 수 없습니다. 현재 쌍을 확정하거나 취소하십시오.`
- `입력 시작 이후 데이터 또는 축이 변경되었습니다. 쌍 지정을 다시 시작하십시오.`

### 4.4 기준의 수명

| 동작 | 종류 기준 처리 |
| --- | --- |
| 다음 쌍 생성 | 기존 A/P 기준 유지 |
| 기존 쌍 편집 | 편집 전 종류 유지, 한 쌍만 다른 종류로 변경 불가 |
| 일부 쌍 삭제 | 남은 확정 마커에서 같은 기준 유지 |
| 첫 쌍 입력 취소 | 확정 마커가 없으면 잠정 기준 해제 |
| 이후 쌍 입력 취소 | 기존 확정 마커 기준 유지 |
| 전체 초기화 또는 마지막 쌍 삭제 | A/P 기준 해제 |
| Undo / Redo | 복원된 마커와 임시 입력 상태에서 기준 재계산 |
| 모델 삭제로 마커 정리 | 기존 소유권 정리 규칙 적용 후 남은 목록으로 재계산 |
| 프로젝트 복원 | 복원된 확정 마커에서 기준 재계산 |

일반 작업에서 종류를 바꾸는 방법은 모든 대응쌍을 비운 뒤 다시 지정하는 것이다. 잠금 해제만 수행하여 서로 다른 종류의 기존 마커를 섞는 기능은 만들지 않는다.

## 5. 연결 메시 마커의 원본 참조

### 5.1 저장할 식별 정보

기존 `PickResult`, `SelectedPoint`, 저장용 마커 구조에 형상 출처를 추가한다.

| 필드 | 의미 |
| --- | --- |
| `model_id` | COLMAP 또는 독립 OBJ 소유 모델 ID |
| `geometry_source` | `MAIN`: 주 형상, `COMPANION`: 연결 메시 |
| `point_kind` | 기존 `COLMAP_POINT`, `MESH_VERTEX`, `MESH_SURFACE` |
| `source_point_id` | 원본 점·정점 ID 또는 원본 삼각형 ID |
| `local_position` | 선택한 원본 형상 좌표계의 실제 위치 |

기존 호출의 기본 출처는 `MAIN`으로 유지한다. 연결 메시 표면은 `COMPANION + MESH_SURFACE`로 저장한다. 독립 OBJ 표면은 `MAIN + MESH_SURFACE`다.

연결 메시를 별도 정렬 모델로 만들지 않으며, 메시 마커를 COLMAP 점 ID로 위장하거나 근처 희소 점으로 치환하지 않는다.

### 5.2 기존 표면 피킹 재사용

현재 `viewport/picking.py`는 독립 OBJ에서 원본 삼각형 BVH와 배정밀도 교차점 재계산을 사용한다. 모델 조회와 좌표 변환에 형상 출처를 전달하도록 확장한다.

- 피킹·저장 좌표 검증·마커 표시·정렬 입력이 같은 형상 해석 규칙을 사용한다.
- 연결 형상은 저장소의 연결 메시 데이터와 메시 축을, 주 형상은 기존 데이터와 주 형상 축을 사용한다.
- BVH 캐시에 소유 모델 ID와 형상 출처를 포함해 두 메시가 같은 캐시를 사용하지 않게 한다.
- 데이터 교체·삭제 시 관련 캐시를 제거한다. 축 변경은 원본 BVH를 재생성하지 않고 역변환 경로에 반영한다.
- COLMAP 점군의 기존 점 선택, 독립 OBJ 표면 선택, 중복 마커 검증을 유지한다.
- 역할별 종류 검증은 UI와 최종 선택·확정 로직 양쪽에서 적용한다. 버튼 비활성화만으로 제한하지 않는다.

BVH의 원본 삼각형 구성과 광선 교차 반환값은 [Blender 공식 BVHTree API](https://docs.blender.org/api/main/mathutils.bvhtree.html)를 참고하고, 실제 실험 Blender 5.2에서 검증한다.

## 6. 정렬 행렬과 COLMAP 적용

소유 모델 `i`에 대해 다음 변환을 사용한다.

- `N(i, 종류)`: 선택한 원본 형상에서 프로젝트 기준 축으로 가는 변환. 기존 개별 축·추가 회전을 포함한다.
- `A(i)`: 해당 데이터셋의 공통 정렬 변환
- `x`: 마커가 저장한 원본 형상의 동차 좌표

```text
마커의 프로젝트 좌표 = A(i) × N(i, 선택한 형상) × x
```

1. 모든 A 마커를 각 소유 모델의 공통 정렬과 해당 형상의 축으로 변환한다.
2. 모든 P 마커를 선택된 이동 모델의 공통 정렬과 해당 형상의 축으로 변환한다.
3. 최소 3쌍의 비공선 대응점으로 P를 A에 맞추는 변환 Δ를 계산한다.
4. 기존 스케일 사용 설정에 따라 강체 또는 균일 스케일 유사변환을 사용한다.
5. 기존 미리보기·ICP·승인 흐름에 결과를 전달하며, 최종 적용은 다음 합성으로 처리한다.

```text
새 P 공통 정렬 = Δ × 기존 P 공통 정렬
```

따라서 P 마커를 메시에서 지정해도 공통 정렬을 공유하는 COLMAP 점군·카메라·연결 메시가 함께 이동한다. 메시와 COLMAP의 원본 축이 다를 수 있으므로 원본 메시에서 구한 행렬을 축 변환 없이 COLMAP 좌표에 그대로 곱하지 않는다.

원본 점, 메시 정점, 카메라 원본 자세를 누적 수정하지 않는다. 출력은 기존 COLMAP 내보내기의 기준 좌표계 변환 경로를 재사용한다. COLMAP 카메라 자세는 world-to-camera 규약이므로 점 변환과의 일관성 및 재투영을 검증한다. 참고: [COLMAP 공식 출력 형식](https://colmap.github.io/format.html).

이미 존재하는 RC용 기본 축과 사용자 개별 축 설정을 존중한다. 이번 마커 기능이 같은 레이어 내부의 메시와 점군 사이의 별도 오프셋·스케일 오차를 자동 보정하는 기능은 아니다.

## 7. 마커 표시와 축 변경 후 결과 유효성

- 마커 표시 좌표도 원본 형상 출처에 맞는 축과 공통 정렬을 사용한다.
- 일반 확인 중 다른 형상으로 전환하면, 현재 표시 형상에 속한 마커만 뷰포트에 표시한다. 숨겨진 마커는 목록과 저장 데이터에 남는다.
- 원래 형상으로 돌아오면 같은 위치의 마커가 다시 표시된다.
- 정렬 입력 지문에는 마커의 형상 출처, 원본 ID·좌표, 관련 형상 리비전, 해당 축, 소유 모델 공통 정렬을 포함한다.
- 연결 메시 축을 바꾸면 그 메시를 참조한 마커 기반 미리보기와 결과·파생 품질 상태를 무효화하거나 재검증한다.
- 메시 마커를 사용하지 않은 희소 점군 직접 ICP 결과는 메시 축만 바꿨다는 이유로 무효화하지 않는다.
- 입력 중 축 변경을 막는 기존 규칙과 축 변경 Undo를 유지하고, 되돌린 상태의 입력 지문도 일치하는지 확인한다.
- 축 변경 시 마커 원본 좌표나 공통 정렬을 덮어써서 화면 위치를 억지로 유지하지 않는다.

## 8. 저장·복원과 이전 파일 호환

저장 스키마를 v5에서 v6으로 올리고 마커의 `geometry_source`를 저장한다. 역할별 지속 종류는 확정 마커에서 유도하며 중복 저장하지 않는다. 입력 중 표시 스냅샷은 임시 상태이므로 프로젝트 파일에 저장하지 않는다.

### 8.1 이전 마커

- v1~v5의 마커는 `geometry_source=MAIN`으로 읽는다. 기존 버전은 연결 메시 표면 마커를 생성하지 않았다.
- 기존 점군·독립 OBJ 정점·독립 OBJ 표면 마커 좌표와 원본 ID를 그대로 보존한다.
- 같은 역할에 점군과 독립 OBJ 마커가 섞인 이전 파일은 자동 삭제하거나 변환하지 않는다.
- 혼합된 파일은 데이터를 복원하되 `마커 종류 충돌` 상태를 표시하고 신규 지정·편집 확정·정렬을 차단한다. 쌍 삭제·전체 초기화·저장은 가능하게 한다.
- 삭제 후 역할별 종류가 일관되면 정상 상태로 돌아간다. 충돌 상태에서 다시 저장해도 기존 마커를 잃지 않아야 한다.
- 연결 형상 참조가 누락되거나 잘못된 파일은 기존 복원 오류 정책에 따라 처리하고, 현재 열린 세션을 부분적으로 덮어쓰지 않는다.

### 8.2 이전 표시 상태

이전의 두 불리언은 다음 순서로 단일 선택 상태로 정규화한다.

1. 유효한 한 형상만 켜져 있으면 그 선택을 유지한다.
2. 두 형상이 모두 켜져 있으면 해당 레이어를 참조한 기존 마커 종류가 하나로 일치할 때 그 형상을 우선한다. 판단할 수 없으면 연결 메시를 선택한다.
3. 두 형상이 모두 꺼져 있으면 위 우선순위로 유효한 하나를 선택해 두고 전체 눈 상태를 꺼서 기존 비표시 상태를 보존한다.
4. 연결 메시가 없으면 점군, 독립 OBJ이면 메시를 선택한다.
5. 원래 눈 상태가 꺼져 있으면 계속 숨긴다.

이전 표시 정책을 바꾸는 과정에서 저장된 축이나 공통 정렬은 변경하지 않는다.

### 13.1 구현한 동작

1. 연결 메시에도 기존 삼각면 BVH 피킹을 사용한다. 원본 면 ID·좌표와 `COMPANION` 출처를 저장하고 해당 메시의 축을 적용한다.
2. 점군·메시 아이콘은 레이어별 단일 선택으로 동작한다. 같은 아이콘을 다시 누르면 선택을 유지하고, 전체 숨김은 눈 버튼으로 처리한다.

4. 잘못된 종류 선택과 입력 중 대상 변경을 안내 후 차단한다. 확정·취소·편집·마지막 쌍 삭제·Undo/Redo에서 기준을 일관되게 복원한다.
5. 복수 레이어 선택을 유지하더라도 마커 입력 중에는 A 뷰와 P 뷰의 대상 형상을 각각 표시한다.
6. 기존 3점 정렬 계산과 미리보기·ICP·승인 흐름을 재사용한다. 각 원본 좌표에 해당 형상의 축을 적용하고 공통 정렬에 결과를 합성한다.
7. v6 저장과 v1~v5 복원을 지원한다. 이전 표시 상태를 단일 선택으로 이전하며, 이전 파일의 혼합 종류 마커는 보존하고 충돌을 안내한다.
8. 이전 정렬을 참조하는 메시 축이 변경되면 관련 품질 기록을 무효화하고, 축 Undo/Redo에서 관련 모델의 품질 기록도 함께 복원한다.

### 13.2 구현 중 확인하여 보완한 계약

ICP 승인은 기존 동작대로 마커 목록을 정리한다. 따라서 승인 후에도 사용한 형상을 알 수 있도록 `IcpAlignmentSeed`와 `AlignmentProvenanceRecord`에 `marker_geometry_dependencies`를 추가했다. 마커 기반 초기값에만 종속 출처를 기록하며, 직접 희소 ICP에는 남아 있는 마커를 임의로 연결하지 않는다.

종속 출처는 과거 정렬 기록이므로 A 모델이 삭제되어도 보존한다. 실제 마커의 원본 조회는 엄격하게 검증하되, 과거 감사 기록 때문에 삭제된 A 모델의 현존을 요구하지 않는다.

교차 검토에서 한 점군의 뒤쪽 점이 화면상 더 가깝다는 이유로 앞쪽 점을 후보에서 제외하여 중간 깊이의 메시를 선택하는 문제가 재현됐다. 실제 광선 피킹에서는 점군 내부와 형상 간 깊이 우선순위를 일치시키고, 광선이 없는 기존 명시적 테스트 입력의 화면 거리 우선 계약은 유지한다.

### 13.3 주요 변경 경계

- `marker_capture.py`: 입력 표시·원본·축·정렬 캡처와 유효성 검사
- `marker_geometry.py`: 주 형상·연결 메시 원본과 축의 공통 조회
- `state.py`, 마커·레이어 오퍼레이터, `ui/panels.py`: 종류 제한·단일 표시·사용자 안내
- `viewport/`: 출처별 피킹·마커 표시·역할별 그리기
- `alignment/`, `axis_settings.py`, `axis_settings_state.py`: 기존 계산 연계·승인 종속성·관련 품질의 원자적 복원
- `project_persistence/`: v6 출처·종속성 저장과 이전 형식 복원
- `test_env/manage.py`, `test_env/companion_checks.py`: 관련 소스 회귀와 설치본 실제 클릭 검증 연결

### 13.4 검증과 적용 상태

최종 피킹 수정까지 반영한 소스 회귀 31개 파일이 Blender 5.2의 별도 검증 프로필에서 모두 통과했다. 기존 3점 정렬, 네 가지 역할별 형상 조합, 다중 A, 역할 제한과 Undo/Redo, 출처 저장·복원, 카메라 재투영, 원본 보존 및 승인 후 축 종속성을 확인했다.

검증 결과는 실험 환경의 `outputs/source-marker-verification.json` 및 `outputs/tests/`에 기록한다. 전체 검증 목록은 기존 19개와 관련 마커·저장 12개를 포함하는 31개 파일이다.

설치본 GUI 검사에는 단일 형상·눈 상태 네 조합, 기존 축 팝업·Undo/Redo, 실제 A 메시/P 점군 클릭 3쌍, 입력 중 전환 차단, 역할 고정, 정렬 미리보기, 카메라 재투영과 원본 보존, v6 저장 검사를 추가했다.

실제 설치·GUI 검증은 실험 Blender를 종료한 뒤 기존 관리기의 `verify --gui`로 수행해야 한다. 실행 중 재설치 방지 검사는 우회하지 않는다. 이번 작업에서 원본 main, 사용자 입력 데이터, Git 커밋은 변경하지 않았다.

### 13.5 연결 메시 마커 번호 위치 오류 수정

사용자 화면에서 원형 마커는 메시 위에 있지만 P1·P2·P3 번호가 허공에 표시되는 오류를 확인했다. 원형 마커와 정렬 입력에는 형상 출처가 전달되지만, `viewport/labels.py`의 번호 목록·좌표 변환에는 출처가 빠져 연결 메시의 원본 위치에 주 점군 축이 적용되고 있었다.

- 확정·편집 후보의 번호 목록에 형상 출처를 전달한다.
- 번호 좌표에도 해당 형상의 축과 공통 정렬을 적용한다.
- 원 마커와 동일하게 형상 전환·눈 숨김 때 번호도 숨긴다.
- 기존 주 점군·독립 OBJ 호출의 기본 출처는 `MAIN`으로 유지한다.
- 마커 선택 좌표, 대응쌍, 정렬 계산 및 사용자 데이터는 변경하지 않는다.

실제 Blender 5.2의 화면 투영 함수를 이용한 회귀 두 개를 추가했다. 점군·메시 네 조합, A/P 두 역할, 미리보기 전후에서 번호의 화면 위치를 알려진 기대 좌표와 비교하고, 확정·편집 상태의 표시 전환과 눈 숨김을 검사한다. 기존 마커 상태와 뷰포트 회귀를 포함한 관련 파일 세 개가 모두 통과했다.

이번 수정 검증은 `outputs/marker-label-verification.json`에 별도로 기록했다. 앞선 31개 전체 회귀 보고서는 번호 수정 전 소스 기준이며, 최신 소스 전체·설치본 GUI 검증으로 간주하지 않는다. 현재 실행 중인 실험 Blender 때문에 설치본은 아직 갱신하지 않았다. 실험 실행기를 다시 실행하면 기존 절차대로 최신 소스를 재빌드·설치한다.

화면 투영에 월드 좌표가 필요하다는 계약은 [Blender 공식 화면 투영 문서](https://docs.blender.org/api/4.3/bpy_extras.view3d_utils.html) 및 설치된 Blender 5.2의 `bpy_extras/view3d_utils.py` 구현과 대조했다.

### 13.6 외부 정렬 엔진 모듈 로드 실패 수정

실제 실패 작업 `colmap_align_icp_8xc5hbo_`의 오류 파일은 `외부 ICP solver 모듈을 불러오지 못했습니다.`를 기록했다. 설치된 독립 CPython에서 동일한 모듈을 직접 불러오자 다음 경로로 `ModuleNotFoundError: No module named 'bpy_extras'`가 재현됐다.

`alignment.__init__ → alignment.runtime → marker_geometry → display_axes → bpy_extras.io_utils`

연결 메시 마커 구현에서 추가한 `marker_geometry`의 전역 축 타입 불러오기가 원인이다. 외부 Small GICP는 Blender와 분리된 Python에서 실행되므로 Blender 전용 모듈을 사용할 수 없다. 하위 모듈을 불러올 때 부모 패키지도 초기화되는 동작은 [Python 공식 importlib 문서](https://docs.python.org/3.12/library/importlib.html)와 일치한다.

- 축 타입은 정적 타입 검사 시에만 전역에서 참조하고, 실제 Blender 마커 형상 조회 함수 안에서 불러온다. 원본 축 타입 검증은 유지한다.
- 기존 `--check-environment`의 합성 검사에서 실제 정렬 모듈도 불러오도록 보완한다. 같은 의존성 오류는 실험 빌드 단계에서 검출된다.
- Blender 내부 회귀는 `bpy_extras`가 존재하는 환경이었고, 기존 외부 환경 검사는 Native 라이브러리 합성 연산만 확인하여 이번 패키지 의존성 누락을 검출하지 못했다.

검증 결과:

1. Blender 모듈이 없는 독립 CPython에서 실제 정렬 모듈 불러오기가 통과했다.
2. 실패 작업의 NPY 입력을 별도 출력 폴더에 복사하여 실제 Small GICP 작업을 재실행했다. 약 6.328초에 `SMALL_GICP_COMPLETED_PASS`로 완료했고, 결과 행렬·NPZ와 품질 `PASS`를 확인했다. 이번 입력의 스케일 추가 보정 단계는 `SKIPPED`였다.
3. 수정된 외부 환경 검사·합성 GICP와 연결 메시 마커 정렬·저장·Small GICP 회귀 세 파일이 모두 통과했다.
4. 사용자 원본 데이터, 실패 작업 입력 및 현재 Blender 세션에는 재현 결과를 적용하지 않았다.

재현 보고서는 `outputs/engine-replay-latest.json`, 최종 수정 소스 검증은 `outputs/engine-module-verification.json`에 기록했다. 현재 실행 중인 설치본에는 아직 수정이 적용되지 않았으며, 실험 실행기로 재시작해야 재빌드·설치된다.
