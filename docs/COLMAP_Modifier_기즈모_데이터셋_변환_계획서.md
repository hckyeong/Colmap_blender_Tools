# COLMAP Modifier 기즈모·데이터셋 변환 계획서

- 작성일: 2026-09-12
- 상태: **소스 구현 및 자동 검증 완료 / 실제 화면 조작감 검수 대기**
- 기준: COLMAP Tools 0.3.41 및 현재 작업 트리
- 요청: Modifier에 Align의 기즈모 기능 추가
- 현행 규칙: [완료 기능·구조 통합 문서](README.md), [Modifier 매뉴얼](manual/MODIFIER.md), [Align 매뉴얼](manual/ALIGN.md)

## 1. 목표와 적용 범위

Modifier에서 가져온 **현재 COLMAP 데이터셋 전체를 점군과 카메라가 함께 이동·회전·균일 확대되도록** 한다. Align의 기즈모 조작 방식을 따르되, 확정 결과는 Modifier의 편집 이력·저장·내보내기·Projection Paint 데이터 업데이트에 연결한다.

이번 계획은 단일 데이터셋 전체 변환을 대상으로 한다. 선택한 점만 이동하거나 개별 카메라 자세를 바꾸는 기능, Align의 A/P 레이어·마커·ICP·OBJ 기능은 포함하지 않는다. 기존 점·카메라 선택은 삭제와 검토에 계속 사용한다.

| 기능 | 계획 |
|---|---|
| 이동 | 화면의 전역 X/Y/Z 축 화살표 및 G 조작 |
| 회전 | 전역 X/Y/Z 축 회전 링 및 R 조작 |
| 배율 | 중앙 핸들 및 S 조작, 양수 균일 배율만 허용 |
| 피벗 | 기본은 데이터셋 원점, 점 더블클릭으로 변경 |
| 회전 중심 | 점 더블클릭 시 뷰포트 회전 중심도 함께 이동 |
| 표시 | N 패널에서 기즈모 표시 켜기·끄기 |
| 이력 | 한 번의 확정 조작을 전용 Undo 한 단계로 기록 |
| 출력 | 점 좌표와 카메라 자세에 같은 변환을 반영 |

비균일 배율·반전·전단 변환은 지원하지 않는다. 숫자 입력·스냅·로컬 축 등 추가 조작 체계는 이번 범위에서 확장하지 않는다. 수동 배율에는 Align ICP의 ±10% 보정 범위를 적용하지 않는다. 다만 0 이하·비유한 값·출력 표현 범위를 벗어나는 변환은 확정할 수 없다.

## 2. 현재 코드에서 확인한 구조

### Align

- `tools/align/operators/layer_transform.py`에 기즈모, 모달 조작, 단축키, 피벗 처리가 있다.
- `tools/align/alignment/layer_transform.py`와 `types.py`가 변환 계산과 양수 균일 배율 계약을 다룬다.
- 선택 레이어·A/P 역할·Align 세션·미리보기·Journal에 결합되어 있다.
- 드래그 중 행렬을 미리 적용하고 확정과 취소를 구분한다.

### Modifier

- `modifier_runtime_domain.py`와 `runtime_state.py`의 독립 Runtime Domain이 실제 편집 상태를 소유한다.
- Blender 점군·카메라 오브젝트와 표시용 루트는 Domain에서 만든 파생 표시다.
- `axis_display.py`는 표시 축 변경 시 루트의 `matrix_world`를 다시 설정한다. 기즈모가 이 오브젝트 행렬만 수정하면 축 변경·표시 재생성 때 결과가 유실될 수 있다.
- `edit_types.py`, `edit_journal.py`, `edit_replay.py`, `domain_persistence.py`는 현재 삭제 중심의 이력과 저장 계약을 갖는다. 변환을 새 편집 종류로 추가해야 한다.
- `projection_snapshot_provider.py`가 확정 데이터를 불변 값으로 복사해 Painter에 제공한다. 동기 생성 경로와 단계별 생성 경로를 모두 다룬다.
- Export 성공 시 출력 결과를 새 기준 데이터로 삼고 편집 이력을 비운다.

도구 사이 직접 import를 금지하는 현행 규칙을 유지한다. Align의 조작·수학 계약을 참고해 Modifier 전용 기즈모와 변환 어댑터를 작성한다. 이번 작업 때문에 Align Runtime을 공용화하거나 기존 Align 공개 API를 변경하지 않는다.

## 3. UI와 조작

### N 패널

기존 `COLMAP Import`와 `Point Selection` 사이에 `Dataset Transform` 패널을 둔다. 앞서 맞춘 N 패널 폭을 유지하고 긴 가로 버튼 배치를 추가하지 않는다.

```text
▼ Dataset Transform
  대상: 전체 점군·카메라
  ☑ 기즈모 표시
  [이동] [회전] [배율]
  [피벗을 데이터셋 원점으로]
```

- 데이터가 준비되면 기즈모 표시 기본값은 켜짐이다.
- 표시 토글은 화면 핸들만 숨긴다. 허용된 상태에서는 패널 버튼과 G/R/S를 사용할 수 있다.
- 패널 버튼은 Blender 기본 키맵과 Industry 키맵 모두에서 같은 기능을 제공한다.
- 점·카메라 편집 중이거나 데이터 복원·장기 작업 중이면 변환 버튼을 비활성화하고 이유를 표시한다.
- 데이터가 없는 상태에서는 비활성화한다.

### 기즈모와 단축키

- 전역 축 기준 이동·회전 핸들과 중앙 균일 배율 핸들을 표시한다.
- 이동·회전 모달에서 X/Y/Z로 축을 제한한다. 배율에는 축별 크기 변경을 허용하지 않는다.
- 핸들 드래그는 마우스 왼쪽 버튼을 놓으면 확정한다.
- G/R/S 또는 패널 버튼으로 시작한 모달은 왼쪽 클릭 또는 Enter로 확정한다.
- Esc 또는 오른쪽 클릭은 시작 전 행렬로 복원한다.
- 포커스 상실·작업공간 전환·파일 로드·세션 종료·Domain 교체 시 미확정 조작을 취소한다.
- 초기값과 실질적인 차이가 없으면 이력을 추가하지 않는다.

### 피벗

- 기본 피벗은 변환된 데이터셋 원점이다.
- 점 더블클릭은 **일반 탐색 상태**에서만 처리한다. 기존 점·카메라 편집 모드에서는 해당 모드의 입력을 유지한다.
- 실제로 표시 중인 점을 선택한 경우에만 피벗과 현재 뷰포트 회전 중심을 바꾼다. 빈 공간 더블클릭은 변화가 없다.
- 피벗은 기준 좌표와 점 ID를 보관하고 현재 데이터셋 변환으로 표시 위치를 계산한다.
- 피벗 이동 자체는 COLMAP 데이터를 바꾸지 않으므로 편집 Revision이나 Journal을 증가시키지 않는다.
- 선택했던 점이 삭제되면 데이터셋 원점으로 복귀한다. 파일 재진입 시 기본 피벗으로 시작하며 피벗을 별도의 영구 데이터 편집으로 저장하지 않는다.

## 4. 표시 축과 실제 데이터 변환

다음 두 행렬을 분리한다.

- `D`: 기존 COLMAP 표시 축 변환. 화면 표시 설정이다.
- `T`: 기즈모로 확정한 데이터셋 변환. 원본 COLMAP 좌표계의 양수 균일 배율·회전·이동이며 초기값은 단위행렬이다.

기준 좌표를 `p`라고 하면 화면 위치는 다음과 같다.

```text
p_view = D × T × p
```

화면의 전역 축으로 기즈모 변화량 `Δ`를 만들었을 때는 다음과 같이 원본 좌표계로 환산한다.

```text
T_preview = inverse(D) × Δ × D × T_start
```

`Δ`에는 피벗을 기준으로 한 이동·회전·배율 합성이 포함된다. 이렇게 하면 표시 축 프리셋을 바꿔도 확정된 데이터 변환 `T`가 유지된다. 내보내기에는 `T`를 적용하고 표시 전용 `D`를 포함하지 않는다.

점군과 카메라의 표시용 부모에는 중앙화한 표시 갱신 경로로 `D × T`를 적용한다. 카메라 자체의 기존 로컬 축 변환은 유지한다. 모든 재생성·Undo 후 재동기화·파일 복원 경로가 같은 조합을 사용하도록 한다.

## 5. Domain·메모리·피킹

- 현재 삭제 편집이 적용된 기준 좌표 레코드와 확정 변환 `T`를 Domain에서 관리한다.
- `T`는 변환 이력에서 재생 가능한 상태다. Scene 속성과 Blender 오브젝트는 이를 표시하는 파생 값으로 둔다.
- 드래그 중에는 작은 미리보기 행렬만 변경한다. 전체 점 좌표 배열이나 카메라 레코드를 매 마우스 이벤트마다 복사·재계산하지 않는다.
- 순수 변환 확정 때도 전체 재구성을 두 벌로 상주시킬 필요 없이 행렬과 이력만 보관한다.
- 좌표가 필요한 소비자에는 변환된 점·카메라 값을 구하는 명시적 경로를 제공한다. 기존 `current_reconstruction`을 읽는 호출부를 확인해 기준 좌표와 변환 결과를 혼동하지 않도록 한다.
- 내보내기와 Painter 전달은 필요한 레코드 값을 작업 예산에 맞춰 생성한다. 기존 출력·전달 버퍼의 메모리 비용은 별도로 측정한다.
- 피킹·화면 투영·카메라 검토는 동일한 최종 행렬을 사용한다. Blender가 부모 변환을 이미 반영한 경로에는 중복 적용하지 않는다.
- 기준 좌표 기반 공간 인덱스는 가능한 한 재사용한다. 질의 좌표를 기준 공간으로 환산하고 거리와 배율의 관계를 반영한다.
- 변환은 ID·관측 관계를 바꾸지 않는다. 관계 인덱스를 다시 만들 필요 없이 현재 편집 Revision에 맞는 유효성 토큰을 갱신한다.

## 6. Undo·Redo·저장·복원

### 변환 명령

전용 변환 명령에 이전·이후 `T`, 작업 ID, Dataset 식별자, 이전·이후 Revision을 기록한다. 한 번의 드래그 확정이 명령 하나가 된다. 전체 점 배열의 전후 복사본을 Journal에 넣지 않는다.

현재 이력의 구체 타입 검사와 `Revision == 작업 수` 계약을 함께 확장한다. 삭제와 변환을 섞어 실행한 뒤 Undo·Redo·전체 편집 초기화를 해도 적용 순서가 보존되어야 한다.

### 저장 계약

- 확정된 변환 명령을 편집 이력에 직렬화하고 복원 시 재생한다.
- 새 작업 종류에 맞춰 이력·Payload 스키마와 해시 검증을 갱신한다.
- 현재 지원되는 이전 저장 형식은 변환이 없는 상태인 `T = I`로 읽을 수 있도록 후방 호환한다. 이미 지원 종료한 Legacy 파일의 복구 범위를 임의로 넓히지는 않는다.
- 미확정 드래그 값은 저장하지 않는다. 저장 시 확정 Domain을 직렬화하고 표시 미리보기가 저장본의 권위가 되지 않도록 한다.
- 기존 규칙대로 원본 COLMAP 파일 의존성은 유지한다. 이번 작업으로 COLMAP 원본 내장 기능을 추가하지 않는다.
- Blender Global Undo가 파생 표시를 되돌렸을 때도 현재 Domain의 확정 `T`로 재동기화한다.

## 7. COLMAP 출력과 카메라 자세

COLMAP은 이미지 자세를 월드에서 카메라로 가는 회전·이동으로 저장한다. 이 규약에 따라 아래 변환식을 사용한다. 공식 규약을 바탕으로 도출한 구현 계약이며, 알려진 좌표와 재투영 시험으로 검증한다. [COLMAP 출력 형식](https://colmap.github.io/format.html#images-txt)

```text
데이터셋 변환: p' = s × Q × p + b
기존 카메라:   x_camera = R × p + t

새 카메라 회전: R' = R × transpose(Q)
새 카메라 이동: t' = s × t - R' × b
새 카메라 중심: C' = s × Q × C + b
```

- 점과 모든 이미지 자세를 함께 변환한다. 회전에 배율 성분이 들어가지 않도록 분리한다.
- 카메라 내부 파라미터·이미지 크기·2D 관측 좌표·연결 ID·RGB는 유지한다. 재투영 오차의 픽셀 단위 값에 공간 배율을 곱하지 않는다.
- `frames`가 있으면 월드→리그 자세도 변환한다. 리그 내부 센서의 상대 회전은 유지하고 상대 이동에는 균일 배율을 적용한다.
- 프레임과 센서 자세의 합성이 이미지 자세와 일치하는지 검사한다. `rigs`·`frames`가 없는 기존 입력도 유지한다. [리그·프레임 출력 규약](https://colmap.github.io/format.html#frames-txt)
- 변환만 수행한 데이터셋도 내보내기가 가능한 편집 상태로 처리한다.
- 기존 백업·준비·검증·출력 확정 절차를 유지한다.
- Export 성공 시 변환된 출력 레코드를 새 기준으로 채택하고 `T = I`, 빈 Journal로 전환한다. 두 번째 Export에서 같은 변환이 다시 적용되지 않아야 한다.
- 실패·취소 시 기존 확정 Domain·변환·Journal을 유지한다.

## 8. Projection Paint 전달

`projection_snapshot_provider.py`의 동기 생성과 단계별 생성 모두 확정 `T`를 적용한 점 좌표·이미지 자세를 내보내도록 한다. 값 생성과 내용 지문 계산은 동일한 변환 결과를 사용한다.

- 변환 이력 확정 시 Revision·HistoryHash도 바뀌므로 기존 출처 검사를 통해 변경을 감지한다.
- 전달 시작 시 출처와 확정 `T`를 고정한다. 도중에 출처가 바뀌면 새 Snapshot을 확정하지 않는다.
- 드래그 중 업데이트 시작은 차단한다. 이미 진행 중인 전달의 출처가 변하면 기존 실패·이전 Snapshot 보존 절차를 따른다.
- Painter의 `COLMAP 데이터 업데이트`를 눌렀을 때만 복사한다. 기존 Painter Snapshot은 자동 변경하지 않는다.
- Painter의 자체 표시 축은 유지하고 `T`를 이중 적용하지 않는다.
- Paint 대상 메시·텍스처·레이어는 기존 독립 경계를 유지한다. 새 COLMAP 위치로 갱신하면 Paint 대상 메시와의 위치 관계는 사용자가 확인할 수 있어야 한다.

## 9. 입력·수명·충돌 방지

G/R/S와 더블클릭은 Modifier가 소유한 활성 화면의 **3D 뷰포트 WINDOW 영역**에서만 처리한다. N 패널 입력 칸, 타임라인, 다른 작업공간의 단축키를 가로채지 않는다.

다음 상태에서는 새 변환을 시작하지 않는다.

- 데이터 Import·복원·Export 진행 중
- 점 또는 카메라 편집 모드와 미확정 편집·필터 처리 중
- 다른 변환·Undo·Redo·초기화 트랜잭션 진행 중
- Domain이 준비되지 않았거나 읽기 전용인 상태

변환 진행 중에는 삭제·축 프리셋 변경·Export·편집 모드 진입 등 충돌하는 동작을 막는다. 작업공간 교대와 파일 로드는 미확정 변환을 정식 취소한 뒤 진행한다.

모달 시작 시 Window·Screen·Domain UUID·Generation·Revision을 고정하고 유효성을 확인한다. 등록 실패·애드온 해제 시 자기 기즈모·키맵·Handler만 해제하며, 재등록으로 중복 입력이 생기지 않도록 한다.

## 10. 구현 순서와 대상

| 단계 | 주요 대상 | 완료 기준 |
|---|---|---|
| 1. 변환 데이터 계약 | Modifier `core`의 변환 수학, `edit_types`, `edit_journal`, `edit_replay`, `domain_persistence`, Blender `runtime_state`·Domain | 점·카메라·리그 수학 검증, 삭제와 섞인 Undo·복원 통과 |
| 2. 표시·조회 연결 | `axis_display.py`, 점·카메라 표시 재생성, 피킹·카메라 검토 경로 | 표시 축 변경·표시 재생성 후 동일한 변환 유지 |
| 3. 기즈모·UI | Modifier 전용 기즈모·모달 모듈, `panels.py`, 속성·입력 가드·생명주기 | 핸들·버튼·단축키·피벗·취소·충돌 차단 동작 |
| 4. 출력·전달 | Export 준비·검증·`export_completion.py`, `projection_snapshot_provider.py` | 출력에 한 번만 적용, Painter 수동 업데이트에 반영 |
| 5. 통합 검증·문서 | Modifier Core·Blender 검사, 도구 공존 검사, 사용자 매뉴얼 | 저장·출력까지 일치하는 기능을 검증하고 매뉴얼 갱신 |

위 경로는 `tools/modifier/` 아래의 기존 구조를 기준으로 한다. 새 모듈 이름은 구현 시 해당 계층의 명명 규칙에 맞춘다. 단계 3의 화면 조작만으로 기능을 완료 처리하지 않는다. 단계 4까지 연결한 후 사용자에게 사용할 수 있는 기능으로 제공한다.

이번 계획 작성에는 제품 코드 수정·설치본 교체·버전 증가·커밋·푸시를 포함하지 않는다.

위 문장은 계획 작성 당시의 범위다. 이후 사용자 구현 승인으로 아래 작업을 수행했고, 추가 설치 승인에 따라 0.3.42 빌드와 설치본 교체까지 완료했다. 커밋·푸시는 수행하지 않았다.

| 이력 | 삭제→변환→삭제→Undo→Redo→초기화에서 좌표·삭제 ID·Revision·해시가 일치함 |
| 취소 | Esc·포커스 상실·세션 이동 시 확정 데이터와 이력이 변경되지 않음 |
| 저장 | 변환 후 파일 재실행 결과가 같고 현재 지원되는 기존 파일은 단위 변환으로 복원됨 |
| Export | TXT·BIN 재읽기 결과가 확정 변환과 일치하고 두 번 내보내도 중복 적용되지 않음 |
| 실패 | 출력·전달 중 실패나 출처 변경 시 이전 확정 상태를 유지함 |
| Painter | 수동 업데이트 전에는 기존 Snapshot 유지, 업데이트 후 변환된 점과 카메라 반영 |
| 입력 | 기본·Industry 키맵 모두 사용 가능하며 편집 모드·다른 도구·패널 문자 입력과 충돌하지 않음 |
| 성능 | 대용량 점군에서도 드래그마다 전체 좌표 복사·공간 인덱스 재생성이 발생하지 않음 |

성능은 서로 다른 점 수의 데이터로 드래그 지연·확정 시간·추가 메모리를 측정한다. 구현 전 특정 FPS나 메모리 수치를 보장하지 않는다. 단순 부모 행렬 갱신에도 Blender 의존성 그래프 비용은 생길 수 있으므로 실제 표시 부하를 확인한다.

사용자 화면 조작과 캡처를 자동으로 수행하지 않는다. 자동 검증은 Core와 Blender 배경 실행으로 진행하고, 기즈모의 조작감·시각적 겹침은 사용자가 직접 확인할 항목으로 별도 기록한다.

## 12. 구현·검증 기록

2026-09-12에 Modifier 전용 기즈모·행렬 수학·편집 이력·저장 복원·출력·Painter 전달을 구현했다.

- 실제 편집 진입점은 `tools/modifier/blender/edit_workflows.py`의 `commit_dataset_transform(context, matrix)`다. Domain 모듈에서 UI·편집 흐름을 역참조하지 않도록 의존 방향을 유지했다.
- 삭제 작업 스키마 2는 유지하고 변환 작업에는 스키마 3을 추가했다. Payload 외피 필드는 그대로여서 외피 버전 1을 유지한다. 이전 삭제 전용 Payload는 단위 변환으로 복원한다.
- 순수 변환 확정·Undo·Redo는 기존 Point Mesh와 기준 좌표를 유지하고 루트 행렬만 갱신한다. 드래그 시작 시 표시 루트를 한 번 수집하여 마우스 이벤트마다 전체 오브젝트를 탐색하지 않는다.
- 출력용 좌표 변환은 PREPARE 단계에서 시간 예산에 따라 나누어 실행한다. 출력 성공 후 새 기준 좌표로 표시를 재구성한다.
- 저장·출력 연계 검사에서 Export 뒤 이미지 경로 Manifest가 유실되어 Painter 업데이트가 막히는 문제를 재현했다. 이미 검증된 경로를 새 출력 출처와 연결해 유지하도록 수정했다.
- 표시 축 변경 취소와 키 입력은 콜백 등록으로 연결해 모듈 순환 의존을 제거했다.
