# Artec KD 생성·입력 준비 추적 및 개선 검증

2026-10-21 · `codex/artec-align-engine` · 네이티브 엔진 `1.2.0`

**실제 Artec Align에서 확인한 공간 중간값 KD 분할과 입력 버퍼 공유 원칙을 적용했다. 같은 두 메시에서 전체 시간 중앙값은 25.2~27.4%, KD 생성은 약 52% 감소했다. 변경 전후 최종 정렬 행렬과 독립 표면 오차는 같았다. 새 엔진 18회 모두 수렴·PASS이며 REVIEW는 없었다.**

## Artec에서 확인한 동작

사용자가 같은 두 모델로 Align을 실행한 2026-10-21 11:16:47.327~11:16:52.554 KST의 관측을 사용했다. 대상은 Artec Studio 16 Professional 16.0.8.2, 프로세스 24004, 실행 모듈 기준 주소 `0x7ff6d6a80000`이다.

### KD 생성

호출 경로는 다음과 같다. 주소는 실행 파일 기준 RVA다.

```text
모델별 준비 0x1c44110
  → 준비 래퍼 0x21dfba0
  → 색인 생성·복사 0x21a36b0 / 0x21a7a50
  → 원본 표면 참조와 번호 배열 준비 0x21a2580
  → 루트 생성 0x1df6f40
  → 재귀 분할 0x1df92a0
```

`0x1df92a0`의 정적 분석에서 확인한 규칙:

1. 원본 점 번호를 따라 경계상자를 구한다. 좌표는 단정도 세 성분, 점 번호는 64비트 배열이다.
2. 경계상자의 가장 긴 축을 고른다. 길이가 같으면 X, Y, Z 순서를 우선한다.
3. 분할 위치는 `(최솟값 + 최댓값) / 2`다. 단정도 경계를 배정도로 승격해 계산한다.
4. 번호 배열을 양쪽 끝에서 훑어 **중간값 이하 / 중간값 초과**로 나눈다. 점 개수를 반씩 맞추는 중앙값 선택은 없다.
5. 점 수가 16을 넘고 양쪽 구간이 모두 비어 있지 않을 때 재귀 분할한다. 분리할 수 없는 좌표는 16점을 넘는 잎이 될 수 있다.
6. 해당 함수는 왼쪽·오른쪽을 순차 호출한다. 두 모델의 외부 준비 작업은 서로 다른 스레드에서 관측됐지만, 단일 트리의 재귀 생성이 병렬이라는 근거는 없다.

실제 실행에서도 개수 중앙값과 다른 분할이 확인됐다.

| 입력 | 원본 점 수 | 루트 왼쪽 / 오른쪽 | KD 생성 시간 |
|---|---:|---:|---:|
| 작은 원본 표면 | 188,400 | 72,852 / 115,548 | 17ms |
| 큰 원본 표면 | 10,173,478 | 3,720,077 / 6,453,401 | 1,003ms |
| 후속 변환된 큰 표면 | 10,173,478 | 3,720,010 / 6,453,468 | 974ms |
| 후속 변환된 작은 표면 | 188,400 | 72,852 / 115,548 | 16ms |

각 트리 상위 3단의 분할 7개씩, 총 **28개**를 검증했다. 모두 최장축·중간값 경계·자식 점 수 합·번호 구간 연속성 조건을 만족했다. 전체 노드를 실시간으로 훑은 것은 아니다. 네 번 모두 잎 기준 16, 법선 원뿔 설정 1을 관측했다.

### 입력 준비와 복사 범위

입력 준비 2회와 색인 복사 4회에서 **표면 객체, 좌표 버퍼, 삼각형 버퍼, 법선 버퍼의 주소와 원소 수가 동일**했다. 준비 단계가 좌표·법선 배열을 다시 복사하지 않고 참조를 넘긴다는 관측이다. 정적 분석에서도 공유 참조의 수명 카운터와 점 번호 배열 할당을 구별할 수 있었다.

그러나 후속 정렬 작업에서 사용하는 두 표면은 원본과 **다른 버퍼 주소**였다. 따라서 Artec 전체 입력 처리를 무복사라고 볼 수 없다. 이번 실행에서는 전체 점 수가 유지된 새 표면과 새 트리가 만들어졌다.

정적 분석에서 작업 함수 `0x1c433c0`의 가상 호출, 래퍼 `0x21dfd80`, 표면 합성 준비 경로 `0x21dc6e0 → 0x21c3080 → 0x21c9ff0`를 추가로 확인했다. 마지막 함수는 기존 표면과 변환 목록을 받아 새 표면을 준비하고 `0x2331d80`에 넘긴다. **이번 동적 관측은 준비·색인 복사·KD 생성 진입점에 한정**되며, 이 합성 함수의 개별 호출과 내부 복사 횟수까지 실측한 것은 아니다. 정적 후보 경로와 실행 중 새 버퍼 관측을 구분한다.

작은 표면의 준비 시간은 18ms, 큰 표면은 1,030ms였다. 큰 표면의 준비 대부분이 그 안에서 수행하는 KD 생성 1,003ms였다. 법선이 이미 들어 있는 Artec 표면과 작업마다 법선을 계산하는 현재 Blender 경로의 준비 비용은 다르다.

## 브랜치에 반영한 변경

- 기존 `std::nth_element`의 **점 개수 중앙값 분할**을 최장축의 **공간 중간값 분할**로 교체했다. 원본 번호 배열만 재배치한다. 번호 배열 용량도 원본 점 수로 미리 확보한다.
- 파일 적재 결과를 별도 Eigen 좌표 배열로 복사하던 과정을 제거했다. `std::array<double,3>` 배열의 소유권을 넘기고 `Eigen::Map`으로 읽는다. KD와 법선 계산은 이 좌표 버퍼를 공유한다.
- 명시 법선 입력도 같은 방법으로 적재 버퍼를 재사용한다. 삼각형에서 생성하는 법선은 소유 버퍼에 누적·정규화한다.
- 동일 좌표처럼 분리 불가능한 큰 잎에서도 취소 요청을 확인한다.
- 결과에 `kd_build_policy=LONGEST_AXIS_SPATIAL_MIDPOINT`, `input_buffer_policy=OWNED_PACKED_F64_EIGEN_MAP`, 엔진 버전 `1.2.0`을 기록한다.

Eigen 객체의 메모리 배치를 추측해 파일 바이트를 덮어쓰지 않는다. 표준 값 배열의 연속 저장 크기와 단순 복사 가능 조건을 컴파일 시 검사한다. Eigen 뷰는 소유 배열보다 먼저 소멸하며 트리가 임시 버퍼를 참조하는 생성은 금지했다. 기존 버퍼를 별도 데이터 복사 없이 계산에 연결하는 방식은 [Eigen 공식 Map 문서](https://eigen.tuxfamily.org/dox/group__TutorialMapClass.html)를 따른다.

원본점 전체, 배정도 좌표·계산, 정확 최근접 적격점 검색, 거리 동률의 원본 번호 우선, 법선·반경·먼 5% 제거, 스레드 설정과 [상대 변화 종료식](COLMAP_Align_Artec_종료식_적용검증.md)은 유지했다. 점군끼리와 점군–메시의 기존 계약도 유지한다. Python 작업·네이티브 작업 프로토콜과 `point-kd-icp-v2`는 그대로다.

Artec은 단정도 경계를 더해도 배정도 범위 내에 있지만, 현재 엔진은 배정도 좌표를 보존한다. 따라서 중간값은 경계를 각각 절반으로 나눠 더해 극단값의 덧셈 오버플로를 피한다. Artec의 단정도 저장, 법선 원뿔 가지치기, 여러 트리 생성, 최저 오차 후보 반환까지 복제한 것은 아니다.

## 같은 두 모델의 비교 방법

- 작은 모델: 188,400점·357,749면. 큰 모델: 10,173,478점·20,128,488면. 합계 **20,486,237면**.
- 사용자 `test.align.blend`를 별도 Blender 5.2.0 LTS 백그라운드 프로세스에서 복원했다. 열린 사용자 장면이나 원본 파일을 저장·변경하지 않았다.
- 이전 종료식 적용 완료본의 네이티브 `1.1.0`과 새 `1.2.0`을 비교했다. Python 정렬 코드의 모든 `icp*.py`가 이전 배포본과 바이트 단위로 동일하다. 양쪽 매개변수·종료 허용치·31스레드도 같다.
- 정렬 상태, Z축 0.5°와 이동 `(0.6, −0.4, 0.2)` 추가, 기준·이동 역할 반전의 세 조건을 사용했다.
- 조건마다 엔진별 준비 실행 1회 후 순서를 교차하여 **각각 5회 측정**, 총 36회 실행했다. 준비 실행은 시간 통계에서 제외했다.
- 시간은 입력 준비 시작부터 미리보기 결과 검증 완료까지다. 프로젝트 복원·화면 그리기는 제외하며, 측정 중 다른 빌드나 성능 작업을 병행하지 않았다.
- 이전 실행 파일의 해시·최종 행렬이 [직전 검증](COLMAP_Align_Artec_종료식_적용검증.md)과 같은지 확인했다.

### 어느 단계가 빨라졌는가

정렬된 상태의 5회 중앙값이다. 단계별 중앙값의 합은 전체 중앙값과 정확히 일치하지 않을 수 있다.

| 단계 | 이전 | 개선 후 | 해석 |
|---|---:|---:|---|
| KD 생성 | 2.031초 | **0.972초** | 약 52.1% 감소, 개선 대부분을 차지 |
| 네이티브 입력 적재·유한성 검사 | 0.248초 | **0.212초** | 약 14.5% 감소 |
| 법선 생성 | 0.401초 | 0.408초 | 거의 같음 |
| 대응점 검색 | 0.099초 | 0.097초 | 거의 같음 |
| 대응점 제거 | 0.053초 | 0.053초 | 거의 같음 |
| 네이티브 전체 | 2.940초 | **1.855초** | 약 1.09초 감소 |
| Blender 입력 준비·작업 시작 | 0.688초 | 0.670초 | Python 코드는 동일 |

기존 중앙값 선택에는 매 노드의 좌표 비교와 순서 선택 작업이 필요했다. 새 방식은 경계상자로 정한 위치에 대해 양방향 선형 분할한다. 원본점 감소나 반복 횟수 감소로 빨라진 결과가 아니다.

큰 모델에서 약 244MB의 좌표 중간 배열 복사를 제거했지만, 작업 트리의 관측 최대 작업 집합 중앙값은 **761.1→757.2MiB**로 거의 같았다. 법선·KD·번호 배열이 함께 존재하는 후반 단계가 최대 메모리를 결정하기 때문이다. 이는 0.1초 간격 표본 관측이며 정확한 동시 최고값이나 전체 시스템 메모리 절감량은 아니다.

남은 비용은 KD 생성 약 0.97초, 법선 약 0.41초, 적재 약 0.21초와 Python의 준비·해시·프로세스 기동·결과 확인이다. **Python 불변 스냅샷과 작업 파일 전달까지 제거한 것은 아니다.**

## 독립 표면 정확도

기존과 같은 양방향 표면 표본 각 30,000개와 고정 겹침 마스크 **59,187개**를 사용했다. 표본·마스크 해시가 직전 검증과 일치한다. 평가기는 정점 거리가 아닌 삼각형 표면 최근접 거리를 계산한다. 단위는 프로젝트 세계좌표이며 mm로 단정하지 않는다.

| 조건 | 표면 RMS 이전 = 이후 | 95백분위 이전 = 이후 | 최종 행렬 |
|---|---:|---:|---|
| 정렬 상태 | 1.4838016324 | 3.6283410754 | 정확히 동일 |
| 회전·이동 추가 | 1.4838172991 | 3.6273437780 | 정확히 동일 |
| 역할 반전 | 1.4838016324 | 3.6283410754 | 정확히 동일 |

각 조건의 모든 반복에서 변경 전후 최종 행렬이 원소별로 정확히 같았다. 독립 RMS·95백분위와 기존의 양방향 정확도 기준도 모두 통과했다. 같은 최종 행렬은 같은 표면 거리 결과를 재사용하며, 서로 다른 변환을 같은 결과로 취급하지 않는다.

이 검증은 **직전 브랜치 엔진 대비 정확도 유지**를 뜻한다. Artec의 이번 최종 변환을 내보내 독립 평가한 것은 아니므로 Artec과 정확도가 같다고 주장하지 않는다.

## Artec 실측과의 비교 범위

이번 Artec 관측에서 큰 표면 KD 생성은 1.003초와 0.974초였다. 개선 후 엔진의 약 0.96~0.97초와 비슷한 범위다. 다만 Artec은 단정도 저장·법선 원뿔 설정·복수 트리 생성이고 현재 엔진은 배정도·대상 트리 한 번 생성이므로 같은 작업량의 엄격한 비교는 아니다.

Artec의 Align 진입부터 작업 종료까지 관측 간격은 5.227초, 내부 작업 함수는 4.188초였다. 사용자가 현재 정렬된 Artec 장면에서 실행한 값이며, 초기 배치·입력 준비 범위·계측 비용이 Blender 실험과 다르다. **이 수치로 전체 엔진이 Artec보다 빠르다고 결론 내리지 않는다.** Artec 시간은 한 번의 계측 실행이고 타이머 해상도는 1ms다.

## 검증·배포 산출물

- 정확 KD 검색의 무작위 전수 비교 500회, 적격점·동률·자기 제외·편향 분포·중복 좌표 2만 점·취소·버퍼 주소 공유 검증 통과.
