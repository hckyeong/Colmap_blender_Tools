# Align 화면 ID·깊이 기반 마커 선택

## 변경 범위와 계약

`codex/artec-align-engine`의 마커 표면 선택을 GPU 정수 삼각형 ID·깊이 읽기로 교체한다. 기존 피벗의 BVH 경로, COLMAP 점 선택, 원본 데이터, 정렬 엔진과 저장 형식은 유지한다.

- 표시용 GPU 배치가 사용하는 불변 프록시의 원래 삼각형 순서를 그대로 사용한다. 재질별 분할 배치의 primitive 번호를 원본 ID로 오인하지 않는다.
- 무텍스처 메시의 전체 면 배치를 재사용한다. 재질별로 나뉜 메시도 표시 배치를 그대로 사용하고, 읽어 온 표시 순서 번호만 원본 삼각형 번호로 복원한다. 후속 [GPU 버퍼 공유 구현·검증](COLMAP_Align_GPU_버퍼_공유.md)을 따른다.
- 클릭 위치를 중심으로 3×3 정수 ID·깊이 버퍼를 렌더링한다. 샘플 간격은 원래 화면의 1/64픽셀로, 얇은 면의 경계 양쪽 후보를 얻는다. 클릭마다 패스를 갱신하여 카메라·모델 변환·가시성 변경으로 낡은 화면 정보를 읽지 않는다.
- 정수 ID 후보만 원본 `float64` 좌표로 광선 교차를 다시 계산한다. 깊이 역투영 좌표를 저장 좌표로 사용하지 않는다. 원본 삼각형 ID·Source Local 좌표·주 형상/연결 표면 계약을 유지한다.
- GPU 실패나 준비되지 않은 배치를 BVH 생성으로 우회하지 않는다. 오류를 기존 마커 입력 오류 경계에 전달한다.
- GPU 렌더링 대상 자체가 프록시이므로 기존 BVH의 내장 Mesh→프록시 전체 대조가 클릭 경로에는 필요하지 않다. 가져오기·복원·내보내기의 원본 검사와 마커 좌표 검증은 유지한다.
- 사용자 Scene·Object·Mesh와 선택·모드를 변경하지 않는다. GPU 상태는 `finally`로 복원하고 세션 종료 때 셰이더 참조를 해제한다.

## 검증 계획

실제 GPU에서 정수 ID, 겹침·배면·화면 가장자리·원근/직교·변환·연결 표면·텍스처 분할과 실패 정리를 확인한다. 원본 삼각형에 대한 독립 배정밀도 교차 및 기존 BVH와 ID·좌표를 비교한다. 같은 `test.align.blend`의 두 모델에서 기존 첫 선택과 새 첫 선택·반복 선택을 동일 광선으로 측정한다. 렌더링 준비 비용과 클릭 비용을 구분하며, 검사 때문에 기존 사용자 세션이나 원본 파일을 저장하지 않는다.

## 구현·검증 결과

2026-10-21, `codex/artec-align-engine`에서 구현했다. 마커의 첫 선택 때 수행하던 내장 메시 전체 대조와 BVH 생성을 없애고, 이미 표시 준비가 끝난 GPU 배치에서 원본 삼각형 ID를 읽는다. 최종 좌표는 읽은 깊이를 역투영하지 않고 원본 삼각형에 광선을 다시 교차해 배정밀도로 계산한다.

Artec 실측에서 확인한 것은 화면 정수 ID·깊이 읽기다. 이번 구현의 3×3 미세 샘플, 선형 깊이 정규화, 배정밀도 재교차까지 Artec 내부와 같다고 주장하지 않는다. 기존 정렬 엔진과 피벗 BVH는 변경하지 않았다.

### 정확도를 위해 함께 해결한 문제

1. 기존 Blender 광선 계산에서 단정도 역행렬 때문에 실제 클릭과 재투영 위치가 최대 약 1픽셀 어긋났다. 메시 마커는 같은 투영 행렬을 배정밀도로 역산하며, 점군만 선택하는 기존 경로는 유지한다.
2. 실제 대형 모델의 원근 깊이가 1 부근에 몰려 일반 깊이 버퍼에서는 앞뒤 면이 뒤바뀌었다. 모델 경계의 눈 좌표 깊이를 정규화한 선형 깊이를 기록해 순서를 보존한다. 화면의 근·원평면 클리핑은 기존 투영을 사용한다.
3. 원래 화면의 한 픽셀 간격으로 주변 면을 읽으면 아주 얇은 면이 후보에서 빠졌다. 1/64픽셀 간격의 3×3 후보를 얻고 실제 클릭 광선과 교차하는 면만 채택한다. 주변 픽셀의 좌표로 마커를 이동시키지 않는다.

### 같은 두 모델의 속도

Blender 5.2.0 LTS, OpenGL, RTX 4090에서 `C:/Users/gksru/Desktop/test.align.blend`를 별도 프로세스로 복원했다. 합계 **20,486,237개 삼각형**이다. 실제 사용자 뷰의 투영 행렬을 사용했고, 저장 프로젝트에서는 큰 모델을 P 대상으로 선택해 두 모델의 공개 마커 함수를 각각 실행했다.

| 모델 | 삼각형 수 | 기존 첫 선택 | 새 첫 선택 | 기존 반복 선택 | 새 반복 선택 |
|---|---:|---:|---:|---:|---:|
| test_1 | 357,749 | 88.512ms | **1.336ms** | 0.135ms | 0.804ms |
| test_2 | 20,128,488 | 6,248.897ms | **4.702ms** | 0.170ms | 2.800ms |

첫 선택은 각 3회 중앙값이다. 새 선택의 범위는 작은 모델 1.200~6.137ms, 큰 모델 4.210~6.529ms였다. 반복 선택은 모델별 60회 중앙값이다. 큰 모델의 첫 선택 지연은 약 **99.925% 감소**, 중앙값 기준 약 **1,329배 단축**됐다. 캐시가 이미 있는 BVH의 반복 선택은 더 빠르다. 새 경로는 클릭마다 GPU 패스와 읽기를 수행하는 대신 처음 수 초 멈추는 비용을 제거한다.

측정 경계는 새 공개 `pick_nearest_point` 호출과 기존 표면 선택 함수다. 양쪽에 같은 배정밀도 광선을 제공했다. OS 입력 대기·마커 확정·다음 화면 표시까지 포함한 사용자 체감 전체 지연은 아니다. 원본 복원 및 일반 화면 표시 비용도 제외했다.

새 경로는 첫 선택마다 Python 셰이더 참조를 비워 생성 비용을 포함했다. 드라이버의 디스크 셰이더 캐시까지 지우지는 않았다. GPU 배치가 아직 한 번도 그려지지 않은 조건을 첫 마커 비용으로 오인하지 않도록, 일반 표시 셰이더로 최초 GPU 업로드를 먼저 완료했다. 이 기존 표시 작업은 작은 모델 약 4.3ms, 큰 모델 약 305.1ms였다. 무텍스처인 실제 두 모델은 원래의 전체 면 배치를 그대로 재사용하며 새로운 전체 메시 배치를 만들지 않는다.

### 원본 ID와 좌표

- 저장 프로젝트의 **1,970개 화면 지점**을 비교했다. 1,969개는 기존 BVH와 원본 삼각형 ID 및 반환 좌표가 정확히 같았다.
- 다른 1개는 새 선택이 앞쪽의 원본 삼각형 `19113220`을, 기존 BVH가 뒤쪽의 `17122891`을 선택했다. 전체 **20,128,488개 면을 검색 구조 없이 배정밀도 평면 교차·면적 좌표로 전수 검사**해 새 결과가 실제 가장 앞쪽 면임을 확인했다. 두 면의 광선 깊이는 각각 약 842.478과 857.079다. ID 재번호화가 아니라 기존 단정도 검색에서 놓친 얇은 앞쪽 면을 선택한 경우다.
- 위 불일치를 포함해 독립 전수 검사 5개 광선을 확인했다. 새 ID는 모두 일치했고 최대 좌표 차이는 **4.14×10⁻¹³ 원본 좌표 단위**였다. 단위를 mm로 가정하지 않는다.
- 큰 모델의 173개 검사 지점은 ID가 `2²⁴`보다 컸다. `R32UI` 정수 버퍼를 사용하므로 부동소수 색상 인코딩의 정수 손실이 없다.
- 실행 중인 사용자 미리보기 상태에서도 별도 읽기 전용 검사 **1,968개 광선**이 기존 BVH와 같은 ID·좌표를 반환했다. 이 검사는 저장 프로젝트의 초기 변환과 별도 조건이다.
- 원본 배열·삼각형 순서·마커의 형상 슬롯·Source Local 좌표 계약은 유지한다. 같은 ID에서 좌표 오차를 허용하도록 검증 기준을 완화하지 않았다.

### 회귀와 자원

- `build_tools/test_align_source.ps1`의 **47개 Blender 검사 스크립트 전부 통과**. 새 화면 광선·깊이·낡은 배치 거절·GPU 오류 전달·모달 드래프트 보존 검사 6개를 포함한다.
- 실제 GPU 검사에서 원근·직교, 배면, 반전·비균일 배율, 근접한 앞뒤 표면 **24조건** 통과. 혼합·전체 텍스처 메시 **2조건**에서 원본 두 번째 면의 ID `1`을 확인했다.
- 실제 공개 마커 함수의 정밀 좌표, BVH 미생성, 그리기 예외 뒤 프레임버퍼·깊이·블렌드·뷰포트·시저 상태 복원을 검사했다.
- 연결 표면·점군 혼합·숨김·피벗 BVH·마커 상태·Undo·저장 복원 회귀를 통과했다. 사용자 장면에 검사 마커를 추가하거나 원본 `.blend`·OBJ를 저장하지 않았다.
- 이 최초 측정 당시에는 텍스처 메시의 별도 GPU 선택 배치 비용이 존재했다. 후속 GPU 버퍼 공유 변경에서 제거했다. 위의 무텍스처 두 모델 측정에는 해당하지 않는다.
- GPU 패스는 전체 메시의 정점을 처리한다. 메시를 줄이거나 대표 점으로 마커 위치를 근사하지 않는다. 이번 성능 수치는 검사한 RTX 4090/OpenGL 환경의 결과다.
