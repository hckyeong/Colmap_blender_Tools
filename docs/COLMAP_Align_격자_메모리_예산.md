# Align 메시 거리 계산의 격자 메모리 예산

## 적용 범위

0.3.56부터 CCCoreLib의 정확한 점–삼각면 거리 계산에 메모리 예산을 적용한다. 겹침 후보 준비, ICP 내부 반복, 최종 거리 평가가 같은 보호 경로를 사용한다. 점군끼리의 계산과 거리 맵 근사 경로는 변경하지 않는다.

OBJ 파일의 바이트 크기만으로 격자 단계를 정하지 않는다. 실제 메시 경계, 질의 점군과 합친 옥트리 경계, 셀 크기, 실행 시점의 가용 메모리를 사용한다.

## 확인된 원인

`Taiwan_cat_bone_GaussianToMesh.obj`의 실제 실패 작업을 복제하여 재현했다. 원본은 857,143,860바이트, 정점 5,651,583개, 삼각면 11,303,398개다. 기존 퇴화면 정리 후 실제 네이티브 계산 입력에는 11,303,378개 면이 사용된다.

기존 자동 선택은 두 번째 준비 거리 계산에서 옥트리 20단계를 골랐다. 메시 교차 격자는 `1,047,530 × 307,326 × 464,486`칸이 되어 포인터 배열에만 `1,196,267,732,443,544,640`바이트를 요구했다. 배열 할당의 `std::bad_alloc`이 네이티브 오류 `-973`으로 전달되었다. 원인은 정렬 자체의 실패가 아니라 과도한 격자 할당이었다.

## 선택 규칙

1. Windows에서는 `GlobalMemoryStatusEx`로 가용 물리 메모리와 현재 프로세스의 가용 커밋 메모리를 조회한다.
2. 포인터 격자 예산은 `min(256MiB, min(가용 물리 메모리, 가용 커밋 메모리) / 16)`이다. 조회 실패 또는 다른 운영체제에서는 16MiB를 사용한다.
3. 기존에 요청한 단계부터 낮추며 실제 격자의 단정도 좌표 계산, 정수 인덱스, 평면축의 최소 3칸 보정을 동일하게 재현한다.
4. 정수 범위·곱셈 넘침과 예산을 검사하여 요청 이하에서 가장 높은 단계를 선택한다. 기본값 0단계는 기존 의미를 유지한다.
5. 가능한 단계가 없으면 메모리 오류로 종료한다. 거리 정확도, 입력 면, 표본 수, 반복 수 또는 품질 기준을 완화하지 않는다.

이 예산은 포인터 배열에 대한 제한이다. 메시 좌표·삼각면 목록·병렬 작업까지 포함한 전체 프로세스 메모리의 상한은 아니다. 격자 단계가 바뀌면 검색 속도는 달라질 수 있으나 점–삼각면의 정확 거리 계산 방식은 유지된다.

가용 커밋 메모리의 정의는 [Microsoft MEMORYSTATUSEX 문서](https://learn.microsoft.com/en-us/windows/win32/api/sysinfoapi/ns-sysinfoapi-memorystatusex)를 따른다.

## 구현과 배포 검증

- 코어 패치: `mesh-grid-memory-budget-v1`.
- 공개 C++ API, 네이티브 프로토콜, 저장된 정렬 이력 형식은 유지한다.
- 잠금 파일에 패치 원문과 적용 전후 소스 해시를 기록한다. 빌드·배포·Python 실행 경계에서 패치 식별자와 최종 소스 해시를 검증한다.
- LGPL 재빌드 원문과 변경 고지에 패치를 포함한다.
- 정식 네이티브 회귀 40개 통과. 기존 바이너리에서 실패한 대형 격자 거리·등록 사례도 포함한다.
- Windows 경로와 메모리 조회 없는 경로에서 각각 10,000개 격자 추정 비교 및 경계 조건 검사를 통과했다.
- 기존 실패 질의를 8·9단계로 계산한 8,192개 거리는 모두 동일했다. 이 관측을 모든 입력에서 비트 단위 결과가 같다는 보장으로 확대하지 않는다.

실제 입력의 전체 정렬, 설치, 배포 검증 기록은 `build/verification/grid-budget-0.3.56/`에 보관한다. 원본 Blender 작업을 변경하지 않고 복제한 계산 입력에서 검증한다.

고양이의 전체 작업은 원래 입력 파일·초기 변환·표본 수·31스레드 설정을 그대로 복제하여 실행했다. 거리 명령 195개가 성공했으며, 사용자가 전체 검증을 다음 작업으로 넘기도록 선택해 395.344초에 정상 취소했다. 전체 정렬의 완료 시간과 최종 품질은 검증 완료로 취급하지 않는다. 원본 입력 네 파일의 전후 SHA-256은 같고, 작업 식별자를 제외한 설정도 동일하다.

0.3.55 설치 ZIP과 비교했을 때 이번 버전 변경은 버전 정보, 네이티브 패치·배포 검증과 관련 원문에 한정된다. 기존 다른 작업의 수정 내용은 추가로 바뀌지 않았다. 실행 중인 사용자 Blender 프로세스는 유지했으며 새 Python 코드를 적용하려면 작업을 저장한 뒤 Blender를 재시작한다.

## 다음 속도 개선 범위

현재 `icp_cccore_overlap.py`는 후보 준비 시 원본 면을 8,192개씩 나누어 거리 질의한다. 대용량 메시에서는 이 과정과 후속 후보 분류가 수천 번의 거리 호출을 만들며, 네이티브 코드는 각 호출에서 메시 교차 격자를 다시 만든다. 원본 메시가 바뀌지 않는 동안 격자를 재사용할 수 있는지 별도로 검토한다.

이번 변경은 격자 할당 실패를 해결한다. 이 반복 생성 병목의 최적화나 대용량 전체 정렬 성능 개선은 포함하지 않는다.
