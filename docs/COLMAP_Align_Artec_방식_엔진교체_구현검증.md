## 1. 구현 범위

기본 Align을 `POINT_KD_ICP`로 연결했다. Artec에서 관측한 흐름을 참고해 만든 독립 구현이며 Artec 바이너리나 코드를 포함하지 않는다. `point-kd-icp-v1`, `point-kd-job-v1`, `point-kd-native-v1`로 알고리즘·작업·네이티브 계약을 구분한다.

| 항목 | 이번 구현 |
|---|---|
| 메시–메시 | 유효점이 작은 쪽을 질의하고 큰 쪽 전체 정점에 KD-tree를 구축, 점–평면 강체 계산 |
| 점군–메시 / 메시–점군 | 점군을 질의하고 메시 정점을 검색, 사용자 P 방향과 반대이면 결과 역변환 |
| 점군–점군 | 작은 점군을 질의, SVD 기반 점–점 강체 계산 |
| 입력 | 전체 유효점 사용. 면적 표본·고정 개수 축소·메시 간소화 없음 |
| 대응 검색 | 리프 16, 반경·법선 조건을 만족하는 정확 최근접점, 대상 색인은 작업당 한 번 |
| 대응 제거 | 유효 검색 중 먼 5%의 가중치 0, 동률은 원본 순서로 결정 |
| 반복 | 최대 변환 갱신 30회. 갱신 전후 같은 대응·가중치로 목적함수 악화 검사 |
| 병렬화 | CPU oneTBB. 질의 검색과 고정 블록 계산을 병렬화하고 일정한 순서로 합산 |
| 결과 | 정렬 대응 RMS·반복·종료 사유 표시. 독립 표면 평가 미실시를 명시 |
| 배포 | 기본 `PointKd` 프로필. 기존 CCCoreLib 비교 프로필과 과거 결과 읽기 유지 |

메시–메시 법선 조건은 `abs(dot) >= cos(45°)`다. 이는 새 엔진의 설계이며 Artec의 법선 부호 정책을 확인했다는 뜻이 아니다. 반경은 `max(0.01D, 3h, 2e)`이고 `D`는 작은 형상 대각선, `h`는 최대 4,096개 결정적 검사점의 간격 추정, `e`는 마커 초기 RMS다. 간격 검사점 제한은 정렬 입력 축소가 아니다. 반경이 `0.05D`를 넘으면 입력을 확인하도록 중단한다.

이 보고서의 최초 검증은 목적함수 RMS 상대 변화 `1e-6`, 정규화 이동 `1e-8`, 회전 `1e-8 rad`를 사용했다. 당시에는 합성 정답 복원을 우선해 엄격한 값을 선택했고 대응 수 변화와 급감도 검사했다. 실제 두 메시에서는 30회 상한에 도달해 결과를 `REVIEW`로 표시했다. 이후 사용자 요청에 따라 세 허용치를 `0.001`로 완화했으며, 아래 실측은 변경 전의 기록이다. 변경 후 시간·정확도·검토 상태는 [0.001 재검증](COLMAP_Align_수렴기준_001_재검증.md), Artec 자체의 정확한 조건 결합과 분모는 [종료식 분석](COLMAP_Align_Artec_종료식_분석.md)에 기록한다.

## 2. 보존한 동작과 후속 기능

현재 배치와 마커 미리보기를 초기값으로 사용한다. P의 보정은 기존 공통 변환 앞에 합성하고 A는 고정한다. 기존 마커 배율·표시 배율, 개별 축 변환, 연결 카메라·점군·OBJ의 공통 변환 계약을 유지한다. 미리보기·승인·버리기·취소·Undo/Redo·저장·복원·내보내기 경로를 재사용한다.

원본 배열에 외부의 쓰기 가능한 별칭이 남아 있어 시작·완료의 **전체 SHA-256 검사를 모두 유지**한다. 모델 수명에 묶인 약한 참조와 최대 512MiB·8항목 캐시로 검증된 계산용 불변 복사본을 재사용한다. 개정 번호·배열 식별자·전체 내용 지문이 일치해야 재사용하며, 같은 개수의 내용 변경도 탐지한다.

Windows의 새 경로는 시스템 CNG SHA-256으로 계산한다. 기존 `dtype:shape` 접두사·65,536행 블록·표준 바이트 순서를 그대로 읽으며 출력 지문은 기존과 완전히 같다. 기존 CCCoreLib 비교 경로는 변경하지 않았다. Windows 시스템 API 오류는 정렬을 차단하며 조용히 다른 검사로 대체하지 않는다. 비Windows에서는 기존 `hashlib`를 사용한다.

Blender 내장 Python에서 실제 두 모델의 위치·삼각형 네 배열을 준비 1회·측정 3회 교차 비교한 중앙값은 기존 `2.538885초`, 시스템 SHA-256 `0.194528초`였다. 모든 반복의 네 지문이 완전히 같았다. 이는 **해시 한 차례의 시간**이며 전체 Align의 속도 배율이 아니다. 빈·비연속·읽기 전용 배열과 백만 점 이상에서도 같은 지문을 확인했다.

후속으로 남긴 항목은 ICP 내부 자동 배율, 정확 삼각형 표면 정밀화, 점군 법선 추정, 실행 중 독립 품질 평가와 여러 후보 선택, GPU, 작업 간 KD-tree 상주 재사용이다. 실패나 검토 상태에서 구엔진으로 자동 전환하지 않는다.

시간은 실제 Align 버튼이 호출하는 `begin_icp_job`부터 결과 미리보기 준비까지이며 입력 검사·파일 준비·외부 계산·결과 검증을 포함한다. 백그라운드 검증이므로 화면 클릭·뷰포트 렌더링 시간은 제외한다. 설치본의 등록·오퍼레이터 연결과 사용자 흐름은 별도 격리 설치 검사로 검증한다.

## 4. 최종 속도와 자원 사용

표의 시간은 준비 실행을 제외한 5회의 중앙값이며 괄호는 최소–최대다.

| 시작 조건 | 기존 CCCoreLib | 새 점 KD 엔진 | 속도 배율 | 대기 감소 |
|---|---:|---:|---:|---:|
| 정렬된 상태 | 22.991초 (21.539–25.018) | **5.828초 (5.741–5.895)** | 3.94배 | 74.65% |
| 회전·이동 추가 | 19.134초 (18.704–19.287) | **5.666초 (5.626–5.983)** | 3.38배 | 70.39% |
| A/P 반전 | 20.614초 (19.669–20.681) | **5.834초 (5.727–6.477)** | 3.53배 | 71.70% |

이미 정렬된 사례의 전체 대기 중앙값 **8초 이내 목표를 충족**했다. 준비 실행은 기존/새 엔진 순서로 정렬 상태 `24.357/8.609초`, 회전·이동 추가 `18.332/9.226초`, A/P 반전 `20.005/8.466초`였다. 새 캐시의 생성 비용을 준비 실행에 포함했다. 별도 프로세스에서 `.blend`와 저장 상태를 복원하는 데 약 `21.15–21.48초`가 들었으며, 이미 모델을 올려 둔 상태의 Align 대기 시간과는 구분했다.

정렬 상태의 새 엔진 구간별 중앙값은 다음과 같다. 항목별 중앙값의 합은 전체 중앙값과 정확히 일치하지 않을 수 있다.

| 구간 | 시간 |
|---|---:|
| 입력 전체 검사·변환·작업 파일 준비·시작 | 0.663초 |
| 외부 작업기 전체 | 4.766초 |
| 결과 검증·수신·정리·대기의 나머지 | 0.419초 |
| 작업기 안의 네이티브 전체 | 4.713초 |
| 네이티브 입력 읽기 / 법선 생성 | 0.240 / 0.391초 |
| KD-tree 한 번 구축 | 1.991초 |
| 모든 반복의 검색 / 거리 제거 | 1.022 / 0.655초 |
| 모든 반복의 강체 해 / 목적함수 검사 | 0.031 / 0.100초 |

최종 검색에서 질의점 188,400개 중 거리 제외 4,112개, 법선 제외 1,124개, 먼 5% 제거 9,158개를 거쳐 **174,006쌍**을 사용했다. 대상은 10,173,478점 전체이고 KD 구축은 한 번이었다. 원본 입력 축소로 얻은 속도 향상이 아니다. 작은 쪽 단방향 검색, CPU 병렬화, 자동 배율·표면 후보 평가 단계 제외, 원본 지문 계산 개선이 함께 반영된 전체 사용자 경로 비교다.

정렬 상태에서 작업기 프로세스 트리의 관측 최고 작업 집합은 회차 중앙값 기준 **2,070.07MiB → 761.46MiB**였다. Blender 자체의 관측 최고 작업 집합은 각각 3,255.89MiB와 3,259.24MiB였다. 두 엔진을 같은 프로세스에서 교차 실행하므로 Blender 값에는 복원된 장면과 남아 있는 계산 캐시가 포함된다.

Blender 누적 CPU 시간의 중앙값은 `12.047 → 2.188초`, 작업기 트리에서 관측한 누적 CPU 합은 `77.750 → 33.625초`였다. CPU 시간은 여러 스레드의 합으로 실제 대기 시간과 다르다. 메모리는 0.1초 간격 표본에서 관측한 값이고 작업기 CPU는 마지막 생존 표본까지라 종료 직전 구간을 놓칠 수 있다. 이를 정확한 동시 최고 메모리·완전한 CPU 프로파일로 취급하지 않는다.

### 4.1 네이티브 병렬화 비교

같은 두 메시의 고정 세계 좌표 입력으로 스레드별 준비 1회·측정 3회를 교차 실행했다. 이 비교는 Blender 전처리·해시·미리보기 시간을 제외한 네이티브 실행이다.

| 구간 중앙값 | 1스레드 | 31스레드 |
|---|---:|---:|
| 네이티브 프로세스 실행 | 18.9039초 | 4.3982초 |
| KD-tree 구축 | 1.9710초 | 1.9268초 |
| 전체 반복의 대응 검색 | 13.9328초 | 1.0030초 |
| 전체 반복의 거리 제거 | 0.5349초 | 0.5446초 |
| 전체 반복의 강체 해 계산 | 0.4057초 | 0.0308초 |
| 전체 반복의 목적함수 검사 | 1.2910초 | 0.0945초 |

전체 네이티브 실행은 약 4.30배 빨라졌다. 검색은 크게 단축됐지만 직렬 KD 구축·거리 순서 선택이 남아 있어 31배가 되지는 않는다. 세 비교 모두 최종 행렬의 최대 원소 차이 `0`, 대응 수·반복 수·종료 사유·RMS도 같았다. 다른 하드웨어와 입력에서 같은 배율을 보장하지 않는다.

## 5. 독립 정확도 평가

정렬에 쓰지 않는 시험 전용 평가기로 원본 표면에서 방향별 30,000개를 면적 비례 추출한다. 고정 난수와 삼각형·무게중심 좌표를 저장하고, 초기 상태에서 `0.01D` 안에 있던 59,187개 평가점을 고정한다. 후보 결과가 나빠져도 평가점에서 제외하지 않는다.

거리 계산은 정점 최근접 근사가 아닌 기존 네이티브 BVH의 점–삼각형 표면 거리다. 공통 정규화 단정도 좌표로 계산한 거리를 프로젝트 세계 길이 단위로 환산한다. P/A 반전은 원래 P 좌표계로 역변환해 비교한다. 제품 정렬 실행에는 이 평가기를 호출하지 않는다.

최종 패키지의 준비·측정 36개 결과와 기존 기록 1개, 총 **37개 후보 모두** 합산 및 양방향 각각의 RMS·95백분위가 기존 결과보다 5% 이상 악화되지 않는 기준을 통과했다. 아래는 정렬된 상태의 같은 고정 평가점 비교이며 단위는 프로젝트 세계 길이 단위다.

| 독립 표면 거리 | 기존 결과 | 새 엔진 |
|---|---:|---:|
| RMS | 1.48532216 | **1.48379445** |
| 95백분위 | 3.63346674 | **3.62786418** |
| 평균 | 0.72320303 | 0.73143206 |
| 중앙값 | 0.23433838 | 0.24626010 |
| 최댓값 | 8.27862904 | 8.36426931 |

RMS·95백분위는 약간 감소했지만 중앙값은 약 5.09%, 평균은 약 1.14% 증가했다. **모든 거리 지표가 개선된 결과는 아니다.** 회전·이동 추가 조건의 새 RMS는 `1.48379441`, 95백분위는 `3.62786196`이었고, A/P 반전 결과는 위 정렬 상태 결과와 같았다.

각 조건 안에서 5회 반복의 최종 행렬은 완전히 같았다. A/P 반전 결과를 원래 방향으로 역변환한 행렬의 최대 원소 차이는 `1.11e-16`, 회전·이동을 추가했던 조건과 정렬 상태 조건의 최종 행렬 원소 차이는 최대 `2.90e-6`이었다. 후자는 초기 배치 변화에 대한 재현성 비교이며 외부 정답 변환에 대한 오차로 해석하지 않는다.

통과는 계획에 정한 RMS·95백분위 기준에 대한 판정이다. 거리 평균·중앙값·최댓값도 함께 기록하며, 일부 지표의 감소를 모든 평가점에서 정확도가 개선됐다는 뜻으로 해석하지 않는다.

이 실제 자료에는 외부의 정답 변환이 없다. 기존 CCCoreLib의 `REVIEW` 결과를 절대 정답으로 취급하지 않으며, 알려진 변환 복원은 별도의 합성 시험으로 판단한다.

## 6. 합성 자료의 정확도와 알려진 제한

네 가지 입력 조합, 검색 방향 반전, 초기 배율, 큰 좌표의 작은 비대칭 형상에서 강체 변환 복원을 검사했다. 원본·기준 A 보존과 승인·Undo/Redo도 함께 확인했다.

**점군→성긴 메시의 접평면 근사에는 정밀도 한계가 있다.** 비대칭 8정점·12삼각면을 선형 중점 분할한 동일 다면체에서, P 점군 24,578점을 A 메시 6,146정점·12,288면에 정렬한 사례다. 정답 위치 RMS는 약 `0.00096575`, `RMS/D = 2.13424e-4`로 목표 `1e-6`에 못 미쳤다. 회전 오차는 약 `0.03193°`였고 결과는 `REVIEW`다. 이 사례를 기본 합성 통과 목록에 섞거나 삭제하지 않고 `accuracy_limitations`에 보존했다. 반대 밀도 구성의 메시→점군 사례는 정답 RMS 약 `1.44e-16`이었다.

직접 네이티브 실행에서도 기존 결과와 행렬 원소가 완전히 같았고, **정답 위치에서 시작해도** 정답점 RMS 약 `0.00096464`만큼 이동했다. 같은 정점 밀도로 맞춘 대조는 `1.54e-16`, 모서리 대응을 제외한 대조는 `1.93e-16`이었다. 독립 전수 검색에서 두 입력이 같은 삼각형 표면 위에 있음은 약 `1e-15` 오차로 확인됐지만, 5% 거리 제거 후 정점 접평면 RMS는 `0.00265647`이었다. 이 제곱 잔차는 전부 여러 원삼각면에 걸친 모서리·꼭짓점의 평균 법선 대응에서 발생했다.

이는 변환 역적용 오류나 구속 부족보다 **모서리의 평균 정점 접평면이 실제 면을 대표하지 못하는 근사 편향**이라는 근거다. 독립 최소제곱도 계수 6으로 정답 위치에서 추가 회전을 제안했다. 원인 분석 자료는 `synthetic-runtime/density-analysis.json`에 보존했다.

메시 정점의 접평면은 삼각형 내부의 실제 표면과 다르므로, 모서리·곡률·밀도 차이가 큰 점군–메시 입력에 기존 표면 방식과 같은 정밀도를 보장하지 않는다. 정확 삼각형 표면 정밀화는 사용자 요청대로 후속 범위로 남긴다. 따라서 실제 두 메시의 통과를 모든 점군–메시 자료에 대한 정밀도 보증으로 확대하지 않는다.

계획의 정확도 미달 시 기본 배포를 전환하지 않는 조건에 따라, 이번 산출물은 **현재 브랜치의 검증용 ZIP**으로 제공한다. 1차 구현과 지정된 실제 메시 검증은 완료했지만, 성긴 메시 정밀도까지 포괄하는 운영용 기본 배포 전환은 완료로 판정하지 않는다.

## 8. 의존성과 구현 근거

C++17, Eigen 3.4.0, oneTBB 2022.0.0, nlohmann JSON 3.11.3을 고정하고 다운로드 지문·라이선스·재빌드 지침과 소스 묶음을 배포에 포함한다. 런타임 DLL과 실행 파일 지문도 검증한다.

- [ICP 변형 비교 연구](https://graphics.stanford.edu/papers/fasticp/): 대응 선택·제거·최적화의 일반적 근거.
- [Microsoft CNG 해시 생성 문서](https://learn.microsoft.com/en-us/windows/win32/seccng/creating-a-hash-with-cng): 시스템 SHA-256의 생성·누적·완료·해제 계약.
- [CPython 3.13.13 Windows OpenSSL 빌드 설정](https://raw.githubusercontent.com/python/cpython/v3.13.13/PCbuild/openssl.vcxproj): `no-asm` 설정이 있는 상류 소스. 설치된 Blender 바이너리의 빌드 옵션까지 직접 확인한 것은 아니므로, 해당 옵션을 이번 차이의 확정 원인으로 단정하지 않는다. 실제 성능 차이는 동일 바이트·동일 SHA-256의 교차 측정으로 확인했다.

Artec의 5.319초는 이전에 사용자가 실행한 한 회차의 역사적 참고값이다. 이번 엔진의 반복 횟수·전처리·검증·계측 경계가 다르므로 직접적인 순수 알고리즘 성능 비율로 해석하지 않는다.
