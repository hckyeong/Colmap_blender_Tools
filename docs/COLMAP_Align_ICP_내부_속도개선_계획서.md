## 1. 목표와 범위

**움직이지 않는 기준 메시의 검색 격자를 ICP 반복 동안 유지하는 것이 1차 목표다.** 검사점이 이동한 뒤의 최근접점과 거리는 매번 새로 계산한다. 이후 오차가 충분히 안정됐을 때 반복을 끝내고, 적은 표본으로 시작해 마지막에 정밀 보정하는 방식을 각각 검증한다.

이번 대상은 CCCoreLib의 실제 등록 반복이다. 이전 준비 단계 최적화와 구분하며, C++ 코어 패치·네이티브 워커·Blender Align의 실행 및 결과 계약을 함께 다룬다. 이미 사용 중인 C++ 엔진을 유지한다.

| 단계 | 바꾸는 것 | 유지하는 것 |
|---|---|---|
| 0. 계측 | 내부 시간·반복 횟수·종료 사유 기록 | 계산·수렴·표본 정책 |
| 1. 격자 재사용 | 기준 메시 격자의 수명과 검색 범위 관리 | 정확 거리, 표본·필터, 변환 계산, 반복 상한·종료 조건 |
| 2. 수렴 종료 | 충분히 안정된 반복의 조기 종료 조건 | 최대 반복 상한, 배율 제한, 독립 품질 판정 |
| 3. 단계별 표본 | 초기 단계의 등록 표본 수와 단계 연결 | 최종 등록 표본, 기준 원본 메시, 독립 평가점 |

단계 1은 독립적으로 검증·배포할 수 있게 구성한다. 단계 2와 3은 수치 결과가 달라질 수 있는 알고리즘 변경이므로 각각의 비교 검증을 통과해야 기본 실행에 반영한다. 단계 2 또는 3이 기준을 충족하지 못하면 제품에 미완성 옵션이나 자동 재시도 경로를 남기지 않고, 검증된 앞 단계까지만 채택한다.

이번 범위에는 GPU·엔진 교체, 메시 단순화, 준비 표본 정책 변경, 검색 반경·품질 기준 완화, Modifier·Painting 수정이 포함되지 않는다. 실제 최근접점이 필요한 ICP에서 거리 맵 근사나 임의의 검색 거리 제한으로 계산을 생략하지 않는다.

## 2. 확인된 사실과 아직 모르는 부분

### 최근 실제 실행

같은 형상·마커·초기 행렬로 실행한 0.3.61의 결과다. 프로젝트 열기와 마커 미리보기 재구성 시간은 제외했다.

| 구간 | 시간 |
|---|---:|
| 준비 | 27.047초 |
| 강체 ICP | 281.156초 |
| 배율 보정 ICP | 234.119초 |
| 실제 ICP 합계 | 515.275초 |

실제 ICP가 전체의 약 90%다. 기준 메시에는 정점 5,651,583개, 계산용 삼각면 11,303,380개가 있고 등록 표본은 50,000점이다. 비교 자료는 저장소에서 제외되는 `build/verification/fixed-domain-implementation/blender-comparison.json`과 `blender-operator-run/job/result.json`에 있다. 이전 0.3.60 전체 시간 564.010초와 새 실행은 각각 한 번이므로, 두 값만으로 성능 차이의 원인을 확정하지 않는다.

### 코드에서 확인한 반복 비용

- `RegistrationTools.cpp`의 초기 거리 계산과 반복 후 거리 계산은 모두 캐시 없는 `computeCloud2MeshDistances`를 호출한다.
- 이 함수는 임시 검사점 옥트리와 임시 메시 교차 격자를 만들고 호출 종료 시 해제한다. 따라서 고정된 기준 메시의 격자도 반복 생성된다.
- 현재 격자 범위는 기준 메시와 검사점의 경계를 합쳐 정한다. 검사점이 움직이면 범위가 달라지므로 캐시 인자만 연결해서는 안정적으로 재사용되지 않는다.
- 기준 메시 전체의 옥트리를 이용한 검색 단계 선택은 등록 호출 시작에 수행한다. 이것을 매 반복의 전체 메시 옥트리 생성이라고 잘못 집계하지 않는다.
- 워커는 `MAX_ITER_CONVERGENCE`를 사용한다. 강체 상한은 200회, 배율 보정 상한은 1,000회다. 오차 증가 등의 기존 종료는 있지만, 오차 감소량이 작을 때의 수렴 종료 조건은 사용하지 않는다.
- 배율 보정은 이미 강체 결과를 적용한 좌표에서 시작한다. 이를 초기 위치부터 중복 수행하는 문제로 취급하지 않는다.

현재 결과에는 실제 반복 횟수와 ICP 내부 격자 생성 시간이 없다. 외부 세션의 격자 생성 통계 0은 내부에서 격자를 만들지 않았다는 뜻이 아니다. **515초 전부가 격자 생성 비용이라고 가정하거나, 개선 후 1분 미만을 약속하지 않는다.**

## 3. 0단계: 초반 반복만 분리 계측

### 입력과 실행 제한

1. 실제 프로젝트에서 보존한 형상·초기 행렬·마커·정규화·등록 표본·시드·필터·31스레드 설정의 지문을 확인한다. 저장된 `.blend`를 그냥 열었을 때 이미 겹친 상태와 실제 3점 정렬 입력을 혼동하지 않는다.
2. 강체는 동일한 초기 등록 입력, 배율 보정은 기존 실행에서 보존한 강체 결과를 적용한 입력을 사용한다. 배율 구간을 보기 위해 매번 강체 전체를 다시 실행하지 않는다.
3. 먼저 각 구간을 최대 5회 변환 반복으로 실행한다. 더 필요한 경우에만 10회까지 늘린다. 각 진단 실행의 상한은 120초로 두고, 초과 시 검증용 프로세스만 정상 취소한다.
4. 진단의 반복 제한은 검증 도구에만 적용한다. 중간 결과를 사용자의 정렬 결과나 전체 완료 시간으로 표시하지 않는다.

### 계측 항목

| 항목 | 기록 내용 |

| 시작 비용 | 등록 입력 구성, 최초 검색 단계 선택, 최초 거리 계산 |

| 거리 검색 | 최근접 삼각면·대응점 계산 시간 |

내부 구간 시간은 서로 겹치지 않게 누적하며 상위 `kernel_seconds`에 다시 더하지 않는다. 최초 거리 호출과 반복 후 호출을 구분하고, 회차 번호를 그대로 실제 변환 횟수로 해석하지 않는다. 진행률을 역산하거나 표시 문자열을 파싱해서 반복 수를 만들지 않는다.

제품에는 완료 결과의 합계·실제 횟수·종료 사유만 정식 통계로 남긴다. 회차별 상세 파일은 검증 도구에서만 수집하며 임시 출력문·디버그 로그를 제품에 남기지 않는다. 계측 유무의 결과 일치와 추가 비용을 짧은 대조군으로 확인한다.

**통과 조건:** 짧은 실행의 시간 분해가 설명되고, 실제 반복 생성 횟수를 확인할 수 있어야 한다. 전체 9분 실행을 먼저 반복하지 않는다.

## 4. 1단계: ICP 내부 격자 재사용

### 4.1 등록 호출 하나가 격자 하나를 소유

메시를 기준으로 하는 등록 호출에 전용 문맥을 둔다. 문맥에는 불변 기준 메시 식별 정보, 선언 범위, 실제 격자 단계, `Cloud2MeshDistancesCache`, 통계를 보관한다.

- 기존 `Register` 공개 시그니처와 `Parameters` 구조체의 기존 의미를 유지한다.
- 새 실행 문맥을 받는 별도 등록 진입점을 추가하고, 기존 등록 본문은 공통 내부 구현으로 연결한다. 기존 API 호출과 점군 간 등록은 현행 경로를 유지한다.
- 워커의 메시 등록만 새 진입점을 사용한다. 기존 준비 격자는 등록 시작 전에 해제하고, 등록 내부 격자는 반환·취소·오류 때 해제한다.
- 강체와 배율 보정 호출 사이의 독립 거리 평가까지 격자를 보관하지 않는다. 우선 한 번의 등록 내부 재사용에 집중한다.
- 전역·정적 캐시를 사용하지 않는다. 병렬 검색은 완성된 동일 격자를 읽고, 생성·교체·해제는 검색 작업이 모두 종료된 뒤 수행한다.

메모리와 범위가 안정적인 사례의 목표는 **강체 등록에서 최초 1회, 배율 보정 등록에서 최초 1회 생성**이다. 두 등록의 실제 거리 호출 합계를 `N`이라 하면 생성 2회·재사용 `N-2`회가 목표다. 범위 확장과 메모리 단계 하향에 따른 추가 생성은 별도로 집계한다.

### 4.2 이동을 허용하는 범위 관리

준비 단계와 달리 ICP에서는 검사점의 미래 위치를 처음부터 모두 알 수 없다. 다음 수명 규칙으로 처리한다.

1. 등록 시작 시 기준 메시 전체와 최초 등록 표본 전체를 포함하는 정육면체 선언 범위를 정한다. 단정도 변환 시 경계를 바깥쪽으로 보수적으로 변환하고, 기존 코어의 정육면체 여유·평면축 보정을 유지한다.
2. 초기 거리와 이후 모든 거리 호출에 같은 선언 범위를 전달한다. 기존 `computeCloud2MeshDistancesWithCacheAndBounds`를 연결하고, 현재 검사점의 옥트리는 그 좌표계 안에서 다시 만든다.
3. 변환 후 검사점 전체의 경계가 선언 범위 안이면 격자를 유지한다. 점의 개수·순서가 필터로 바뀌어도 기준 메시와 범위·실제 단계가 같으면 재사용할 수 있다.
4. 범위를 벗어나면 기존 중심을 기준으로 선언 큐브의 한 변을 2배씩 늘려 새 검사점 전체를 포함시킨다. 축소는 하지 않는다. 고정된 확대 규칙으로 작은 이동마다 미세하게 경계를 바꿔 재생성하는 것을 피한다.
5. 확장은 등록 문맥에서 명시적으로 수행하고 사유를 기록한다. 이전 격자를 해제한 뒤 새 범위의 메모리 예산을 적용하여 재생성한다. 준비 단계의 잘못된 범위 입력을 오류로 처리하는 기존 계약은 바꾸지 않는다.

구현 시 확인한 보완 조건: 큐브가 두 배 커지면 검색 단계도 한 단계 높여 물리 셀 크기를 유지한다. 메모리 하향으로 정해진 단계 상한도 같은 좌표계 기준으로 보정하며, 최대 옥트리 단계와 매 호출의 메모리 예산을 계속 적용한다. 처음 구현에서는 격자 생성이 6회에서 2회로 줄었지만 셀 크기가 두 배가 되면서 최근접점 검색이 4.289초에서 8.828초로 늘어 총시간이 감소하지 않았다. 이 보완 없이 재사용만 성공한 결과를 속도 개선으로 채택하지 않는다.

경계 검사와 거리 API에 전달하는 선언 범위가 일치해야 한다. 유한하지 않은 변환, 경계 오버플로, 검사점의 옥트리 투영 누락은 오류로 처리한다. 범위 밖의 점을 잘라내거나 이전 대응점을 결과로 반환하지 않는다. 큰 범위 확장으로 검색 시간이 증가하면 이를 계측하고 개선 효과 판정에 포함한다.

### 4.3 재계산해야 하는 것

각 반복에서 검사점 옥트리, 최근접 삼각면·표면 대응점·거리, 필터, RMS와 변환 계산은 계속 수행한다. 이동 전 옥트리나 최근접 삼각형 번호를 검증 없이 재사용하지 않는다. 먼 점 필터의 대응점·삼각형 ID 동기화와 기존 배율 제한 패치를 유지한다.

격자 재사용 조건은 기준 메시 신원, 실제 공통 큐브 경계, 실제 단계, 셀 크기의 정확 일치다. 캐시 신원만 같다는 이유로 경계 검사를 생략하지 않는다.

### 4.4 메모리와 취소

- 기존 포인터 배열 예산 `min(256 MiB, min(가용 물리 메모리, 가용 커밋 메모리) / 16)`을 유지하고 매 거리 호출에서 검사한다.
- 예산에 맞춰 단계가 낮아지면 해당 등록 문맥에서는 그 상한을 유지한다. 메모리가 일시적으로 회복됐다고 다시 고해상도 격자로 확대하지 않는다.
- 새 격자 할당 전에 기존 격자의 용량을 반환한다. 상주 격자는 한 개이며 기준 메시 전체의 옥트리를 새로 상주시켜 단계 선택 비용을 줄이지 않는다.
- 포인터 예산을 전체 메모리 상한으로 보고하지 않는다. 셀별 삼각형 목록, 조회점 옥트리와 병렬 검색 임시 메모리를 포함해 실제 사용량을 측정한다.
- 생성·검색·반복 경계에서 취소를 확인한다. 공통 진행 콜백을 연결하더라도 내부 거리 진행률이 사용자 전체 진행률을 덮어쓰지 않게 한다. 실패·취소 시 이전 확정 결과를 보존한다.

## 5. 2단계: 수렴한 반복의 조기 종료

단계 1을 적용한 상태에서 반복별 변화량을 확인한 후 별도로 구현한다. 기존 강체 200회·배율 1,000회 상한을 단순히 낮추거나, 상한이 적용되지 않는 다른 모드로 바꾸는 방식은 사용하지 않는다.

1. 기존 오차 증가·취소·오류 처리와 최대 반복 상한을 유지한다.
2. 새 종료 조건은 오차 감소가 작고, 회전·이동 변화도 작으며, 배율 보정에서는 배율 변화까지 작은 상태가 연속으로 유지되는 경우로 한정한다.
3. RMS 감소량은 절대값과 상대값을 함께 다룬다. 0에 가까운 RMS에서 나눗셈이 불안정하지 않게 하며, 이동 기준은 정규화된 형상 크기로 정의한다.
4. 필터로 대응 집합이 바뀌면 RMS의 비교 대상도 달라진다. 최소한 유효 점 수 변화 시 연속 안정 횟수를 초기화하고, 변환 안정 조건과 독립 평가를 함께 사용한다. 첫 번째 작은 개선만으로 종료하지 않는다.
5. 최소 반복 수, 연속 안정 횟수, RMS·회전·이동·배율 임계값은 단계 0·1의 기록과 알려진 정답 회귀를 바탕으로 정한다. 후보 값을 먼저 고정한 뒤 별도 검증 입력에 적용하며, 고양이 한 사례에 맞춰 사후 조정하지 않는다.
6. 종료 사유를 반복 상한, 수렴 안정, 오차 증가, 초기 변화 없음, 취소, 오류로 구분한다. 제품의 최종 품질 판정은 기존 독립 평가가 계속 담당한다.

배율이 실제로 다른 입력과 작은 부분 겹침에서도 충분히 보정돼야 한다. 임계값을 만족했어도 독립 품질 검사에서 탈락한 결과를 강제로 승인하거나 자동으로 긴 등록을 다시 실행하지 않는다.

**통과 조건:** 기존 정확도 기준·배율 경계·품질 판정을 유지하면서, 실제 수행 반복과 시간 감소가 확인돼야 한다. 최종 행렬의 비트 일치는 요구하지 않지만 수치 허용 기준은 실험 전에 고정하고 완화하지 않는다.

## 6. 3단계: 적은 표본으로 시작해 정밀 보정

단계 1·2의 효과를 분리해 확인한 뒤 수행한다. 현재 준비가 만든 50,000점은 그대로 보존하고 그 안에서 결정적으로 부분집합을 선택한다. 준비 전체 비용을 줄이는 작업은 아니다.

- 최초 비교 후보는 5,000점 → 20,000점 → 50,000점이다. 이 수치는 실험 후보이며 채택이 확정된 기본값이 아니다.
- 첫 몇 개의 점만 취하지 않고 공간 분포를 보존하는 결정적 순서로 중첩 부분집합을 만든다. 시드·원본 표본 ID를 기록하고 중복 점을 생성하지 않는다.
- 이전 단계의 누적 변환을 다음 단계 좌표에 정확히 한 번 적용한다. 먼 점 필터로 이전 단계에서 제거된 점 때문에 다음 단계의 원래 표본이 영구 소실되지 않게 한다.
- 최종 단계는 기존 전체 등록 표본을 사용한다. 점군 입력이 50,000개보다 적으면 기존 고유 표본 수를 기준으로 단계 수를 줄이고 점을 복제하지 않는다.
- 각 단계의 대응 비율과 필터는 해당 입력에 맞게 계산하며, 줄어든 점 수로 최소 대응·분포 기준을 충족하지 못하는 구성을 채택하지 않는다.
- 강체와 배율 보정의 다단계 적용 효과를 각각 비교한다. 단계가 늘어나며 발생하는 초기 거리·격자·수렴 비용을 포함한 전체 등록 시간으로 판단한다.
- 독립 평가점과 평가 순서는 고정한다. 평가점을 등록 입력으로 섞거나, 새 결과에 유리하게 다시 뽑지 않는다.

다단계는 등록 호출 수·알고리즘 정책·실행 감사 기록을 변경한다. 기존의 등록 두 번을 가정하는 순서 검증과 요약도 실제 단계 목록을 검증하도록 함께 바꾼다. 여러 단계를 실행했는데 기존 두 번으로 집계하지 않는다.

**통과 조건:** 단계 추가 비용을 포함해 단일 단계보다 빨라야 하며, 전체 표본 정밀 보정과 기존 독립 품질·정답 검사를 통과해야 한다. 격자 재사용만의 성과와 혼합 보고하지 않는다.

단계 2의 수렴 정책은 별도 패치로 관리하여 단계 1과 독립 비교할 수 있게 한다. CCCoreLib 고정 커밋을 임의로 최신 버전으로 교체하지 않으며, 캐시 폴더만 수정한 바이너리를 배포하지 않는다. 기존 패치 해시는 보존하고 새 패치 이후 최종 해시를 연결하며 LGPL 재빌드 원문과 변경 고지를 포함한다.

실제 ICP 통계를 정식 네이티브 응답에 추가하므로 네이티브 계약은 `cccore-native-v6`으로 갱신한다. 요청·응답 검증·자체 검사·빌드 Manifest를 함께 맞춰 구버전 실행 파일 혼용을 막는다. 단계 1에서는 표본·수렴 정책 버전을 바꾸지 않되 바이너리·패치 식별자로 계산 캐시를 분리한다. 단계 2·3의 채택 시에는 알고리즘 정책 버전과 매개변수 지문도 갱신하며 단계별 유효 필드를 명시한다.

과거 승인 이력과 확정 행렬은 계속 복원한다. 현재 실행 통계가 없는 과거 기록을 잘못된 기록으로 거부하지 않는다. 현재 작업의 완전한 실행 기록 검증과 과거 요약 읽기를 구분한다. 새 함수·수정 함수에는 짧은 한국어 주석 또는 문서화 문자열을 작성한다.

## 8. 검증 순서와 채택 기준

### 작은 입력의 정확도·수명 검사

- 알려진 회전·이동·배율을 가진 비대칭 입체와 곡면에서 정답 오차를 검사한다.
- 평면·얇고 긴 형상, 넓은 삼각형, 경계 위·밖 검사점, 누적 이동으로 범위가 여러 번 확장되는 경우를 포함한다.
- 작은 메시의 전수 삼각형 검색과 거리·대응점 위치를 비교한다. 동거리 삼각형 ID 차이는 단순 실패 처리하지 않되, 대응점 차이가 변환과 품질에 주는 영향을 검사한다.
- 단일·다중 스레드, 먼 점·부분 겹침 필터, 서로 다른 등록의 연속 실행, 취소·오류·메모리 단계 하향 후 해제를 검사한다.
- 단계 1에서는 표본 좌표·순서·시드·필터 정책과 수렴 조건을 고정하고, 기존 경로와 변환·RMS·품질 결과를 비교한다. 차이가 있으면 원인을 설명하고 기존 수치 기준 안에서 검증한다.
- 메모리 하향은 결정적인 예산 입력으로 검사한다. 사용자 시스템 메모리를 고의로 고갈시키지 않는다.

### 동일 프로젝트의 짧은 성능 비교

기준 0.3.61과 단계 1 수정본을 같은 전체 기준 메시·실제 표본·31스레드로 비교한다. 각 버전 예열 1회 후 번갈아 3회 순차 실행한다. 강체와 배율 보정의 짧은 구간을 따로 비교하며 다른 성능 작업을 동시에 실행하지 않는다.

두 구현이 서로 다른 궤적으로 진행하면 같은 검사점열을 재생하는 보조 실험으로 구조 비용을 분리하되, 이를 실제 ICP 실행 시간으로 표시하지 않는다. 시간 중앙값·범위, 생성/재사용/확장/하향 횟수, 최대 메모리와 결과 차이를 함께 기록한다.

**단계 1 채택 조건:** 안정 범위에서 등록당 최초 한 번 생성되고, 기존 정확도 기준을 충족하며, 짧은 실제 ICP 구간 중앙값이 감소해야 한다. 반복 생성은 줄었지만 검색 비용이 더 늘어 총시간이 줄지 않으면 속도 개선 완료로 처리하지 않는다.

### 후속 정책 비교

단계 1, 단계 1+2, 단계 1+2+3을 각각 분리해 비교한다. 곡면의 100%·70%·40%·20%·10% 겹침, 실제 배율 차이, 초기부터 정렬된 사례와 잔여 변환이 있는 사례를 포함한다. 기존에 실패하던 5% 겹침·얇은 곡면 진단 결과도 숨기지 않는다. 알려진 정답과 독립 품질 평가의 기존 허용값을 느슨하게 바꿔 통과시키지 않는다.

### 최종 실제 Align

앞 단계에서 효과가 확인된 뒤 별도 Blender의 검증용 사본에서 같은 마커 시작 상태를 재현하고 실제 Align 연산자를 한 번 실행한다. 결과가 모호하거나 새 실패가 있을 때만 추가 반복한다. 기존 573.048초는 단일 실행 참고값이며 한 번의 새 결과로 보편적인 단축률을 주장하지 않는다.

최종 검증 상한은 720초로 두고, 초과 시 검증 프로세스만 정상 취소해 미완료로 보고한다. 전체 실행은 준비·강체·배율·평가·결과 반영 시간을 분리하고 실제 반복 수·종료 사유를 함께 기록한다. 사용자 프로젝트·원본 OBJ·현재 마커·미리보기는 보존한다.

결과 채택, 승인·취소·되돌리기·다시 실행, 저장·복원과 네 형상 조합의 기존 검사를 수행한다. 짧은 계측 성공을 전체 Align 품질 검증 성공으로 대신하지 않는다.

## 9. 빌드·설치 및 완료 보고

검증된 최종 소스로 C++ Release와 확장 ZIP을 빌드한다. 필수 빌드 검사, 패치·DLL·원문 ZIP·Manifest의 일치, 격리 설치의 실제 등록과 이력 복원을 확인한다. 설치본을 새 Blender 프로세스로 확인하고, 이미 열린 Blender가 유지하는 이전 모듈·DLL과 디스크에 설치된 버전을 구분한다.

최종 보고에는 다음을 포함한다.

- 실제 채택한 단계와 보류한 단계 및 이유.
- 같은 입력의 구간별 시간, 실제 반복 수·종료 사유, 격자 생성·재사용·재생성 사유.
- 최종 행렬·배율·독립 평가·정답 오차와 기존 대비 차이.
- 격자와 프로세스 메모리, 검증 통과·미완료·기존 한계.
- 배포 버전·패치 식별자·검증한 설치본과 원본 작업 보존 여부.

이번 계획 작성은 새 문서에 한정한다. 구현·빌드·설치·커밋·푸시는 구현 작업에서 수행하며, 다른 작업이 수정 중인 파일을 함께 포함하지 않는다.

## 11. 구현 중 확인한 사항

### 단계 0·1의 정확도 보완

실제 ICP에 `RegisterWithMeshContext`와 호출 범위의 격자 재사용을 연결했다. 검증 전용 반복 관찰자는 별도 C++ 하네스에서만 사용하며 제품은 최종 합계 통계만 기록한다. 기존 공개 `Register`와 매개변수 구조체는 유지한다.

큰 검색 범위 안의 작은 메시·먼 점을 함께 사용하는 병렬 회귀에서 두 원인을 확인했다.

1. 점유 셀이 한 개인 축의 여유 영역을 만들 때 메시 격자 원점을 옮기면 옥트리의 셀 중심과 어긋났다. 공통 원점을 유지하고 점유 인덱스 양쪽을 확장하도록 수정했다.
2. 새 거리 필드의 오프셋을 첫 유한값으로 정하는 과정이 병렬로 수행됐다. 먼 점의 큰 제곱거리가 먼저 기록되면 가까운 점의 거리 차이가 정밀도 손실로 뭉개졌다. 정확 거리 검색 전에 미설정 오프셋만 직렬로 초기화하여 해결했다. 실제 조회 초기값은 계속 미정 값이며 모든 점의 거리를 계산한다.

수정 전 80개 등록 중 18개가 같은 잘못된 결과를 냈다. 수정 후 직접 거리 50회×2단계의 거리·최근접점·삼각형 ID가 모두 동일했고, 등록 30회 및 별도 스트레스 80개가 모두 통과했다. 최종 네이티브 회귀 51개와 실제 워커를 사용하는 조정자 통합 57개도 통과했다. 31스레드의 부분 겹침 100·70·40·20·10% 사례는 기존 고정 정답 기준을 통과했다.

### 후속 정책의 사전 고정 실험

수렴 후보는 제품에 반영하기 전에 검증 도구에서만 분석한다. 최소 채택 20회 이후 연속 5회 동안 RMS 감소 절대값 `1e-7` 이하와 상대값 `1e-5` 이하, 정규화 좌표의 이동 `1e-6` 이하, 회전 `1e-5` 라디안 이하, 배율 변화 `1e-6` 이하를 모두 요구한다. 상대값의 분모는 `max(이전 RMS, 1e-12)`이며 점 수 변화 또는 미채택 때 연속 횟수를 초기화한다. 가장 이른 후보는 24회차다. 이는 실험 후보이고 제품 기본값이 아니며 실제 결과를 본 뒤 완화하지 않는다.

단계별 표본 후보는 보존된 5만 점 안에서 공간 분포를 유지하는 결정적 5천·2만·5만 중첩 부분집합을 사용한다. 매 단계 다음 원본 표본에 누적 변환을 한 번 적용하고, 배율 단계는 남은 배율 경계를 전달하여 전체 기존 경계를 유지한다. 각 단계는 기존 반복 상한을 유지한다. 모델 적재·추가 격자·입력 준비를 포함한 비용으로 단일 단계와 비교하며, 불리한 후보를 제품의 숨은 옵션으로 남기지 않는다.

### 수렴 종료 후보의 검증 결과

격자 재사용을 적용한 같은 실제 입력의 전체 반복 기록을 분석했다. 강체는 200회 모두 채택되어 계산 91.444초에 반복 상한으로 끝났고, 배율은 159회 중 158회를 채택하여 37.353초에 기존 RMS 증가 조건으로 끝났다. 배율 비교 입력에는 보존한 기존 강체 결과를 적용했다. 두 시간의 합을 강체부터 연속 수행한 전체 Align 시간으로 해석하지 않는다.

### 최종 검증 도구의 파일 접수 충돌 보완

첫 Blender 검증은 첫 네이티브 요청의 원자 접수에서 종료됐다. 수집기가 접수 대기 `*.request.json`까지 일반 읽기로 열고 있었고, 같은 동작을 작은 파일로 재현하면 읽기 핸들이 열린 동안 `MoveFileExW`가 공유 위반 32로 실패하고 닫은 뒤 성공했다. Windows의 파일 공유 규칙과 일치한다. [Microsoft 파일 열기 문서](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilea)

검증 수집기는 접수된 `*.accepted.json`, 완성 응답과 세션 결과만 보존하도록 수정했다. 접수 대기 요청과 불필요한 네이티브 진행 파일은 열지 않는다. 루트 작업 진행 관측과 원본 보존 검사는 유지했다. 실패 기록은 `blender-operator-collector-failed/`, 재현 결과는 `collector-sharing-reproduction.json`에 남겼다. 완료되지 않은 첫 시도는 성능 비교에서 제외한다.
