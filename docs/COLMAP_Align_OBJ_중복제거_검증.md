# OBJ 준비 중복 계산·복사 제거

> **철회됨 — 2026-10-21:** 첫 마커 선택 지연 증가에 따른 사용자 요청으로 이번 중복 제거 변경을 되돌렸다. 런타임 파일 3개는 측정에 사용한 변경 전 소스와 바이트 단위로 일치하며, 이번 변경 전용 회귀 검사와 실행 목록 항목도 제거했다. 기존 CPU 배열 재사용·GPU 버퍼 공유는 유지한다. 아래 구현·성능 수치는 철회된 변경의 검증 기록이며 현재 브랜치의 적용 상태를 뜻하지 않는다. 설치본은 변경하지 않았다. 테스트 창을 정상적으로 열고 실제 뒤로 배치하는 실행기 수정은 유지한다.

> **후속 설치 — 2026-10-21:** 사용자 요청으로 되돌린 현재 브랜치를 다시 빌드하여 실제 Blender 5.2 설치본을 업데이트했다. 버전은 0.3.75이며 패키지 파일 1,231개 일치, 변경 전 소스 일치, 자동 활성화, CPU 재사용·GPU 공유 유지와 사용자 환경설정 파일 불변을 확인했다. [설치 검증 결과](../build/verification/install-rollback-20261021/installed-verification.json). 이 세션의 후속 GUI 작업과 Blender 창 실행은 데스크톱 2에서 수행하며, 데스크톱 2가 없을 때만 데스크톱 1을 사용한다. [세션 데스크톱 작업 규칙](세션_데스크톱_작업규칙.md)을 따른다.

## 범위와 보존 계약

2026-10-21, `codex/artec-align-engine`에서 앞서 확인한 OBJ 준비 중복을 제거한다. CPU 모델, 점 표시, 텍스처 표시와 마커용 공유 GPU 배치를 모두 가져오기 단계에서 준비한다. 최초 마커 선택이나 Align 실행으로 준비를 미루지 않는다.

원본 Blender Mesh의 정점·면·코너·UV·재질, 원본 삼각형 ID와 배정밀도 마커 교차 좌표를 보존한다. 네이티브 OBJ 파서, 정렬 엔진, 표시·선택 셰이더, GPU 버퍼 분할 크기와 공유 구조는 유지한다.

## 구현

- 표시 좌표를 `float32`로 한 번 변환해 점 표시, 법선 계산, 텍스처 배치 준비에 전달한다. 전체 정점 표시에서는 점 좌표 배열도 그대로 참조한다. 표시 상한을 명시한 부분 샘플은 해당 정점만 선택한다. 기존 법선 계산의 단정도 입력·배정밀도 누적 순서는 유지한다.
- 메시의 캐시 키는 전체 점 ID·흰색 RGB 배열 없이 원래 표시 번호를 참조해 만든다. 262,144개 단위로 기존 리틀엔디언 `uint64` 바이트열을 해시하므로 키의 결과는 같다. `tobytes()`에 의한 전체 해시 입력 복사도 제거한다. 점 표시 RGBA는 최종 흰색 배열을 직접 만든다. COLMAP 점군의 RGB 경로는 유지한다.
- 삼각형만 있는 원본은 `_ValidatedTriangleGeometry`가 좌표 유한성·면 인덱스·반복 정점을 검사하고 경계를 한 번 계산한다. 같은 동기 호출에서 같은 읽기 전용 배열일 때만 모델 생성자가 이 결과를 재사용한다. 일치하지 않는 배열은 거부하며, 일반 생성자는 계속 전체 검증한다. 검증 결과는 모델에 저장하거나 타이머 호출 사이에 캐시하지 않는다.
- 등록·표시 번호가 같은 배열이면 검사도 한 번 수행한다. 정수형 변환 뒤에는 의미 없는 유한성 검사를 하지 않는다. UV 인덱스 범위는 전체 배열을 직접 검사해 검사용 마스크 복사를 제거한다. 혼합 N-gon은 원본 코너 검사와 파생 삼각형 검사를 각각 유지한다. 공개 원본 검사에서는 필요 없는 프록시·경계 준비를 하지 않는다.
- Blender UV는 원래 `float32`로 읽어 최종 3열 `float64` 배열에 바로 대입한다. 중간 2열 `float64` 배열을 만들지 않는다. 세 번째 성분 0과 UV 성분 수 2 계약은 같다.
- 전체 면이 한 재질 그룹이면 면·UV 인덱스를 마스크로 복사하지 않고 원본 배열을 참조한다. 혼합 재질의 순서·부분 UV·원본 번호는 기존 방식으로 보존한다. 재질마다 반복하던 면의 UV 유효성 판정은 한 번만 한다.

마스크를 이용한 NumPy 고급 인덱싱은 복사를 만든다. 전체 그룹을 원본 참조로 바꾸는 근거는 [NumPy 공식 문서](https://numpy.org/doc/stable/user/basics.copies.html)다. 최종 GPU 속성 배열과 UV 이음매를 위한 꼭짓점 전개는 필요한 비용으로 유지한다.

## 검증 방법

- 변경 직전 `mesh_io/types.py`, `mesh_io/embedded_obj_store.py`, `viewport/renderer.py`를 보존했다. 변경 전 실행에서는 첫 모듈 가져오기부터 이 세 파일을 연결한다. 나머지 소스와 GPU 공유 코드는 같다.
- 같은 7,640,571,796바이트 OBJ를 기본 Blender·변경 전 애드온·변경 후 애드온에서 각각 세 번 측정한다. 정점 30,109,486개, 삼각형 60,206,247개, UV 코너 180,618,741개다.
- 최초 세 회차는 새 공장 초기 GUI 프로세스에서 `--no-window-focus`와 숨김 실행 옵션을 사용했다. 이 옵션만으로 뒤 배치가 보장되지 않는 문제가 확인되어 추가 회차에서는 정상 창을 연 뒤 측정 전에 실제 창 순서의 맨 뒤로 옮긴다. 사용자 Blender 장면과 설치본은 변경하지 않는다. 운영체제 파일 캐시는 비우지 않으며 두 번째 회차는 실행 순서를 반대로 한다.
- 기본 Blender는 실행 취소를 켠 `wm.obj_import` 명령, 애드온은 실제 `MeshImportJob`의 전체 단계를 측정한다. 축 `Y/Z`, 배율 1, 메시 검증, 오브젝트·그룹 분리 해제 조건을 맞춘다.
- 가져오기 완료와 1024×768 첫 표면 프레임·픽셀 회수 완료를 구분한다. 파일 선택, 프로세스 시작, 타이머 대기, 창 합성, 배열 해시와 독립 교차 검증 시간은 측정에서 제외한다. 따라서 버튼 클릭부터 실제 창 표시까지의 시간은 아니다.
- 모든 애드온 실행에서 원본·UV·원본 대응 등 12개 CPU 배열의 전체 SHA-256, 표시 픽셀, 같은 세 마커의 원본 삼각형 ID와 좌표를 비교한다. 첫 회의 첫 마커는 전체 원본 삼각형을 검사하는 독립 광선 교차 결과와 비교한다.
- 기본과 애드온은 표시 조명이 다르므로 두 표시 방식 간 픽셀 일치를 요구하지 않는다. 변경 전후 애드온끼리의 전체 픽셀 일치는 확인한다.

## 결과

각 방식 3회 중앙값이다. 단위는 초이며, 각 행의 중앙값은 독립적으로 계산한다.

|---|---:|---:|---:|
| 가져오기 완료 | 44.824 | 83.014 | 76.368 |
| 가져오기 + 첫 GPU 프레임 | 49.348 | 85.573 | 78.738 |
| CPU 모델 준비 | — | 18.065 | 14.256 |
| GPU 배치 준비 | — | 20.732 | 18.811 |
| 읽기 후 CPU·GPU 준비 합계 | — | 38.846 | 33.067 |

전체 가져오기 중앙값은 **6.646초, 8.0% 감소**했다. 읽기 후 CPU·GPU 준비는 **5.779초, 14.9% 감소**했다. 변경 후 애드온은 기본 Blender보다 **31.544초 더 걸리며 약 1.70배**다. 기본 경로에 없는 정렬용 CPU 모델과 사용자 정의 표시·마커 배치를 준비하는 비용은 여전히 남는다. 이 측정에는 KD-tree 생성과 Align 실행이 포함되지 않는다.

프로세스 전체 최고 작업 집합 중앙값은 변경 전 33.51GiB, 변경 후 33.60GiB였다. 임시 배열 복사 제거가 전체 과정의 최대 메모리 감소로 이어졌다고 말할 수는 없다.

### 창 배치 수정 후 추가 비교

창을 숨기거나 최소화하는 대신 정상 GUI를 열고 실제 맨 뒤로 보낸 상태에서 같은 세 방식을 한 번씩 추가 실행했다. 이 회차는 위 3회 중앙값과 구분해서 제시한다.

| 측정 항목 | 기본 Blender | 변경 전 애드온 | 변경 후 애드온 |
|---|---:|---:|---:|
| 가져오기 완료 | 43.665 | 85.794 | 75.560 |
| 가져오기 + 첫 GPU 프레임 | 48.005 | 88.313 | 78.003 |

세 프로세스 모두 최소화되지 않은 표시 상태와 다른 작업 창 뒤의 배치를 확인했다. 추가 실행에서도 원본·UV·대응 배열 12개, 표시 픽셀, 마커 ID·좌표와 GPU 배치 공유는 앞선 결과와 일치했다.

### 정확도와 회귀

- 전체 원본 정점·삼각형·UV와 등록·표시 정점, 원본 면·코너 대응, 경계를 포함한 12개 배열의 크기·자료형·전체 SHA-256·읽기 전용 상태가 여섯 애드온 실행에서 일치했다.
- 정점 30,109,486개 전체 표시, 삼각형 60,206,247개와 UV 코너 180,618,741개를 유지했다. 모든 실행 전후 원본 OBJ 크기와 수정 시간이 같았다.
- 변경 전후 애드온 1024×768 표시 픽셀 전체가 일치했다. 22개 텍스처 배치와 마커용 배치 공유도 유지했다.
- 세 마커의 원본 삼각형 ID는 `54965523`, `129076`, `36755487`로 같으며 좌표 값도 완전히 같다. 첫 회의 첫 지점에서 독립 전체 삼각형 교차 기준과 좌표 오차는 두 방식 모두 0이다. 모든 가능한 클릭 지점을 전수 검사한 것은 아니다.
- 소스 회귀 스크립트 51개 통과. 추가 검사는 검증 결과의 잘못된 연결, 잘못된 경계·정점·면·UV·표시 번호 거부, 캐시 키·표시 샘플 호환성과 좌표 공유를 포함한다.
- 실제 GPU 검사: 표면·투영·변환 24개, 혼합 재질 면 8개, 깊이 가림 2개, 큰 정수 ID 3개와 표시 픽셀 비교 2개를 통과했다. 실패 정리·캐시 교체 검사도 포함한다.

| 마커 선택 중앙값 | 변경 전 | 변경 후 |
|---|---:|---:|
| 첫 선택 | 18.410ms | 50.307ms |
| 반복 선택 | 16.494ms | 16.451ms |

첫 마커 선택은 변경 후 더 오래 걸렸다. 반복 선택 시간과 원본 삼각형 ID·좌표는 유지됐으나, 첫 선택의 지연 원인은 이번 측정으로 확정하지 못했다. 마커 계산식과 표시·선택 셰이더는 이번 변경에서 바꾸지 않았다. 이 차이를 단순한 실행 편차로 단정하지 않는다.
