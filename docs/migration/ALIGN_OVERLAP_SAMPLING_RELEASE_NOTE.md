# Align 겹침 후보 우선 샘플링 0.3.41

- 기준: main의 0.3.40
- 상태: 구현·배포 ZIP·격리 설치 검증 및 정식 Blender 5.2 설치 완료
- 계획: [겹침 후보 우선 샘플링](../COLMAP_Align_CC_겹침후보_우선샘플링_계획서.md)

## 변경 동작

사용자가 만든 3점 초기 정렬이나 현재 행렬에서 겹침 후보를 선별한 뒤 CC 정밀 정렬을 실행한다. 후보 선별용 초기 ICP는 추가하지 않는다.

- 메시: 전체 원본 면을 보존하고, 경계를 가로지르는 큰 삼각형을 임시 분할해 후보 영역을 찾는다. 그 영역에서 면적 비례로 실제 거리 검사를 통과한 50,000점을 확보한다.
- 점군: 실제 거리 반경 안의 고유 원본 좌표를 공간 구간별로 최대 50,000개 선택한다. 후보가 적으면 그 수를 사용하며 복제로 채우지 않는다.
- 후보 거리와 평가 거리는 초기 위치에서 고정한다. 점 간격이나 마커 잔차 때문에 평가 반경이 작은 형상 대각선의 5%를 초과하면 초기 정렬·밀도 확인 메시지로 중단한다.
- 등록 직전 표본의 유효 대응 비율로 코어 겹침 비율을 추정한다. 강체와 배율 단계는 동일한 원본 표본을 사용하며, 시작값 대비 추가 배율 ±10%를 유지한다.
- 후보 감소 후 남던 수렴 오차를 확인해 기본 상한을 강체 200회·배율 1,000회로 분리했다. 코어 종료 조건을 먼저 만족하면 일찍 끝나며, 등록 호출은 두 번으로 유지한다.
- 정렬 후보는 처음 고정한 방향별 최대 30,000개의 겹침 표본으로 평가한다. 이후 멀어진 평가점을 삭제하지 않는다. 초기 대응과 분포를 잃은 후보를 먼저 제외하고, 남은 후보의 방향별 RMS 평균으로 선택한다.
- UI 주지표와 개선율을 겹침 평가 RMS로 통일하고 전체 참고 RMS, 전체 평가 표본 수, 주방향 유효 대응 수를 구분한다. 기존 레이어 아이콘·미리보기·승인·버리기·Undo 흐름을 유지한다.

## 네이티브와 저장 계약

알고리즘·작업·네이티브 프로토콜은 v4다. 준비 거리 조회는 1~2048회로 제한하며, 이후 평가·등록 전 거리·강체·배율 순서와 캐시 출처를 검증한다. 한 작업은 네이티브 프로세스 하나를 사용한다. 두 원본 메시를 다시 적재하지 않으며, 등록 전 조회와 등록이 공유하는 표본은 세션 동안 유지한다.

고정 CCCoreLib의 먼 점 필터가 메시 최근접점의 삼각면 번호를 누락하던 접근 위반을 별도 안전 패치로 수정했다. 기존 배율·병렬 상태 패치는 그대로 유지한다. 안전 패치가 없는 v4 실행 환경은 사용 전에 거부한다. 패치와 최종 원문은 배포 ZIP에 포함하고 해시를 검증한다.

기존 `.blend`의 확정 행렬과 출처는 복원하며 자동 재정렬하지 않는다. OBJ 원본 면·UV, COLMAP 점·카메라와 내보내기 변환은 바꾸지 않는다.

늘어난 준비 조회의 원문을 승인 기록에 전부 복제하면 기존 256 KiB 저장 한도를 초과했다. 실행 중에는 전체 명령 순서·집계·캐시 연결을 검증하며, 승인할 때만 PREPARING 명령과 COMMAND 수명 형상을 원문 개수·SHA-256으로 요약한다. 등록·평가 명령, SESSION 형상, 세션 총계, 품질·표본 출처는 보존한다. `execution_audit_storage`가 요약 범위를 명시하며 기존 승인 기록은 그대로 읽는다. 저장 크기 제한을 늘리거나 검증을 생략하지 않았다.

## 검증

Blender 5.2.0 LTS, 전용 CPython 3.12.10·NumPy 1.26.4, 잠금된 CC·oneTBB 환경에서 검증했다.

| 검사 | 결과 |
|---|---|
| 네이티브·메시 필터 접근 위반 재현 | 38개 통과, 수정 후 접근 위반 재발 없음 |
| 후보 표본·v4 계약 | 각각 8개·5개 통과 |
| 솔버 네 조합·큰 좌표·스레드 동등성 | 43개 통과 |
| Blender 런타임·UI·저장 | 각각 8개·11개·10개 통과 |
| 합성 부분 겹침 100%·70%·40%·20% | 네 사례 모두 고정 위치·회전·배율 기준 통과 |
| 기본 배포 검사 | 279개 및 통합 등록·스테이징 실제 정렬·ZIP 무결성 통과 |
| 격리 설치본 | 네 입력 조합 정렬·승인·Undo/Redo·OBJ 면/UV·설정 검사 통과 |

저장은 준비 조회 2,048회의 최대 계약에서도 한도 안에 들어가며 재가져오기 후 동일한 감사 정보를 복원한다. 설치본의 정답 행렬 최대 원소 오차는 네 조합 모두 `3.35e-7` 이하로 기존 `1.5e-3` 허용값을 만족했다.

### 사용자 파일의 동일 표본 비교

`Untitled.blend`에 저장된 세 마커로 만든 초기 행렬을 v3와 v4에 똑같이 전달했다. 최종 비교는 v4가 처음 고정한 동일한 방향별 평가점에서 다시 계산했으며, 각 버전이 표시했던 서로 다른 표본의 RMS를 직접 비교하지 않았다.

| 결과 | 고정 겹침 RMS | 전체 참고 방향 평균 RMS | 주방향 유효 대응 비율 |
|---|---:|---:|---:|
| 3점 초기 정렬 | 0.345435 | 4.429829 | 100.00% |
| v3 결과 | 1.290505 | 3.483424 | 34.56% |
| v4 결과 | 0.297436 | 4.173361 | 95.40% |

v4는 강체 결과를 선택했다. 초기 정렬 대비 고정 겹침 RMS는 약 13.9% 감소했지만 일부 공간 구간의 잔차 증가와 더 나쁜 배율 결과 때문에 `REVIEW`를 유지한다. 전체 참고 RMS만 보면 v3가 더 작지만, 동일한 겹침 부위는 오히려 멀어진 사례다.

16스레드에서 최종 실행 벽시계 시간은 37.55초였다. 솔버 37.38초 중 후보·표본 준비 20.67초, 강체 등록 7.57초, 배율 등록 6.18초였다. 네이티브 프로세스는 하나, 물리 명령은 153회이며 원본 메시 적재는 각 1회였다. 서로 다른 질의 범위 때문에 옥트리·메시 격자는 각각 302회·151회 생성됐다. 원본 적재 공유와 공간 구조 재사용을 같은 의미로 해석하지 않는다. 네이티브 최고 작업집합은 113.36 MiB였으며 Blender·Python 전체 메모리 수치는 아니다.

v3 기준선은 다른 검사와 함께 실행되었으므로 벽시계 시간으로 속도 개선율을 확정하지 않는다. 사용자 원본은 저장하지 않았고 읽기 전후 SHA-256이 `e6088f74498ddeddf4428ce0e36ab2e94f88fb91b0ebdb4b3d7f301ca5b87406`으로 동일하다.

### 합성 높은/낮은 겹침 반복 측정

같은 시드·4스레드·강체 200회/배율 1,000회 상한에서 각 3회 순차 실행했다. 겹침 비율은 곡면 가로 구간의 공유 비율이며 실제 면적 비율과 구분한다.

| 겹침 | 세 실행 시간(초) | 중앙값(초) | 최대 정답 위치 RMS |
|---|---|---:|---:|
| 100% | 15.359 / 15.984 / 15.250 | 15.359 | 0.00000667 |
| 20% | 21.047 / 21.469 / 20.734 | 21.047 | 0.00048647 |

반복 실행에서 결과 수치와 표본 지문이 재현됐다. 상세 계측을 보존한 두 회차의 네이티브 최고 작업집합은 각각 460.55~460.96 MiB, 530.52~531.22 MiB였다. 최초 회차의 최고 메모리는 보고서에 보존하지 않아 미상으로 기록한다. 명령은 31회/71회, 원본 메시 적재는 양쪽 각각 1회였다. 기존 정확도 허용값을 완화하지 않았다.

### 재현 명령과 산출물

명령은 저장소 루트에서 실행한다. 실제 파일 비교의 출력 폴더는 실행마다 새 이름을 사용한다.

```powershell
& .\.cccore-runtime\python\python.exe -X utf8 tests/align/test_icp_cccore_partial_overlap.py --threads 4
& .\.cccore-runtime\python\python.exe -X utf8 tests/align/experiments/benchmark_overlap_sampling.py compare `
  --baseline-job build/overlap-real-v3-baseline --candidate-job build/overlap-real-v4-final `
  --solver-source tools/align/alignment --native-worker .cccore-runtime/cccore/colmap_cccore_worker.exe `
  --output build/overlap-real-common-evaluation-new
.\build_tools\test_installed_extension.ps1 -PackagePath "$PWD\build\colmap_tools-0.3.41.zip" `
  -ReportDirectory "$PWD\build\overlap-v4-final-installed"
```

- 최종 ZIP: `build/colmap_tools-0.3.41.zip`
- ZIP SHA-256: `cb12466394a0964081f4252c17884755be374b59c64fec27b03ddaf99968a473`
- 네이티브 SHA-256: `27bc503fb0fdbacba9308140789140a3245a7fb69d6508b1b9b6637065624caa`
- 설치 검증: `build/overlap-v4-final-installed/verification-report.json`
- 정식 설치: `build/overlap-v4-production-install.json`. 설치 전후 `userpref.blend` 지문이 동일하며 열린 Blender는 재시작하지 않았다. 다음 Blender 실행부터 새 설치본을 사용한다.
- 실데이터 비교: `build/overlap-real-common-evaluation/comparison.json`
- 성능 집계: `build/overlap-performance-summary.json`

겹침 RMS는 같은 부위를 알고 있는 정답 오차가 아니다. 실데이터의 독립 검사점·공통 부위 시각 판정과 RC 재구성은 이번 자동 검증에 포함하지 않았다. 반복 무늬·대칭·평행한 다른 표면을 자동으로 구별한다는 보장은 없으며, 실제 정확도 개선율과 RC 최종 품질은 별도로 확인해야 한다.
